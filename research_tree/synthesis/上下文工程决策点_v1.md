## 0 总判断（一句话）

**2024–2026 的上下文工程已具备「版本化可回滚 / 缓存连续性优先 / 承诺级可验证压缩 / 主动工具发现」四根可移植支柱，且全部可吸附 Studium 的 L0 锚点红线（压缩后仍可 grep/可锚点、机械信号只定向不结案）。** 它不再是「提示技巧」，而是被明确列为 agent 执行 harness 的**六大运行时职责之一**（harness 综述 2606.20683）——上下文管理应内建为基础设施，而非每轮让模型自选。

## 1 决策点地图

### D1 上下文解构/重构：组件移除时副作用如何回滚（H3-1）

| 维度 | 代表证据 | 等级 | 对 Studium 的进入方式 | 不进入方式 |
|---|---|---|---|---|
| **理论根基** | DSH temporal composability（北大+DeepSeek，revertible effects） | A（本地全文） | 借「组件移除=副作用完全回滚」语义作 harness 上下文管理的形式化目标 | 不引入 Cordis 运行时全栈 |
| **整库级语义回滚** | ChronoMem 2607.27773（首个开源，集成 Google ADK） | A | 借「整库快照+版本历史+自然语言回滚+post-exposure counterfactual」作长程会话状态回滚模式 | 不强求逐字段 diff（记忆天然累积覆盖） |
| **单上下文内增量重构** | LEDGER 2606.28379（依赖图局部编辑） | A | 借「依赖图+图引导精选取」保跨引用一致、替代昂贵内部推理 | 不整库处理每次编辑 |
| **上下文即运行时职责** | harness 综述 2606.20683（context=六职责之一） | A | 把上下文管理内建为 harness 基础设施 | 不当提示技巧让模型每轮自选 |

**总判断（C）**：解构/重构的核心可移植模式 = **「上下文组件应可版本化、可整版快照回滚到任一稳定点」**，且跨会话用快照+版本、单上下文内用依赖图+精选取——与 Studium L0「回滚后回到可 grep 的稳定原版」红线同向。

### D2 上下文预算/切分：何时缓存、按什么切分（H3-2）

| 维度 | 代表证据 | 等级 | 结论 | 张力 |
|---|---|---|---|---|
| **缓存收益实证** | Don't Break the Cache 2601.06007（500+会话，降本 41-80%/TTFT 13-31%） | A | 缓存**策略敏感**非普适无效；动态内容置末、防前缀断裂、排除动态工具结果比 naive 全量更稳 | 与既有 memory「网关 6%」**不冲突**——澄清为负载形态差异（稳定长前缀会话 vs 前缀多变通用负载） |
| **token≠成本** | Token Reduction 2607.12161（压缩 38.4% token 反 +6.8% 成本；r=0.15） | A | 成本度量应以 **cost-per-successful-task** 而非 token 数；缓存创建/读取主导输入侧成本 | 反对「按 token 数本地优化」 |
| **缓存连续性 trade-off** | TokenPilot 2606.17016（降本 61-87%） | A | 切分第一约束=**缓存连续性（前缀稳定）**，不是任务语义分区 | 「按上下文预算切分代理」获文献支持，但须与缓存结构对齐 |
| **缓存语义演进** | MiniPIC 2606.13126（位置无关缓存，TTFT 降两个数量级） | A | 前缀缓存→位置无关缓存，放宽「相同前缀」限制 | vLLM 类引擎默认前缀缓存不够 |

**总判断（C+A）**：**「按上下文预算切分代理，不按任务语义」获文献强支持**，且切分第一约束是缓存连续性。缓存该不该做的判定 = 看负载形态：稳定长前缀会话值得（可达 41-80% 降本），前缀多变通用负载收益有限（呼应 memory 6%）。既有 memory 不被推翻，但其适用前提须标注，避免被误读为普适断言。

### D3 上下文压缩/记忆窗口：压缩后如何保持可锚点（H3-3）

| 维度 | 代表证据 | 等级 | 对 Studium 的进入方式 | 不进入方式 |
|---|---|---|---|---|
| **承诺级可验证压缩** | Context Codec 2605.17304（commitments+round-trip recoverability） | A | **直接服务 L0 红线**：上下文=承诺集，CCL（ASCII 可读符号原子）+ 原子召回/往返可恢复性给「压缩后可 grep/可锚点」可机械验证判据 | 不用连贯散文摘要（丢承诺） |
| **符号重表达胜摘要** | Context Compression Is Not One Thing 2606.14875（+13-20 F1） | A | 借「结构化 entity-relation 符号重表达」保实体密度，匹配锚点取向 | 不优先流畅摘要 |
| **压缩盲区** | Sleeping Agent 2608.11775（时序保留 3.05%→62.39%） | A | 压缩须显式保 **temporal 原子**（日期/时间），否则时序推理退化 | 不用朴素 gist 压缩含时序事实 |
| **中编码/软压缩** | SeDeM 2608.00311、PReM 2607.14327 | A | 记忆窗口可用隐藏态+查询条件选择/刷新时机，但**需训练**，非推理期即插即用 | 不当推理期零成本方案 |

**总判断（C）**：要「可 grep/可锚点」就选**「符号化原子 + 原子级度量 + 可回退」的压缩形态**，而非连贯摘要——Context Codec 的 round-trip recoverability 给出一条可机械验证的判据，与 Studium L0 JSONL 锚点取向高度共振。

### D4 上下文与工具编排：MCP 与主动工具发现（H3-4）

| 维度 | 代表证据 | 等级 | 对 Studium 的进入方式 | 不进入方式 |
|---|---|---|---|---|
| **标准化底座** | MCP 官方规范 2024-11-05（open protocol，tools/resources/prompts） | A（官方原文） | MCP 可作工具暴露的标准底座 | 其机制局限须在 harness 层补 |
| **LLM 行为偏好致低效** | LLM within MCP Matters 2608.08467（54000 试验） | A | **风险必读**：嵌入式数据被忽略由行为偏好主导（搜索在场时 9/24 模型<15%）；host 须显式让 server instructions 优先于工具选择 | 不假设「嵌入即被读」 |
| **主动工具发现** | SING 2606.16591（减全库 schema 暴露 99.8%） | A | 借 intention-tool graph 按需发现工具，替代全量静态注入（成本高且强加 closed-world） | 不全量 schema 注入 |
| **工具选择优化** | MagicSelector 2607.17751、Over-Privileged 2606.20023 | A | 反事实分解+动态 Top-K 缓解 context distraction；特权维度须约束（最小特权） | 不放任自主选高特权工具 |
| **harness 定义** | MemoHarness 2607.14159（harness 六维度） | A | 工具编排是 harness 六职责之一，可与 DSH 组件维对齐（方向1 种子） | 不把工具编排游离于 harness 之外 |

**总判断（C）**：工具编排优先**「主动工具发现（意图-工具图）+ 动态 Top-K + 按 schema」**而非全量静态注入——匹配「有限上下文预算」与「机械信号只定向不结案」红线（工具发现是定向信号）。MCP 是标准化底座，但其「LLM 行为偏好致嵌入式数据被忽略」要求 host 层显式上下文优先级治理。

## 2 跨方向横向对照（四子方向收敛点）

四子方向在两点上**收敛**，提示它们是同一底层问题的不同切面：

1. **「上下文是一组必须存活的承诺/原子，不是一串 token」**——H3-1（组件副作用回滚）、H3-3（承诺级可验证压缩）、H3-4（server instructions 优先）都把上下文当作**有语义身份、可版本化、可回退**的对象，而非可任意裁剪的字符流。这与 Studium「锚点=原文对应、证据边不数值化」红线同源。
2. **「机械信号只定向，不结案」红线在 LLM 时代依然成立且被强化**——H3-2（依赖图可替代推理但只定向）、H3-3（压缩给候选不给结案）、H3-4（工具发现是定向信号）都未把机械结果当结案；这正是 Studium 既有红线在 harness 时代的延续。

## 3 与 Studium 既有红线/结论的逐条协调

| Studium 既有项 | LLM 主线证据 | 协调结论 |
|---|---|---|
| **L0 JSONL 锚点可 grep** | Context Codec round-trip recoverability；Telegraph 符号重表达 | 压缩选「符号化原子」形态即可保可 grep；**不冲突，且给出可机械验证判据** |
| **网关不做 prompt caching（6%）** | Don't Break the Cache（41-80%）；TokenPilot（61-87%） | **不冲突**：澄清为负载形态差异。稳定长前缀会话值得缓存（可达 41-80%），前缀多变负载收益有限（6% 适用）。memory 适用前提须标注 |
| **上下文随输入平方增长、prefill 撞 180s 墙** | SeDeM（prefill 二次方实证）；PI-Mem（3.6M token 退化路径）；MiniPIC（TTFT 降两数量级） | **不冲突**：长上下文极限靠记忆外置/位置无关缓存而非无限 prefill，印证「按预算切分代理」 |
| **按上下文预算切分代理，不按任务语义** | TokenPilot（缓存连续性 trade-off）；Don't Break（动态内容置末） | **获文献强支持**，且切分第一约束是缓存连续性 |
| **机械信号只定向不结案** | LEDGER（依赖图替代推理但定向）；SING（工具发现定向）；压缩给候选 | **红线延续成立**，LLM 时代证据强化之 |

## 4 给 Studium 的可移植模式清单（推荐草案，C）

1. **上下文组件可版本化可回滚**：长程会话改上下文组件时，整版快照+版本树回滚到稳定点（仿 ChronoMem），回滚后回到可 grep 的 L0 原版。
2. **压缩形态选符号化原子**：上下文压缩用「ASCII 可读符号原子 + 原子召回/往返可恢复性」（仿 Context Codec），不用连贯摘要；时序事实须显式保 temporal 原子。
3. **缓存策略按负载形态裁决**：稳定长前缀会话启用前缀/PIC 缓存（动态内容置末）；前缀多变通用负载维持低缓存依赖；成本按 cost-per-successful-task 度量。
4. **工具编排用主动发现**：工具按 intention-tool graph 按需检索（仿 SING），不全量 schema 注入；MCP 作底座但 host 层补「server instructions 优先于工具选择」。
5. **上下文管理内建为 harness 职责**：把 context 列为 harness 运行时职责之一（仿 harness 综述六职责），不当提示技巧。
