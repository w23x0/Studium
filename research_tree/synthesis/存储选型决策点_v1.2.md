## 6 对 M08/M09 存储选型的最终建议（推断 C 与实测 A/B 严格分开）

### 6.1 实测确立的事实（A/B，可直接引用）

1. **yaml-ld 全链路对真实 frontmatter 无损，但有两个迁移硬边界**（M1）：81/81 无损往返 + 双真相消解（YAML 权威 + RDF 派生 + 再生比对防漂移）成立；但 pyld `from_rdf` 双转义 bug 会损坏含 `\n\t\r` 的文本（5/616 字段），6/109 真实文件非法 YAML 转义（`\s`）不可严格解析——「锚点引文进 RDF」在该 bug 修复前不可行。
2. **RMLMapper JSONL→RDF 可行，但需三重约束**（M2）：原生 .jsonl 直接映射 exit=1，须 prep 成单 JSON 文档；嵌套 anchors 须第二个 triples map；增量靠行切片+分批+拼接去重（151≠145→145=145）。
3. **「JSONL 单真源 + 按需全量重建」优于「双写 + 影子读」**（M3）：522/1433 重建 0.145s、幂等字节一致；双写边际 0.0728ms/边但每笔都付；影子读 1.116s/轮。影子读能定位丢边/反向/改文/丢节点四类偏离，但**反向边对计数检查失明，必须行级多集比对**；悬空判定必须用 `rdf:type`。
4. **rdf-canonize@5.0.0 是 rdflib no-op 的可行替代**（M4）：真 RDFC-1.0；921 锚点指纹 SHA-256 稳定（10 排列 + 3 重跑 + 空白/行尾变体一致），删/增/改/换 4 变异全检出；指纹是内容判据，**不能替代字节级等同检查**（字节级另用文件字节 SHA-256）。
5. （继承 v1.1）P1：L0 保持 JSONL + 转义感知工具；P2：标准层 SHACL 在该量级可行但秒级（8.48s/81MB），接入须库调用 + 守卫；P3：ShEx '~' 不能表达 9+other，改闭合 10 列表或 sh:in；S1：NebulaGraph 不采用；S2：图查询层等触发；S3：属性图系观望维持。

### 6.2 建议方向（推断 C，供决策层采纳）

1. **L0 原文层**：维持 append-only JSONL；锚点逐字引文**留在正文**（原文侧 100% grep），不搬进 RDF（M1）；锚点校验沿用 P1 双路径（无转义锚点 grep -F + 含转义锚点转义感知解析）。
2. **迁移主路线（M1-M4 组合）**：L0 JSONL 真源 + 半自动映射（yaml-ld 管 frontmatter，RMLMapper 管结构化 nodes/edges，均含前置归一化与去重）+ 按需全量重建（0.145s/522 节点、幂等）+ 迁移校验双判据（canonical SHA-256 判内容 + 文件字节 SHA-256 判字节）+ 影子读只作迁移期验收（验证后即停）。
3. **迁移前置工程**：先修 6 个非法 YAML 转义文件（`\s`→`\\s` 或改单引号）；pyld bug 绕行方案落地前「锚点进 RDF」暂缓；RML 管线固定 `prep_jsonl.py` + `mapping-full.ttl`，增量入库前统一去重。
4. **CI 漂移检测**：把 `M1_drift.py` 的「`regen == stored` 失败即拦」固化为迁移后每次改 frontmatter 的回归门禁（M1 注入漂移全命中已实证）。
5. **L2 版本层**：FHIR _history vs 时态属性图双区间二选一仍未决，属上游设计决策，M 系列不代定；任选其一，M3 重建 RDF 的一致性好底子都可复用。
6. **图查询层触发监控**：重建成本已实测（0.145s/522 节点），S2 触发后的「只读派生索引」可行性有底数；触发判据实验仍列入待实测，避免停留在纸面。

### 6.3 一句话总结

第四轮迁移路径实测没有推翻 v1.1 的「分层双轨」总判断，但把迁移路径从「纸面设想」压实为**四件套实测**——yaml-ld 无损但有两个硬边界（M1）、RMLMapper 可行但需预处理+去重（M2）、「JSONL 单真源 + 按需重建」优于「双写 + 影子读」且须行级比对（M3）、canonical 指纹采纳 rdf-canonize 且是内容判据非字节判据（M4）；三个候选方向（S1 不采用 / S2 等触发 / S3 观望）全部维持，L2 版本层二选一仍是唯一未决的设计裁决点。
