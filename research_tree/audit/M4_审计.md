## 四、整改意见（PASS，非阻断）

1. **计时/内存读数标注加固（可选）**：报告已把耗时标为"单次运行墙钟、非性能基准"，但内存读数（rss 59.70 / heapUsed 18.94）未同句标注。复跑中这些读数同样随运行抖动（rss 71.36 / heapUsed 16.54）。建议在内存行后加一句"单次进程读数，随运行环境抖动，非基准"，或与耗时段合并为同一标注，保持自查声明"一切数字可溯源"的精确性。不构成判死，因语义结论不依赖任何计时/内存数字。
2. **canonical 输出文件的字节稳定性留痕（可选）**：报告称输出文件"在多次运行间字节稳定"。审计员复跑生成的文件 119504 字节/921 行、指纹不变，佐证成立；但未在 M4 目录留存第二份运行拷贝供后续比对。若要强化可复现留痕，可在 README 记一次运行前后文件 SHA-256，或把首次生成的 canonical 文件单独存档。
3. **P1 对照数字归因（信息性）**：问 1 中 rdflib no-op 的三重证据（`**kwargs` 吞参、`canonical_identical_to_regular: True`、`canonical_ordered == canonical_shuffled: False`）均来自 P1，报告已以"P1 三重证据"归因，标注正确；若后续审计希望 M4 独立复现该对照，可在含空白节点补测时（第 6 节建议 3）顺带用 venv 内 rdflib 7.6.0 重跑一次 canonicalize 对照，使对照证据留在 M4 自己的产物里。
