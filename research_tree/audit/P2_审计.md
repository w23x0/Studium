## 四、整改意见（均为非致命文字级问题）

1. **§5.1 的"同文件"措辞不准确**：实测复算 78.8%（734/931）来自"evidence 命中**任一节点**锚点"，与文件无关（按文件同文件锚点匹配实测为 0）。数字 78.8% 是真实且可复现的，但"同文件"定语会误导读者以为该比例带文件边界。建议改为"命中任一节点锚点（不限文件）"。
2. **§4 的 pyshacl README 声明**：报告称"README 声称 0=合规、1=不合规、2=错误"。实测/源码显示 exit=2 还覆盖 RuleLoadError（源码 L364–367），报告"坑 3"列举的 pyshacl 错误类漏了 RuleLoadError。建议补一句"及 RuleLoadError"，避免读者以为 2 只覆盖列出的四类。
3. **§2 的"初版曾误报 1638 条"**为开发史注记，无法从当前脚本状态独立复现（当前 shapes/代码已修正，复跑 0 条 Closed 违规）。作为透明的修正记录可接受，但若下游引用该数字宜标注"历史注记，非当前输出"。
4. **时序建议**：报告结论按"秒级量级"表述正确；若后续进 CI 作量级哨兵（§6.5），阈值建议按报告自述 ±20% 带设宽容度（本次复跑 10.0 s 已落在该带内）。
