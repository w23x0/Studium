## 0. 一句话结论

**五家族对「理科知识表达」的实质能力与局限可以三句话收拢：类型论（命题即类型）把「证明做成对象、推导做成类型」——它是唯一把「断言之间的关系」做成可机器校验结构的家族，但只能保证「从所选公理可推导」、不保证「断言与某本教材原文对应」，这一条与 06-M08 §8「瓶颈不在表达力、在验证」的判据完全同向；因果模型（SCM/do-演算）为「关联/干预/反事实」三层语义提供了统计关联之外唯一成熟的表达能力，但其因果结构本身是模型员的断言（带同样的锚点对应负担）、且干预语义无法落在 RDF/OWL 的标准语义里；概率程序（Church/WebPPL/Stan）把「不确定性知识」表达成可执行的生成式程序，但模型=程序、推理=采样，其执行语义同样在 RDF 之外；程序合成（DreamCoder wake-sleep）证明「从解法提炼可复用抽象、库变厚」的循环在 2021 年即已被机器跑通（rediscover 牛顿/库仑定律），但其抽象来自解法语料的重构，不是无中生有；向量（word2vec/SAE）提供的是分布相似度与「特征=方向」，天然只能定向、不能结案——SAE 官方自述「特征不完整、缺乏评估是否忠实捕获计算的方法」。对已定 v1.3：五家族的「对象/形态」层（定理=节点、因果图骨架、抽象库产物、嵌入字面量）都能承载在 L1 RDF 语义层上；五家族的「语义」层（推演、干预、采样执行、身份）全部在 RDF/OWL 2 语义之外——这一分界恰好就是 06-M08 §8「借形态、不借验证」的存储侧印证，存储选型无需因五家族而改动。**

## 1. 父会话问题逐条回答（每问：结论+依据+等级）

### Q1. 《几个方向》五家族从谱系清单推进到证据级：各自对「理科知识表达」的实质能力与局限？

**总判断：五家族在「理科知识表达」上可归为两条轴——「对象轴」四家族（类型论/因果/概率程序/程序合成）都能表达「对象及其关系」，只是各自的强语义不同；「相似轴」向量家族只表达「对象间的分布相似度」。五家族的能力都是真能力（有原文佐证），局限也都在原文里。**

**类型论（命题即类型）**
- 能力：把命题与类型合一（Curry-Howard），「证明=λ 项」成为一等地对象（SEP A）；依赖类型把定义/命题/证明统一在同一语法里；归一化定理给良型项以计算内容（任何归约序列终止）。Univalence/HoTT 增加「相等即结构」（等式的路径解释）、可运输性质，HoTT 官方自述「最终会成为集合论的替代基础」（A）。
- 局限：Girard 悖论迫使 Martin-Löf 取走（2）——类型论是**谓词的**（SEP A），不能同时有不可谓词化+依赖类型+命题即类型；同一性类型不保证至多一个元素（内涵性）；这些局限让「一套类型论」表达不了「教材的全部断言」，只表达「形式化出来的那一部分」。**最实质的局限：它保证的是可推导性，不是对应性。**
- 等级：A（SEP + HoTT 书页原文）。

**因果模型（SCM / do-演算）**
- 能力：Pearl 给出三层因果阶梯（关联/干预/反事实），各层问题只能由≥该层信息回答；SCM=图模型+结构方程+反事实/干预逻辑三件套；do-算子把「观察」与「干预」区分开（A，Pearl ar5iv 全文）。对理科知识：它给「如果我把 X 设为 x 会怎样」这类**反事实问题**提供了统计学之外唯一的成熟语义。
- 局限：Pearl 自己断言当前 ML 系统「几乎全部运行在统计/无模型模式，不能推理干预与回溯」（A）；因果结构（图、方程、假设）是模型员**编码的断言**，需要可检验性（d-分离），不是从数据自动涌现——这带着与锚点判等相同的「断言对应」负担。
- 等级：A。

**概率程序（Church/PLoT 线）**
- 能力：PPL「统一了计算的正式描述与不确定知识的表示与使用」（dippl，A）；模型=程序、以「条件化」为基本计算（van de Meent，A）；一阶 PPL 对应图模型、高阶 PPL 支持动态计算图（每次执行可能实例化不同随机变量集）（A）。
- 局限：推理=「反复执行程序采样」（van de Meent，A）——表示层与推断层分离，推断是近似的；「模型=程序」意味着一个概率程序的真假是关于**生成数据的过程**，不是关于教材断言的对应。
- 等级：A。

**程序合成（DreamCoder）**
- 能力：wake-sleep 三阶段（清醒解题→抽象睡眠扩库→梦境训练模型）把「从解法提炼可复用抽象、库变厚」做成机器可跑的循环；DreamCoder 在经典归纳编程+绘画/搭场景任务上 rediscover 了函数式编程、向量代数、经典物理（牛顿/库仑定律）（A，abstract+HTML 全文）。产出是「可解释、可迁移、组合式」的符号抽象。
- 局限：抽象来自**解法语料的重构**（把常见程序片段抽象成新原语），不是凭空发明；能力受 DSL 表达力边界约束；且 DreamCoder 的扩库是自动的——把「人工审计」这一环加上是 Studium 的自有要求，不是 DreamCoder 的。
- 等级：A。

**向量嵌入 / SAE**
- 能力：word2vec 从超大数据集学连续词向量，在词相似任务上达 SOTA（A）；SAE 从残差流抽出最高 3400 万特征，对应「著名实体/地点」与「讽刺/代码错误」等抽象概念，且操纵这些特征「因果性地影响模型输出」（Scaling Monosemanticity，A）。对理科知识：向量给「哪些对象相似/可能同义」提供了廉价候选信号。
- 局限：SAE 官方自述「特征套件不完整、缺乏严格方法评估特征是否忠实捕获模型计算」（A）；word2vec 的评估基准是词相似度，不提供身份判定；KG 嵌入调查明确嵌入是**为链接预测设计、对图谱实体的低维投影**（A）——派生投影不能做身份本体。
- 等级：A。

### Q2. 06-M08 §8 取用结论（借证明作为对象/向量只定向/DreamCoder 循环形状）逐一验证：哪些成立、哪些需修正？

**Q2a. 借「证明作为对象」——成立，无修正；且给出更精确的存储语义。**

- 成立证据（跨 V1 与本任务）：V1 已用 Metamath/MML/Lean 证明形式化库把证明存成引用列表（A）；本任务 SEP Type Theory 给出理论侧根源——「命题即类型」、「证明=λ 项」、「同一性类型=等式证明的类型」（A）。"证明作为对象"在类型论不是比喻，是语法：proof 是类型为命题的项，可被引用、可被区分（群胚解释中同一性类型可有多个元素）。→ M08 把定理的假设/结论放进节点字段、`requires` 由字段派生，正是"证明对象化"的形态借用。
- 需要修正/精确化的点：SEP 显示证明对象在**内涵**类型论里可区分（同一性类型不保证单元素）、且依赖类型是谓词的（Girard 悖论）。这意味着「证明作为对象」的形态借用**只能在"节点带结构字段"这一层成立**，一旦想借"证明的推导语义"（依赖类型/归一化），就超出 M08 需要、也超出 06-M08 §8 当初"不借整套形式化验证"的边界。§8 的取舍无需改。
- 等级：A（SEP/V1）+ C（对应 M08 映射）。

**Q2b. 向量「只做定向，不借结案权」——成立且被本任务更强支持，无修正。**

- 成立证据：word2vec 官方评估=词相似度（A），SAE 官方自述特征不完整、缺乏忠实性评估（A）——两个原始文献都只把向量定位在"相似/特征方向"层，没有任何原始文献声称向量可判定对象身份。KG 嵌入调查进一步说明嵌入是**对图谱实体的投影**（为链接预测设计）（A）——投影天然不承载身份。
- 需要修正/精确化的点：无方向性修正，但可加一条——KG 嵌入的存在说明「向量与图」不是竞争而是派生关系（向量由 RDF/L0 结构派生），这与 v1.3「L0 JSONL 真源」同构：向量应视为 L0/L1 的**派生可丢弃层**，不是独立真源。
- 等级：A。

**Q2c. DreamCoder「从解法提炼可复用抽象、库变厚」循环形状，与 L2 提案同构——成立，但需一处精确化。**

- 成立证据（原文逐句）：wake 阶段「在库与识别模型固定下推断程序」；抽象睡眠阶段「更新库、把清醒时找到的程序重构、把常见片段抽象成新代码原语」；梦境阶段「训练识别模型逼近程序后验」。原文明确「该机制增加学习者**陈述性知识**（其学到的库）的广度与深度」；「每轮抽象建立在早前睡眠周期发现的概念上」→ 库变厚的循环是原文直接描述的（A，HTML 全文）。
- 需精确化/修正的点一：循环不是"库变厚→自动解更难任务"单向自动——抽象睡眠的输入是**清醒阶段解出的程序**（解法语料），抽象是从解法里**重构**出来，不是凭空涌现。对 M08/L2 的含义：抽象候选必须有「一批已确认的下层对象（members）」作为重构来源——与 M08 §4.1「候选池+审计晋升、抽象来自 members」完全一致，也解释了为何没有 members 就没有抽象。
- 需精确化/修正的点二：DreamCoder 的扩库是**自动**的（机器重构）；§8 借的是"循环形状"、明确不借自动入库（16.7% 存活率须人工审计）——本任务确认：人工审计是 Studium 的**增量要求**，DreamCoder 原样不含这一环。§8 的取舍无需改。
- 等级：A（DreamCoder 原文）+ C（与 L2 同构映射）。

**Q2 总评：三条取用结论全部成立，无一需推翻；两处需在合成/实现侧精确化（证明对象=形态非语义；DreamCoder 循环=解法重构 + 人工审计是增量）。这印证 06-M08 §8「没有一个家族现在到了可选型的程度，因为瓶颈不在表达力，在验证」——五家族的原始文献都不承诺「断言与原文的对应」。**

### Q3. 五家族与已定 L0 JSONL/L1 RDF/L2 FHIR 式（v1.3）的结合：哪些表达形式能承载在 RDF 语义层上，哪些冲突？

**总判断：把五家族切成「形态层」与「语义层」——形态层（对象、字段、图骨架、抽象产物、嵌入字面量）全部可承载于 L1 RDF；语义层（推演、干预、采样执行、身份判定）全部在 RDF/OWL 2 标准语义之外，只能外部计算或以注释/推理 reification 形式挂靠。**

**可承载于 L1 RDF 语义层的（不冲突）：**
- 类型论的「对象形态」：定理=节点 + hypotheses/conclusion 字段（已在 06-M08 §3/§8 采用），RDF 里就是节点+字面量/属性边，无冲突。【A 本地 §8 + A OWL2】
- 因果模型的「图骨架」：DAG 边、结构方程断言、d-分离可检验的图结构——图结构是 RDF 的表达主场；PROV-O 的 wasDerivedFrom/wasGeneratedBy 提供了"派生/生成/使用"关系（A W3C），可承载"哪个结果由哪个活动生成"的骨架。【A W3C PROV-O】
- 程序合成的「抽象库产物」：抽象=节点 + members + 定义，与 M08 L2 抽象候选节点同构；每个抽象候选用 v1.3 的 FHIR 式版本化（versionId/_history）独立演化，无冲突。【A DreamCoder + A 本地 v1.3】
- 向量的「派生嵌入」：把嵌入向量作为节点上的字面量（如 embedding literal）存放，向量是 L0/L1 的派生注释，不参与身份判定。【A KGE + A 本地 §8】

**在 RDF 语义层上冲突 / 需留外部计算的：**
- 类型论的「推演语义」：依赖类型、univalence、高阶归纳类型超出 OWL 2（SROIQ 描述逻辑=FOL 的片段，"useful computational properties"即可判定性换取表达力）——想表达"证明可推导"需要外部证明检查器，RDF 只存证明对象不存推导关系。【A W3C OWL2】
- 因果模型的「干预语义」：do-算子、反事实分布 P(y|do(x)) 需要三层（关联/干预/反事实）代数语义，RDF/OWL 是经典一阶语义、无干预算子；PROV-O 的 wasDerivedFrom 是"变换/依赖/构造"类关系（W3C 原文），**不是干预语义**。想表达"若干预 X 则…"必须外部计算或自定义扩展（超出标准 RDF/OWL 2）。【A W3C PROV-O + A Pearl】
- 概率程序的「执行语义」：模型=程序、推理=采样，执行在 RDF 之外；把程序文本作为注释字面量可以挂靠，但"程序执行产生分布"的语义不在 RDF 语义内。概率本体的研究线（PR-OWL/MEBN，B 级二手）表明"在 OWL 上加概率"是活跃方向，但 PR-OWL 不是标准 RDF/OWL 2，v1.3 的 L1 若保持 OWL 2 语义则概率语义须留外部。【B PR-OWL 二手 + A van de Meent】
- 向量的「身份语义」：向量是投影，RDF 身份仍是 IRI/锚点；向量不能作为 RDF 的身份机制（呼应 M08 §1 同名异物）。这不算"冲突"而是"向量不承载身份"——与 v1.3 无冲突，只是约束【A KGE + A 本地 §1/§8】。

**对 L2 FHIR 式版本层的结合**：五家族的产物（定理节点、因果图节点、抽象候选、向量注释）都可作为 FHIR 式"资源"独立版本化——refuted（复检推翻）与 entered-in-error（写错撤回）两个状态正好可映射到「某个抽象候选被审计推翻」与「手写节点写错撤回」，无冲突。【A 本地 v1.3 + C 映射】

**等级：A（OWL2/PROV-O/DreamCoder/KGE/Pearl/van de Meent 原文）+ C（映射组合）。**

## 3. 对决策点的输入

**决策点 = 「五家族表示形式系统化与 M08 结合」（state.json meta decision_points #2）。**

**输入 1（能力画像，供 M08 判断借什么）**
- 类型论：唯一把「断言间关系（推导）」做成机器可校验结构的家族，但只保可推导不保对应。【A】→ 借「证明作为对象」形态（已是 §8 定案），不借推导语义。
- 因果模型：唯一提供「反事实/干预」语义的家族。【A】→ 因果图骨架可落 RDF；干预语义留外部，且因果断言本身带锚点对应负担（同人工审计）。
- 概率程序：唯一把「不确定性」做成可执行模型的家族。【A】→ 程序文本可作注释字面量；采样执行留外部。
- 程序合成：唯一实证「从解法自动提炼可复用抽象」的家族。【A】→ 抽象候选节点可落 RDF + L2 FHIR 式版本化；抽象须有 members 来源（解法语料）。
- 向量：唯一提供「相似度候选」信号的家族，且是图谱/文本的派生投影。【A】→ 只定向不结案（§8 定案）；向量是 L0/L1 派生可丢弃层。

**输入 2（与 v1.3 的结合边界——本任务新增、可直接进合成）**
- 五家族切「形态/语义」两层：形态层（对象、字段、图骨架、抽象产物、嵌入字面量）全部承载于 L1 RDF；语义层（推演、干预、采样执行、身份）全部在 OWL 2（SROIQ=FOL 片段）标准语义之外。【A 组合 + C】
- 因此存储选型不需要因五家族而新增任何层或格式；「更强载体暂不选、只借三处局部机制」在存储侧被印证：L1 RDF 就是那「三处局部机制」的载体。【A 本地 §8 + C】

**输入 3（L2 版本层映射）**
- 五家族产物（定理/因果图节点/抽象候选/向量注释）均可作为 FHIR 式资源独立版本化；refuted（复检推翻）↔ 抽象候选被审计推翻、entered-in-error（写错撤回）↔ 手写节点写错撤回——与 v1.3 L2 条件性定案无冲突。【A 本地 v1.3 + C】
