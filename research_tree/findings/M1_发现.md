## 0. 一句话结论

真实 frontmatter（7 个字段、81 个 L1 文件）经 python-yaml-ld 做 YAML→RDF→YAML 往返是**语义无损**的（81/81 通过、N-Quads 字节相等、图同构、字段级 541/541 一致），双真相可消解为「frontmatter YAML 权威 + RDF 确定性派生 + 再生比对防漂移」（确定性/再生/注入漂移均实测通过），L0 锚点红线在**原文侧 100% 保持可 grep**（94/94）；但原型暴露了两个迁移硬边界：① **6/109 个真实文件的 frontmatter 无法被严格 YAML 解析**（双引号串含 `\s` 等非法转义），② **pyld `from_rdf` 存在 N-Quads 双转义 bug**，会把含 `\n`/`\t`/`\r` 的 LaTeX 文本（如 `\nearrow`、`\theta`、`\tag`、`\to`）损坏为「反斜杠+控制符」——这直接威胁"锚点引文进 RDF"的迁移设想。

## 1. 问题逐条回答

### Q1 python-yaml-ld 能否把真实带 frontmatter 的 md 语义无损转 RDF 并往返（YAML→RDF→YAML）？

**实测结论：能，且对真实 frontmatter 是语义无损的（81/81 文件通过）；但存在两个必须处理的边界。**

- **frontmatter 往返（迁移主场景）：81/81 文件通过。** N-Quads 两次转换**字节相等**（`byte_equal_nquads: True`），rdflib 图同构（`graph_isomorphic: True`），字段级逐键比较 541/541 一致、0 缺失 0 不匹配（`run_output_roundtrip_frontmatter_only.txt`）。字段覆盖 L1 的 `name/name_en/node_type/origin/layer/sections/aliases` 全部 7 个；数组字段（sections、aliases）经 `@container: @list` 转 RDF list，顺序保持。
- **实测的「无损」口径 = 语义级（YAML 数据结构），不是字节级。** 与 B7a K12/Q2 结论一致：注释、键顺序不保留；且**文件里双引号串中的 `\n` 在解析阶段即被 YAML 解释为换行**（标准 YAML 转义，非 bug）——例如 increasing-sequence.md 的 aliases `"$f(n)\nearrow$"` 解析后实为 `$f(n)<换行>earrow$`（逐字符 U+000A 证实），该值往返一致。这符合 YAML-LD Basic profile「语义信息无损」承诺，但对「逐字 grep 原文」工作流意味着：**frontmatter 解析后的值 ≠ 文件原始字节**，逐字红线只对正文成立（见 Q3）。
- **边界①（解析阻塞）：6/109 个 frontmatter 无法被严格 YAML 解析。** PyYAML 与 ruamel(safe) 均拒绝，错误均为「double-quoted scalar 中出现 unknown escape character」，例如 asymptotic-equality-notation.md 的 `name: "渐近相等记号 $a_n \sim b_n$"` 里的 `\s`。6 个文件：asymptotic-equality-notation、decreasing-sequence、euler-constant、gamma-function、mixed-improper-integral-notation、riemann-zeta-function（均 L1）。Obsidian 自己的 frontmatter 解析器是宽容的，但 python-yaml-ld 栈（PyYAML/ruamel）是严格的——**迁移路径上必须先对这批文件做引号转义修复或改用宽容解析器**。
- **边界②（往返数据损坏）：把正文 LaTeX 引文并入 RDF 往返时，5 处值损坏。** `--with-anchors` 把正文「原文锚点」逐字引文（LaTeX 密集）作为字面量字段并入文档后，616 个字段检查中 5 个 mismatch，76/81 文件通过。损坏模式：`\theta`→`\`+TAB+`heta`、`\tag`→`\`+TAB+`ag`、`\nearrow`→`\`+换行+`earrow`、`\to`→`\`+TAB+`o`（见 violations.json）。**根因已定位到 pyld `from_rdf` 的 N-Quads 解析器**：to_rdf 产出的 N-Quads 文本正确（`"a\\nb"`，即 N-Quads 对反斜杠的标准转义），rdflib 解析同一文本得到正确值 `a\nb`，唯独 pyld 的 `from_rdf` 把它解成 `a\`+换行+`b`（U+005C+U+000A）。受影响的转义集合实测为 `\n`、`\t`、`\r` 三个（`\b \f \u \s \l \\ \"` 均不受影响）。

### Q2 双真相风险在迁移路径上如何消解——迁移后权威载体是哪一个、如何验证不漂移？

**实测结论：权威载体 = frontmatter YAML（md 文件内，人手编辑、git 跟踪、grep 直达）；RDF(N-Quads) = 派生构件，绝不手改。双真相靠「确定性纯函数 + 再生比对」消解，四项实测全部通过（`run_output_drift.txt`）。**

- 迁移：103 个合法 frontmatter 节点 → 979 条三元组 / 98950 字节 N-Quads（`migrate=0.0089s`），存为 `out/migrated/graph.nq`。
- **[1] 确定性**：同一 doc 两次 `to_rdf` 字节相等（`deterministic_bytes_equal: True`）——RDF 是 YAML 的纯函数，同一输入必得同一输出，这是「不会漂移」的机理基础（注：blank node 命名在 pyld 中也是稳定的，实测字节级成立）。
- **[2] 再生比对**：`to_rdf(当前 YAML) == stored RDF`（`regen_matches_stored: True`）——这就是漂移检测器的实现：每次改 YAML 后重新生成并 diff，不等即漂移。
- **[3] 注入漂移全命中**：手改 stored RDF 一个字面量（`"theorem"`→`"theoremXXX"`）→ 再生比对准确定位（True）；改 frontmatter 一个值后重新转换 → 与 stored 不等（True）。即双向漂移（RDF 被手改、YAML 被改动）都能被检测。
- **[4] 反向恢复**：`from_rdf(stored RDF)` → compact → 逐字段对比原 frontmatter：**651/651 一致、0 缺失 0 不匹配**（`recovery_field_stats`）——RDF 是 YAML 的忠实投影：RDF 丢失可从 YAML 重建，YAML 丢失可从 RDF 还原，二者不构成相互矛盾的权威。**唯一例外**是含 `\n`/`\t`/`\r` 的字段：pyld 双转义 bug 会让反向恢复损坏（见 Q1 边界②），这类字段必须以 YAML/正文为权威、禁止进 RDF 再读回。
- 消解规则（实测支撑）：**YAML 是唯一手写真相源；RDF 只写不读、只做查询/校验/推理；任何 RDF 消费前先跑再生比对**。漂移验证命令即重跑 `M1_drift.py`（见 §7）。

### Q3 迁移产出的 RDF 能否回到可 grep 文本（守住 L0 锚点红线）？

**实测结论：能，但分层——原文侧 100% 可 grep；RDF→文本恢复侧 94% 直接可 grep；N-Quads 原始文本仅 51% 可直接 grep。三条路径数字各异，正是「正文逐字 vs 图值语义」两种口径的分界（`run_output_grep.txt`）。**

| 路径 | 命中 | 说明 |
|---|---|---|
| A 原文 .md 内 grep（等价 grep -F） | **94/94 = 100%** | 迁移不改正文，锚点逐字串原样可 grep；3 个样本用真实 `grep -F` 复验全过（3/3 文件） |
| B N-Quads 文本内直接 grep | 48/94 = 51% | N-Quads 把字面量中的 `\` 转义为 `\\`，含反斜杠的 LaTeX 锚点原文子串不命中（标准序列化转义，非数据损坏） |
| C RDF→YAML 恢复文本内 grep | 88/94 = 94% | 6 个不命中：5 个是 pyld 双转义数据损坏（`\n`/`\t`/`\r`）+ 1 个是 YAML 单引号转义（raabe-test 的 `Raabe's`→`Raabe''s`，属正确序列化） |

- **L0 红线结论**：锚点逐字 grep 的守护目标在「原文正文」，而迁移路径保持正文不动 → **红线 100% 守住**（A 94/94，含真实 `grep -F` 佐证）。RDF 不是逐字 grep 的载体——它是语义载体；从 RDF 恢复文本后直接 grep 命中率 94%，且那 6 个不命中里 5 个是数据损坏（必须修 pyld bug 才能保住），1 个是转义（用转义感知 grep 即可）。

## 2. 实测方法与脚本说明

三个脚本存于 `C:/Users/Wang/Desktop/Studium/research_tree/_sources/M1/`（含 `README.md`），全部在 Studium 仓库根目录运行，用真实数据：

1. **M1_roundtrip.py**（Q1）。对每个真实文件：正则切出首部 `---` frontmatter 块 → PyYAML `safe_load` → 附 `@context`（7 字段映射到 `https://studium.example/vocab#`）+ `@id`（文件路径派生）→ `yaml_ld.to_rdf`（N-Quads）→ `yaml_ld.from_rdf` → `yaml_ld.compact` 回 YAML。三重判等：① 两次 N-Quads 字节相等；② rdflib 图同构（`rdflib.compare.isomorphic`）；③ compact 结果逐键比对原 frontmatter。可选 `--with-anchors` 把正文「原文锚点」引文并入文档测 LaTeX 过 RDF。解析失败的 frontmatter 单独计入 `files_parse_failed`，不混入违规。
2. **M1_drift.py**（Q2）。迁移生成 stored N-Quads → 重新生成测确定性/再生比对 → 分别注入 RDF 与 YAML 漂移验证检测命中 → `from_rdf`+compact 反向恢复并逐字段比对。
3. **M1_grep.py**（Q3）。对每文件提取正文锚点，跑 A（原 .md 子串=grep -F 语义，另 3 文件真实 `grep -F`）、B（N-Quads 文本子串）、C（RDF→YAML 恢复文本子串）。

判定红线：不伪造数字——全部数字来自 `run_output_*.txt`（tee 保存的真实 stdout）与 `out/*.json`。

## 5. 未决与风险
