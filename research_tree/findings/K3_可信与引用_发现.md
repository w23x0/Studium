## 0. 一句话结论

**2024–26 的外部证据不仅保住、还加严了「锚点判等=原文逐字对应」「机械信号只定向不结案」这条红线：LLM 自己的引用/归因信号本身被证不可靠——同一批输出在不同校验器下无支撑引用率在 3%~18% 之间漂移（2607.20527）、pinpoint 页级支撑漏判 37–63%（2608.12571）、临床 RAG 能通过全部自动化检查却把 B 药证据安到 A 药头上（2607.09349）、模型贴引用的机制并非语义接地（2606.28358）——所以「机械信号」这一族现在必须扩到**包含 LLM 生成的引用、归因、entailment、相似度**；而 2024–26 给出的补救机制（gold-anchored 评估协议+确定性重归因+conformal 界、retrieve-then-verify、sufficiency check、文本回退、实体归因校验）在结构上与 Studium「锚点+人工闭环审计」同构，其新增可机械化检查（实体归因校验 97% 精度、CiteCheck 式元数据判等）只能当**更强的定向信号**，结案权仍归锚点 grep -F 对 L0 原文。V6 的 CS-RAG 反转（图结构不单独结案、退回原文）被泛化为「一切非原文信号都不结案」；V3 的「本体推理只定向」被 2024–26 实测直接支持并扩展。**

## 1. 父会话问题逐条回答（每问：结论+依据+等级）

### Q1 2024–2026 文献中，LLM 生成/检索的知识如何保证可信与可溯源？有哪些新机制？

**结论：可信/可溯源从「输出质量」转向「验证过程与成本」——新机制可归为五族：归因作为一等输出、检索接地的事实核查代理、sufficiency/停止判据、元数据级引用校验、系统级多层防御。没有任何一族的结案级输出被证可靠。**

- **归因作为一等输出（A）**：Attributed QA 系把「答案+归因报告」作为产品形态——2410.16708（ARE）把长回答拆成原子事实再逐条检索编辑、2506.16988（RAGentA）多智能体迭代过滤+行内引用+完整性校验、2606.07130（FullCite）结构化行内引用+约束解码+事后 span 对齐。但 FullCite 实测：**LLM 选对文档但选不对支撑 span**——归因粒度卡在「span 级」。
- **检索接地的事实核查代理（retrieve-then-verify，A）**：2507.03671（RAV 三代理：出题/作答/判题）、2608.08612（REVEAL 检索→sufficiency 校验→缺口重检索）、2607.18240（ECE 证据链评估+允许弃权 abstention）、2604.21193（DAVinCI 归因+entailment 校验+置信度校准）。共同点：**验证不再是一次模型判断，而是「检索证据→按判据核对→不足则重检索/弃权」的流程**。
- **sufficiency check 与停止判据（A）**：CS-RAG（V6 种子，2603.14828）的 sufficiency check 在 2026 被一般化为独立机制——2608.08612（REVEAL「检索相关但证据不足就停下来回答」是病、sufficiency 判据是药）、2604.09174（facet×chunk 矩阵逐原子面评估 sufficiency+grounding）、2608.13237（S2G 式结构化 sufficiency-and-gap 判据作为 RAG 停止策略，77 次检索调用换来 -0.625pp Exact Match）。
- **元数据级引用校验（A）**：2605.27700（CiteCheck：外部学术库检索+结构化 LLM 比对→Exact/Minor/Major 三档，88.7 macro-F1）、2607.11127（法律条文引用造假双语基准：GDPR 直取 94–100% vs 沙特法 60–77% 多数编造，法规 vs 条例混淆致最高 67% 编造率）、2605.28565（CITETRACE 761,495 个引用对，三维框架：意图-目的对齐/来源适配/答案-来源保真）。
- **系统级多层防御（A）**：2607.17883（HALO 六层：接地生成/约束执行/多信号验证…，把幻觉当「可包容的失败模式」而非「可消除的属性」）、2606.17467（PARSE provenance-aware 检索消毒+一致性校验回路）、2608.00033（SIRIN 三类探测器统一工具包：表示探测/不确定性/判官校验+回答前置 answerability）。
- **证据等级**：Q1 结论 A（全部依据为 curl 到手的 abs 摘要/部分全文）+ C（归族为综合）。

### Q2 锚点判等（引用=原文逐字对应）在 LLM 时代如何落？LLM 抽取的知识是否需可核、如何核？

**结论：锚点判等在 LLM 时代不是被替代，而是被证明**不可少**——因为 LLM 自己的引用/归因全部落在「claim/文档」粒度、且在该粒度也不可靠；逐字 span 级（=Studium 锚点所在粒度）恰恰是 LLM 机制实测最弱的环节。LLM 抽取的知识必须可核，2024–26 的核法收敛为「retrieve-then-verify + sufficiency check + 文本回退」三元流程，而这正是 Studium 锚点 + 人工闭环审计的流水线化。**

- **LLM 机制在 span 级失败（A）**：2606.07130（FullCite）「LLMs are generally effective at identifying relevant documents, they struggle to identify the precise supporting spans within them」——逐字 span 对应是 LLM 归因最弱处，恰是锚点所在粒度。2608.12571「Models catch 93-100% of wrong-case corruptions. They catch only 37-61% of wrong-pinpoint corruptions…they accept the citation based on topical overlap rather than page-level support」——**顶层话题对上了 ≠ 页面级支撑对上了**，与 memory 盲区笔记的 D 型（射程不足）+A 型（对象错）同构。2607.09349 更极端：通过全部检查（零幻觉/近满分保真/真引用）却实体错位。
- **LLM 归因机制本身不语义接地（A）**：2606.28358 机制可解释研究「the faithfulness of these citations…remains a critical, unverified assumption」，发现引用由一个分布式「attributional ensemble」决定，与模型表面推理「存在脱节（disconnect）」——**模型决定贴引用不等于它真用了该来源**。这直接推翻「LLM 行内引用=接地证据」的默认假设。
- **核法收敛为三元流程（A）**：(1) retrieve-then-verify——2507.03671/2608.08612/2607.18240；(2) sufficiency check——2608.08612/2604.09174/2608.13237 + V6 的 CS-RAG；(3) 文本回退——V6 的 CS-RAG textual recovery + 2607.20527 把「确定性 BM25 重归因」当 commodity 步骤。2607.20527 的关键是：**给「校验器不可靠」这件事加界**——split-conformal 对「漏过所选标记规则的真正无支撑引用」给有限样本分布无关上界。
- **CiteCheck 的 Exact 档 = 元数据级锚点判等（A）**：2605.27700 把引用与外部检索候选做结构化比对、映射为 Exact/Minor/Major——这是 LLM 时代对「判等」的最接近实现，但判等对象是**引用元数据**（是否存在、作者年份是否一致），**不是引文内容逐字对应**；Studium 锚点判等对象是内容 span。二者互补不替代。
- **与 memory anchor-verification-blind-spot 的衔接（A 外部 + C 综合）**：盲区笔记的「grep 逐字校验证明不了引文支撑断言」在 LLM 时代获得大规模独立复现——2605.28565「30.6% of citations distort their sources」且用户「rarely verify the cited pages themselves」；2606.26449（ProvenAI）「citation-influence gap：citation audit 干净但被引来源只有弱影响、七个未引来源反而显著改变输出」；2605.29084（同问不同源不同答）把 B 型「同一 (file,quote) 被多节点引用」外化为「来源依赖」轴。**没有 2024–26 证据表明机器能独立结案；只有更多证据表明机器只能定向、且定向也要带界。**
- **证据等级**：Q2 结论 A（外部依据均为 curl 到手的摘要/全文）+ C（与本地盲区笔记的映射）。

### Q3 对 Studium「锚点判等=原文对应」「机械信号只定向不结案」红线（V6/06-M08）提供什么强化或修正？前 LLM 旧结论 V6(CS-RAG 反转)/V3(本体推理只定向) 哪些被 2024-26 新做法支持或推翻？

**结论：红线获三项强化、零项推翻；两个旧结论都被支持并扩展，无一被 2024–26 新做法推翻。**

- **强化 1——「机械信号」的域必须扩到 LLM 生成的信号（A）**：V6 红线的「机械信号」原本指向量/图/嵌入。2024–26 证明 **LLM 的引用、归因、entailment、相似度都是机械信号且同样不可结案**：2607.20527 校验器不一致（无支撑引用率 3%~18%，negative-specific agreement 仅 0.27–0.30，「no single flag set is trustworthy」）；2606.28358 引用机制不接地；2606.03728「semantic similarity does not correlate with passage attribution…similarity-based ranking performs worse than random selection at surfacing gold citation paragraphs」——**连相似度定向都被实测为坏信号**（需换成扰动归因）。红线升级为：**「一切非原文信号（含 LLM 生成的引用/判等/校验器结论）只定向不结案」**。
- **强化 2——机器校验的出口从「通过率」改为「带界的抓漏保证」（A）**：2607.20527 的 gold-anchored 协议+split-conformal 界、2608.08709 的 Verification-Cost Errors（VCE：在给定验证预算内、声明比例的验证者群体识别不出的错误）——把「N/N 锚点机器通过」这类表述的盲区显式化为指标维度：**报告抓不到什么、多少抓不到，而不是报告通过率**。这与盲区笔记「机器通过率读成正确性保证」的警告直接互证。
- **强化 3——A 型盲区（对象错）出现首个半机械化定向信号（A，但仍是定向）**：2607.09349 的 entity-attribution verification（查「引文证据是否适用于被问实体」）对 deceptive grounding 达 97.0% 精度 / 98.7% 召回（IPW 调整人工金标）。这是 memory 笔记里「不可机械化」的 A 型/变量位置错的一个外部可机械化对应物——**但它仍是模型判官，仍有 2607.20527 的校验器失稳问题，故只够当定向信号、不够结案**；且它只覆盖「实体」这一维度，对 C 型（终点冒充中间步）/D 型（射程不足）无对应物。
- **V6 CS-RAG 反转（图结构不结案、退回原文）：被支持并泛化（A）**。2024–26 把「图结构不可靠」推广到「LLM 引用不可靠（2606.28358）、校验器不可靠（2607.20527）、相似度不可靠（2606.03728）、实体归因不可靠（2607.09349 反向——可靠时需要专门检查）」。CS-RAG 的 sufficiency check + textual recovery 已是 2026 年 RAG 停止策略（2608.13237）与证据不足重检索（2608.08612）的标准零件。**无任何 2024–26 新做法表明语义/图/LLM 信号可独立结案。**
- **V3 本体推理只定向（OWL sound 但 incomplete）：被支持并扩展（A + C）**。V3 的「推理 sound 但可能 incomplete，只能定向」在 LLM 时代被 2607.20527 的「校验器 3%~18% 漂移」、2607.08700 的「判官方向性偏差被标量 F1 掩盖（comparable F1 下 pass-rate drift/FPR/FNR 差异显著）」直接复现为「**LLM 判官同样 sound-不确定、同样只定向**」。无推翻证据。
- **证据等级**：Q3 结论 A（外部）+ A 本地（V6/V3/memory 基线原文）+ C（域扩展为综合）。

## 2. 关键发现（每条：论断+URL+标题+机构+日期+原文摘录+等级）

- 等级: A（abs+HTML 全文字词核对）。意义: 「机器校验结案」的最直接反证；其对症（gold-anchored 协议 + split-conformal 界）正是红线的工程化出口。

- 等级: A（abs+HTML 全文核对）。意义: 锚点判等的「逐字/页面级」粒度正是 LLM 时代机械机制最难落的地带；话题相关≠支撑成立，与 D 型盲区同构。

**K3. 欺骗性接地：全部自动化检查通过仍实体错位——deceptive grounding**
- URL: https://arxiv.org/abs/2607.09349 | 标题: Deceptive Grounding: Entity Attribution Failure in Clinical Retrieval-Augmented Generation | 机构: 未核（Caruzzo/Yoo/Tae Soo Kim）| 日期: 2026-07-10
- 摘录: 「A clinical RAG response can pass every automated check (zero hallucinations, near-perfect faithfulness, real citations) while presenting drug Y's clinical evidence as evidence about queried drug X」「a failure invisible to faithfulness, hallucination, and citation checks because every claim is sourced from a real document, about the wrong entity」；entity-attribution verification「detects DG at 97.0% precision and 98.7% DG recall」

**K4. LLM 决定贴引用的机制不语义接地：分布式「归因集合」，与表面推理脱节**

- 摘录: 「the faithfulness of these citations…remains a critical, unverified assumption」；「not a single, localized component but a distributed, multi-stage 'attributional ensemble'」；「a potential disconnect between the model's apparent reasoning and its internal computational pathway」
- 等级: A。意义: 直接推翻「LLM 行内引用=接地证据」的默认假设；机械干预（激活修补）修 90% 漏引、消 69% 假引——说明引用行为可被机械操纵，离「证据」更远。

**K5. 归因粒度卡在 span：文档选对、支撑 span 选不对**
- URL: https://arxiv.org/abs/2606.07130 | 标题: Explicit Evidence Grounding via Structured Inline Citation Generation（FullCite）| 机构: 未核（Yeginbergen/Wührl/Rogers/Agerri，HiTZ-UPV/EHU 等）| 日期: 2026-06-05
- 摘录: 「while LLMs are generally effective at identifying relevant documents, they struggle to identify the precise supporting spans within them」
- 等级: A。意义: 逐字 span 对应（=锚点粒度）是 LLM 归因最弱环节；FullCite 三种策略（prompt/约束解码/posthoc span 对齐）都补不齐。

**K6. 引用质量三维框架 + VERIFIED MISGUIDANCE：30.6% 引用扭曲来源**
- URL: https://arxiv.org/abs/2605.28565 | 标题: Verified Misguidance: Measuring Structural Citation Failures in Search-Augmented LLMs | 机构: 未核（Seo/Jeong/Eunyoung Kim/Jang/Dongha Lee）| 日期: 2026-05-27
- 摘录: 「Across our pool, 30.6% of citations distort their sources and 27.1% originate from domain-inappropriate sources」「models cite real, accessible sources yet fail along one or more dimensions」；761,495 引用对、三维（intent-purpose/source suitability/answer-source fidelity）
- 等级: A（abs+HTML 全文核对）。意义: 引用质量是多维的，真引用≠支撑；CITETRACE 是首个把「引用链：查询→来源→答案」整体追踪的大规模基准。

**K7. 检索接地式引用幻觉检测：CiteCheck，Exact/Minor/Major 判等档**
- URL: https://arxiv.org/abs/2605.27700 | 标题: CiteCheck: Retrieval-Grounded Detection of LLM Citation Hallucinations in Scientific Text | 机构: 未核（Khajavi/Sadeghi/Adhikari/Tessier）| 日期: 2026-05-26
- 摘录: 「retrieves candidate publications from external scholarly sources, compares the citation against the retrieved candidate using a structured LLM verifier, and maps verifier scores into three labels: Exact, Minor, and Major」；88.7 macro-F1 / 88.9% 准确率
- 等级: A。意义: 元数据级锚点判等的最接近 LLM 实现——判等对象是「引用存在性与元数据」，非「内容逐字对应」；与 Studium 锚点互补。

**K8. 检索-生成/判等中间层错位：语义相似度与归因不相关、比随机还差**
- URL: https://arxiv.org/abs/2606.03728 | 标题: Re-Ranking Through an Attribution Lens for Citation Quality in Legal QA | 机构: 未核 | 日期: 2026-06-02
- 摘录: 「semantic similarity does not correlate with passage attribution. Within a retriever's candidate pool, similarity-based ranking performs worse than random selection at surfacing gold citation paragraphs」
- 等级: A。意义: 连「相似度定向」都被实测为坏信号——机械信号要定向也得换更好的信号（扰动归因）。

**K9. 归因-影响缺口：引用审计干净但被引来源弱影响、未引来源强影响**
- URL: https://arxiv.org/abs/2606.26449 | 标题: ProvenAI: Provenance-Native Traces of Evidence in Generated Answers | 机构: 未核（Faizan/Alharthi）| 日期: 2026-06-24

**K10. 来源依赖轴：同问不同源不同答——单金标范式测不出**

## 3. 对决策点的输入

**决策点 = 「锚点判等=原文对应」「机械信号只定向不结案」红线（V6/06-M08）在 LLM 时代如何维持/升级。**

**输入 1（判定：红线维持，且机械信号域扩到 LLM 生成信号）**
- 2024–26 无一证据支持「LLM 信号可独立结案」；反证密集：校验器漂移 3%~18%（K1）、pinpoint 漏判 37–63%（K2）、deceptive grounding（K3）、引用机制不接地（K4）、相似度定向失效（K8）、归因-影响缺口（K9）。【A】
- 红线表述升级为：**「机械信号（向量/图/嵌入/OWL/以及 LLM 生成的引用、归因、entailment、校验器结论）只定向不结案；身份与结案永远由锚点 grep -F 对 L0 原文做出」**。V6/06-M08 原表述不废，只是「机械信号」清单加项。【C 综合，A 依据】

**输入 2（若需强化机器核验，采用「带界抓漏」而非「更高通过率」）**
- 2607.20527 的 split-conformal 界：对「漏过规则的真无支撑引用」给分布无关有限样本上界——报告「保证抓漏率 ≥x%」而非「通过率 y%」。【A】
- 2608.08709 的 VCE：把「验证预算内验证者识别不出的错误」当指标。【A】
- 对 Studium：机器校验报告格式改为「锚点未篡改 N/N + 引文支撑断言由人审 + 机器定向信号对 X 类缺陷的抓漏保证」，明确写「机器通过率证明不了支撑」。【C 综合】

**输入 3（新定向信号可按需引入，但只进候选池）**
- 实体归因校验（2607.09349，97.0% 精度）可作 A 型盲区（对象错）的候选定向；CiteCheck 式元数据判等（2605.27700）可作引用存在性/元数据候选；ProvenAI 式 leave-one-out 影响估计可作 C/D 型盲区候选。【A 依据 + C 应用】
- 它们全部是模型判官，受 K1 校验器失稳约束，**只能把「候选审计集」收窄，不能把任何一条 claim 判为结案**。【C】

**输入 4（sufficiency check 与停止判据可直接借用）**
- 「检索到相关证据≠证据充分」已是 2026 标准机制（K13/K14）；Studium 的「检索充分性触发条件」（H2-1）可与之互证：sufficiency 判断的产物是「继续检索/转人工」，不是结论。【A + C】

**输入 5（LLM 引用质量是缺口区监测器）**
- 引用编造率随知识覆盖剧烈变化（K25：GDPR 94–100% vs PDPL 60–77%）；「训练外/长尾区引用最易编造」→ 锚点要求对长尾/开放字段最严。【A + C 应用】

## 4. 与范围/红线的冲突张力（无则明说无）

- **红线（锚点判等=原文对应；机械信号只定向不结案）：无冲突，强化**。K1–K11 全部支持并把「机械信号」域扩大；唯一需要改的是红线的**表述范围**（加入 LLM 生成的信号），不是实质。【C】
- **张力 1——entity-attribution verification 的 97% 精度可能被读成「可结案」**：它只覆盖「实体对象」这一维度、仍是模型判官（K3/K16 vs K1）。引用时必须标注「定向信号」，防合成阶段把它当结案证据。【C】
- **张力 2——CiteCheck 的 Exact 档与 Studium「逐字对应」是两回事**：Exact 指引用元数据与真实论文一致，不指引文内容逐字支撑断言。术语同音不同物，须分别标注。【C】
- **张力 3——「零幻觉」话语**：HALO（K23）用「系统强制」叙事，但 Studium 红线要求的是**锚点级**强制，HALO 的接地层是「检索到的内容」而非「逐字原文」；借鉴其架构但锚点粒度不同。【C】
- **范围边界：无越界**。未评估具体事实核查产品（K20 CRAG/K19 CiteME 只引其机制结论，不做产品选型）；未重复 V6 的 CS-RAG/KG-grounding 取证；2023 前老货（ALCE/RARR/SelfCheckGPT/FActScore）只作背景一句带过、不标 A。
- **时间锚定：全 A 级来源均 ≥2024-01**（最早 2406.04744），符合硬约束。

## 5. 未决与风险

1. **多数 2026 新作机构未核**：abs 页只给作者名，机构名未逐篇核对；引用时不标机构或标「未核」。不排除个别机构标注错误风险。【未核部分】
2. **只到摘要级、未读全文的比例**：36 篇中仅 3 篇（2608.12571/2607.09349/2605.28565）抓了 HTML 全文核对关键句；其余引用的数字/机制均在摘要可见范围内，方法节细节未核。【未核部分】
3. **LLM 引用/校验器失稳的具体根因未解**：2607.20527 给出校验器严格度差异，但「为什么负例一致率只有 0.27–0.30」的机制未明；对「机器定向信号要强到什么程度才值得纳入流水线」没有阈值研究。【C】
4. **实体归因校验的可迁移性未核**：2607.09349 是临床领域；对理科教材（Studium 语料）的实体归因校验是否有同效未验证。【未核】
5. **sufficiency 判据的操作化缺口**：2608.13237 的 sufficiency-and-gap 在 HotpotQA 上只省 3.7% 检索、掉 0.625pp EM；「证据充分」判据本身仍是模型学出来的，对 Studium 的人工闭环审计只是参照不是替代。【C】
6. **外部证据的语料域差异**：法律/医学/科学文献引用与 Studium 结构化教材性质差异大；引用编造率（K25）、pinpoint 漏判率（K2）的绝对数值不能直接外推为 Studium 预期缺陷率。【C】
