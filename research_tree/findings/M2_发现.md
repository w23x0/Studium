## 0. 一句话结论

RMLMapper 7.3.3 在 Java 17 上对第 15 章真实 JSONL 子集**可行**（11 行 → 145 条 nquads，5/6 测试 exit=0、0 违规），但**不能直接吃 .jsonl**——必须先预处理成单个 JSON 文档（数组 `[...]` 或包裹 `{"nodes":[...]}`），且嵌套 `anchors` 数组需用第二个 triples map + 迭代器 `$[*].anchors[*]` 降级映射；增量映射 RMLMapper **无内建逐行模式**，靠"行切片 + 分批跑 + 拼接去重"实现，实测拼接需去重（原始拼接 151≠145，去重后 145=145，差异来自 3 对跨批次重复 anchor 三元组）。

## 1. 问题逐条回答（每问：实测结论 + 具体数字 + 证据）

### Q1. RMLMapper（java 17）对 JSONL 源（嵌套 JSON 结构）的实际映射运行是否可行？

**结论：可行，但有明确前提——原生 .jsonl 直接映射失败，必须预处理成单个 JSON 文档；嵌套结构用"第二个 triples map + 下沉迭代器"映射。**

- **原生 .jsonl 直接映射：失败（exit=1）。** 用 `mappings/mapping-jsonl.ttl`（`rml:source "data/nodes-A2-s1.jsonl"`，iterator `$[*]`）实测，RMLMapper 报错（out/T3-raw-jsonl.stdout.txt 原文）：
  `java.lang.IllegalArgumentException: Cannot deserialize value of type java.util.LinkedHashMap<java.lang.Object,java.lang.Object> from Array value (token JsonToken.START_ARRAY)`
  定向探针（probes_log.txt P1–P4）证明机制：`$[*]` 在根为对象时取的是对象各字段值，字段值里出现数组（sections/aliases/anchors）时 Jackson 按对象反序列化数组 → 报错；失败与扩展名无关（同内容 .json 同错）。无数组字段的对象根 + `$[*]` 虽不报错但产出 0 条三元组（模板取不到 id）。
- **预处理成 JSON 数组 + `$[*]`：可行（T1）。** `prep_jsonl.py` 把 11 行转成 `[ {...}, ... ]`，`mapping-full.ttl`（NodeMap + AnchorMap）实测：exit=0，**145 条 nquads，37 个主体（11 node + 26 anchor），9 个谓词，0 违规，约 1.5 s**（含 JVM 启动，非基准）。
- **包裹形式 `{"nodes":[...]}` + `$.nodes[*]`：可行（T2），产出与数组形式完全一致。** 同一规则集下 T2=145 quads、37 主体、9 谓词，与 T1 逐项相等（`equal=True`）。两种文档形态等价。
- **嵌套 anchors（数组内嵌对象）**：用 AnchorMap 迭代器 `$[*].anchors[*]` 逐 anchor 生成主体，实测 29 个 anchor 映射出 **26 个 anchor 主体**（3 对 `(file,quote)` 完全相同的 anchor 在源里就重复，RML 内存模型按 RDF 集合语义去重为 26）；anchor 的 `file`/`quote` 两字段各映射 26 条。
- **第二个第 15 章文件稳健性（T6）**：nodes-A2-s2.jsonl（10 行）同管线 → exit=0，**109 quads、27 主体**（10 node + 17 anchor，源内无重复）。

### Q2. 增量映射（只映射新增行）如何做、RMLMapper 是否支持？

**结论：RMLMapper 无内建逐行增量模式（官方 README 自述 "loads all data in memory"）；增量靠管线层"行切片 + 分批映射 + 拼接去重"实现，实测可行但必须去重。**

- **无内建增量**：CLI 只有 `-t/--triplesmaps` 的"按 triples map 选择执行"粗粒度控制（实测 NodeMap 单独 93 条、AnchorMap 单独 52 条，93+52=145=全量，见 probes_log T7），没有"只映射新增行"的开关；每次运行读取并处理整个源文件。
- **管线层增量可行（T4/T5/C4）**：把 11 行按行号切片（行 1–6 → part1-array.json，行 7–11 → part2-array.json），同一规则集分批映射：**part1（6 行）→ 83 quads / 22 主体；part2（5 行）→ 68 quads / 18 主体**。只跑 part2 即"只映射新增行"。
- **拼接必须去重（C4/C4b）**：原始多集拼接 `part1+part2=151 ≠ full=145`，多出 **6 条**，全部是 3 对跨批次重复的 anchor 三元组（每对 file+quote 两条）；C5 证实 3 对重复 anchor 全部跨越 1–6/7–11 批次边界。原因：RMLMapper 单次运行内存模型会去重相同三元组，跨两次运行不去重。**下游去重后多集相等（145=145，C4b `multiset_equal=True`）**。本样本不去重的重复开销 6/145≈4.1%。
- 增量流程（实测跑通）：`新行追加 → prep_jsonl 生成新 JSON 文档（或仅含新行的切片）→ RMLMapper 只跑该切片 → 输出追加进已去重的 RDF 库`。

### Q3. 映射产出 RDF 的规模/结构与 JSONL 原源的对应关系？

**结论：结构一一对应、规模可逐字段核对；nquads 默认空图，IRI 自动百分号编码。**

- **对应账（T1，145 = 44+12+8+29+52）**，源 11 节点 / 29 anchors / 12 sections / 8 aliases：
  - 每个节点 → 1 个主体 × 4 个标量谓词（name_en/name_zh/node_type/statement）= **44**
  - sections（字符串数组）→ 每元素 1 条 `ex:section` = **12**
  - aliases（字符串数组）→ 每元素 1 条 `ex:alias` = **8**
  - anchors（对象数组）→ 每个 anchor 1 条 `ex:hasAnchor`（多值引用） = **29**；AnchorMap 给每个 anchor 主体 2 条（file+quote）= 26×2 = **52**
  - 谓词分布实测：`{"alias":8, "file":26, "hasAnchor":29, "name_en":11, "name_zh":11, "node_type":11, "quote":26, "section":12, "statement":11}`
- **nquads 规范性**：145/145 行以 ` .` 结尾（空图）；消息模板 IRI（如 `node/{id}`、`anchor/{file}#{quote}`）中的 `:` `$` `{}` 等被自动百分号编码，无非法 IRI 报错。
- **去重语义**：anchor 主体 IRI 由 `file#quote` 生成，跨节点共享同一锚点文本的 anchor 在单次运行内折叠为同一主体（26<29）——这是 RDF 模型语义（相同三元组去重），非缺陷，但影响"每条锚点记录是否独立可寻址"的建模选择。

## 5. 未决与风险

- **性能与内存未测（按范围红线）**：约 1.5 s 为含 JVM 启动的单次耗时，非基准；峰值内存未测。README 自述全量入内存，对第 15 章全量（522 节点级）虽大概率无压力，但未实测，规模放大需另证（可参考 B8b 的 RMLStreamer 流式候选）。
- **anchor 主体身份语义未决**：`anchor/{file}#{quote}` 使跨节点共享锚点文本折叠为一个主体（26<29）。若要求"每条 anchor 记录独立可寻址"（含它在哪个节点出现），需把节点 id 纳入 anchor IRI 或改用空白节点；这是建模决策，非工具缺陷。
- **原生 .jsonl 的失败机制边界**：只对 RMLMapper 7.3.3 实测；其他处理器（SDM-RDFizer/RocketRML/Morph-KGC/CARML/RMLStreamer，B8b 候选）对 .jsonl 的处理未测，不可外推。
- **只测了 nodes 文件**：edges-*.jsonl（关系边）未在本卡实测，但其结构与 nodes 同构，预计同管线可跑（未核）。
- **只用了 nquads 输出**：turtle/jsonld/trig/hdt 等序列化未测；`-d` 去重开关未测（增量拼接去重用的是外部多集去重）。

## 6. 建议的下一步

1. **管线落定**：把 `prep_jsonl.py`（jsonl→单文档数组）作为 RML 管线固定前置步骤；`mapping-full.ttl` 作为第 15 章 nodes 的规范规则；增量采用"行切片 + 分批跑 + 入库前去重"。
2. **决定 anchor 身份方案**：若需逐条可寻址，改 anchor 模板把父节点 id 纳入（如 `anchor/{id}/{file}#{quote}`），或空白节点；并明确 29→26 折叠是否符合业务语义。
3. **扩展到 edges**：把第 15 章 edges-*.jsonl 纳入同管线，验证关系边的映射与 triples map 数量。
4. **接入校验闭环**：对产出的 nquads 跑 SHACL（接 B5/B8 的 pyshacl 发现），把"规则版本化 + 校验形状"一并纳入（呼应 B8b Q5 的可审计增益）。
5. **规模探针**（属后续非本卡范围）：若全量 522 节点跑通后再评估流式替代（RMLStreamer），避免 RMLMapper 全量入内存的放大风险。
