## 1. 问题逐条回答

### 问 1：rdf-canonize 5.0.0（node）是否真正实现 RDFC-1.0（对比 P1 证实的 rdflib canonicalize 静默 no-op）？

**实测：是，真正实现。** 用带不同空白节点标签的两个同构图实测（run_output.txt）：

```
bnode input1 canonicalized: "_:c14n0 <urn:q> <urn:x> .\n_:c14n1 <urn:r> _:c14n2 .\n_:c14n2 <urn:p> _:c14n0 .\n"
bnode input2 canonicalized: "_:c14n0 <urn:q> <urn:x> .\n_:c14n1 <urn:r> _:c14n2 .\n_:c14n2 <urn:p> _:c14n0 .\n"
isomorphic datasets canonicalize identically: true
blank node labels were relabeled (c14nN prefix present): true
```

- 输入 `_:a/_b/_c` 与 `_:z/_y/_w`（同构、标签全异）经 RDFC-1.0 后输出**逐字节相同**，空白节点被重标号为 `_:c14nN`——这正是 RDFC-1.0 的"同构数据集规范化到同一 canonical 形式"的核心行为。rdflib 7.6.0 做不到（P1 三重证据：`**kwargs` 吞参、canonical 与普通输出逐字节相同 `canonical_identical_to_regular: True`、输出随插入顺序漂移 `canonical_ordered == canonical_shuffled: False`）。
- 幂等性单独验证：`canonize(canonical) == canonical`（smoke_test.js：`idempotent: true`）。
- 解析能力：rdf-canonize 自带 N-Quads 解析器在 921 数据上 `NQuads.parse quad count: 921`，无解析错误（解析失败会抛错中止）。
- **结论**：任务卡问 1 成立。rdf-canonize 5.0.0 是真 RDFC-1.0 实现，可作 P1 建议的 rdflib canonical 替代（P1 发现第 6 节第 1 条）。

### 问 2：921 锚点 N-Quads 的 canonical 指纹是否稳定（不随三元组插入顺序漂移）且可复现？

**实测：是，稳定且可复现。** 指纹定义为 canonical N-Quads 全文的 SHA-256（hex，64 字符）。真实 stdout：

```
fingerprint(original order) sha256: 47cf0717bb431dc436901a5977b3118e246755118e37f4efe6f52266a7553ec2
canonical != raw input serialization (order got normalized): true
order-independence: all 10 permutations share the same fingerprint: true
run2 fingerprint equal: true
run3 fingerprint equal: true
whitespace/line-ending variant same dataset same fp: true
```

- **顺序不敏感**：10 个种子化排列（seed `0xC0FFEE+i`，mulberry32，可复现）各自 canonical 化后指纹全部等于原始指纹 `47cf0717...`（perm 00–09 全部 `equal=true`）。canonical 输出按行字典序排序（实测 `sort -c` 通过），故插入顺序被完全吸收。
- **可复现**：同一输入连跑 3 次指纹全等；输出文件 `anchors_921_c14n_rdfcanonize.nq`（119504 字节，921 行）在多次运行间字节稳定。
- **跨序列化稳定**：同一数据集的空白/行尾变体（双空格→`\t`、LF→CRLF）canonical 化后指纹仍等于原始指纹——指纹作用于"解析后的 RDF 数据集"而非文件字节。
- **结论**：任务卡问 2 成立。canonical 指纹不随三元组插入顺序漂移、可复现。

### 问 3：canonical 指纹用于迁移校验的可行性：指纹比对能否替代全量重读？

**实测：就"内容等价"判据而言可行；就"文件字节等同"判据而言不可行（也本就不该用指纹）。** 真实 stdout：

```
remove-1-quad fingerprint differs: true
add-1-quad fingerprint differs: true
modify-1-literal fingerprint differs: true
swap-2-literals (same value multiset, diff mapping) fingerprint differs: true
```

- **差异敏感（内容级）**：删 1 条 quad、增 1 条 quad、改 1 条字面量内容、**交换 2 条 quad 的字面量**（值多重集相同、锚点→quote 映射改变）→ 指纹全部不同。最后一类证明指纹检出的不只是"值的集合变了"，而是"RDF 内容映射变了"。
- **无损失（oracle 交叉验证）**：rdflib 7.6.0 独立解析 输入 与 canonical 输出，quad 集合逐项判等：
  ```
  input quads : 921
  c14n quads  : 921
  quads only in input : 0
  quads only in c14n  : 0
  dataset equality (set-of-quads): True
  literal values containing backslash (input) : 281
  literal values containing backslash (c14n)  : 281
  literal value multiset equal: True
  ```
  rdf-canonize 的 parse→serialize 对 921 数据里出现的转义（`\\` 971 处、`\"` 38 处，P1 实测）无损失：canonical 输出与输入是同一 quad 集合，281 个含反斜杠字面量的值多重集完全一致。
- **替代语义**：迁移校验的目标是"迁移后内容未变"。指纹比对把"重读 N 条 quad 逐条比较"（P1 是 921 条）压缩成"比较两个 64 字符 hex"。等价条件为：指纹相等 ⟺ 两侧解析为同一 RDF 数据集（无 SHA-256 碰撞前提下）。921 数据 0 空白节点，canonical 形式即"排序后的 quad 集合"，指纹相等与集合相等严格等价；若未来含空白节点，RDFC-1.0 使指纹对"同构数据集"也相等（空白标签规范化），语义上仍是正确的"同一 RDF 内容"。
- **边界**：指纹是内容判据，检不出（也不该检出）不改变 RDF 数据集的差异——例如文件字节格式、行序、注释、序列化转义写法（`\u0061` vs `a`）。若迁移校验还要验证字节级一致，需另做字节哈希（P1 已有先例）。
- **结论**：任务卡问 3 部分成立。作为迁移校验的**内容等价判据**，指纹比对可替代全量重读；作为**字节等同判据**，不能替代，需另用文件字节哈希。

## 5. 未决与风险

1. **指纹是"内容判据"不是"字节判据"**。canonical 指纹基于解析后的 RDF 数据集，因此检不出不改变 RDF 内容的差异：文件行序、空白/缩进、换行符、序列化转义写法（如 `\u0061` 与 `a` 是同一字面量值）、文件注释/元数据。若迁移校验还要求字节级一致（如校验审计链的原始字节），必须另加文件字节 SHA-256，不能只靠 canonical 指纹。
2. **SHA-256 碰撞理论非零**。工程上可忽略，但若校验对象是强对抗场景，应降级为全量重读或改用更长摘要 + 字节双重校验。
3. **空白节点场景未在 921 数据上实测**。921 数据 0 空白节点，指纹相等与"quad 集合相等"严格等价。未来数据若引入空白节点，RDFC-1.0 会把"同构但标签不同"的数据集归一到同一指纹——对"同一 RDF 内容"语义仍正确，但若校验方期待"字节级标签一致"就会误判。需在含空白节点的真实数据上补一轮验证。
4. **API 误用风险**。`canonize` 对字符串输入必须传 `inputFormat: 'application/n-quads'`，否则读 `.termType` 抛 TypeError（实测踩到）。`_canonizeSync` 为同步变体。文档标注不足，管线接入时需注意。
5. **指纹计算本身有成本**。指纹比对替代的是"重读比较"步骤，但生成指纹仍需完整解析 + canonical 化（921 数据单次 ~10ms，见第 3 节；非性能基准，仅说明非零成本）。对超大图这是 N-Quads 解析 + 排序的开销，规划管线时要计入。
6. **rdflib 侧的 lone surrogate 破坏风险仍存在**（P1 发现第 5 节第 2 条）：rdflib 序列化把 lone surrogate 静默写成 `?`。本任务用 rdf-canonize 解析 P1 产出的 N-Quads 文件，该文件由 rdflib 生成且无 surrogate（P1 已证 921 数据无）；若未来数据含 surrogate，破坏发生在**源头序列化**，指纹方案无法修复，只能检测。

## 6. 建议的下一步

1. **采纳 rdf-canonize 5.0.0 作 rdflib canonical 的替代**（落地 P1 建议第 1 条）：921 数据上验证通过，真 RDFC-1.0、幂等、排序确定。迁移/校验管线可直接依赖。
2. **指纹校验管线落地为双判据**：内容等价用 RDFC-1.0 canonical SHA-256（本任务验证）；字节级一致（若审计需要）另加文件原始字节 SHA-256。两个 64-hex 比较即可，替代全量重读的逐条比较。
3. **在含空白节点的真实数据上补一轮**：验证指纹对"同构不同标签"与"非同构"的区分度（RDFC-1.0 的 isomorphism 语义在指纹判据上的实际行为），并确认 canonical 化在更大图上的正确性。
4. **把"指纹相等 ⟺ 内容等价"写成可复用工具**：输入两个 N-Quads 文件 → 各自 canonical 化 → 比较 SHA-256 → 输出"等价/不等价 + 差异样例"。封装 `inputFormat` 等 API 细节，避免误用。
5. **记录 canonical 输出格式事实**：输出为 LF 行尾、行字典序、` .\n` 结尾、默认图省略 graph 分量（源码 `serializeQuadComponents` 实测确认）。下游若做字节比对需统一换行约定。
