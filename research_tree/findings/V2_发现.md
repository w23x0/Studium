## 0. 一句话结论

**理论图是 M08「基础关系网络 + 高层可迁移结构」现成的、经 MKM 领域 25 年验证的结构模式：以「概念/方法对象=理论 theory（含符号声明）+ 两类边（导入 includes=继承/前置类，理论态射 views=翻译/模型/迁移类）」组织知识，其「little theories 少冗余、态射搬运、网络而非树」三大性质逐条对应 M08 主干需求；biform（公理+算法混合）在结构上能表达「概念+方法+可迁移结构」三要素（符号=概念、transformers=算法、理论态射=迁移），但其「方法」只覆盖可形式化的符号操纵算法，非形式方法（启发式、思维框架）仍需 flexiformal/自然语言承载，且形式化需 quotation+evaluation 元推理设施（工程成本高）；TNTBase 与 L2 FHIR 式（v1.3 条件性终裁）在版本结构上同构（单链、只追加、不物理删除、可回溯），最大可借鉴是「提交时增量语义校验 + ABox 知识图缓存 + 依赖闭包查询」三件套——其中 ABox 直接对应已定 L1 RDF 语义层角色，增量校验为 P2 实测（pySHACL 8.48s/522 节点）后「校验是否进写路径」的张力提供了第三条路（模块级增量而非全图重验）。**

## 1. 父会话问题逐条回答（每问：结论+依据+等级）

### Q1 MMT/OMDoc 的模块化理论图 + 查询语言（QMT）对理科知识组织提供什么结构启示？

**结论：理论图为 M08 提供四组直接可迁移的结构模式。**
1. **粒度**：概念/方法对象=理论（theory，一组带类型的符号声明），不是资料切片或章节；跨资料索引用 doc?mod?sym 式规范 URI。对应 M08「对象不等同于章节或切片，是基础网络的节点和跨资料索引」。
2. **边族**：两类边即可覆盖 M08 基础关系族——includes 导入边（继承/前置/上位/组成类）+ views 理论态射边（等价/推导/迁移/实现类）。M08 的「方法、结构模型、思维框架、迁移方向」高层对象在理论图里就是可继续连边、可继续向上抽象的普通节点（网络而非树），与 M08 审查问题 5「层只作为抽象深度、不设固定层数」一致。
3. **标识 + RDF 投影**：MMT URI 规范标识符 + ABox 本体（10 一元 + 11 二元谓词、结构完备）把理论图投影为 RDF 语义层——正好落在已定 L1 RDF（v1.3：RDF 1.2 + TriG 命名图）上，不另起格式。
4. **查询**：QMT 把 unification/语义网(SPARQL 式)/XQuery 式三种检索范式统一在 MMT 上，可跨库、可查理论图组件（includes/declares/views 用简单查询即得）。

依据（全部 A 级原文，逐句对应）：
- 「An Mmt theory graph is the multigraph formed by using the theories as nodes and all theory morphisms between them as edges.」（arXiv:1204.4685 QMT，Rabe 2012）
- 「Theories are related via theory morphisms called *views*. These are truth-preserving translations from one theory to another and represent translations and models.」（arXiv:1204.4685）
- 「This yields theory graphs where the nodes are theories and the paths are theory morphisms.」（arXiv:1005.5232 Towards MKM in the Large，Kohlhase/Rabe/Zholudev 2010）
- 「QMT can integrate various search paradigms such as unification, semantic web, or XQuery style queries, and QMT queries can span different mathematical libraries.」（arXiv:1204.4685 摘要）
- 「the API computes the ABox of a theory graph with respect to the Mmt ontology. It has Mmt-URIs as individuals and 10 types like theory or symbol as unary predicates. 11 binary predicates represent relations between individuals such as HasDomain ... These relations are structurally complete: The structure of a theory graph can be recovered from the ABox.」（arXiv:1005.5232）
- 「MMT represents logical knowledge on three levels: module level (theories and theory morphisms)... On the symbol level ... Sets of symbol declarations yield theories and correspond to OpenMath content dictionaries.」（arXiv:1005.5232）

等级：A（结构模式全部来自原文核对）。

### Q2 biform 理论图（公理+算法混合）能否表达 M08 需要的「概念+方法+可迁移结构」？

**结论：结构上能表达，且映射是自然的——但有两个硬性边界，不能全包。**
- 能表达：符号=概念（「Each symbol is the name for a concept of T」，arXiv:1805.02709）；transformers/算法=方法（公理+算法同处一理论）；理论态射=可迁移结构（「theory morphisms serve as information conduits that enable definitions and theorems to be transported from one theory to another」，arXiv:1805.02709/1704.02253）。M08 审查问题 2 的高层候选最小表达（组成对象、共同机制、适用条件、边界/反例、迁移方向）在 biform 理论图里对应：理论组成（imports）、规范层（specification theory）+ 实现层（implementation theory + 态射，见 arXiv:1306.3198「views T1→T2 represent implementations of T1 in terms of T2」）、定理迁移路径（态射）。
- 硬边界一（方法类型）：biform 的「算法」是操纵符号表达式的 transformer / 语法型数学算法 SBMA（「algorithms that apply arithmetic operations to numerals, factor polynomials, transpose matrices, and symbolically differentiate expressions」），不是 M08 的全部「方法」。M08 的方法既含程序性知识（怎么做）也含结构性知识（思维框架、迁移方向）；biform 只能覆盖前者中可形式计算的部分。非形式方法仍须 flexiformal/自然语言承载（C 级判断，基于 A 级定义）。
- 硬边界二（工程成本）：形式化 biform 需「quotation + evaluation」元推理基础设施（把算法操纵的表达式作为句法实体推理），有本地（deep embedding）/全局两种路径，且需支持不同底层逻辑间的互逻辑态射——这是论文自身反复强调的挑战（「Formalizing a biform theory ... is very challenging」，arXiv:1805.02709；「Biform theories are challenging to formalize」，arXiv:1704.02253）。对 M08，若「方法」不作为一等形式对象、只作为标注+自然语言描述，则无需此成本（C 级判断）。
- 结论落点：biform 理论图可作 M08「概念+方法+可迁移结构」的**语义目标形态**（证明「三者能在同一图里共存且能形式化」），但落地到个人知识库（M06/M07 资料 + M08 通用结构）时，方法层降级为 flexiformal 标注是工程上更可行的路径——这与 MKM 的 flexiformal 主流（「flexiformal documents ... contain semantic annotations at different levels of formality」，arXiv:1105.2392）一致。

等级：A（三要素映射与挑战均来自原文）；边界一/落点判断 C。

### Q3 MKM 的版本化存储（TNTBase）与存储选型 L2 FHIR 式（v1.3）有何可借鉴/冲突？

**结论：版本结构同构、无红线冲突；最大可借鉴是「增量语义校验 + ABox 缓存 + 依赖闭包查询」三件套；唯一真实张力是「提交即校验保证库内一致」vs 项目 P2 实测后「校验层只读审计、写路径不触发全量校验」。**

TNTBase 结构模式（全部 A 级原文，arXiv:1005.5232 + arXiv:1105.0548 §9.2）：
- 版本化 XML 数据库 = Berkeley DB XML 集成进 Subversion 服务器；HEAD 修订存 DB XML，非 XML 内容（PDF/图片/LaTeX 源）与修订差异存 SVN 后端；SVN 单链（无并发分支），可查历史修订。
- 提交时增量校验（validation-upon-commit）：tntbase:validate 可配 no/XML/structural/foundational 四级；非法提交被拒→「TNTBase can guarantee that it only contains well-formed documents」；「validation ... is incremental, i.e., only those documents added or changed during a commit are validated」——依赖用已缓存 ABox、不重新验证（分离编译）。
- ABox 缓存：每个提交文档生成关系表示（知识图 ABox）以 XML 存旁边 + 索引→高效全局查询（如一次 XQuery 取整条依赖闭包、取某符号全部记号）。
- 虚拟文档：可编辑的「XML 数据库视图」，提交时补丁透明回写原文件；支持一步前向依赖锥重命名（重构工具）。

可借鉴（机制 A 级，映射 C 级）：
1. **增量校验模式 ↔ 校验层定位**：v1.3/P2 把校验钉在只读审计层（全量 pySHACL 8.48s 不能进写路径）。TNTBase 证明语义校验要进写路径就必须是「变更对象 + 已缓存依赖」的增量，而不是全图。若 M08/M09 未来需要写时一致性保障（概念更正不得让下游悬空），TNTBase 的增量+ABox 是现成先例，不必回到全量校验（C 级：项目当前无模块级校验设施，落地需模块粒度设计）。
2. **ABox 缓存 ↔ L1 RDF 语义层**：项目 L0 JSONL + L1 RDF 双轨里，L1 的角色（语义投影、查询加速、版本层承载体）与 TNTBase 的 ABox 完全同构；且 MKM 已验证该模式规模化（Isabelle 库导出 40M RDF 三元组、Coq 12M，arXiv:2005.03089）。
3. **依赖闭包查询 ↔ M08 前置回溯/变更影响**：M08 更正要「不静默覆盖、保留依据和历史」；MKM 的 change management 核心就是把结构关系显式表示、据此计算受影响对象（push/pull 工作流，arXiv:1105.2392）——M08 更正/候选审计晋升可借用「影响范围=依赖闭包」语义。

冲突/张力：
1. **提交即校验 vs 校验不进写路径**（真实张力，标 C 判断）：TNTBase 以「库内保证 well-formed」为价值取向（非法提交被拒）；v1.3 以「写路径不触发全量校验」为约束（P2 实测 + L2 发现 §5-6）。TNTBase 靠增量化解性能，但项目红线禁止性能基准、且 M08 对象粒度尚未定义「模块」，增量校验的粒度可行性未验证。需产品裁决（不改红线，只把「校验粒度」与「写时校验是否允许」列为待决输入）。
2. **版本粒度**：TNTBase/SVN 是文档级版本 + MMT URI 符号级标识（内容寻址/标识寻址）；FHIR 式是资源（结论对象）级 versionId。M08 概念对象粒度更接近 MMT 的「理论/符号」级，与 FHIR 的「资源」粒度可互操作但哲学不同（映射 C 级）。
3. **无冲突项**：单链无分支（TNTBase 与 FHIR 一致）、不物理删除（SVN 保留历史 + _history 只追加，一致）、可回溯（均按版本/修订回溯，一致）。
4. **差异存储先例**：TNTBase 的 SVN 快照+差异存储，可视为 v1.3「CB 增量补丁压缩历史」的工程先例（但 SVN 是字节级差异、非语义级；仅作参照，不评估软件栈）。

等级：A（TNTBase 机制全部原文核对）；映射与张力判断 C。

## 2. 关键发现（每条：论断+URL+标题+机构+日期+原文摘录+等级）

**F1（A）理论图=理论节点+态射边，是 MKM 组织大知识量的通用形态。**
- URL: https://arxiv.org/abs/1806.00810｜A New Style of Proof for Mathematics Organized as a Network of Axiomatic Theories｜Farmer, McMaster University｜2018-11-30
- 摘录：「A network of theories connected with theory morphisms is called a *theory graph*. The theories are the nodes of the graph, while the theory morphisms are directed edges. ... the architecture of a theory graph is well suited for organizing bodies of mathematical knowledge.」
- 关联：M08 审查问题 5（层=抽象深度，网络非树）。

**F2（A）理论态射的别名族 = 翻译/解释/模型/实现/视图；语义是「保真搬运」。**
- URL: https://arxiv.org/abs/1806.00810
- 摘录：「Theory morphisms are also known as immersions, realizations, theory-interpretations, translations, and views. ... Theory morphisms serve as information conduits that enable theory components such as definitions and theorems to be transported from an abstract theory to a more concrete theory or equally abstract theory.」
- 关联：M08 的等价/推导/对比/迁移关系均可用态射带方向表达。

**F3（A）little theories 方法的收益逐条对应 M08：最少冗余、跨词汇共享、等价整合(realm)、并行开发、反向态射查相关对象。**
- URL: https://arxiv.org/abs/1806.00810
- 摘录：「In accordance with the little theories method, the development of a mathematical topic can be done in the theory ... with the most convenient underlying logic, the most convenient level of abstraction, and the most convenient vocabulary and then concepts and facts produced in the development can be transported to many other contexts via the theory morphisms. ... enables a large body of mathematical knowledge to be developed with a minimal amount of redundancy.」
- 关联：M08「合并别名/不同表述」「多资料与模型综合候选」「高层结构可迁移」。

**F4（A）QMT 查询语言：统一 unification / 语义网(SPARQL 式) / XQuery 式三种范式，理论图组件用简单查询即得。**
- URL: https://arxiv.org/abs/1204.4685｜A Query Language for Formal Mathematical Libraries｜Rabe, Jacobs University Bremen｜2012-04-20
- 摘录：「Based on the generic representation language MMT, we introduce the mathematical query language QMT: It combines simplicity, expressivity, and scalability while avoiding a commitment to a particular logical formalism. QMT can integrate various search paradigms such as unification, semantic web, or XQuery style queries, and QMT queries can span different mathematical libraries.」
- 摘录 2：「The components of the theory graph can be retrieved with a few simple queries.」

**F5（A）MMT URI（doc?mod?sym）是跨应用一致的规范符号标识，ABox 本体（10 一元+11 二元谓词）结构完备地把理论图投影为 RDF。**
- URL: https://arxiv.org/abs/1005.5232｜Towards MKM in the Large: Modular Representation and Scalable Software Architecture｜Kohlhase, Rabe, Zholudev (Jacobs University)｜2010-05-28
- 摘录：「URIs are the main data structure needed for cross-application scalability ... they provide canonical names for all symbols that are in scope, including those that are only available through imports.」
- 摘录 2：「These relations are structurally complete: The structure of a theory graph can be recovered from the ABox.」
- 关联：M08 概念对象的跨资料索引需要稳定标识符；理论图可经 ABox 直接落在 L1 RDF。

**F6（A）MKM in the large 的五障碍与模块/包区分，指明「概念对象=模块（语义受增删影响）、资料=包（命名空间管理）」的分层。**
- URL: https://arxiv.org/abs/1105.0548｜A Scalable Module System｜Rabe & Kohlhase｜2011-05-03
- 摘录：「a mathematical theory should be represented as a module because moving axioms between theories changes the semantics; a mathematical paper should be represented as a package ...」
- 摘录 2：五障碍 = Informality, Logical Heterogeneity, Foundational Assumptions, Modularity, Global Scale。

**F7（A）biform 理论 =（语言 L，transformers Π，公理 Γ）；公理/算法互补且两者都需要。**
- URL: https://arxiv.org/abs/1805.02709｜Biform Theories: Project Description｜Carette, Farmer, Sharoda (McMaster)｜2018-04-29
- 摘录：「A biform theory T is a triple (L, Π, Γ) where L is a language of some underlying logic, Π is a set of transformers that implement functions on expressions of L, and Γ is a set of formulas of L. ... We say T is an axiomatic theory if Π is empty and an algorithmic theory if Γ is empty.」
- 摘录 2：「Each symbol is the name for a concept of T.」
- 关联：M08「概念+方法」的语义承载。

**F8（A）理论图使知识「在最方便的抽象层用最方便的词汇」形式化，态射提供找到并跨语境应用的通道。**
- URL: https://arxiv.org/abs/1805.02709
- 摘录：「A theory graph enables mathematical knowledge to be formalized in the most convenient underlying logic at the most convenient level of abstraction using the most convenient vocabulary. The connections made by the theory morphisms in a theory graph then provide the means to find this knowledge and apply it in other contexts.」
- 关联：M08 高层结构候选的「共同机制、迁移方向」。

**F9（A）biform 案例研究确认：理论图结构提供「访问相关概念事实、减少重复、多方式解释」三能力；双形式化（CTT+Agda）证明该结构可落地。**
- URL: https://arxiv.org/abs/1704.02253｜Formalizing Mathematical Knowledge as a Biform Theory Graph: A Case Study｜Carette & Farmer (McMaster)｜2017-07-27（CICM 2017, LNCS 10383）
- 摘录：「The structure of a theory graph provides the means to access relevant concepts and facts (c&f), reduce the duplication of c&f, and enable c&f to be interpreted in multiple ways.」
- 关联：M08「减少重复、等价/多语境解释」。

**F10（A）Universal Machine 框架把「规范→实现」也表示为理论态射（T1 spec → T2 编程语言 = 实现），biform 理论图混合规格与实现、共享模块系统与类型信息。**
- URL: https://arxiv.org/abs/1306.3198｜A Universal Machine for Biform Theory Graphs｜Kohlhase, Mance, Rabe｜2013-06-13
- 摘录：「Views uniformly capture the relations "T2 interprets/implements/models T1". ... if T1 represents a specification and T2 a programming language, then views T1→T2 represent implementations of T1 in terms of T2.」
- 摘录 2：「This yields a formal, modular framework of biform theory graphs which mixes specifications and implementations sharing the module system and typing information.」

**F11（A）TNTBase = 版本化 XML 数据库（Berkeley DB XML 集成进 SVN 服务器），Head 存 DB XML、差异存 SVN 后端，可查历史修订。**
- URL: https://arxiv.org/abs/1005.5232
- 摘录：「TNTBase, a versioned storage system for XML-based document formats. TNTBase becomes an Mmt database by instantiating it with special MKM operations for Mmt.」
- 摘录 2（1105.0548 §9.2）：「It was obtained by integrating Berkeley DB XML into the Subversion Server, is intended as a basis for collaborative editing and sharing XML-based documents, and integrates versioning and access of document fragments.」

**F12（A）提交时增量语义校验：tntbase:validate 四级可配，非法提交被拒，依赖用已缓存 ABox 不重验。**
- URL: https://arxiv.org/abs/1105.0548
- 摘录：「Using the tntbase:validate property, folders and files can be configured to require validation. Thus, users can choose between no, XML-based, structural, or foundational validation of Mmt files. Since the commit of ill-formed files can be rejected, TNTBase can guarantee that it only contains well-formed documents.」
- 摘录 2（1005.5232）：「it is crucial that validation of interlinked collections of Mmt documents is incremental, i.e., only those documents added or changed during a commit are validated. ... References to previously committed files are not resolved; instead their generated ABox is used for validation.」

**F13（A）ABox 缓存 + 依赖闭包查询 + 虚拟文档：关系表示随文档存、索引化，一次 XQuery 取依赖闭包；虚拟文档编辑补丁回写。**
- URL: https://arxiv.org/abs/1005.5232（及 1105.0548 §9.2）
- 摘录：「TNTBase indexes the files containing the relational representation so that such queries scale very well. For example, our XQuery module includes a function that computes the transitive closure of the structural dependency relation between Mmt modules and dynamically generates a self-contained Mmt document that includes all dependencies of a given module.」
- 摘录 2（虚拟文档）：「They are essentially 'XML database views' analogous to views in relational databases. They are editable, and TNTBase transparently patches the differences into the original files in the underlying versioning system.」

**F14（B）OMDoc 理论层「理论可互相导入、形成图」，且扩展向其他理科（PhysML），并规划 OWL 本体 + RDF 导出。**
- URL: https://en.wikipedia.org/wiki/OMDoc（百科转引，其下引 OMDoc 书）｜B 级转引
- 摘录：「Theory level: A theory is a set of contextually related statements. Theories may import each other, thereby forming a graph. Seen as collections of symbol definitions, OMDoc theories are compatible to OpenMath content dictionaries.」；「OMDoc is being extended towards sciences other than mathematics. The first result is PhysML, an OMDoc variant extended towards physics.」；「an OWL ontology of OMDoc is under development, as well as an export facility to RDF.」
- 说明：本条目正文为 Wikipedia（B 级），但其理论层三层次与 OMDoc 书（LNAI 4180）一致，且与 A 级原文 1005.5232 的 OMDoc 描述互相印证。

**F15（A）数学内容导出 RDF 的规模化先例：Isabelle 40M RDF 三元组、Coq 12M RDF 三元组；OMDoc/MMT 作通用交换格式。**
- URL: https://arxiv.org/abs/2005.03089｜Experiences from Exporting Major Proof Assistant Libraries｜Kohlhase & Rabe｜2020-05-05
- 摘录：「we translated the libraries of multiple proof assistants, specifically the ones of Coq, HOL Light, IMPS, Isabelle, Mizar, and PVS into a universal format: OMDoc/MMT.」
- 摘录 2：「we define an upper library ontology and use it to export linked data representations for the Isabelle (40M RDF triples) and Coq (12M RDF triples) libraries.」
- 摘录 3：「MMT can even represent alternated nesting of formal and informal text.」（flexiformal 承载）

**F16（A）RDF 承载数学的边界：RDF 推理限于可判定一阶子集，不足以承载数学公式语义；公式需 MathML/OpenMath，RDF 只承载结构骨架。**
- URL: https://arxiv.org/abs/1004.3390｜Publishing Math Lecture Notes as Linked Data｜David, Kohlhase, Lange, Rabe, Zhiltsov, Zholudev｜2010-04-20
- 摘录：「RDF-based reasoners are often limited to decidable first order logic subsets, which is insufficient for mathematical applications, and XML has a straightforward notion of order ...」
- 摘录 2（HELM 先例）：「HELM pioneered representing structures of mathematical knowledge in RDF, e.g. what mathematical theory introduces a symbol, what of its properties have been declared or asserted, and how the latter are proved.」
- 关联：直接落到 v1.3 范围约束——理论图的**结构骨架**（对象、边、边类型、来源）可进 L1 RDF；**语义载荷**（公理、公式、推导细节、算法）留在 M07 原文/L0 JSONL（C 级映射）。

**F17（A）flexiformal 是理科资料的常态：教科书=形式公式+自然语言混合，MKM 的 change management 用显式结构关系预测变更影响。**
- URL: https://arxiv.org/abs/1105.2392｜Workflows for the Management of Change in Science, Technologies, Engineering and Mathematics｜Autexier, David, Dietrich, Kohlhase, Zholudev｜2011-05-12
- 摘录：「the documents in the libraries are flexiformal (flexibly formal) because they contain semantic annotations at different levels of formality. A good example is an informal, but rigorous statement from a mathematical textbook, which intermixes mathematical formulas (formal representations of mathematical objects) with natural language (informal representations of their relations).」
- 摘录 2：「Change management makes use of the fact that MKM formats explicitly represent the relations between objects to compute related objects and predict the way changes affect them.」
- 关联：M06/M07 理科资料入库 + M08 更正不静默覆盖。

**F18（A）MMT 官方定位：统一表示科学知识的四大范式（表示语言/叙述/演绎/计算/制表）。**
- URL: https://uniformal.github.io/｜MMT Language and System｜KWARC (FAU)｜持续维护
- 摘录：「MMT integrates the 4 major paradigms for representing scientific knowledge」：Representation Languages / Narration（subsumes natural languages）/ Deduction（subsumes logical languages）/ Computation（subsumes programming languages）/ Tabulation（subsumes data description languages）。
- 关联：M08 需要同时承载自然语言（教材）+ 逻辑（公式）+ 计算（算法方法）+ 数据（表）——理论图的混合承载能力是 MKM 已设计目标。

## 4. 与范围/红线的冲突张力（无则明说无）

1. **理论图进入 vs L1 RDF 整合（v1.3 约束）——有张力，但可化解**：理论图的语义载荷（公理、公式、推导、算法）RDF 装不下（F16：RDF 推理限于可判定一阶子集，公式需 MathML/OpenMath）；MKM 自己的实践（F15：Isabelle/Coq RDF 导出）证明 RDF 承载的是**结构骨架**（对象/边/边类型/来源），语义载荷留在原文。化解：M08 的 L1 RDF 只承载「对象、关系、来源、状态、版本」结构索引，公式/推导/算法载荷留在 M07 原文 + L0 JSONL；这不另起格式、不改变 L1 RDF 定案（C 级映射，A 级先例）。
2. **提交即校验 vs 校验不进写路径（v1.3 红线/实测约束）——真实张力，需产品裁决**：TNTBase 以「库内保证 well-formed」为价值（非法提交被拒）；项目 P2 实测全量校验 8.48s 过慢 → v1.3 定为校验层只读审计。TNTBase 的增量模式（只验变更文档 + ABox 缓存依赖）是化解路径，但项目无模块级校验设施、红线禁性能基准，增量可行性与粒度未验证。本任务不改变红线，仅将「校验粒度/是否允许写时增量校验」列为待产品裁决的输入（A 级机制 + C 级判断）。
3. **biform 的「方法」范围 vs M08「方法」外延——张力，降级处理**：biform 只覆盖符号操纵算法（SBMA）；M08 的方法含思维框架等非形式结构。建议 M08 方法对象默认 flexiformal 承载（结构标注 + 自然语言 + 可选的算法对象），而非全量形式化 biform（C 级）。
4. **与红线「不物理删除/可回溯」无冲突**：TNTBase 与 FHIR 式在单链、只追加、不删历史、可回溯上同构，理论图版本化（每资源每版本命名图）保持只追加（A 级机制）。明说：无红线冲突。
5. **中文来源缺失不构成范围问题**：如实记录，不因此降级任何结论（F19）。

## 5. 未决与风险

1. **M08 概念对象粒度未定义（C 级）**：理论图的「理论/符号」粒度 vs FHIR「资源」粒度可互操作但哲学不同；M08 对象=理论？=符号？=主题？决定 ABox 谓词集与版本粒度的落法，交产品裁决。
2. **ABox 谓词族是 MMT 特定的（A 级事实 + C 级映射）**：10 一元 + 11 二元谓词（HasDomain、HasOccurrenceOfInType…）不能照搬；M08 关系族开放（上位/组成/前置/推导/等价/对比/混淆 + 高层），需自定谓词并写入 L1 @context（v1.3 §3.3 词表统一前置）。
3. **biform 成本（A 级事实 + C 级判断）**：若 M08 要求方法为一等形式对象，需 quotation+evaluation 元推理设施，工程成本高；建议默认 flexiformal 承载、算法对象按需加。是否要有「算法对象」一等对象交产品裁决。
4. **增量校验可行性未验证（C 级）**：项目红线禁性能基准；「模块级增量语义校验」仅是 TNTBase 先例支撑的方向，落地前需形态验证（非基准）。
5. **TNTBase 站点不可达（未核）**：http://tntbase.org 抓取返回空应答（未核/已停维护）；TNTBase 证据全部来自两篇 A 级论文（1005.5232、1105.0548 §9.2），不依赖官网。
6. **中文一手文献空白（F19，C 级）**：中文网络无 MKM 理论图直接来源；若产品需中文对照，只能依赖译介（未核）。
7. **「对比/混淆」关系在理论图无直接对应（C 级）**：M08 的对比/混淆是教学诊断关系，MKM 理论图不建模它；需自定义谓词或挂 flexiformal 注解。
