## 0. 一句话结论

GQL v2 不是"尚无决议"，而是**已经进入 ISO 标准流程的 Committee Draft 阶段**（ISO/IEC CD 39075，stage 30.60，CD 投票/评论期于 2026-01-30 截止；WG3 召集人目标 2027 年中出版），其 CD 内容含**『Constraints and Keys』（BCN-047，SQL 风格键/唯一约束）**与在讨论的 **Schema information graph**，直接回应 B2b 的『属性图校验』缺口；但 **LEX/PG-Schema 设计未被公开点名"整体采纳"**，LEX 侧以 **LEX-2026 版本化规范 + 个人参考实现（grasch-lex）**形式推进并准备 WG3 输入（含 LEX-096 键约束）。PG-Schema 仍**无标准校验器、无正式采纳动作**（2606.06127 NP-complete 理论结果无更新）；Neo4j GQL 强制特性覆盖**已从"GG01 最小符合"大幅扩展为"most mandatory"（2026.04 文档）**，但 **SESSION / CURRENT_GRAPH / AT 三项仍明确未支持**（无变化）。总体：『观望』的等待对象已从"悬空"变为"可见管线"，但两缺口（9+other 词表封闭、属性图校验）的最终闭合仍取决于 2027 GQL v2 内容与厂商落地，**2026-08 之后（即基线快照之后）仅观察到 2026-08-05 的 Text2GQL-Bench v2 修订一项**；其余关键证据多为 2025-09 至 2026-07 产物、为基线所未覆盖的新证据。

## 1. 父会话问题逐条回答

### Q1. GQL v2 是否已决定采用 PG-Schema / LEX 设计（上一轮 B2b U3：『进行中无最终决议』）？

- **结论**：**部分新进展 + 部分无变化**。GQL v2 已不再是"无最终决议"的悬空状态——它是**正式 ISO 项目（ISO/IEC CD 39075），已到 Committee Draft stage 30.60，投票/评论期于 2026-01-30 截止**（genorma.com 与 iss.rs 两页互证，A）。WG3 召集人 Keith Hare（2025-09-06 TUC deck，A）明确：GQL V2 目标 2027 出版，CD 咨询 2025-11-03 至 2026-01-25，DIS 投票 2027-01 至 2027-03。但"是否**整体采纳 PG-Schema/LEX 设计**"无公开决议：Hare deck 列的 v2 增强清单（已接受：Conditional Procedures、Vector；进行中：**List Element References、Constraints and Keys（BCN-047）、CALL PER()、SUM/PRODUCT**；在讨论：Optimal paths、**Schema information graph**）未点名 PG-Schema 或 LEX；LEX 组长 Alastair Green deck（2025-09-06，A）显示 LEX 以 2025.x 系列交付物（SQL-style Keys、Content Types、Information Schema Graph、Subtyping、JSON constraints、ER/UML 基数、FK、Subgraph Types、N-ary）向 WG3 输入，并称 LEX 输出定义是"Extends GQL graph types (compatible with GQL and SQL/PGQ)"、"**LEX can be the first manifestation of that concept, which is explored in PG-Schema**（OPEN and CLOSED element types）"。=> **采用关系是"启发/输入"而非"决议采纳"；约束与键方向确已进入 v2 工作项（新进展），LEX/PG-Schema 整体进 v2 无公开决议（无变化）**。

### Q2. PG-Schema 是否有标准校验器或正式采纳进展（上一轮：无标准校验器，2606.06127 证明 combined NP-complete）？

- **结论**：**无变化（校验器）+ 无变化（正式采纳）**，但**新增一条参考实现线**。
  - 无新标准校验器：arXiv 检索（2026-08-13，A）显示 PG-Schema 学术论文自 2606.06127 后无新增；2606.06127 仍 v1，无修订（A）。检索到的 pg-schemata、pgplex/pgschema 均为 PostgreSQL 工具，与属性图 PG-Schema 无关（A，已排除）。
  - **新增**：alastai/grasch-lex（Alastair Green 公开仓库，A）——"Grasch - GQL Catalog and LEX-2026 Schema Library"，"implementing **LEX-2026 as the first version of the LEX standard**"，提供 schema definition + validation + Kuzu 集成，388 commits，**design/spec 阶段、0 star、无 release**。这是 LEX-2026 的参考实现雏形，含内部校验能力，但**非 ISO/官方标准校验器**。
  - 正式采纳：无新动作。Information Systems 2026-02 论文《Graph functional dependencies: Analysis and translation to PG-schema》（DOI 10.1016/j.is.2025.102633，B，Crossref 元数据）延续图依赖→PG-schema 研究，非标准采纳。
  - 2606.06127 的 NP-complete 结论仍为最新理论下界（A，重确认）——这是"为什么没有简单校验器"的结构性原因。

### Q3. Neo4j 对 GQL mandatory 特性的覆盖是否扩展（上一轮 F9/F10：Cypher 按 GG01 最小符合、SESSION/CURRENT_GRAPH/AT 未支持）？

- **结论**：**覆盖面已扩展（新进展）+ 具体三项未支持（无变化）**。
  - Cypher GQL conformance 文档更新到 **2026.04（2026-04-30）**，主句："**Cypher now accommodates most mandatory GQL features and a substantial portion of its optional ones**"（A，文档镜像原文）。supported-mandatory 表已覆盖 MATCH/OPTIONAL MATCH、INSERT、SET、REMOVE、DELETE、ORDER BY/SKIP/OFFSET/LIMIT、RETURN、FINISH、CASE、聚合、图模式/标签表达式/路径模式、值类型谓词等大量强制子条款（A）——远超 GG01 最小符合。
  - **但** unsupported-mandatory 表仍明确列出：**7.1–7.3 SESSION SET/RESET/CLOSE**、**8.1–8.4 START TRANSACTION/COMMIT/ROLLBACK**、**11.1 CURRENT_GRAPH/CURRENT_PROPERTY_GRAPH**、**17.1 AT clause（HOME_SCHEMA/CURRENT_SCHEMA）**、21.3 保留字差异（A）。=> **SESSION/CURRENT_GRAPH/AT 三项仍未支持**，与 B2b 基线一致（无变化）；变化的是整体覆盖广度。
  - 备注：Neo4j 文档站对抓取工具 403，本取证基于 2026.04 版文档的 GitHub 镜像（A），并已与 2025.06 版镜像比对（措辞一致）。

### Q4. 若 GQL v2 / LEX 落地，对『9+other 词表封闭』与『属性图校验』两个缺口（B2b）的解决前景？

- **结论（前瞻，标 C 推断为主，附 A 级事实依据）**：
  - **『属性图校验』缺口**：前景**显著改善但非确定性闭合**。GQL v2 的 **Constraints and Keys（BCN-047）**把 SQL 风格键/唯一约束（`CREATE CONSTRAINT ... REQUIRE n.name IS UNIQUE` / `REQUIRE n.emp_nr IS KEY`）纳入标准工作项（A，Hare deck）；LEX 侧 **LEX-096 "Key and unique constraints in GQL"（Microsoft 提交 WG3/LEX）**与 LEX 2025.11 SQL-style Keys 直接对齐（A，Alastair deck）。若 v2 CD 保留该工作项，GQL 将在**标准层面**获得约束/键 DDL（对 B2b 的"结构不变量/状态枚举"可表达性有直接帮助）。**但**：① CD 草案内容不公开，范围裁剪风险未核；② 完整 schema 管理（GQL Annex D 可选特性 **GC01 Graph schema management**）在微软 Fabric 上仍标 No（A），说明"丰富 schema 管理"在现行 GQL 是可选特性、落地滞后；③ PG-Schema 全量校验仍受 2606.06127 NP-complete 约束——v2 的"Constraints and Keys"是 GQL 图类型（封闭子集）层面的约束，不等于 PG-Schema 全量校验器。
  - **『9+other 词表封闭』缺口**：前景**取决于 v2/LEX 对封闭图类型与标签表达式的正式化**。GQL v1 的 label expression（16.8，`&`/`|`/`!`）与 graph types（GG02 closed graph type）已提供"显式标签联合"的语法基础；Fabric 已实现 **GG02 封闭图类型**（"allowed node and edge types"）（A）。LEX 的 OPEN/CLOSED element types、STRICT 语义（Alastair deck 引 PG-Schema）若进 v2，则"9 固定 + other 兜底"中的 **other 是否受控**这一 B2b 遗留分歧（OPEN=任意 other vs 受控 other）将由标准语义裁决。目前仍无官方示例（无变化，未核），前景标 C。
  - **附带**：GQL v2 与 LEX 落地不解决 B2b 的**状态机转换规则**缺口（无触发器/时序原语进 v2 清单；PG-Triggers 仍为研究论文）——该结论维持无变化（C）。

## 3. 对决策点的输入

对决策点『属性图系（Neo4j/Cypher/NebulaGraph 等引擎）到底该不该进入 L1 语义层/查询层』及『等 GQL v2/LEX』立场复审的输入：

1. **等待对象的可见性变了**：GQL v2 已进 ISO CD 流程（30.60 截止 2026-01-30），目标 2027 出版（A）。『观望』不再是"等一个无期的东西"，而是"等一个可见管线的 2027 产物"。若个人项目的时间尺度允许等到 2027，观望的成本预期可算；若需要在 2026 内定案，则不能把决定押在 GQL v2 的约束/键特性上。
2. **『属性图校验』缺口的闭合路径已清晰但未落地**：v2 的 Constraints and Keys（BCN-047）+ LEX-096 键约束 = 标准层路径；grasch-lex = 参考实现路径（非官方）。两者都未交付可依赖的标准文本/库。决定者应把该缺口视为"有路径、无成品"。
3. **『9+other 词表封闭』的裁决点仍未到**：GQL v1 的 label expression + GG02 封闭图类型已提供语法基础（Fabric 落地）；但"other 是否受控"的语义由 LEX/PG-Schema 的 OPEN/CLOSED 设计决定，而该设计尚未进标准文本（C）。对 9+other 敏感的应用层决策，不应假设标准会在 2026 给出裁决。
4. **GQL 强制特性覆盖的扩展（Neo4j 到 most mandatory）降低了对标准就绪度的担忧，但不改变 SESSION/CURRENT_GRAPH/AT 未支持**：若应用依赖"图上下文切换（多图会话）"或"时间点 AT 子句"，Neo4j 目前仍不能做（A）；若只是单图查询层，则 GQL 兼容面已够用。
5. **实现生态在扩展（GraphLite/Fabric/BigQuery/Yueshu）**：标准采纳面在变宽，间接支持"GQL 系值得等"；但这些多为最小符合或自述级别，不等同于 PG-Schema 校验可用。

## 4. 与范围/红线的冲突张力

1. **时间窗口张力（必须明示）**：任务卡要求"只查 2026-08 之后的新进展"，而 B2b 基线快照为 2026-08-12，本复审为 2026-08-13——严格"之后"仅约 1 天。本任务的实际贡献是把**基线未覆盖的关键证据**（TUC20 两份 deck、CD 39075 项目状态、Cor1、Neo4j 2026.04 conformance、grasch-lex/LEX-2026、Fabric conformance、Text2GQL-Bench）首次纳入，并逐项标注日期与状态（新进展/新证据/无变化），由上层按时间口径取舍。**未把任何 B2b 已证结论当新进展**；凡基线已确认项（SESSION/CURRENT_GRAPH/AT 未支持、无标准校验器、2606.06127 NP-complete）均标"无变化"。
2. **"decks 是否算新进展"的口径张力**：Keith Hare/Alastair Green deck 为 2025-09-06 产物（早于基线），但基线未覆盖。本任务按"新证据（基线未覆盖）"与"新进展（状态确实前进）"分开标注，避免把旧材料伪装成 2026-08 后事件。
3. **"采纳 vs 启发"张力**：Hare deck 列 v2 增强未点名 PG-Schema/LEX，但 LEX 组长 deck 明言 LEX 输出"Extends GQL graph types"且"first manifestation of ... PG-Schema"。二者并存说明"整体采纳"无决议、"输入/启发"属实。本文不做超出证据的"已采纳"断言（C 级区分）。
4. **厂商 conformance 声称的采信边界**：GraphLite "full ISO GQL"、Yueshu "全面支持 ISO-GQL"均为自述，无官方 conformance 测试背书；Neo4j conformance 文档经 GitHub 镜像取证（官方页 403）。已分别标 A（镜像原文）/B/C，不放大为"标准通过"。
5. **不越界**：未做实现选型（Neo4j vs NebulaGraph vs Kuzu 等选择不评判）；NebulaGraph/Yueshu 仅作 GQL conformance 声称的引用，不评价引擎本身（邻接 S1/S2 不越界）。

## 5. 未决与风险

1. **GQL v2 CD 草案内容不公开**：CD 39075 的 Constraints and Keys（BCN-047）、Schema information graph、以及 LEX-096 键约束是否真的进入最终 CD/DIS，无公开文本可核（未核）。存在范围裁剪/评审否决风险。
2. **LEX/PG-Schema "整体采纳"无公开决议**：即便 LEX 侧全力输出，WG3 是否把 LEX 设计整体纳入 v2 仍是黑盒（未核）。Hare deck 中 v2 清单不含显式 "LEX/PG-Schema DDL" 条目，可能是"以约束/键子集方式吸收"而非整体吸收（C）。
3. **ISO 官网页持续 403**：iso.org/standard/76120.html（GQL）、93701.html（Cor1）、obp 页均无法直接抓取（未核）；Cor1 与 CD 状态以第三方标准商店/镜像（genorma、iss.rs、en-standard、CSA）佐证，存在转引误差风险（等级 A 指第三方页原文，非 ISO 官方页原文）。
4. **Neo4j conformance 取证依赖镜像**：官方文档页对抓取工具 403，本文取证使用 GitHub 镜像的 dev 分支 adoc（2026.04 版与 2025.06 版）；若镜像与官方发布版本有滞后，措辞细节可能不同（低风险，已比对两镜像一致）。
5. **grasch-lex 的地位存疑**：个人仓库、0 star、design/spec 阶段、无 release；"implementing LEX-2026"是作者自述，LEX-2026 尚未被 GDC/ISO 背书为正式标准文本（C）。其内部 "validation" 不等于标准校验器。
6. **BigQuery GQL 文档正文抓取受限**：docs.cloud.google.com 正文经 WebFetch 只能拿到导航（B）；BigQuery GQL schema 支持细节未核。Fabric 与 Spanner 的 GQL 文档可作替代证据。
7. **Text2GQL-Bench 是基准而非校验器**：2026-08-05 v2 修订虽为本窗口唯一新事件，但它测的是 LLM 文本→查询，不直接改变 PG-Schema 校验/词表封闭两缺口状态。

## 6. 建议的下一步

1. **在决定点复审时采纳"时间显式"口径**：把 GQL v2 进 CD（30.60，2026-01-30）、目标 2027 出版、Cor1 已发布（2026-07-31）作为标准进程事实；把 Constraints and Keys/LEX-096 作为"路径已清、成品未出"的中间态，而非可依赖结论。
2. **若需在 2026 内定案**：不把决定押在 GQL v2 的约束/键特性上；『属性图校验』与『9+other 封闭』继续视为需应用层自建或独立于 GQL 进度处理（与 B2b 结论一致，本复审未推翻）。
3. **盯两个可观测信号**：① ISO/IEC CD 39075 的下一步 stage 变化（30.60→40 DIS 或回退），可经 genorma.com/iss.rs 等镜像周期性复检（每次 A 级快照）；② grasch-lex 是否从个人仓库转为 GDC 官方发布、LEX-2026 是否出稳定版。
4. **补核缺口**：ISO 官方项目页（76120/93701）直抓仍 403 时，改用 ISO OBP 或国家采纳方（ANSI/BSI/CSA）页面；BigQuery GQL schema 文档改用非 JS 镜像（如 github.com/GoogleCloudPlatform 的 markdown 源）复核。
5. **对 LEX 交付物做一次性深核**：若未来决策需要，可抓 LEX-080r1 strawman 与 LEX-096（若公开）核对"9 固定+other"在 LEX DDL/YAML 中的具体语法，把 B2b 的 OPEN 等价性推断升级为 A 级。
