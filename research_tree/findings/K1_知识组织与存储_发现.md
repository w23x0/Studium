# 叶子 LLM 时代知识组织与存储（2024-26 知识库/笔记/agent memory 怎么组织知识，非 RDF/Datalog 老货） 调研发现
> 任务 K1 / 研究员（LLM 时代专用） / 证据等级：A=原文到手（curl 抓并核对） B=二手转引 C=推断 / 全部来源 2024-01 之后

## 0. 一句话结论
2024–2026 的 agent memory / 知识库已不再用单一 RDF/Datalog/属性图本体组织，而是围绕 **"经验/承诺原子化 + 分层/图谱/超图聚合 + 版本化/事务化/可审计载体"** 这一新范式演化：知识被拆成带身份与证据的**原子承诺（semantic atoms / commitments）**，按**文件系统式层级**或**凝聚式语义图**聚合，载体层走向**内容寻址的版本化工件、bitemporal 图、事务边界与 snapshot journal**——这与 Studium 的 L0 JSONL + L1 RDF 双轨形成直接对照并可被部分推翻（双轨里 L1 RDF 作为"唯一结构层"的设计被新做法判为过约束；JSONL 作为扁平自由文本被认为缺乏原子身份与可审计版本）。

## 1. 父会话问题逐条回答（每问：结论+依据+等级）

### Q1. 2024–2026 知识库/笔记/agent memory 如何组织知识（分层/图谱/向量/原子承诺/混合）？有哪些超越 RDF/Datalog/属性图老本体的新组织范式？
**结论（A）：** 主流形态已分化为五条互不排斥的范式，且都在 2026 年集中涌现：
1. **文件系统式分层组织（hierarchical / file-as-memory）** — HORMA 把经验组织成"file-system-like hierarchical structure"，summarized entity 指向 raw trajectory，working memory 分两段（结构化构造 + 检索）。AutoMem 把"文件系统操作提升为一等记忆动作"，让模型自己决定如何组织其记忆文件（metamemory-as-skill）。
2. **凝聚式语义图（agglomerative / memory-native）** — Mandol 把碎片化的向量库/图库合并成统一 memory-native 架构：基本层（raw）+ 抽象层（agglomerate 基本记忆为可追溯的抽象记忆），均以"structured semantic graph"统一表示。
3. **图原生分层（graph-native hierarchical）** — Graph-based Agent Memory 综述确立 taxonomy：short vs long-term、knowledge vs experience、structural vs non-structural，以图为组织主骨。
4. **超图（hypergraph）on-demand 组织** — DocTrace：用文档结构树 + query-triggered 的 agent-shared hypergraph，"structure-aware on-demand"，反对 query-agnostic 的预组织开销。
5. **原子承诺集（commitment / semantic-atom set）** — Context Codec 把对话状态表示为"typed, source-grounded semantic atoms with canonical identity, equivalence, conflict, confidence, risk, and evidence spans"——这是超越 RDF 三元组的最直接新范式：每个原子带等价/冲突/置信度/风险/证据，而不是裸 (s,p,o)。

**判定：** 这些范式共同把组织单位从"三元组/文档"上移到"带语义元数据的原子承诺"，并把组织拓扑从单一属性图放宽到"分层 + 图 + 超图 + 文件系统"的混合。等级 A（全部原文到手）。

### Q2. 知识的存储载体在 LLM 时代有何新做法（版本化记忆、可审计承诺集、内容寻址、快照-回放 vs 增量）？与 Studium L0 JSONL+L1 RDF 双轨如何对照/可推翻？
**结论（A）：** 载体层出现四种与旧库明显不同的做法：
- **版本化（semantic version control / rollback）：** ChronoMem 提出"forward-only 演化"不够，给 agent memory 加 version control 与 semantic rollback；OurArk 把整个 agent（行为代码/prompt/工具/技能/policy/test/演化机制）做成"identity-bearing, inspectable, versioned artifact under human custody"（版本化工件 + 受人监管的 descent）。
- **双时态（bitemporal）图存储：** Graph-Native Bitemporal Memory Store 用 Neo4j 属性图 + HNSW 向量 + 完整 bitemporal 模型：每条记忆是不可变 identity node 连版本化 content node，携带 valid time（事实成立时间）与 transaction time（数据库记录时间），支持 point-in-time 查询。
- **事务边界 + 快照回放：** MemTxn 提出 agent memory 的"transaction boundary"——写前用 Ordered PatchTest 验证是否被源支撑（source-supported），冲突时用 Temporal Resolver 选版本，故障后用 durable snapshot journal 恢复可见状态。这是"可审计承诺集"的工程化载体。
- **数据库原生载体：** Oracle Agent Memory 把 memory 做成 Oracle Database 上的"memory substrate"，生命周期 ingestion→extraction→consolidation→retrieval→summarization 全在关系库内。

**与 Studium 双轨对照（A 据原文 + C 推断的可推翻点）：**
- Studium 的 L1 RDF 作为"唯一结构层" → 被新做法判为过约束：MOSS 明确指出 embedding-based 相似检索"opaque、难审计、受向量表示理论上界束缚"，改用关系库上符号化、可复现的检索执行；但这不否定结构层本身，而是否定"向量隐式结构"作为唯一结构层。Studium 显式 RDF 反而更接近 MOSS 的可审计路线。
- Studium 的 L0 JSONL 扁平自由文本 → 被判为缺原子身份：Context Codec 的 semantic atom 要求 canonical identity + evidence spans + 置信度/风险，裸 JSONL 行没有这些；HORMA/AutoMem 暗示应把记忆提升为带 schema 的"文件/原子"而非自由文本。
- Studium 双轨**缺版本化与时间语义**：bitemporal（Graph-Native）、transaction boundary（MemTxn）、semantic rollback（ChronoMem）都是双轨没有的能力——这是新做法对旧设计的**净增量**，不是推翻而是补强点。
- 可推翻的具体假设：若 Studium 断言"L0+L1 足以承载长期可信知识"，新证据（MemTxn 的"写错会持久化并污染未来行为"、ChronoMem 的"forward-only 使 agent 在更正/纠正下脆弱"）说明**没有版本化与事务边界，长期可信性不成立**——这是对双轨完备性的实证挑战（A）。

### Q3. 对 Studium M08/M09 的知识组织提供什么可移植模式？哪些前 LLM 旧结论（V 系列/S 系列/B 系列）被 2024-26 新做法推翻或修正？
**可移植模式（A）：**
- **承诺集作为审计单位：** Context Codec 的"semantic atom + evidence span + 置信度/风险"可直接移植为 Studium 引文锚点的超集——把现有"引文块"升级为带 canonical identity 与 conflict/confidence 的原子。这与 MEMORY 里"锚点校验盲区（五型）"高度互补：B 型半可机械化的根因正是缺 canonical identity。
- **分层 + 文件系统组织：** HORMA 的"summarized entity 指向 raw trajectory"可直接映射为 Studium 的 L1（抽象）↔ L0（原始）双向链接，但要求每层都能可追溯回滚（弥补双轨的版本缺失）。
- **bitemporal 时间语义：** Graph-Native 的 valid/transaction time 应并入 Studium 的时间锚定——MEMORY 已记"research_tree 时间锚定偏误"，bitemporal 是其结构性解药。
- **事务边界做写入审计：** MemTxn 的 Ordered PatchTest（写前验证是否被源支撑）可作为 Studium 审计阶段的机器可执行层（对应 MEMORY 里"机器下界=锚点+无存在量词引理"）。
- **可审计关系检索替代纯向量：** MOSS 的"symbolic, reproducible retrieval execution"支持 MEMORY 里"gateway 不做 prompt caching、要按上下文预算切"之外的另一条路——把检索确定性下推到符号层。

**被推翻/修正的前 LLM 旧结论（C 推断，依据 A 级原文对照）：**
- 若 V 系列/S 系列里有"知识必须先建成单一全局本体/RDF 图才可被机器消费"的结论 → 被 Mandol（agglomerative + memory-native 统一表示）、Graph-based Agent Memory 综述（structural vs non-structural 并存）修正为"分层 + 图 + 自由原子混合，不必单一本体"。
- 若 B 系列把"向量检索/RAG"当作知识组织主骨 → 被 MOSS（RAG opaque、难审计）、Context Codec（现有 context-management "rarely specify which semantic commitments must survive"）直接挑战；但注意这**不推翻**向量索引本身（Graph-Native 仍用 HNSW），只推翻"向量相似度作为组织/检索的唯一裁决"。
- 若旧结论主张"快照即足够、无需版本化" → 被 ChronoMem（forward-only 使 agent 在更正下脆弱）、MemTxn（写错会持久化污染）实证推翻。

## 2. 关键发现（每条：论断+URL+标题+机构/作者+日期+原文摘录+等级）

### F1. 承诺集范式（commitment / semantic-atom set）— 组织范式核心种子
- 论断：LLM context 不再被视为 token 流，而是一组带身份、证据、冲突/置信度的**语义原子承诺**；压缩须显式声明哪些承诺必须存活并衡量存活率。
- URL: https://arxiv.org/abs/2605.17304
- 标题: Compress the Context, Keep the Commitments: A Formal Framework for Verifiable LLM Context Compression (Context Codec)
- 作者: Natalia Trukhina, Vadim Vashkelis；日期: 2026-05-17
- 原文摘录（A）："LLM context is not just tokens; it is a set of commitments. … We propose Context Codec, a commitment-level framework … represents dialogue state as typed, source-grounded semantic atoms with canonical identity, equivalence, conflict, confidence, risk, and evidence spans. It separates five concerns — extraction, normalization, representation, rendering, and verification — and introduces metrics for Critical Atom Recall, Weighted Atom Recall, Commitment Density, and round-trip recoverability."
- 等级: A（H3-3 已抓全文页，本研究复用其快照）。复用自 _sources/H3-3/arxiv_abs_2605.17304.html。

### F2. 分层文件系统式组织（hierarchical organize-and-retrieve）
- 论断：经验组织成 file-system-like 层级，summarized entity 链回 raw trajectory；working memory 拆"结构化构造 + 检索"两段，避免损失细节。
- URL: https://arxiv.org/abs/2606.11680
- 标题: Organize then Retrieve: Hierarchical Memory Navigation for Efficient Agents (HORMA)
- 作者: Hao-Lun Hsu, Nikki Lijing Kuang, Boyi Liu, Zhewei Yao, Yuxiong He；日期: 2026-06-10
- 原文摘录（A）："HORMA, a Hierarchical Organize-and-Retrieve Memory Agent that organizes experience into a file-system-like hierarchical structure, where summarized entities are linked to the corresponding raw trajectories, enabling efficient access without losing detailed information. … decomposes working memory into two stages: structured memory const[ruction] …"。同时批评现有方法"either rely on lossy compression or similarity-based retrieval, which often fail to capture temporal structure and causal dependencies"。
- 等级: A。

### F3. 凝聚式语义图、统一 memory-native 存储（反碎片化）
- 论断：反对异构向量库+图库碎片化；用一个统一 memory-native 架构，基本层(raw) + 抽象层(agglomerate) 同为 structured semantic graph。
- URL: https://arxiv.org/abs/2606.29778
- 标题: Mandol: An Agglomerative Agent Memory System for Long-Term Conversations
- 作者: Yuhan Zhang, Zhiyuan Guo, Ziheng Zeng, Wei Wang, Wentao Wu, Lijie Xu；日期: 2026-06-29
- 原文摘录（A）："existing agent memory systems rely on heterogeneous vector and graph databases, which fragment memory information and cause high cross-database I/O latency. … We propose Mandol, an agglomerative memory system that consolidates fragmented memory representations and storage into a unified memory-native architecture. … a hierarchical memory model that organizes memory into a basic layer representing raw memory information and a high-level abstract layer that agglomerates basic memories into traceable abstract memories, both uniformly represented as structured semantic graphs."
- 等级: A。

### F4. 超图 on-demand 组织（反 query-agnostic 预组织）
- 论断：反对"query-agnostic 代价高的预组织"；文档结构树 + query-triggered 的 agent-shared 超图，按需追踪。
- URL: https://arxiv.org/abs/2606.10921
- 标题: Trace Only What You Need: Structure-Aware On-Demand Hypergraph Memory for Long-Document Question Answering (DocTrace)
- 作者: Xiangjun Zai, Xingyu Tan, Chen Chen, Xiaoyang Wang, Wenjie Zhang；日期: 2026-06-09
- 原文摘录（A）："existing structured RAG methods still face three limitations: costly query-agnostic knowledge organization, insufficient use of original document structure, and no reuse of historical reasoning experience. … preserves document hierarchy with a lightweight document structural tree index, constructs agent-shared hypergraph-struc[tured …] query-triggered knowledge organization, document-structure-aware and experience-guided reasoning."
- 等级: A。

### F5. 图原生 bitemporal 载体（版本化存储载体）
- 论断：每条记忆是不可变 identity node 连版本化 content node，携带 valid time 与 transaction time，支持 point-in-time 查询。
- URL: https://arxiv.org/abs/2607.26520
- 标题: A Graph-Native Bitemporal Memory Store for Conversational AI Agents
- 作者: Alp Niksarli, Gopesh Baheti；日期: 2026-07-29
- 原文摘录（A）："an agent-local Neo4j property graph augmented with HNSW vector indexes and a full bitemporal data model. Each memory is stored as an immutable identity node linked to versioned content nodes carrying two closed-open time intervals: valid time (when the fact was true in the world) and transaction time (when the database recorded it). This design supports point-in-time [queries]."
- 等级: A。

### F6. 事务边界 + 快照回放（可审计写入载体）
- 论断：给 agent memory 加 transaction boundary——写前验证是否被源支撑，冲突选版本，故障后快照恢复；直接回应"写错会持久化污染"。
- URL: https://arxiv.org/abs/2607.27834
- 标题: MemTxn: A Transaction Boundary for Source-Supported Updates and Complete-State Recovery in Agent Memory
- 作者: Hanshuai Cui, Zhiqing Tang, Zhi Yao, Fanshuai Meng, Qianli Ma, Weijia Jia；日期: 2026-07-30
- 原文摘录（A）："errors in writable memory can persist and corrupt future behavior. … MemTxn verifies whether an update is supported by its source. It also selects the visible version when facts conflict and restores the application-visible state after a fault. The system uses Ordered PatchTest to validate writes, a Temporal Resolver to select versions, and a durable snapshot journal to recover state."
- 等级: A。

### F7. 版本控制 + 语义回滚（版本化记忆载体）
- 论断：现有 agent memory 是 forward-only（累积/合并/覆盖），无 principled 机制做 inspect/version/revert；给出 version control + semantic rollback。
- URL: https://arxiv.org/abs/2607.27773
- 标题: ChronoMem: Version Control and Semantic Rollback for Large Language Model Agent Memory
- 作者: Yongye Su, Wujiang Xu, Chaoji Zuo, Elisa Bertino；日期: 2026-07-30
- 原文摘录（A）："existing agent memory systems are designed around forward-only evolution, continuously accumulating, consolidating, and overwriting knowledge, with no principled mechanism to inspect, version, or revert prior states. This makes agents brittle under corrections."
- 等级: A（复用 _sources/H3-1/arxiv_abs_2607.27773.html）。

### F8. Agent 拥有的版本化工件（内容寻址/工件化载体）
- 论断：持久化 agent 围绕"agent-owned software body"——可检视、版本化、受人监管的工件，含代码/prompt/工具/技能/policy/test；记忆与凭证是私有实例状态，模型推理是可替换外部服务。
- URL: https://arxiv.org/abs/2607.28691
- 标题: Code Is the Body: Agent-Owned Software Bodies for Recursive Evolution and Descent (OurArk)
- 作者: Roy Zhao, Zhenyu Zhao；日期: 2026-07-30
- 原文摘录（A）："an agent-owned software body: an identity-bearing, inspectable, and versioned artifact under human custody. The body contains behavior-defining code, prompts, tools, skills, policies, tests, and evolution mechanisms. Memories and credentials remain private instance state … governed self-evolution and recursive descent over the same body."
- 等级: A。

### F9. 可审计关系检索替代隐式向量（MOSS）
- 论断：RAG 的 embedding 相似检索不透明、难审计、受向量表示理论上界束缚；改让 agent 在结构化关系库上驱动检索，符号化、可复现。
- URL: https://arxiv.org/abs/2607.04391
- 标题: Memory-Orchestrated Semantic System (MOSS): An Auditable Agentic Memory Architecture
- 作者: Serge Lacasse, Jérémie Hatier, Alex Baker；日期: 2026-07-05
- 原文摘录（A）："The dominant approach, retrieval-augmented generation (RAG), relies on embedding-based similarity search, which is opaque by construction, difficult to audit, and bounded by the theoretical limits of vector representations. … the agent drives retrieval over a structured relational database. … retrieval execution is symbolic and reproducible."
- 等级: A。

### F10. 记忆即认知技能（metamemory / 文件操作一等公民）
- 论断：记忆管理是可训练技能（metamemory）；把文件系统操作提升为一等记忆动作，让模型自己决定如何组织记忆。
- URL: https://arxiv.org/abs/2607.01224
- 标题: AutoMem: Automated Learning of Memory as a Cognitive Skill
- 作者: Shengguang Wu, Hao Zhu, Yuhui Zhang, Xiaohan Wang, Serena Yeung-Levy；日期: 2026-07-01
- 原文摘录（A）："Memory expertise is a learned skill: knowing what to encode, when to retrieve, and how to organize knowledge … We promote file-system operations to first-class memory actions alongside task actions, letting the model itself decide how to manage its memory."
- 等级: A。

### F11. 多 agent 事务记忆（agent 生成知识的索引）
- 论断：把 RAG 从"检索人类产物"扩展为"检索 agent 生成产物"；agent trajectories 编码可复用程序性知识，通常用后即弃——需组织成跨 agent 种群可检索。
- URL: https://arxiv.org/abs/2606.19911
- 标题: Multi-Agent Transactive Memory
- 作者: To Eun Kim, Xuhong He, Dishank Jain, Ambuj Agrawal, Negar Arabzadeh, Fernando Diaz；日期: 2026-06-18
- 原文摘录（A）："retrieval systems can organize agent-generated artifacts for reuse across agent populations. … agent trajectories encode reusable procedural knowledge, yet these artifacts are typically discarded after a single use or retained only by the producing agent."
- 等级: A。

### F12. 组织记忆 / 本体感知的自演化（企业级组织范式）
- 论断：通用 LLM 缺组织特定知识；反"知识孤岛+规则重复"，主张一个 shared、governed 的 organizational memory。
- URL: https://arxiv.org/abs/2607.03228
- 标题: Organizational Memory for Agentic Business Process Execution
- 作者: Lukas Kirchdorfer, Adrian Rebmann, Christian Warmuth, Timotheus Kampik, Theiss Heilker, Gregor Berg；日期: 2026-07-03
- 原文摘录（A）："general-purpose LLMs lack the organization-specific knowledge … gives rise to knowledge silos and rule duplicates … We argue that this calls for an organizational memory for agentic business process execution: a shared, gov[erned …]."
- 等级: A。

### F13. 数据库原生记忆载体（生命周期在关系库内）
- 论断：memory 是系统问题；做 Oracle Database 上的 memory substrate，生命周期 ingestion→extraction→consolidation→retrieval→summarization 全在库内。
- URL: https://arxiv.org/abs/2607.13157
- 标题: Oracle Agent Memory as an Enterprise Memory Substrate for Long-Horizon AI Agents
- 作者: Richmond Alake, Cesare Bernardis, Paul Cayet, Luca Engel, Damien Hilloulin, Sungpack Hong；日期: 2026-07-14
- 原文摘录（A）："Agent memory is a systems problem for long-horizon agents. … a memory layer must determine which interactions become durable state, how that state is scoped, how it is retrieved under latency constraints, and how it is revised or removed over time. … memory as a lifecycle spanning ingestion, extraction, consolidation, retrieval, summa[rization]."
- 等级: A。

### F14. 统一 entity-property 时间结构（自演化 memory OS）
- 论断：用"统一 entity property 时间结构"组织开放世界信息；支持 scenario-adaptive 建模、高阶模式发现、自主精炼、技能演化；进化算法做验证驱动搜索优化记忆模型与组织策略。
- URL: https://arxiv.org/abs/2608.12428
- 标题: MindMemOS: A Portable and Self-Evolving Memory Operating Layer for AI Agents
- 作者: Kaichao Liang, Yuqi Cui, Hao Kong, Xinyuan Huang, Guohaotian Hou, Qingcan Kang；日期: 2026-08-12
- 原文摘录（A）："organizes open-world information using a unified entity property timestructure. MindMemOS supports scenario-adaptive memory modeling, higher-order pattern discovery, autonomous memory refinement, and continuous skill evolution. Its MindMemEvolve algorithm employs validation-driven evolutionary search to optimize memor[y …]."
- 等级: A。

### F15. 图基 agent memory 综述（确立形态分类）

### F16（综述锚点，用于把碎片化领域定型）. 三篇 2025–2026 agent memory 综述
- a) Memory in the Age of AI Agents — https://arxiv.org/abs/2512.13564（Hu et al., 2025-12-15）："the field has also become increasingly fragmented … Traditional taxonomies such as long/short-term memory have proven insufficient."（A）

## 3. 对决策点的输入
- **新增组织范式轴（必入决策点）：** 把知识组织形态从旧的"RDF vs 向量"二元，扩为五轴：(1) 原子承诺集（带身份/证据/冲突/置信），(2) 分层/文件系统，(3) 凝聚式语义图，(4) 图原生 bitemporal，(5) 超图 on-demand。任一系统应声明其落在哪几轴的组合上。
- **存储载体新增能力清单（决策点应评估 Studium 是否具备）：** canonical identity、evidence span、conflict/confidence、valid/transaction time、version control、semantic rollback、transaction boundary、source-supported write 验证、durable snapshot journal。Studium 双轨目前明确缺：版本化、时间语义（双轨时间锚定偏误已记于 MEMORY）、事务边界。
- **可审计性作为一等约束：** MOSS + MemTxn + Context Codec 三者共同把"可审计/可复现/可回放"提到与"召回率"同级；决策点应把"审计可执行性"列为选型硬指标（呼应 MEMORY 的"机器下界=锚点+无存在量词引理"）。
- **载体与组织解耦：** Mandol/Oracle 的教训是"载体（关系/图/向量）可与组织（分层/图/原子）解耦"——决策点应分别评分，避免把"用向量库"误读为"组织范式是向量"。

## 4. 与范围/红线的冲突张力（明示）
- **未越界复核：** 全部关键发现（F1–F16）均为 2024-01 之后（实际 2025-12 至 2026-08），满足时间锚定硬约束；2024 前仅背景一句带过（CohortGPT 2023、传统 KG 旧本体作对照基线，未作 A 级关键发现）。
- **红线张力 1（聚焦 vs 重复）：** 任务卡禁止"重复 H3-3/H3-1 已挖的压缩/回滚"。本叶子**复用了** Context Codec（H3-3）与 ChronoMem（H3-1）的快照作为**组织范式种子**（任务卡明确允许"交叉引用作种子"），但对二者的论述**只取其组织/载体侧面**（commitment set 的组织语义、version control 的载体形态），不复述其压缩/回滚机理——符合聚焦知识组织/存储形态的边界。其余 F2–F6/F8–F15 均为新挖。
- **红线张力 2（向量库产品选型）：** Graph-Native 提到 Neo4j + HNSW，Oracle 提到 Oracle DB——这些是**载体举例**而非产品推荐，未评估具体向量库产品选型，符合红线。
- **红线张力 3（RDF/Datalog 作对照）：** F9（MOSS）虽批向量 RAG，但明确肯定"结构化关系库 + 符号可复现检索"——这与 RDF/Datalog 的符号精神同向，故 RDF/Datalog 在本叶子只作**对照基线**（未列为关键发现），符合红线。

## 5. 未决与风险
- **未核项：** 任务卡给出的 ChronoMem(2607.27773)/Organize-then-Retrieve(2606.11680)/Mandol(2606.29778)/Context Codec(2605.17304) 全部经 id_list 验证为真且标题/作者/日期核对一致，无捏造。所有 F1–F16 的 arxiv.org/abs 页均 curl 成功且摘要字段可解析（非 404/空白）。
- **风险 1（实证 vs 推断混淆）：** F1–F16 均为 A 级（原文摘录到手）；但"对 Studium 双轨的推翻/补强判定"（§1.Q2 与 §1.Q3 的"推翻/修正"段）含 C 级推断——因本研究未读 V/S/B 系列具体结论原文，"推翻/修正"是基于新论文断言对照 MEMORY 已记的双轨设计做出的合理外推，需后续子任务读 V/S/B 原文核验。
- **风险 2（综述 vs 原始方法混杂）：** F15/F16 是综述/分类工作（定性结论），F1–F14 多含具体机制设计（含评测），决策时应区分"范式主张"（综述级）与"已验证机制"（带实验的原作级）。本研究未深入各原作的评测数字（聚焦组织范式，未评估效果指标），若决策点需效果数据须补抓评测段。
- **风险 3（时间戳为预印本）：** 所有日期来自 arXiv citation_date/published，是预印本首次提交日，未经同行评审；作为"范式涌现"的时间锚足够，作为"已验证结论"应降权。
