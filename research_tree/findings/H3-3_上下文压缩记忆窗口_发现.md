# 叶子 H3-3 上下文压缩与记忆窗口管理 调研发现

> 任务 H3-3 / A=原文到手 B=二手转引 C=推断
> 调研主题：上下文压缩主流形态、压缩后如何保持可 grep/可锚点（吸附 Studium L0 红线）、记忆窗口管理
> 时间锚定：全部证据 2024-01 之后

## 0. 一句话结论
**上下文压缩已从「猜摘要」演进为「可验证的承诺保留」**：2025–2026 文献把上下文重新定义为「一组必须存活的语义承诺（commitments）」，并给出分离提取/归一化/表示/渲染/验证五关注点的形式化框架（Context Codec）与度量（原子召回、往返可恢复性）；同时实证表明「可读符号重表达」在匹配预算下比「流畅连贯摘要」保留更多推理证据（Telegraph English 胜 13–20 F1）——这直接支持 Studium L0「压缩后仍可 grep/可锚点」的红线取向，且给出一条 L0 兼容的压缩形态（ASCII 可读符号原子）。

## 1. 父会话问题逐条回答

**Q1. 上下文压缩的主流形态与权衡？**
- 结论：三形态并存。**（a）重 LLM 摘要（gist/循环状态）**：把旧历史压缩成紧凑表示，但 Sleeping Agent 实证其系统性丢失时间/日期表达式（保留率从 3.05% 提到 62.39% 才修复时序问题），时序推理、实体/事件之外的 temporal 信息是盲区。**（b）中编码/隐藏态记忆（soft）**：SeDeM 用中间 Transformer 层隐藏态 + 轻量压缩器存 memory block + 查询条件选择器只解压选中块，且把「紧凑记忆存储」与「解码器条件」解耦；PReM 用记忆层 + 刷新 token <m> 决定保留什么/何时刷新。**（c）窗口/淘汰**：仍是朴素基线，但非压缩主流。权衡：重摘要省 token 但丢时序/承诺；中编码保留语义但需训练；符号重表达保留实体密度但牺牲流畅。
- 依据：2608.11775、2608.00311(SeDeM)、2607.14327(PReM)、2606.14875
- 等级：A

**Q2. 压缩后如何保持可 grep/可锚点（吸附 L0 红线）？**
- 结论：**有两篇直接给出 L0 兼容答案**。（i）Context Codec：上下文=承诺集，用 ASCII-first 的 CCL 渲染把规范 JSON 原子渲染成可读紧凑符号（介于结构散文与 JSON 之间：比 prose 更显式可审计、比 JSON 更紧凑、比重度 minify 更安全），并定义 round-trip recoverability（往返可恢复性）——这就是「压缩后仍可回到稳定原子、可逐字比对」的形态化。（ii）Context Compression Is Not One Thing：可读符号重表达（Telegraph English=结构化 entity-relation 陈述）在匹配 token 预算下，实体内容保留密度高于自然语言散文和连贯摘要。共同启示：**要「可 grep/可锚点」就选「符号化原子 + 原子级度量的压缩」，而非连贯摘要**。
- 依据：2605.17304、2606.14875
- 等级：A

**Q3. 记忆窗口管理对 Studium 长程会话状态的可移植模式？**
- 结论（C/A 混）：可移植四点。（i）**分层记忆导航**（Organize then Retrieve）：长程 agent 因 statelessness 需全部状态进上下文，分层组织+检索式导航避免全量进窗口——记忆「组织后检索」而非「全进上下文」。（ii）**凝聚式/Γ-记忆**（Mandol、Recurrent/Gamma 类）压成固定大小状态。（iii）**记忆即上下文的一类，与压缩同源**：H3-3 与 H3-1 的交叠处=「记忆版本化+回滚」（ChronoMem）与「记忆承诺保留」（Context Codec）是同一问题的两面——都要求状态可回退、原子不丢。（iv）**刷新时机**（PReM）：不是一股脑刷，是记忆层感知何时需刷新。
- 依据：2606.11680、2606.29778、2606.18406、2605.17304、并表 H3-1 ChronoMem
- 等级：C（迁移模式推断）+ A（各文献机制实证）

## 2. 关键发现

**F1. 【Context Codec：上下文=承诺集，可验证压缩的形式化框架】**
- 论断：把对话状态表示为类型化、源头接地（source-grounded）的语义原子，剥离五个关注点（提取/归一化/表示/渲染/验证）；定义 Critical Atom Recall / Weighted Atom Recall / Commitment Density / **round-trip recoverability**；给出语义压缩错误分类、低置信与安全关键原子的保守回退规则、CCL（ASCII-first 紧凑渲染）；小规模诊断示 CCL-Core 介于结构散文与 JSON 之间（比 prose 更显式可审计、比 JSON 更紧凑、比重度 minify 更安全）。主张不是「速记解决压缩」，而是「让压缩可验证」。
- 来源：arXiv 2605.17304，abs 页 arxiv_abs_2605.17304.html；Natalia Trukhina, Vadim Vashkelis；published 2026-05-17
- 原文摘录：「LLM context is not just tokens; it is a set of commitments」；「separates five concerns - extraction, normalization, representation, rendering, and verification」；「make context compression verifiable: compress the conversation, keep the commitments」
- 等级：A

**F2. 【Context Compression Is Not One Thing：可读符号重表达胜于连贯摘要】** 
- 论断：Telegraph English（把检索段落重写成结构化 entity-relation 陈述）在 MuSiQue/TwoWiki/HotpotQA 上胜匹配预算的字符删减/截断/随机子采样三基线，13–20 F1 点；且在最难数据集上胜同编码器产生的连贯散文摘要。解读：可读符号重表达比自然语言/连贯摘要更密实地保留实体内容（at matched token budget）。预注册的「深度交互」假设为 null（优势不随推理深度增长）。
- 来源：arXiv 2606.14875，abs 页 arxiv_abs_2606.14875.html；Sisong Bei 等；published 2026-06-12
- 原文摘录：「readable symbolic re-expression preserves entity content more densely than either natural language or coherent summarization at matched token budget」
- 等级：A

**F3. 【The Sleeping Agent：gist 压缩系统性地丢时间/日期】** 
- 论断：gist 压缩在 multi-hop reasoning/单跳事实问答上显著优于截断，但 **temporal 问题在压缩下显著更难**；机制=gist 抽象提示保留关系与事件结构却丢弃日期时间；保存分析证实时间表达保留率 3.05%→62.39%（一句话提示修改），而命名实体/事件保留率几乎不变（x1.02/x1.11）；修复该段可恢复 +0.314 judge accuracy（temporal 类）。
- 来源：arXiv 2608.11775，abs 页 arxiv_abs_2608.11775.html；Nicholas E. Kyrkewood；published 2026-08-12
- 原文摘录：「the gist abstraction prompt preserves relational and event structure while discarding dates and times」
- 等级：A

**F4. 【SeDeM：软压缩记忆的选择性子解压，解耦存储与解码条件】** 
- 论断：prefill 自注意随序列平方增长、KV 缓存随 token 增长；软压缩方法多用 LLM 当压缩器+紧凑 memory token 既存信息又条件解码器。SeDeM 解耦「紧凑记忆存储」与「解码条件」：中间层隐藏态→轻量压缩→查询条件选择→只解压选中块；1B/3B 同骨干超压缩基线，3B 超全上下文微调于三数据集；降 TTFT、提解码吞吐 relative to ICAE。
- 来源：arXiv 2608.00311，abs 页 arxiv_abs_2608.00311.html；Maryam Haghifam, Jason Cong, Yizhou Sun；published 2026-07-31
- 原文摘录：「self-attention during prefill scales quadratically with sequence length」；「decouples compact memory storage from decoder conditioning」
- 等级：A

**F5. 【PReM：保留什么+何时刷新，记忆层感知刷新时机】** 
- 论断：长上下文推理还要让有用证据随生成可及；早期挑选或外置压缩器都难适应后续推理需要的证据。PReM 把长上下文保持为模型内层式 KV 记忆，记忆层做选择、特殊 token <m> 触发刷新；32K 上下文中 16x/32x 压缩超强基线。
- 来源：arXiv 2607.14327，abs 页 arxiv_abs_2607.14327.html；Bohan Yu 等；published 2026-07-15
- 等级：A

**F6. 【Organize then Retrieve / Mandol：分层与凝聚式记忆导航】** 
- 论断：（i）Organize then Retrieve：LLM agent 天然 statelessless、需全部任务状态进上下文，分层组织+检索式导航提效率（长程任务）。 （ii）Mandol：跨会话多型信息关联的凝聚式记忆系统。均属「记忆窗口管理」的近期形态。
- 来源：arXiv 2606.11680、2606.29778（API summary 到手）
- 等级：A（元数据级，正文未核）

## 3. 对决策点的输入
- **压缩形态选型**：Studium 若压缩上下文，优先「符号化原子 + 原子级度量 + 可回退」而非连贯摘要——直接匹配 L0 可 grep/可锚点红线；Context Codec 的 round-trip recoverability 给出一条可机械验证的判据。
- **压缩盲区**：gist 式压缩丢时间/时序——Studium 若含时序事实，压缩须显式保 temporal 原子（Sleeping Agent 的机制级证据）。
- **记忆窗口与 H3-1 并表**：记忆版本化回滚(ChronoMem) + 记忆承诺保留(Context Codec) 是同一「状态可回退、原子不丢」问题的两面。

## 4. 与范围/红线的冲突张力
- 无红线冲突。压缩技术不实现（不写码），只评估结构模式与可审计性（bounds 遵守）。

## 5. 未决与风险
- Context Codec 是「小规模诊断研究」（作者自述），CCL 的生产级验证不足 → 标 C 悬置其对大负载的泛化。
- SeDeM/PReM 需训练，非推理期即插即用——对「不写码、评估结构」边界下的适配需权衡训练成本。
- F6 两篇仅元数据级，正文未核。

## 6. 建议的下一步
- 若需坐实「符号化压缩可锚点」，可把 Context Codec 的 CCL + 该叶 F2 的 Telegraph English 并表，评估对 Studium L0 JSONL 锚点的映射可行性（C 级草案）。
- Sleeping Agent 的 temporal 保留机制可作为 Studium 压缩策略的「必保字段」清单来源。
