## 0. 一句话结论

GPM 五契约条款（I1 账本完整性 / I2 源绑定 / I3 冲突隔离 / I4 不复活 / I5 释放闭包）与 Studium 审计状态机**逐项同构确认（8 项对应）+ 三处真实差异**：①GPM 的**派生生命周期状态**（状态由事件派生、不信任调用者声明）对应 Studium「机械信号只定向不结案」但 GPM 是**运行时执行义务**、Studium 是**审计/晋升设计原则**；②GPM I4「不复活」覆盖**删除屏障 + 陈旧索引/物化投影不得复活**，Studium 有撤回但**无删除屏障、无索引/投影复活防护**（缺口）；③GPM I5「释放闭包」要求**结构化释放必须逐字绑定源事实 ID + 单已验证 head 上 fail-closed**，Studium L2 verificationStatus 有状态机但**无释放层闭包语义**（L0 锚点逐字=对应 I2 源绑定，非 I5）。**净结论：同构从 C 升级为 A 级逐项确认；三处差异给出 Studium 可移植补丁（删除屏障/派生状态/释放闭包），其中 I4 缺口最值得产品裁决。**

## 1. GPM 五条款（A，全文逐字）

| 条款 | 精确内容 | 性质 |
|---|---|---|
| **I1 账本完整性** | 相对可信本地承诺，序列/前驱/规范事件哈希/段清单/索引分片承诺一致；失败停止公共服务或进显式恢复路径 | 存储层完整性义务 |
| **I2 源绑定** | 每个公开事实有有效、直接、同用户的 witness 绑定源字节+位置元数据；调用者声明的推断事实在公开前隔离/拒绝；投影重查源绑定而非永久信任准入；**不**证明引文语义蕴含规范化 claim | 准入+投影双层 |
| **I3 冲突隔离** | 无未解决冲突对 cᵢ⋈cⱼ 同时作为可断言公开事实 | 冲突隔离 |
| **I4 不复活** | 公开读在当前已验证头应用撤回+用户删除策略，即使请求更早前缀；被覆盖事实及其绑定事件**不得经历史时间/陈旧引擎索引/引擎维护的物化投影复活** | 删除屏障+索引防护 |
| **I5 释放闭包** | 每个释放的结构化答案 claim 精确匹配新鲜公开视图中的可断言事实，提供非空源事实 ID 集合；返回记录绑定规范完整 claim 多重集/策略与规范化版本/用户/查询/快照/已验证头；**释放仅在头保持 h_b 时允许，头变更即 fail-closed 无记录** | 释放层闭包 |

## 3. 逐项对照（A+C）

| GPM 条款 | Studium 对应 | 对应度 | 差异 |
|---|---|---|---|
| I1 账本完整性 | L3 哈希链 | **同构** | GPM 含「段清单+索引分片承诺」；Studium L3 只哈希版本链，索引完整性未承诺（可补） |
| I2 源绑定 | L0 锚点逐字 + 候选区来源标记 | **同构** | GPM「不证明语义蕴含」=Studium「逐字校验证明不了引文支撑断言」（[[anchor-verification-blind-spot]]）；GPM「投影重查」对应候选晋升后仍可更正/撤回；但 GPM 是**运行时强制**，Studium 是**审计/晋升门** |
| I3 冲突隔离 | M08 候选审计「逻辑冲突」检查 | 部分同构 | GPM 冲突定义可执行（同用户/规范化实体/单值属性/重叠有效区间/不等值/无撤回无取代→冲突对隔离）；Studium 冲突检查是**候选审计项**，未定义可执行冲突判定（可借 GPM 定义） |
| I4 不复活 | M08「撤回保留依据和历史」 | **部分缺口** | Studium 有撤回（correct/retract/refute 状态），但**无用户删除屏障**、**无「陈旧索引/物化投影不得复活」防护**；GPM 明确防历史时间/索引/投影三重复活 |
| I5 释放闭包 | L2 verificationStatus + M08 输出 | **缺口** | GPM 释放=「结构化 claim 逐字绑定源事实 ID + 单头 fail-closed」；Studium 输出物直接引用锚点，但**无「释放层闭包」语义**（无「释放记录绑定 claim 多重集+版本+头」的契约） |

## 4. 三处真实差异与可移植补丁（C）

1. **派生生命周期状态（GPM）→ Studium 可借**：GPM「状态由事件派生而非调用者自由标注」（Table 1：episode.add/fact.quarantine/fact.assert/fact.retract/user.delete 全由事件触发）。Studium 的 verificationStatus（unconfirmed→provisional→confirmed）已是事件驱动雏形，但**未定义「谁有权标状态」**（M08 审查单 Q3：人工/学习者/规则/模型各有什么确认权）——GPM 的「派生而非调用者声明」可直接回答：状态只能由审计/晋升事件派生，模型不得自标状态。
2. **I4 删除屏障缺口 → 最值得产品裁决**：Studium 有「撤回」（retract→refuted），但**无「用户删除」屏障**（学习者的历史记录删除后，陈旧索引/派生投影是否会复活旧结论？）M09 明确「不静默覆盖旧结论」，但**未规定删除语义**——GPM I4 提供现成答案：删除设屏障，屏障之前的记录不得经任何路径（历史读/索引/投影）复活。
3. **I5 释放闭包缺口 → L0 锚点的强化位**：Studium 现依赖「锚点=原文逐字」（I2 对应物）保证输出可信，但**没有「释放层」概念**——即「对外交付的答案 claim 必须精确绑定它引用的源事实 ID 集」这一契约未成文。对 M08/M09 的输出（教学/诊断依据）是自然补强：结构化输出应带「完整 claim 多重集 + 源锚点 ID 集 + 版本」的闭包记录。

## 5. 与既有红线协调（A+C）

- **GPM I2 与红线不冲突，且独立强化**：GPM 明确「引文语义蕴含不是源绑定的一部分」= Studium「逐字校验证明不了支撑」的红线外部复现（不同团队、同一结论）。
- **GPM I5 不推翻「锚点判等=原文对应」**：I5 是释放层的补充契约（claim 绑定源 ID），不是替代锚点逐字；与 K3「机械信号只定向不结案」兼容。
- **派生状态 = K3「机械信号域扩到 LLM 信号」的结构化落点**：模型自标状态属于「LLM 信号」，按红线只定向不结案；状态晋升权归审计事件（人/规则），非模型。

## 6. 建议的下一步（C）

1. **产品裁决 I4 缺口**：Studium 是否需要「用户删除屏障 + 陈旧索引/投影不复活」语义？M09「不覆盖旧结论」已暗示需要，但删除语义未定义。
2. **M08 冲突判定可执行化**：借 GPM 冲突定义（同实体/单值属性/重叠有效区间/不等值/无撤回无取代→隔离）落为 M08 候选审计规则。
3. **释放闭包成文**：M08/M09 输出物契约加「claim 多重集 + 源锚点 ID + 版本 + 头」字段（可选，产品裁决）。
