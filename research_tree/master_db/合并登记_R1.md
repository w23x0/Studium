## 二、合并要点（去重后净新增，按分支）
- **B1**：RDF 1.2（CR Snapshot 2026-04-07 / WD 2026-06/07）以 triple term/reifier 承接 RDF-star；RDF 数据模型 atemporal（"RDF graphs are static snapshots"）；N-Triples/N-Quads 追加行天然合法；canonical 形态确定性仅对 Canonical 文档强制；锚点逐字 grep 在 RDF 序列化上必须先解析还原转义（与 audit-nodes.md 的 grep -qF 直接作用于源 markdown 不同——注意：本项目锚点校验作用于源文本而非图谱文件，B1 的"转义破坏"只影响图谱文件内嵌锚点串的判等，不影响现有 grep 源文本流程）。
- **B2**：GQL=ISO/IEC 39075:2024 已发布；SQL:2023 含 SQL/PGQ；两者共享 GPML 核心；GQL 未定义交换格式与版本化语义；属性图原生边挂属性 vs RDF 需 reifier（模型层差异）。
- **B3**：EDB+IDB 可表达审计门控；增量 Datalog（DDlog/DBSP/RDFox/LogicBlox）有成熟先例；"当前视图=最新版本"非单调须与单调事实层分离；事实文本可 grep 只是语法层更直接。
- **B4**：M09 应建模为 bitemporal append-only 事实流 + 快照回放；防篡改最低=逐行哈希链+签名锚点，Merkle 树是规模化升级（RFC 6962/Crosby&Wallach 支撑）；nanopub 三段式与 trusty URI 可承载出处；墓碑/撤回需显式建模。
- **B5**：封闭词表/引用完整=封闭世界校验，SHACL(sh:in/sh:closed)/ShEx(valueSet/CLOSED) 最贴合；OWL/SKOS 开放世界语义做不了"只有这些值"；OWL 推理对 522 节点规模非必需；KIF/CLIF/Topic Maps 历史对照=不采用。
- **B6**：五先例共性="不可变+显式版本或追加历史+机器可读身份与校验"；承诺等级不一（Anki revlog 可撤销删除）；FHIR 支持纯文件模式把版本放资源自身；xAPI/IEEE 将 statement 不可变定为规范；红线须自写 MUST 级。
- **B8**：JSONL 的每个弱点都有成熟替代件（Frictionless 配套 schema、PROV-JSON 行内 provenance、Crosby&Wallach 哈希链、Avro/Protobuf schema 演化、outbox 原子迁移）；校验规则可版本化可审查是程序式脚本最缺的增益；"JSONL-LD"无权威标准先例（未核）；RML/YARRRML 成熟但自述无官方地位。

## 三、冲突登记（不删旧，双轨保留）
1. **B1 atemporal vs B4 bitemporal**：RDF 图是静态快照（B1 F17），M09 需要双时间轴版本（B4）。调和：命名图=快照+应用层版本约定，SPARQL 无原生时态算子 → 版本查询落应用层。
2. **B2 标准已发布 vs B1 标准未冻结**：GQL 是正式 ISO 标准但无交换格式；RDF 1.2 有交换格式家族但未达 REC。标准化成熟度与工程可用性错位。
3. **B3 非单调当前视图 vs B4 事件回放**：两者互补但须分层，不得混在单调事实层。
4. **B5 封闭世界校验 vs OWL/SKOS 开放世界**：本体语言表达不了封闭约束，SHACL/ShEx 才是载体——不是二选一，是分工。
5. **B6 Anki 可删 revlog vs 本项目"不物理删除"红线**：先例承诺等级不足，红线须自定 MUST 级（B6 明言）。
6. **B8 演化强化 vs B1/B2 整体替换**：JSONL+配套 schema/哈希链是候选之一，与 RDF/属性图/Datalog 同等查证，不预设优劣（与中心禁令一致）。
