# 任务卡 B8 — 校验、互操作与迁移路径
角色：深度调研树分支调研员（B8）。
分支名：校验技术谱系、格式互操作与从 JSONL 现状出发的迁移路径。

## 问题清单
1. 现状隐式信息盘点（本分支起手任务）：append-only JSONL + Python 校验脚本方案中，哪些语义是"脚本里隐式存在、数据里不显式存在"的（边词表枚举、锚点判等规则、候选池状态机、四图边界、时间版本规则）？逐条列出并标注迁移到新载体时是"可机械转换"还是"需人工决策"。
2. 校验技术谱系：声明式 schema（JSON Schema/SHACL/PG-Schema）vs 程序式校验脚本 vs 查询式校验（SPARQL/Datalog 否定查询）——各自的表达力边界、可审计性（校验规则本身是否可版本化、可审查）？
3. JSONL 的"演进化强化"路径（作为候选之一，与替换路径同等查证）：逐行 JSON-LD（JSONL-LD 先例）、行内 W3C PROV 注解、伴随 schema 文件 + schema 版本号、行哈希链——有没有真实先例？
4. 互操作转换：JSONL 到 RDF/属性图/Datalog 事实的机械转换成熟度（RML/YARRRML、通用 ETL、手写转换器）？"开放字段必须可稳定查询审查"对各查询语言的最小要求清单？
5. 迁移模式：双写/影子读/格式内嵌演进（在 JSONL 行内逐步增加结构化字段直到可整体转换）的工程先例？"522 节点/1433 边/921 锚点"规模下迁移的真实成本量级（有没有公开的类似规模迁移报告）？
