# 任务卡 B4 — 时间版本化、事件溯源与内容寻址
角色：深度调研树分支调研员（B4）。
分支名：时间版本化机制、事件溯源与内容寻址/可验证出处。

## 问题清单
1. Bitemporal（valid time + transaction time）数据模型的权威定义与最小实现要求？M09 的"复检/遗忘/重新掌握各成新版本"是单时间轴还是双时间轴问题？
2. 事件溯源（event sourcing）：事实流+快照+物化视图模式用于个人学习记录的先例与已知陷阱？"审计晋升、处置单单点"与事件溯源的 append-only 事件日志是否天然同构？
3. 内容寻址与可验证出处：nanopublication 模型（assertion + provenance + publicationInfo 三段式）与 trusty URI 的机制细节？IPLD/Merkle DAG 对"锚点-节点-版本"链式验证的适用性？
4. 透明日志/审计日志先例（Certificate Transparency RFC 6962、通用 append-only 验证结构）：M08/M09 是否需要防篡改到 Merkle 树级别，还是逐行哈希链即可？各方案的最小机制是什么？
5. "不物理删除（写回收站）"在各机制下的表达：墓碑（tombstone）、撤回事件、retraction（nanopub 有撤回机制吗）？
