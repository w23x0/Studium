# 任务卡 B2 — 属性图系
角色：深度调研树分支调研员（B2）。
分支名：属性图数据模型与查询语言标准（Cypher/openCypher/GQL/SQL:PGQ）。

## 问题清单
1. 属性图模型对"边挂属性"的原生支持度：候选池状态、审计晋升记录引用、处置单单点引用能否直接挂在边上？与 RDF 的"边挂元数据需 reification 或 RDF-star"相比，这是模型层差异还是序列化层差异？
2. GQL（ISO/IEC 39075）的标准化状态：发布日期、范围、是否有开源/免费可得的正式文本或权威解读？SQL:2023 的 SQL:PGQ 范围与 GQL 的差异？
3. 属性图如何表达"三类结构"：不变量层、各自表示层、对齐边？schema 约束（PG-Schema 提案）能否表达封闭边词表 9+other？
4. 时间版本化：GQL/Cypher 标准层是否有任何内建时间/版本语义？若无，社区有哪些建模范式（版本节点法、时间戳属性法、快照法）？
5. 锚点=逐字字符串集合 + grep -F 硬校验：属性图的标准序列化/交换格式是否存在（GQL 是否定义了交换格式）？若无，锚点校验是否必须依赖具体引擎导出？

## 候选空间与线索
Cypher（含 openCypher 规范）、GQL、SQL:PGQ、PG-Schema/PG-Keys 学术提案、Gremlin（对照）、LDBC 相关基准与论文。线索：GQL 于 2024 年 4 月由 ISO 发布；SQL:2023 含 property graph queries；openCypher 有公开语法规范但非正式标准。
