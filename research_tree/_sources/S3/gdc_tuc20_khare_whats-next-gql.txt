Conditional Procedures

· The SC32 WG3 paper [GYD-030] was accepted for the next edition of the GQL
 standard at the September, 2024 WG3 meeting. The following example is from that
 paper:

· MATCH (n)
     WHERE EXISTS {
         WHEN n.age_in_month > 1
         THEN
            MATCH (n)<-[:IS_PARENT]-(x:Person)
            RETURN x
         ELSE
            MATCH (n)<-[:IN_HOSPITAL]-(x:Hospital)
            RETURN x
     }

 RETURN n, x

Vector Distance Function

· VECTOR_DISTANCE (<vector 1>, <vector 2>, <vector distance metric>)
· Result is a relative distance between the two vectors

   · The smaller the distance, the more similar the vectors

· Distance metrics are common algorithms for comparing vectors

   · EUCLIDEAN
   · EUCLIDEAN_SQUARED
   · MANHATTAN
   · COSINE
   · DOT
   · HAMMING

Search for things that are similar

· GQL Example

   MATCH (a: Articles)
   RETURN a.author, a.article_text

              ,VECTOR_DISTANCE($ParamVec, a.article_vector, EUCLIDEAN) as distance
   ORDER BY distance
   LIMIT 10

· Calculate Vector Distance between a parameter and an Article property
· Ascending sort by the calculated distance
· Return 10 results

Approximate

· GQL standard does not say anything about indexes
· Vector queries need vector indexes for performance
· Vector indexes often use Approximate Nearest Neighbor (ANN) algorithms
· ANN indexes find "pretty good" neighbors, not exact neighbors
· LIMIT APPROXIMATE allows GQL implementation to use vector index
· Example:

   MATCH (a: Articles)
   RETURN a.author, a.article_text

              ,VECTOR_DISTANCE($ParamVec, a.article_vector, EUCLIDEAN) as distance
     ORDER BY distance
   LIMIT APPROXIMATE 10

How are vectors created?

· Create a vector using an external service or function ­ outside of the
 standards

   · Thousands of vectorization functions
   · Specialized for various datatypes and purposes

· Store (embed) the vector in the database

· Query data using the vector_distance function

· Satisfactory performance requires specialized vector indexes ­ outside of the
 standards

Additional vector operators

· VECTOR(vector-string, dimension, coordinate type)

   · Constructor function

· VECTOR_DIMENSION_COUNT(vector-name) ­ return size of a vector
· VECTOR_NORM(vector-name, vector distance metric)

   · Distance between a vector parameter and a zero vector
   · Only makes sense for EUCLIDEAN and MANHATTAN

· VECTOR_SERIALIZE(vector-name)

   · Return vector as a character string

Partitioned CALL Operator ­ CALL PER()

· Example

MATCH (x IS Person)

OPTIONAL path = MATCH (x) -[has_direct_report]-> (r)

LET job = x.title

CALL PER (job) ON (x, r) { // Working record type: (job) (fixed variable)

   MATCH ...           // Working Table record type: (x, r) (iterated variables)

   FILTER job IN (..)

   RETURN p, q         // output record type: (p, q)

}

                       // output record type: (job, p, q)

RETURN job, p, q + length(p) AS extra

SUM and PRODUCT

· SUM

   · Current aggregation function ­ NULL if empty set or all values are NULL
   · Add "0 ON EMPTY" or "NULL ON EMPTY"
   MATCH (a) WHERE a.PartColor = 'red' AND a.PartColor = 'blue'
   RETURN SUM(a.Cost, 0 ON EMPTY)

· PRODUCT

   · New aggregation function ­ NULL if empty set or all values are NULL
   · Includes "1 ON EMPTY" or "NULL ON EMPTY"

       MATCH (a) WHERE a.PartColor = 'red' AND a.PartColor = 'blue'
       RETURN PRODUCT(a.SomeFactor, 1 ON EMPTY)

· Useful capabilities by themselves, needed for OPTIMAL PATH
· BCN-044 SUM and PRODUCT for GQL ­ proposal September 2025 WG3

 meeting
