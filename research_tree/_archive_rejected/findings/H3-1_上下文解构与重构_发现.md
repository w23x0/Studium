## 0. 一句话结论
**LLM/agent 时代的「上下文解构/重构」已从抽象提法落成可执行机制**：以 {@DSH temporal composability} 为形式化根基，agent 记忆层出现了首个开源的「快照+版本历史+语义回滚」实现（ChronoMem），且上下文工程被明确列为 agent 工程四大范式之一、context 是执行 harness 的六大运行时职责之一——「组件移除时上下文副作用回滚」不再是哲学命题，而是有实现、有基准、有可审计语义的工程能力。

## 1. 父会话问题逐条回答

**Q1. 文献如何形式化「上下文组件/插槽的解构与重构」？组件移除时如何补偿副作用？**
- 结论：存在两条独立又互洽的轨道。（a）**理论形式化**：DSH 把「组件移除时完全回滚副作用」形式化为 temporal composability，机制是 revertible effects（每个上下文变换携带运行时跟踪的逆），配 reactive coeffects（每个上下文变化按 coeffect 规范通知组件）。两条轨道（effect 上下文 + coeffect 上下文）统一成单一 context type。（b）**工程实现**：ChronoMem 把这种可回滚语义落到 agent 记忆层——whole-memory snapshots 提交、结构化 version history、natural-language rollback(把 undo 意图经混合词典+语义检索+rank fusion+rerank 映射到具体历史版本)。对齐结论：DSH 是通用动态组合的元框架（Cordis），ChronoMem 是它在「agent 记忆」这一具体领域的第一份开源兑现。
- 依据：DSH paper full.md §3.1/§3.2（原理）；2607.27773 ChronoMem abstract（实现）
- 等级：A

**Q2. 有无「可逆上下文编辑 / context rollback / 补偿动作」的显式机制？快照-还原、diff-patch、版本化各自适用什么？**
- 结论：有，且明确在往「版本化 + 语义级回滚」收敛。ChronoMem 采用**整库快照(whole-memory snapshot)提交 + 版本树**而非 diff-patch，因为 agent 记忆天然是累积覆盖式的、逐字段 diff 难以在后续信息污染后保持一致语义；其回滚是**语义级**（自然语言 undo 意图→历史版本），配 post-exposure 协议验证"仿佛未来更新从未发生"的 counterfactual 能力。对比：LEDGER 在同一文档内的局部编辑选**依赖图 + 图引导检索**（只取必要上下文、不整库处理）以保持跨引用一致——在「单个结构化对象内部」用依赖图做增量，在「跨会话记忆」用快照+版本做回滚。启示：快照-版本化适合跨会话长程状态（agent 记忆），依赖图+精确上下文选取适合单文档/单上下文内部的增量重构。
- 依据：ChronoMem abstract（版本化+语义回滚）；LEDGER abstract（依赖图局部编辑）
- 等级：A

**Q3. 这种解构/重构语义对 Studium 的 harness 上下文管理提供什么可移植模式？**
- 结论（推断为主，标 C）：三条可移植。（i）**上下文组件应可版本化可回滚**：Studium 长程会话若改上下文组件，应能整版快照回滚到任一稳定点，而非逐字段 diff——这直接呼应 DSH 「组件移除=temporal 回滚」与 Studium L0 原文锚点红线（回滚后能回到可 grep 的稳定原版）。（ii）**上下文工程是 harness 的运行时职责而非提示技巧**：harness 综述把 context 列为六职责之一，意味上下文管理应内建为基础设施（预算、选取、压缩、回滚），不是每轮让模型自选。（iii）**依赖图可替代昂贵内部推理**：LEDGER 证明显式依赖表示在低推理强度下匹配高推理强度基线且省 token——对 Studium「机械信号只定向不结案」红线，依赖图可作为定向的信号来源，不越级结案。
- 依据：2606.20683（六职责）；LEDGER 结论；DSH 原理
- 等级：C（模式迁移为推断）

## 2. 关键发现（每条：论断+URL+标题+机构+日期+原文摘录+等级）

**F1. 【DSH：temporal composability 的理论根基——组件移除=副作用完全回滚】**
- 论断：动态组合的两条正交维：temporal(组件移除时完全回滚副作用) + spatial(声明式管理组件间依赖)；机制=revertible effects + reactive coeffects；实现为 Cordis 元框架(含 hot module replacement)。
- 来源：本地原文 docs/DSH/paper/full.md（北大 Yifan Shi / Wei Zhang + DeepSeek-AI Tianyi Cui）——arXiv 检索无此条目（0 entries，非 arXiv 收录）
- 原文摘录（abstract）：「We identify two orthogonal dimensions of the problem: temporal composability, the ability to completely revert a component's side effects upon removal, and spatial composability, the ability to declare and reactively manage inter-component dependencies. ... we formalize revertible effects, in which every context transformation carries an inverse that the runtime tracks.」
- 等级：A（本地全文到手）
- 时间锚定：本地论文（2026，DeepSeek-AI）✓

**F2. 【ChronoMem：首个开源「整库快照 + 版本历史 + 语义回滚」的 agent 记忆层】**
- 论断：agent 记忆系统此前是 forward-only(累加/合并/覆盖，无检验/版本/回滚机制)，在更正、概念漂移、记忆损坏下脆弱；ChronoMem 提供语义版本控制层，whole-memory snapshot 提交 + 自然语言回滚 + post-exposure counterfactual 评估；集成进 Google Agent Development Kit（生产级开源）。
- 来源：arXiv 2607.27773v2，abs 页快照 arxiv_abs_2607.27773.html；authors: Yongye Su, Wujiang Xu, Chaoji Zuo, Elisa Bertino；published 2026-07-30
- 原文摘录：「We present ChronoMem, a semantic version-control layer for agentic memory ... ChronoMem commits whole-memory snapshots at each memory write, maintains structured version histories, and supports natural-language rollback requests by mapping undo intents to concrete historical versions through hybrid lexical and semantic retrieval, rank fusion, and reranking. ... the first open-source system and benchmark for systematic semantic global memory rollback in LLM agents.」
- 等级：A（abs 页 + API summary 到手，逐字命中）

**F3. 【context engineering 是 agent 工程四大范式之一，context 是 harness 六大运行时职责之一】**
- 论断：agent 从 prompt engineering → workflows & context engineering → harness engineering → agent-native training 演进；执行 harness 拆成 observation/context/control/action/state/verification 六职责；agent 质量源于模型×运行时×任务×评估的交互而非模型单点。
- 来源：arXiv 2606.20683（surve，17 作者：Jianyuan Guo 等），abs 页 arxiv_abs_2606.20683.html；published 2026-06-14
- 原文摘录：「we trace four paradigms of agent engineering, and decompose the execution harness into six coupled runtime responsibilities: observation, context, control, action, state, and verification.」；「agent quality -- including success, efficiency, safety, and generalization -- emerges from the interaction between model capability, runtime infrastructure, task structure, and evaluation design.」
- 等级：A

**F4. 【LEDGER：依赖图引导的局部编辑——解构/重构不整库、保持跨引用一致、省 token】**
- 论断：agentic 文档编辑的局部编辑不破坏 cross-references/语义一致性；依赖图显式建模文档结构；图引导检索只取必要上下文；1.9k 测试六模型 consistency 56%→76% 且减 token；低推理强度+依赖图匹配高推理强度基线。
- 来源：arXiv 2606.28379，abs 页 arxiv_abs_2606.28379.html；authors: Mike Hang Wang 等(Microsoft 关联作者）；published 2026-06-19
- 原文摘录：「LEDGER constructs a lightweight dependency graph that explicitly models document structure ... For each edit, graph-guided retrieval selects only the necessary context, avoiding full-document processing while preserving consistency ... explicit dependency representations can partially substitute for expensive internal reasoning.」
- 等级：A

**F5. 【上下文按 distinct information 组织而非 token——可审计工作记忆】**
- 论断：现有上下文计量以 token 为单位（压缩为受限循环状态 / 每 token 一个 KV / 固定窗口淘汰），但流冗余时 token 不是记忆语义单元；按「任务如何依赖过去」归类：recall-carried→内容寻址 novelty cache，summary-carried→循环状态，locality-carried→recency 窗口；保留的记忆是可检视的模板表而非不透明状态。
- 来源：arXiv 2607.10441，Dirichlet 工作记忆；authors: Siddharth Pal, Viktoria Rojkova；published 2026-07-11
- 原文摘录：「the retained memory is an inspectable table of templates, codes, drugs, or places rather than an opaque state.」；「context can scale with distinct information rather than tokens, in a working memory that is content-addressable and auditable.」
- 等级：A
