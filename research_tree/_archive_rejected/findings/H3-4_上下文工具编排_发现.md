# 叶子 H3-4 上下文与工具调用的编排 调研发现
> ⚠ **已归档（2026-08-15 产品裁决）**：本卡属老旧范式（agent 记忆/RAG/知识库/上下文工程，临床办公场景），与「个人多教材理科学习」项目不匹配，已移入 _archive_rejected/，仅作历史参考，不再作为 Studium 设计依据。

> 任务 H3-4 / A=原文到手 B=二手转引 C=推断
> 调研主题：有限上下文预算下的工具协商、MCP 进入工具编排、工具描述占 budget 的削减
> 时间锚定：全部证据 2024-01 之后；MCP 官方规范 2024-11-05 首发 ✓

## 0. 一句话结论
**工具编排已从「全量 schema 注入 + 一次性检索」演进为「主动工具发现 + 意图-工具图 + 上下文优先级治理」**：当工具生态扩到成百上千 API，exhaustive tool schema 注入成本过高且强加 closed-world 假设；2026 文献给出 intention-tool graph 主动发现（SING 减全库 schema 暴露 99.8%、Recall@5 +59.8%）、反事实分解+动态 Top-K 工具选择（MagicSelector）、以及 MCP 服务器指令与工具选择的上下文优先级实证（54000 试验示行为偏好主导、需 host 显式机制让 server instructions 优先于工具选择）。MCP（2024-11-05 开源标准）是这一编排的标准化底座，但其机制暴露了「LLM 在场即低效」的资源利用问题。

## 1. 父会话问题逐条回答

**Q1. 有限上下文预算下如何编排工具/工具协商：工具数量上限、工具描述压缩、按需加载工具？**
- 结论：三机制。（i）**按需加载/主动发现**：SING 用 intention-tool graph 把用户意图、工具能力、工具协作模式连成图，按演进任务状态动态检索工具，避免全库静态清单——减全库 tool-schema 暴露 99.8%、Global Recall@5 +59.8%、下游成功率 +28.9%；明确指出 exhaustive schema 注入「成本高且强加 closed-world 假设」。（ii）**工具选择优化**：MagicSelector 用反事实任务分解（量化分解对检索排序的边际因果增益）+ 渐进重排（自蒸馏硬负样本）+ 动态 Top-K（按重排分数悬崖与工具间语义位移动态截断），缓解 OOD 冗余噪声与 context distraction，提 token 效率。（iii）**工具描述形态**：CRAFT「Learn the Schema, Execute the Plan」——企业编码 agent 把自然语言分析请求翻译成可执行代码，需先学 schema/指标定义而非每次重塞 schema。
- 依据：2606.16591 SING、2607.17751 MagicSelector、2607.22642 CRAFT
- 等级：A

**Q2. MCP 如何进入工具编排？工具发现/工具选择的机制与局限？**
- 结论：MCP（Model Context Protocol，2024-11-05 开源）标准化服务器如何向 LLM 暴露数据与工具（tools/resources/prompts 三类原语，client-server 架构，open protocol）。**但其机制暴露了关键局限**：常见服务器把常用参考数据（如标识符查找表）直接嵌入 server instructions（服务器交给 host 的系统提示文本），期望模型直接读嵌入式数据而非重复发现；然而 54000 试验/24 LLM 实证示——当搜索工具「仅仅在场」时 9/24 模型嵌入数据命中率跌到 <15%，无搜索工具时 23/24 ≥98%。失败由**行为偏好主导**而非能力缺失。三种指令级干预的 2^3 因子分析示强交互效应：三干预全用对 20/24 模型恢复 ≥86%，但单干预对特定模型族会反噬。结论：per-server prompt 工程是 workaround 而非 fix；**MCP host 应提供显式机制让 server instructions 优先于工具选择进入 LLM 审议**。
- 依据：2608.08467 LLM within MCP Matters、MCP 官方规范（introduction + specification 快照）
- 等级：A

**Q3. 工具调用的上下文开销（工具描述占 budget）如何被定量评估与削减？**
- 结论：SING 直接量化——全库 tool-schema 暴露可减 99.8%（从「全部 schema 注入」到「按意图图按需检索」），且 Recall@5 +59.8%；MagicSelector 的动态 Top-K 按「重排分数悬崖」截断候选清单过滤长尾噪声，提 token 效率；MemoHarness 示 harness 的额外上下文在「检索经验可缓存」时可保持成本竞争力（呼应 H3-2 缓存连续性）。Over-Privileged Tool Selection 补充安全维度：工具选择在特权维度也占上下文与决策开销，agent 倾向过度升级特权，需 privilege-aware 后训练防御。综合：工具编排的上下文开销 = schema 注入量 + 选择噪声分心 + 特权决策，三者各有削减路径（按需发现/动态截断/特权约束）。
- 依据：2606.16591、2607.17751、2607.14159、2606.20023
- 等级：A（量化）+ C（综合为推断）

## 2. 关键发现

**F1. 【MCP 标准化底座：open protocol，client-server，tools/resources/prompts 三原语】**
- 论断：Model Context Protocol 是 open protocol，标准化服务器如何向 LLM 暴露数据与工具；三类原语 tools/resources/prompts；client-server 架构；2024-11-05 首版，后续 2025-03-26、2025-06-18 版本（含 draft/latest）。
- 来源：modelcontextprotocol.io introduction（274KB 快照）+ specification（293KB 快照）
- 原文摘录（introduction）：「open protocol」「client-server」；「tools」(25 次)、「prompts」、「resources」；2024 时间锚定命中
- 等级：A（官方规范原文）

**F2. 【LLM within MCP Matters：54000 试验示行为偏好主导，host 需显式上下文优先级机制】**
- 论断：MCP 服务器把参考数据嵌入 server instructions 期望模型直接读；54000 试验/24 LLM（9 Claude/6 Gemini/9 GPT）于生产法律信息 MCP 服务器；搜索工具在场时 9/24 嵌入数据命中率 <15%，无搜索时 23/24 ≥98%——失败由行为偏好主导而非能力缺失；三干预 2^3 因子分析示强交互，全用对 20/24 恢复 ≥86% 但单干预对特定族反噬；主张 host 应提供显式机制让 server instructions 优先于工具选择。
- 来源：arXiv 2608.08467，abs 页 arxiv_abs_2608.08467.html；Minhan Cho 等；published 2026-08-09
- 原文摘录：「A common server design embeds frequently used reference data ... directly in the server instructions」；「with a search tool merely present, 9 models drop below 15%」；「MCP host applications should provide an explicit mechanism that places server instructions ahead of tool selection」
- 等级：A

**F3. 【SING：intention-tool graph 主动工具发现，减全库 schema 暴露 99.8%】**
- 论断：工具生态扩到成百上千 API/服务/技能，exhaustive tool schema 注入成本高且强加 closed-world 假设，限制 agent 于预定义静态清单；一次性检索难把孤立工具描述对齐真实任务意图（尤其长程任务能力经分解/观察/新子目标涌现）；SING 建 intention-tool graph（用户意图×工具能力×工具协作模式），按演进任务状态动态检索；7471 工具统一语料，Global Recall@5 +59.8%、下游成功率 +28.9%、减全库 schema 暴露 99.8%。
- 来源：arXiv 2606.16591，abs 页 arxiv_abs_2606.16591.html；Qiao Xiao 等；published 2026-06-15
- 原文摘录：「exhaustive tool schema injection becomes costly and imposes a closed-world assumption」；「reducing full-corpus tool-schema exposure by 99.8%」
- 等级：A

**F4. 【MagicSelector：反事实分解+动态 Top-K 工具选择，缓解 context distraction】**
- 论断：反事实任务分解（量化分解对检索排序的边际因果增益，施细粒度结构监督）+ 渐进重排（自蒸馏硬负样本，优 point-wise 与 list-wise 相关性）+ 双语义边界感知动态 Top-K（按重排分数悬崖与工具间语义位移动态截断）；MTDTool（移动多轮交互任务分解基准）上大幅超 SOTA，工具检索精度/OOD 泛化/token 效率均优。
- 来源：arXiv 2607.17751，abs 页 arxiv_abs_2607.17751.html；HONOR Agentic Search Team；published 2026-07-20
- 原文摘录：「effectively mitigating redundant noise and severe context distraction in out-of-domain (OOD) scenarios」
- 等级：A

**F5. 【MemoHarness：agent harness 定义为外部控制层，六可编辑控制维度】**
- 论断：agent harness = 把 base LLM 变成可执行 agent 的外部控制层，管理 context/tools/orchestration/memory/decoding/output handling；harness 设计强影响 agent 行为，但多数自动改进方法只优化更窄产物（prompts/pipelines/workflows），部署 agent 通常全用例复用单一全局 harness；MemoHarness 把 harness 拆成六个可编辑控制维度，双层经验库存逐案诊断+蒸馏全局模式，按检索经验适配无需测试标签/反馈/额外搜索；其额外上下文在「检索经验可缓存」时保持成本竞争力。
- 来源：arXiv 2607.14159，abs 页 arxiv_abs_2607.14159.html；Yue Huang 等；published 2026-07-14
- 原文摘录：「An agent harness is the external control layer that turns a base LLM into an executable agent by managing context, tools, orchestration, memory, decoding, and output handling」
- 等级：A

**F6. 【Over-Privileged Tool Selection：工具选择的安全维度】**
- 论断：agent 自主选工具时，不同特权工具间的选择成安全关切；prior 工具选择研究聚焦 safety-agnostic 元数据偏好；ToolPrivBench（八域五种风险模式）示 over-privileged 选择常见且被瞬时失败放大；通用安全对齐不可靠迁移到 least-privilege 选择，prompt 级控制对瞬时失败仅有限缓解；privilege-aware 后训练防御有效。
- 来源：arXiv 2606.20023，abs 页 arxiv_abs_2606.20023.html；Kaiyue Yang 等；published 2026-06-18
- 等级：A

## 3. 对决策点的输入
- **工具编排形态选型**：Studium 若编排工具，优先「主动工具发现（意图-工具图）+ 动态 Top-K + 按需 schema」而非全量静态注入——直接匹配「有限上下文预算」与「机械信号只定向不结案」红线（工具发现是定向信号）。
- **MCP 适配**：MCP 是标准化底座，但其「LLM 行为偏好致嵌入式数据被忽略」示 host 层需显式上下文优先级治理——Studium 若用 MCP，须在 harness 层保证 server instructions/稳定上下文优先于工具选择。
- **harness 定义**：MemoHarness + harness 综述（H3-1 F3）共同把「context 是 harness 运行时职责」坐实，工具编排是六职责之一。

## 4. 与范围/红线的冲突张力
- 无红线冲突。MCP 优先抓官方规范快照（已落 274KB+293KB），实务局限标 A（2608.08467 实证）；bounds 遵守。

## 5. 未决与风险
- MCP 规范仅抓 introduction + specification 顶层页，具体原语 schema 细节未逐字展开 → synthesis 视需抓具体 spec 子页。
- SING 的 7471 工具语料是其自构，泛化到 Studium 工具生态需评估。
- MagicSelector/Honor 团队工作，复现性数据未核。
- MCP 的「host 显式优先级机制」目前是论文主张（呼吁），尚未见标准化实现 → 标 OPEN。
