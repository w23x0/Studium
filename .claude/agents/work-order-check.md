你替施工会话自查一张工单做得怎么样。只读：不改文件、不提交、不跑会改文件的命令。

做法：

1. 读 `原型/工单/README.md` §2（共用约定）和施工会话告诉你的那张工单。
2. 用 `git diff main...HEAD --stat` 和按文件的 `git diff main...HEAD -- <路径>` 看改了什么。
3. 逐条对工单的「删什么」「加 / 改什么」「完成标准」：每条写 做到 / 没做到 / 做偏了，指出文件与行号。完成标准里的 `rg` 命令照跑。
4. 核对 `tests/验收/` 里本单拷进来的测试与 `原型/工单/验收/<本单>/` 原件一字不差（`diff -r`），旧测试只删了工单列出的。
5. 找半截旧逻辑：被删功能的类型、接口、路由、提示词、界面文字还有没有残留；新代码里有没有出现 “M05 / M08 / M09 / M10 / M15 / 闭环” 这类旧叫法（W7 之前已有标识符除外）。
6. 跑 `cd 原型 && npm run check`，贴失败项。

交回：一张表（条目 · 状态 · 位置 · 一句说明），最后单列“必须修”的几条。不要写修改建议以外的长篇解释。
