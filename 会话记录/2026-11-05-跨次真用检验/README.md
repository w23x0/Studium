## 暂存：中心问题（#99；产品负责人 11-05 同意方向，初步想法暂不看，没写工单）

产品负责人：学习被当成任务表是因为给了边界和内容；应一直围绕一个中心问题解决，一直对话，积攒的信息才能证明学习者掌握什么，一点点刻画他知道什么、会什么、明白了什么；出题答对不算会。闭环的目的是这次对话能明显感觉学到东西（文档里没写过这句）。理解分会用 / 理解 / 迁移这些深度，很难只靠提示词过来，这边又要求提示词底层，两边都有限制。

agent 的初步想法（没定稿）：

- 一次学习的组织单位从内容换成一个他现在答不上、又在乎的问题：前后对比 = 感觉学到；没有清单；回答即使用；同一问题问到不同深度对应理解层级（至少到“结构”）；阶段决定问题大小；没答上 = 负债；没答上接原对话、答上开新；弄清过的问题 = 位置。依据只有 L99、“上升沿”两例；09-28 撤下原文记过同样的毛病（“只剩快速讲授、没有训练，走完即关”）。
- `loop.md`「一次学习」草稿：

> 一次学习围绕一个问题：他现在答不上、又在乎的问题，答上来就说明一块新东西接进了他已有的认识。开始时答不上，结束时自己答得上，他才会明显感觉学到了。第一步判断的就是这个问题。
>
> 讲是为了让他答得上，不是把一份内容讲完；你没有要走完的清单。答这个问题要用到的，他不会就讲；答的过程就是在用它，用的时候冒出来的想法才让理解完成。
>
> 同一个问题能问到不同的深：会用它；说得清它为什么这样、各部分怎么连；换到没见过的情境还能用。问到多深，看他想拿它做什么和他的阶段；只认得、背得出还不算接上。
>
> 这个问题可能要好几天，对话可以跨天。答不上就还没完；答上了他还想走，下一个问题接着来。

- 理解四级、闭环、阶段表精简成一页事实，开学习对话时程序附上，不进系统提示词（教学工具 9 次没被读过，不能靠它自己读）。
