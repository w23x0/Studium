## 谈出的做法（第二条路线，试验中）

| 项 | 做法 |
| --- | --- |
| 底层 | 只做两件事：把上下文映射成界面；把上下文本身设计细。页面不另存，从正本放一遍算出来 |
| 分工 | 主模型一个人管：写话、写组件、改页面；不设框架小模型与固定的页面子代理 |
| 页面形状 | 竖着一条流；宽屏并排的问题以后用别的办法解决 |
| 改页面 | 照 Claude Code Edit（原文唯一匹配替换），加挪、拿掉、拿回；块用行号、组件名或一段原文指；`read_page` 看页面 |
| 学习者回话 | 选中哪里就在哪里说（照 Claude Docs），取代“在这里回” |
| 改动标记 | 前端标出新加 / 改过 / 挪过的块（照 Claude Docs 改动署名） |
| 组件回传 | 照 MCP Apps：立刻发 / 攒着只留最后一次 |
| 监测 | 每轮上下文用量记进正本，不做界面 |

## 原型实现（10-29 晚，已重启服务）

设置（账号菜单“学习页”）里切换，新开的学习默认竖流；改动文件见 `原型/更新记录.md` 与 git。真模型在拷贝数据上跑过一次：模型自己写电路图组件、用 `edit_page` / `move_on_page` / `read_page` 改页面都对；两轮上下文约 4.1 万、4.3 万 token。

没验证的：组件里 `studium.send` / `setState`、组件运行时报错、浏览器里选中出引用条没实际点过；每轮输出 token 的算法改后没重跑；竖流下主模型拿不到学习位置图的依据；工具运行中途学习者插话时页面可能差一块；没开页面时交组件白等约 20 秒。
