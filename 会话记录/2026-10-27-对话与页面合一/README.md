## 谈到的（产品负责人提出，未定稿）

| # | 想法 |
| --- | --- |
| 1 | 模型的上下文不变（一条时间线、只追加）；要做的是界面怎么展示这条上下文：上下文是线，界面是从线里取学习者此刻要看的局部（映射关系） |
| 2 | 显示什么、何时显示由主模型判断，程序不划“只显示最新一段”这种线；很久以前的也可再次拿出来；说完的在界面上就是不显示（不是压缩或折起；“压缩”只指上下文太长时的压缩） |
| 3 | 模型的推进不是完美线性的，容易卡住；每段之间一定有重叠，会的占大部分、不会的占小部分（一次学习之间、每段对话之间都如此）。所以回复要完整、尽量独立（对近几段独立；远处要用时引用展示），可以重复说 |
| 4 | 每块上下文有三样：时间线（在上下文里的位置）· 关系线（指向哪些块）· 内容；内容更新（如图更新）= 新加一块，三样都是新的一版；这样结构化，压缩也好做 |
| 5 | 分两样记进上下文：输入（让模型知道屏幕上现在有什么）· 输出（模型决定接下来有什么） |
| 6 | 子代理只为一件事：让主对话上下文干净，信息流控制和对学习者的理解不被污染；其他的不交给子代理；不行再想别的办法 |
| 7 | 框架 = 承载线性上下文的前端展示；要建什么看为满足上面这些需要什么，目的是让模型少做事、靠近我们想的前端；位置大概由框架定（产品负责人自己也不确定，认为不重要） |
| 8 | 组件要不要被观测，模型生成它时就定；交互的回报先回给做这个组件的，再看是谁指挥做的、要不要往上报告（主对话 / 子代理 / 两边，看具体东西） |
