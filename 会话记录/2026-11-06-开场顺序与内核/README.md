## 产品负责人的问题，答案他还没读

他提的问题：能不能不用原文、有没有更好的方式，从上下文需要什么和那个会话产出了什么来取舍；上下文是不是 SQLite 结构化存的。agent 答在对话原文 `~/studium-sessions/对话/2026-11-06-37b720b9.md` 第 134–210 行（11-06 19:59），他说这段不看了（max 太慢），所以**不算谈过，新会话重新讲**。要点都是 agent 的，没定稿：

- 存储：正本是 JSONL，一行一条带类型的记录；SQLite 只是索引（会话列表、各会话有哪些类型的记录），删了能重建。结构只到事件这一层，按谁说的、按时间挑程序能做，按话题挑得靠模型读。“原文”是渲染出来的视图，不是存下来的东西。
- `bc279f` 的产出（字数）：学习者的话 890、模型写的话 6,601、跨次记录 527、组件代码 8,362、思考概要 14,621、工具返回 26,964。原文里学习者的话只占约一成（另两次 5%、19%）。`dab670` 开口前附了约 1.1 万字，自己又读了约 3.4 万字。
- “不用原文”拆成两件事：能读到（不动）和开口前就进上下文（可以谈）。
- 两次失败是同一件事：11-05 给得少，重问讲过的（低估）；11-06 给得全，接着昨天说（高估）。缺的是“他现在还有什么”的估计，也就是 learner model。只调给多少可能在两头来回摆。
- 几种做法：整份原文（现在）、选段（extractive：他的话 + 引出它的那句）、只给索引（just-in-time，11-05 失败的就是这种）、写的一方留交接（handoff）、单独的读者先读（context isolation，他 11-05 说过不派子代理查找）、提炼成结构（abstractive，`00` §9 不做）。
