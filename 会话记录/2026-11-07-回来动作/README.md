| 点 | 内容 |
| --- | --- |
| 方向 | 不在提示词里让模型克制自己（“隔久了不算他有”一类规则、证据标准清单都不加），改成加工模型看到的上下文。证据标准不进提示词（产品负责人：怕提示词陷阱、进入修改循环） |
| 不叫压缩 | 标准压缩按大小触发、整体换成摘要、对话断开（Codex 源码与提示词已读；Claude Code 文档已读）。这里按时间分两个动作：**缓存内**、**回来动作**（产品负责人命名） |
| 缓存内 | 离开约一小时、缓存快失效时做，每次离开一次；只在末尾追加一段事实（停在哪、还开着什么、他最后那句），不写“他还记得什么”，不动前面；读缓存顺带续一小时，两小时内回来上下文连续。作用小，主要是保温；留作以后挂别的需求的点（如“判断经验、坏习惯”记忆、#87） |
| 回来动作 | 学习者回来说第一句时触发（有确切间隔）。同一个对话隔久了接着聊、主对话开新对话都走它，替换 W14 开场附整份上次原文。流程：新对话先粗看这次学什么 → 模型自己挑以往对话（不固定上一次）→ 分叉那个旧对话的 SDK 会话（不接在旧对话后面），用 Sonnet 问它 → 整理好拼进来；一小时内可追问，话题转了可再问 |
| 等待时 | 先给学习者一条：只摆不用整理也确定的事实（上次停在哪、他最后那句），请他回想，不开讲、不定方向；他的回应就是“他现在还有什么”的第一次观察（agent 提） |
| 重建的形状 | 块之间按学习顺序（接上的先后），块内按时间，时间作文字留着；学习者原话原样；模型的几轮压成一行（留住他下一句接的是什么）+ 回原文的地址；卡住的地方留卡在哪、几次；忘了的、错了的不删只简化；还开着的放最后，挨着他这次的话；块分界写时间关系（隔几天、中间学了什么） |
| 视角局限 | 谁教的谁只描述（检查点、被问的分叉都是），判断给没教过那段的新对话（最强模型）；判断只体现在形状 + 事实标注（哪天讲的、他当时怎么接的），不写“他忘了 / 还记得”（agent 提，产品负责人没反对） |
| 粗看这次学什么 | 只用来挑历史、不作为路线交给教的模型（W12 教训） |
| 每次重建 | 从原文 / 分叉重来，不在上次拼好的上下文上再加工 |
| 实现备忘 | 关 SDK 自动压缩（`autoCompactEnabled: false` 或 `DISABLE_AUTO_COMPACT`）；固定 1 小时缓存（`promptCacheTtl: "1h"`，订阅额度内 SDK 默认就是 1 小时，超额会降 5 分钟）；Claude Code 自带的 idle compaction（约一小时、20 万 token 以上、赶在缓存失效前整体换摘要）只在终端 / VS Code / 桌面版跑；学习对话内按大小的处理到约 25 万 token 再谈 |
| 连带 | “接着原对话还是新开”主要变成页面问题，#99“隔天接哪个对话”变轻 |
