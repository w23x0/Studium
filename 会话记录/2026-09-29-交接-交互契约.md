## 2. 下一步：先深化 3.2（两层分开），再做 3.3（契约由哪些结构保证）

产品负责人 09-29：3.2 很重要，要再深入构思，不是就那样。

| 3.2 还薄在哪 | 要做什么 |
| --- | --- |
| 两层交界没逐项检验 | 例：“每轮放什么进上下文”是基础设施还是契约？“诊断记录不回传”其实是契约，却实现在装配层。逐项过一遍 |
| 契约组成是列出来的，不是推出来的 | 现列五项（谁做事、每轮多少、什么算进展、何时停、记什么）；从“成功 = 学习者脑中的变化 + 稀缺资源是学习者注意力”系统地推，查漏项 |
| 证据偏少 | 只有 me-8、me-9、一次重放；“Opus 被优化成替人做完”是推断 |
| 没对照学习专用系统 | 经典 ITS（如 AutoTutor 的对话动作）、Khanmigo、LearnLM 如何定契约——需联网（本会话联网一直因权限检查故障失败） |

3.3 的出发点（设计侧的初步想法，**未验证**）：让模型“完整完成”一件它擅长的事——判断学习者此刻在哪、设计下一步（后台，可以长）；给学习者的只是其产物，并明确留出属于学习者的那一步。参照 Claude Code “学习”输出风格留 `TODO(human)` 的思路，但那是编程契约上的补丁，不照搬。
