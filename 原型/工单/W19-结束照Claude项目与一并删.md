## 产品负责人定（11-05）

“这个实现逻辑很麻烦，很不对味；Claude 项目实现得很好，为什么不直接用，非要自己一点点搭。”“准备做的那些，比如删掉某些部件，都一并做了。”

所以：**不修补确认条，整套收尾换成 Claude 项目的讨论串做法。** Claude 项目是产品，Agent SDK 没有提供它（SDK 里没有项目 / 讨论串的接口），能做的是照它的行为做，不另设计一套。

为什么走到这：“学习者确认学完了才算合上”“收尾那一句”是 10-07、10-31 定的，比照 Claude 项目（W12）早；W12 对齐讨论串时这块留着没动，于是学习对话成了讨论串里唯一一种有确认仪式的。

## 真用里的问题（数据在本机 `var/`，云端读不到）

- 模型读完自己定的清单就调 `request_close`，3 秒内界面弹确认条，学习者问“？ 为什么直接结束了”。
- 底部“收尾：<那一句>”一直挂着，重开也在（`ui/screen-model.ts` 的 `closeLine` 特意过滤掉 `loop_ended`）。它不是页面上的块，模型拿不掉也看不到。学习者：“这个收尾显示你也收不起来 这个不应该给我看到的吧”。

## 照 Claude 项目逐项定（`docs/调研/Claude项目主对话-问那边模型.md`）

| Claude 项目 | 定 | Studium 怎么做 |
| --- | --- | --- |
| 没有单独的汇报工具：讨论串说的话主对话都看得到 | 用 | 拿掉“收尾那一句”和 `request_close`。这次做了什么、停在哪，就是模型说的最后一段话 |
| `set_thread_resolved` 一个工具，结束或重开 | 用 | 学习对话只留一个结束工具（名字你定），拿掉 `end_loop_unclosed`、`request_close` |
| 用户可以点结束，可以从菜单重开 | 用 | 右栏每行“⋯”里加结束；再说话照旧重开 |
| 做完：发一条带结果的回复，再结束 | 学 | 学习是讨论类，等学习者说完才结束（10-28 定稿）：模型觉得差不多了在话里说，他说可以或说不学了，才结束 |
| 状态：等你 / 进行中 / 空闲 / 已结束，没有“通过” | 用 | 没有“合上 / 没合上”“等确认”；新学习只分开着和已结束，旧学习照旧显示当时的状态 |
| 一周无活动自动结束 | 不用 | 10-28 定不做；#87 另谈 |
| 主对话多半不出声 | 用 | 程序只告诉主对话“结束了”，不再转收尾那一句；这次主对话把它转述得很圆满（“你还自己推出了……”），学习者说“太草率了” |

**提示词草稿**（`loop.md`「收尾」换成）：

> 这一块弄清了，或学习者要停：说一段这次做了什么、停在哪（他和主对话都看得到），用 note_down 记学到哪。你觉得差不多了就在话里说，他说可以、或说不学了，再结束这个对话；他还有话说就不结束。结束后他再说话就重开。

`project.md`、`main.md`、`note_down` 的说明、跨次记录（`cross-notes.ts` 列的“收尾那一句”“合上”）跟着改。跨次记录里每次学习改列最后那段话，或只留“学到哪”，你定。旧数据的收尾那一句照旧列。
