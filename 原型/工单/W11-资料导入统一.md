## 1 一处存放 + 归属

| 项 | 写死的做法 |
| --- | --- |
| 位置 | 新导入一律进 `<数据>/资料/<资料 id>/`（`source.json` · `原件/` · `正文/` · `mineru/`，结构同现在 `Materials` 的一份）。`Materials` 的根从 `<数据>/projects` 改成 `<数据>/资料` |
| 旧位置 | 不并存：迁移时整份搬进 `<数据>/资料/`（见「数据版本」），之后代码只认新位置 |
| `MaterialSource` 加字段 | `owner: { kind: 'learner' } \| { kind: 'project'; projects: string[] }`（可选；旧数据没有 → 按所在旧位置推）· `learned?: { channel: '笔记' \| '对话记录' }`（判为“学过的”的标这个）· `importedFrom?: string`（从哪个项目导入的，只记，不等于归属）· `processedBy?: string[]`（处理过它的导入会话 id，§4） |
| 读范围 | `Materials.ofProject(main)` 改为“本项目能读的”：owner 是学习者的全部 + owner.projects 含 main 的。所有现有调用方（沙盒只读区、`textbook_index` / `read_source` / `search_textbook`、出处核对、定位 `locate.ts` 的“资料须属当前项目”）都走它，不另写一套 |
| 外部导入指针 | `Import.ref` 加一种 `{ material: string }`。笔记 / 对话记录导入 = 建一份资料（owner 学习者、`learned` 标渠道）+ 在 `learned/imports.jsonl` 追加一条 `{ channel, ref: { material }, unverified: true, title, project }`。旧的 `{ file }` 指针迁移掉，`Import.ref` 只剩 `{ session, lines }` 与 `{ material }` |
| `importText` 对 `{ material }` | 返回该资料正文的拼接（每个文件前标 `<!-- 文件：相对路径 -->`），沙盒里 `外部导入/<id>.md` 照旧有一份；另外在沙盒只读区按资料目录挂进去，模型能按原目录读（见 `sandbox.ts` 的 `learnedFiles` / 资料条目） |
| 数据版本 | 不做读侧兼容（产品负责人：不要新旧并存）。`DATA_VERSION` 加到 4，`MIGRATIONS['3']`：`projects/*/资料/*/` 搬到 `资料/<id>/` 并补 owner = 那个项目；`learned/imports/<id>/` 的文件型导入建成资料（owner 学习者、`learned.channel` 照旧），`imports.jsonl` 追加 `{ removed: 旧id }` 与新的 `{ ref: { material } }` 一条；搬完删旧目录（迁移前程序已整份备份）。正本 JSONL 旧行不改，只作历史文字 |
| 删掉 | `Materials.copy`（从别的项目拿一份）与它的 HTTP 入口：跨项目改为改归属 |

## 3 原件层与工作层

| 项 | 做法 |
| --- | --- |
| 原件层 | `原件/`：导入时原样拷入（文件夹保留目录结构），之后任何代码都不写它；`version` 记原件指纹（整份哈希） |
| 工作层 | `正文/`：模型可读的副本。纯文字（md / txt / 代码 / 字幕转出的 md）由程序直接从原件拷或转；其余由 §4 的导入会话写 |
| 笔记 | 不再合成一份 `正文.md`：文件夹照原结构进 `正文/`（`learned.ts` 的 `importFile` 改为走 `Materials.add`，`textFilesIn` 合并逻辑删掉）；对话导出 `.json` 仍由 `chatExportToMarkdown` 转成一份 md，开头仍加 `CHAT_RECORD_HEAD` |
| 改动记录 | 工作层只有导入会话能写；它的读写由沙盒照常记成 `sandbox_action`（在导入会话自己的正本里），`source.json.processedBy` 记会话 id。其他会话对资料仍只读 |
| 说明文件 | 不强求。导入会话觉得又大又乱时可以在 `正文/` 里写一份 `说明.md`；`textbook_index` 列文件时它排第一 |

## 4 导入会话（试验）

| 项 | 做法 |
| --- | --- |
| 何时开 | 一份导入的原件里有不是纯文字的文件（PDF、图片、Word、PPT、表格、epub 等）时，程序拷完原件、把纯文字部分放进 `正文/` 后，在后台开一个导入会话；状态保持“处理中”，会话交回后改。全是纯文字的不开 |
| 不收的 | 音频、视频、可执行文件、压缩包：照旧标“转不了”（`uploads.ts` 的 `BINARY_EXT` 去掉文档类与图片，只留这些） |
| 会话种类 | 新 `import`（`CONVERSATION_KINDS` 加；`STUDIUM_PROFILES` 默认 `{ model: 'sonnet', effort: 'medium' }`，写在 `profiles.ts`）；`parent` = 发起导入的主对话；界面不显示，不进左栏 |
| 沙盒 | 工作区 = 这份资料的 `正文/`；只读 = `原件/`；`commands: true`；`network: false` |
| 自己的工具 | `mineru({ file })`：程序拿 `原件/<file>` 走现有 `convertPdf` 那套（含分页段、`书库处理/` 的 `studium.mineru`），产物进 `mineru/`、md 进 `正文/`，回一句结果；密钥不进模型环境 · `finish_import({ status: '可用' \| '部分可用' \| '失败', note })`：交回，程序写 `source.json`（状态、`problems` = note 里写的问题）并结束会话 |
| 提示词 `prompts/import.md` | 只写：你在什么环境（只读 `原件/`、可写的当前目录就是这份资料给别的会话读的文字版）、目的（把原件里的内容处理成别的会话能读、能按 `文件:行号` 引用、能指回原件哪一处的文字；图片直接看、需要时可裁剪放大；PDF 可用 `mineru`；觉得又大又乱可写一份 `说明.md`）、交回用 `finish_import`。不写规则清单 |
| 跑不起来 | 会话失败或超时 → 状态“失败”、`problems` 写原因，不伪装可用；学习者可重试（`Materials.retry` 改为重开导入会话） |
| PDF 现在的固定流程 | `process` 里 `pdf` 分支不再直接调 `convertPdf`，改为走导入会话；`convertPdf` 本身留着给 `mineru` 工具用。网页、仓库、找资料的流程不动 |

## 5 主对话只读本机

| 项 | 做法 |
| --- | --- |
| 沙盒 | `kind('main')` 加 `sandbox`：只读 = `[{ name: '本机', path: os.homedir() }]`；工作区 = `<数据>/sandbox/<主对话 id>/工作区`；`commands: true`；`network: false` |
| 挡密钥 | 不让读：家目录下所有以点开头的顶层条目（`~/.ssh` `~/.config` `~/.claude` `~/.local` 等）+ 数据目录 + `<数据>-备份` + `../书库处理/.env`，每处先解开符号链接再比。往下走的操作（Glob / Grep 的 path、`import_local` 的 path）还须不是任何被挡位置的祖先（`~`、`~/Studium` 拒绝）。沙盒 `denyRead` 与 `canUseTool` 的读判断都挡；相对路径与缺省路径按 SDK 实际的工作目录解析后再判（自查发现原先按工作区解析，Grep 不给 path 能搜整个数据目录） |
| 续接 | 已有的主对话正本里有续接凭据，SDK 按工作目录找会话文件：**主对话的 SDK `cwd` 必须仍是数据目录**，否则旧主对话接不上。适配器里“有沙盒就把 cwd 设成工作区”对主对话不成立，施工时解决（例：`SandboxSpec` 加可选 `cwd`），命令行的落脚点与可写范围另给；改完拿一个旧主对话真接一次看能不能接上 |
| 联网 | 主对话不开联网（现在也没有）；它带沙盒后照适配器规矩，不会同时有沙盒与联网 |
| 导入工具 | `import_local({ path, title? })`：程序把本机这个路径（文件或文件夹）拷进本项目的 `上传/<上传 id>/`，之后走和拖进来完全一样的分流与落地（`Uploads` 加一个从路径存的入口，复用 `land`）；路径须在家目录下、不在挡掉的位置 |
| 提示词 `prompts/main.md` | 加一小段：学习者给本机路径时可以直接读；读了要当以后的依据（以前学过什么、要配的资料）就用 `import_local` 存一份进来；不改本机文件 |

## 6 问别的项目的主对话（试验）

| 项 | 做法 |
| --- | --- |
| 工具 | `ask_project({ project, question })`：给学习对话、导航、畅谈、主对话；`project` 是主对话 id；工具说明里列出别的项目（id + 名字），或另给 `list_projects`，施工时定 |
| 怎么答 | 从目标项目主对话最近的续接凭据分叉（SDK `forkSession`，`persistSession: false`），用主对话的系统提示与它的读工具；问题前附一句“这是别的会话来问的，只答问题、给出处（资料id/文件:行号 或 会话 id:行号），不对学习者说话”。分叉不写回主对话那条线，界面不显示 |
| 记 | 问的一方：工具调用照常记 `tool_call`。被问的一方：在目标主对话正本追加 `project_asked { type, at, from: 会话 id, question, answer }`（只加类型）；目标主对话的上下文不加这一条（下一轮的 `turn_context` 也不提它） |
| 没有续接凭据 | 目标主对话还没跑过：不分叉，直接开一个临时会话，给主对话的系统提示与读工具 |
