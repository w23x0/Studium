## 和工单不同的地方

| 不同 | 理由 |
| --- | --- |
| 从书库挑的书不拷贝切分目录，`source.json` 记 `bodyPath` 指向书的 `m07/` | 工单允许“指向（或拷贝）”；拷贝整本书费空间，指向又不能用符号链接（沙盒按真实路径放行） |
| 读原文的接口（`Sources`、`Originals`、`Crosslinks`、`Outputs`、学习对话工具）统一经 `Materials`，认不出的 id 退回书库 | W8 之前的单子、依据、出处标记都按书库 id 写，退回书库能让它们照旧定位；资料范围（`scopeOf`）仍只认本项目 |
| 出处标记改写成 `【资料|资料id|文件|L…】`，旧的 `【教材|…】` 照认 | 资料不只是书 |
| `library.ts` 里笔记的扫描（`kind: 'note'`）没删，只是项目资料列表、检索范围、资料浏览里不再有笔记 | 笔记的新存放处与导入归 W9；现在删会让已导入的笔记看不到。W9 接着做 |
| 新 PDF 的转换要本机有 `MINERU_TOKEN` 与 `pdfinfo`，只转出按页段的 md，不做目录切分 | 切分（`m07toc`）要再调一次模型；工单说“只要做到能用” |

## 拿不准的

- 网页转 md 是自写的简单转换（取 `main` / `article`，标题、段落、列表、链接、代码块），复杂网页可能读不顺；以后可换 Readability。
- 云端环境里 Node 的 `fetch` 不走代理，网页抓取在这里没试通；本机应正常。
- 资料 id 用可读的名字，重名加“（2）”；同一本书进两个项目各是一份（id 不同）。
