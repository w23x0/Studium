## 和工单不同的地方及理由

1. **`tests/验收/` 里两个文件名改了**：`闭环依据可见.test.ts` → `依据可见.test.ts`、`跨领域闭环.test.ts` → `跨领域学习.test.ts`。理由：本单测试要求功能清单每条 `JSON.stringify` 不含 `/M0[5-9]|M1[0-5]|闭环/`，而“验证”要写出测试文件路径；文件名带“闭环”就必然命中。W6 工单也写了这两条“改名 W7”。文件内容没动，只改名 + 功能清单里的 id / 验证跟着改。
2. **`tests/验收/状态回看.test.ts` 有 8 行格式改动**（`npm run format` 把两处超长行折行）：sed 把 `/m15/` 换成 `/state/` 后行变长，prettier 折行。断言没动。`教材出处.test.ts` 一处 `prompts.m05` → `prompts.nav`（种类名机械替换，§5 的 sed 没列 `.m05` 这种属性访问）。
3. **`src/core/knowledge/library.ts` 里 `# M07 索引` 出现三处**（§4.11 只写了“各一行”）：常量 `BOOK_DIR`、解析用的正则、写索引标题的 `indexTitle()`。加第三处是为了让 `notes.ts`（个人笔记也写同格式的索引标题）不出现这个字面量——字面量集中在 `library.ts` 一处，符合 §4.11 的意思。
4. **允许留下的旧叫法比 §4.11 多三处**（检查 A 的实际结果，逐个说明）：
   - `scripts/features.mjs` 的 `OLD = /M0[5-9]|M1[0-5]|闭环/`：功能清单的核对规则本身要认得旧叫法，与 §4.11 允许的评测内部词清单同类。
   - `src/ui/wording.test.ts` 的 `'闭环'`：界面叫法表的内部词清单（抓泄露），与 `tests/验收/界面文字.test.ts`、`evals/cases.ts` 同一口径。
   - `tests/helpers/roles.ts` 的 `'m09'`：`tests/验收/录带回放.test.ts` 里有一个 `case 'm09'`（老录带的假应答），删掉这个取值会让那条验收测试类型不过；它已经不对应任何会话。§5 给 `roles.ts` 的改动清单里也没让删它。
5. **`整条链不崩` 多留了一步“畅谈谈定方向”**：§4.9 的表里列了各步，没提这一步；它是原有的判定，删掉会放松检查，所以留着（假模型下照过）。
6. **`数据版本` 的功能描述**按 §4.6 改成“数据目录版本 3 …”，同时把“值是 2 或没有版本文件”写清楚。
7. **e2e 的浏览器**：本机没有 playwright 自带的 chromium，用 `PW_CHROMIUM_PATH=/usr/bin/google-chrome npm run e2e` 跑，两条都过（工单里写的是云端路径 `/opt/pw-browsers/chromium`）。
8. **`library.ts` 的 `SKIP_DIR` 去掉了 `m08$`**：§4.11 要求“用常量拼、不另写 `'m07'`”，而 `m08` 这个字面量会命中检查 A；知识点取消后不再有这种目录，行为上无差别，常量上方加了一行说明。
