## 4 加 / 改什么

### 4.1 单子（`src/shared/records.ts`，形状照 README §2.1）

```ts
export const START_SOURCES = ['学过的记录', '自述', '假定'] as const;
export interface Ticket {
  newPoint: string;                 // 一句话
  clause: string;                   // 预期理解
  startPoints: { point: string; source: (typeof START_SOURCES)[number]; ref?: string }[];
  routeAction: string;
  sourceCheck: { claim: string; at?: string; modelAdded?: boolean }[];   // 没给时存 []
  revisit?: …;                      // 本单不动旧形状（formation_ids），W2 改
  crossDomain?: CrossDomain;
  stageCheck?: boolean;
}
export interface CrossDomain { kind: '补习型' | '对比链接型'; otherPoint: string; problem: string }  // 只这三项
```

卡上一项 → 单子：`new_point`→`newPoint`，`clause`→`clause`，`start_points[{point, source, ref?}]`→`startPoints`（没给 `ref` 就不带这一栏），`route_action`→`routeAction`，`source_check[{claim, at?, model_added?}]`→`sourceCheck[{claim, at?, modelAdded?}]`（`model_added` 只在 `true` 时写 `modelAdded: true`；没给 `at` 就不带），`cross_domain{kind, other_point, problem}`→`crossDomain{kind, otherPoint, problem}`，`stage_check: true`→`stageCheck: true`。`choice_card.options[i]` 存 `{ title, reason, sources, ticket }`，原样，不改写。

### 4.2 选择卡工具 `submit_choice_card`（`cardTool`；参数照 README §2.2）

假模型直接调 `run(args)`、不经 zod，所以**下表每条核对都写在 `run` 里**；任何一条不过：整次 `isError`、报错文字逐条写出不过的项（定位不了的把原串写出来，如“`不存在的书/x.md:1` 定位不了”），什么都不记，模型可在同一轮里改后重交。全部核完才收。

| 项 | 规则 |
| --- | --- |
| `route_decision` | 必有；`decision` `reason` 去空白后非空；`basis` ≥ 1 条，每条都能定位 |
| 每个选项 | `new_point` `clause` `route_action` `title` `reason` 去空白后非空；`sources` ≥ 1 条且每条非空白；`start_points` 每条 `point` 非空、`source` 在 `START_SOURCES` 里、给了 `ref` 就须能定位；`source_check` 每条 `claim` 非空、给了 `at` 就须是能定位的书里那一行 |
| `cross_domain`（可选） | `kind` 只能是 `补习型` / `对比链接型`；`other_point` `problem` 去空白后非空；程序不算领域、不核学没学过 |
| `sources` | 定位不了的**照存**；依据视图（`GET /api/cards/:id`）里每条给 `resolved`（书里那一行查得到 → `book_line` + 原文；其他 → `unknown`、`resolved: false`），不编 |
| 选项数 2–4、`recommended` 范围 | 照旧 |
| `revisit` | 照旧（W2 改） |

**定位规则**（写成一个小模块，如 `src/core/locate.ts`，卡工具、路线决定、依据视图共用）：串里最后一个 `:` 前含 `/` → 当书里那一行，用 `sources.bookLine(raw)`，`resolved` 才算定位到（书、文件存在且行号在文件内）；否则当 `<会话 id>:<行号>`，会话存在且正本里有这一行（任何记录类型）才算。

### 4.3 路线决定（新记录，形状照 README §2.3，一字不改）

| 项 | 规则 |
| --- | --- |
| 何时写 | 导航交的卡被收下后，程序在**项目主对话**的正本里先写一条 `route_decision`，紧接着写 `choice_card`（两行相邻，卡在后） |
| 字段 | `navSessionId` = 交卡的导航会话 id；`trigger` = `requestCard` 的触发原因原样；`decision` `reason` `basis` 取自工具参数原样 |
