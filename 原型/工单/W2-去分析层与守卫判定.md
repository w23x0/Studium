## 4 加 / 改什么

### 4.1 记录类型（`src/shared/records.ts`）

```ts
export const INDEPENDENCE = ['独立', '提示后', '答案暴露后'] as const;
export const DURABILITY = ['仅当场', '含变式', '含延迟'] as const;
export interface Understanding {
  text: string;                                   // 学习者实际表现出的理解，一句到几句
  lines: number[];                                // 学习对话里学习者的行，≥ 1 条
  independence: (typeof INDEPENDENCE)[number];
  durability: (typeof DURABILITY)[number];
}
// GuardVerdict 加：
understanding?: Understanding[];   // 判合上时必有且 ≥ 1 条；判没合上时可有可无（有就照存）
model?: string;                    // 守卫这一轮实际执行的模型 = hub.executedModel(guardSessionId)（取不到时就是它给的兜底串）
// Ticket.revisit 改为（README §2.1）：
revisit?: { kind: '复习' | '复检'; ofLoop: string; verdictLine?: number };
// AfterLoopStep.step: 'card_ready' | 'failed'
// ObjectionTarget: { kind: 'guard_verdict'; … } | { kind: 'm10' | 'm15'; recordId: string }
```

`LoopEnded`（合上）即收口快照：事件记录、单子、通过的判定都已在这次学习的正本里，不另写记录。“通过的那份判定” = `loop_ended` 之前最后一条 `closed: true` 的 `guard_verdict`。

### 4.2 守卫（`verdictTool`、`runGuard`、`prompts/guard.md`）

| 项 | 规则 |
| --- | --- |
| 工具参数 | `closed` `basis` `evidence_lines` 同旧；加 `understanding: { text, lines[], independence, durability }[]`（可选） |
| 程序核对（不过就 `isError` 退回、可重交；全部先核再收） | `closed: true` 时 `understanding` 至少一条；每条 `text` 去掉首尾空白后非空、`lines` ≥ 1 且每行都是学习者的行（判没合上时写了也照此核对）（同 `evidence_lines` 的核对，用同一个 `learnerLines`）；`independence` `durability` 只能是上面几档；`evidence_lines` 规则不变 |
| 存 | `guard_verdict` 照旧由程序写，加 `understanding`（原样，不改写）和 `model` |
| 提示词要点（只写定义、边界、格式，≤ 6 行增量） | 判合上时写下学习者在这次里**实际**表现出的理解（可与单子的预期理解不同），每条指回学习者的行；每条注独立程度（独立 / 提示后 / 答案暴露后）与持久程度（仅当场 / 含变式 / 含延迟）；只认学习者自己的行；这是这次学习唯一的结论性产物，不另写总结。删掉提示词里“读 M08 的点与子句”那句（若 W1 后还在） |

### 4.3 学习结束后的清单（`studium.ts`：`confirmClose` `endUnclosed` `afterLoop`）

| 事件 | 步骤（按顺序） |
| --- | --- |
| 合上（学习者确认） | ① `loop_ended { closed: true }`（收口快照）② 主对话里一条程序事实（“…合上了，下一张卡正在出”，日常话）③ `requestCard('合上：<标题>（<学习 id>）', mainId)` → 学习正本记 `after_loop_step { step: 'card_ready', detail: <cardId> }`；出卡抛错 → `{ step: 'failed', detail: <原因> }` ④ ③ 结束后（成或败）再起后台：状态整理（`organizeStateLater`）与教法记录整理（`recordStrategy`），不等它们 |
| 没合上（`POST /sessions/:id/end` 或 `end_loop_unclosed`） | ① `loop_ended { closed: false, note: <结束原话> }`，不开守卫 ② 同上程序事实 ③ `requestCard('没合上：<标题>（<学习 id>）', mainId)`（导航开场里给这次学习 id；读完整对话归 W3）→ `card_ready` / `failed` ④ 同上后台 |
| 分叉学习（W3 删前仍在） | 不出卡；仍调 `detours.returnToParent`，失败记 `failed`（`detail` 以“回父学习：”开头），成功不记步骤 |

- `requestCard` 的 `trigger` 原样写进 `choice_card.trigger` 与 `route_decision.trigger`（W1 若已如此不用动）。所以合上 / 没合上之后的卡和路线决定，触发原因分别以“合上”“没合上”开头。
- `longterm.onUnclosed`（偏差）照旧调用，W3 再改。

### 4.4 学过的记录按层（新建 `src/core/learned.ts`，类型放 `src/shared/protocol-learned.ts`）

`Learning` `Import` 的形状照 README §2.5，一字不改。

| 接口 | 规则 |
| --- | --- |
| `GET /api/learned?project=<主对话 id>` | `{ learnings, imports }`。`project` 给了：只列 `parent` 是这个项目主对话的学习；项目不存在 → 404。不给：列全部学习（学过的记录按人、不按项目划界）。`learnings` 按 `openedAt` 升序；`imports` 总是全部、按时间升序 |
| `GET /api/learned/<学习 id>` | `{ learning }`；不是 `loop` 会话或不存在 → 404 |
| `status` | 没有 `loop_ended` → `进行中`（搁置也算进行中）；`closed: true` → `合上`；否则 `没合上` |
| `ticket` `title` `openedAt` `endedAt` | 取自学习正本的 `session_opened`（`ticket` `title` `at`）与 `loop_ended.at` |
| `verdict`（中层，只在 `合上` 时有） | 通过的那份判定（§4.1）：`{ line, closed, basis, understanding, model }`；`understanding` 缺（旧数据）给 `[]` |
| `endNote`（只在 `没合上` 时有） | `loop_ended.note` |
| `routeDecision`（只在 `没合上` 时有） | 学习正本里 `after_loop_step { step: 'card_ready' }` 的 `detail`（卡号）→ 项目主对话里那张 `choice_card` → 同一导航会话（`route_decision.navSessionId` = 卡的导航会话 id）的那条 `route_decision`：`{ line, decision, reason }`；找不到就不给这一栏 |
| 下层 | 不进这个接口，照旧 `GET /api/sessions/<id>/records` |

只读、不缓存（每次从正本现算）；不另存摘要。
