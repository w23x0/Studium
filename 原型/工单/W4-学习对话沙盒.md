## 5 加 / 改什么

### 5.1 模型接口（`src/core/model/port.ts`）

照 README §2.6 加 `SandboxSpec`、`ConversationSpec.sandbox?`、`ModelEvent` 的 `sandbox_action`，并定下这几处：

| 项 | 定死 |
| --- | --- |
| `readOnly[].name` | 可含 `/`（如 `资料/大学物理/力学/力学入门样例`）；以 `.md` 结尾的是单个文件（如 `本次对话.md`），其余是目录 |
| 虚拟路径 | 模型侧与记录里的 `path` 一律用虚拟路径：工作区里的文件 = 相对工作区（`诊断.md`）；只读的 = `只读/<name>/<相对>`（按 `name` 最长前缀匹配）；都不是 = 绝对路径原样 |
| `action` 加字段 | `content?: string`：写类动作写进去的文字（整份写 = 全文；追加 = 追加的部分；Edit = `new_string`）；其他动作不填 |
| 路径工具 | 新建 `src/core/model/sandbox-paths.ts`（不引 SDK）：`resolveSandboxPath(sb, p)`（虚拟 / 相对 / 绝对 → 绝对，`..` 规范化）、`virtualPath(sb, abs)`、`canWrite(sb, abs)`（只在 `workdir` 之内）、`canRead(sb, abs)`（`workdir` 或某个 `readOnly.path` 之内 / 等于该文件）。假模型与 SDK 适配器都用它 |

### 5.2 假模型（`src/core/model/fake.ts`）

`FakeStep.sandbox` 照 README §2.6。补充：先执行 `sandbox` 里的动作，再执行 `calls`，再说 `text`；每个动作发一条 `sandbox_action` 事件；`read` 的结果（文件全文；失败时是原因）按顺序进 `ctx.results`；`write` = 覆盖、`append` = 追加，都记 `op: 'write'`，工作区内缺的父目录自动建；越界写（工作区外、只读区、`..` 出去）`ok: false` 且不写；越界读 `ok: false`；`run` 不执行，`ok: true`，`summary` 写明“假模型不执行”。没有 `spec.sandbox` 的会话收到 `sandbox` 步骤：每个动作 `ok: false`（summary“这个会话没有沙盒”）。

### 5.10 Claude Agent SDK 适配器（`claude-agent-sdk.ts`，SDK 0.3.293）

把“由 spec 算 options”抽成导出的纯函数，`SdkConversation.start()` 用它：

```ts
export function sdkOptionsFor(spec: ConversationSpec, o: ClaudeAgentSdkOptions): Options;
export function sandboxPermission(sb: SandboxSpec): CanUseTool;          // sdkOptionsFor 用它
export function sandboxActionOf(sb: SandboxSpec, use: { name: string; input: Record<string, unknown> },
  result: { is_error?: boolean }): SandboxActionEvent['action'] | undefined;
```

| `Options` 字段（`sdk.d.ts` 里的名字） | 没有 `spec.sandbox`（其他会话，保持现状） | 有 `spec.sandbox` |
| --- | --- | --- |
| `tools` | `[]` | `['Read','Write','Edit','Glob','Grep','Bash']` |
| `cwd` | `o.cwd` | `sb.workdir`（续接靠它稳定：同一次学习的工作区不变） |
| `additionalDirectories` | 不给 | `readOnly` 的 `path`（单文件条目给它的父目录），去重 |
| `permissionMode` | 不给 | `'default'` |
| `canUseTool` | 不给 | `sandboxPermission(sb)` |
| `sandbox`（`SandboxSettings`） | 不给 | `{ enabled: true, autoAllowBashIfSandboxed: true, allowUnsandboxedCommands: false, filesystem: { allowWrite: [workdir], denyRead: o.cwd ? [o.cwd] : [], allowRead: [workdir, ...readOnly 路径] } , ...(network ? {} : { network: { allowedDomains: [], strictAllowlist: true } }) }` |
| `mcpServers` / `allowedTools` / `strictMcpConfig` / `settingSources` / `systemPrompt` / `includePartialMessages` / `resume` / `model` / `effort` / `env` | 照旧（`allowedTools` 只放我们的 `mcp__studium__*`） | 同左 |

`sandboxPermission`：返回 `PermissionResult`。`mcp__studium__*` → allow；`Read`（`file_path`）、`Glob` / `Grep`（`path`，没给 = 工作区）→ `canRead` 才 allow；`Write` / `Edit`（`file_path`）→ `canWrite` 才 allow；`Bash` → allow（命令由沙盒卡）；其他工具 → deny。相对路径按 `workdir` 解析。deny 的 `message` 写明“只读 / 工作区外，不能写”。allow 时 `updatedInput` 原样回传。

事件：`read()` 里遇到 `assistant` 消息的 `tool_use` 块（名字是上面六个之一）按 `id` 暂存；遇到 `user` 消息的 `tool_result` 块按 `tool_use_id` 配上，`yield { kind: 'sandbox_action', action: sandboxActionOf(...) }`（`ok = !is_error`）。映射：Read→`read`，Write / Edit→`write`（带 `content`），Glob / Grep→`search`，Bash→`run`（`command`），`path` 一律经 `virtualPath`；`summary` 一句中文（如“读 只读/教学工具/提取练习.md”）。不用 `PostToolUse` 钩子。

**单测** `src/core/model/claude-agent-sdk.test.ts`（施工方写，不进验收目录，不调真模型），断言：
1. 无沙盒：`tools` 是 `[]`，没有 `sandbox` `canUseTool` `additionalDirectories`，`cwd === o.cwd`，`allowedTools` 只有 `mcp__studium__<工具名>`。
2. 有沙盒：`tools` 恰为六个；`cwd === workdir`；`additionalDirectories` 含每个只读目录、单文件条目给父目录且不重复；`permissionMode === 'default'`；`sandbox.enabled` 与 `autoAllowBashIfSandboxed` 为真；`network:false` 时 `sandbox.network.strictAllowlist === true` 且 `allowedDomains` 为空。
3. `canUseTool`：写 `<workdir>/诊断.md` allow；写 `<workdir>/../x.md`、写只读目录里的文件、读 `/etc/passwd` 都 deny；读只读目录里的文件 allow；`Bash` allow；`mcp__studium__request_close` allow；`WebFetch` deny。
4. `sandboxActionOf`：Write `<workdir>/诊断.md` → `{ op:'write', path:'诊断.md', ok:true, content }`；Read `<只读/教学工具 的实际路径>/提取练习.md` → `path: '只读/教学工具/提取练习.md'`；Bash → `{ op:'run', command }`；`is_error` → `ok:false`；`mcp__studium__request_close` → `undefined`。
