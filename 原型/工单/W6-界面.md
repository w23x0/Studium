## 4 加 / 改什么

### 4.1 改单子（核心侧，唯一的新功能）

`POST /api/sessions/:loopId/ticket-edit`，请求体（驼峰，至少一项）：

```ts
interface TicketEditRequest {
  newPoint?: string;
  clause?: string;
  startPoints?: { point: string; source: '学过的记录' | '自述' | '假定'; ref?: string }[];
}
```

| 情况 | 回 |
| --- | --- |
| 会话不存在 | 404 `{ error }` |
| 会话不是 `loop`；学习已结束（有 `loop_ended`）；一项都没给；给了的项不是文字 / 去空白后为空；`startPoints` 不是数组或为空；某条 `point` 为空、`source` 不在三档里、`ref` 给了却定位不了（用 W1 的 `src/core/locate.ts`，同卡工具的规则）；改后与现在的单子完全相同 | 400 `{ error }`，什么都不写；`error` 用日常话写清哪一项不对，不含“闭环 / M0x / M1x” |
| 合格 | 200 `{ line, ticket }`：`line` = 新记录的行号，`ticket` = 改后的整张单子 |

合格时依次做：

| 步 | 做什么 |
| --- | --- |
| 1 记录 | 学习正本追加 `{ type: 'ticket_edited', at, by: 'learner', before: Ticket, after: Ticket }`（加进 `src/shared/records.ts` 的 `LogRecord`）。`before` = 现在的单子（`currentTicket`），`after` = `before` 把给了的项整项替换（`startPoints` 整个数组替换），其余字段（`routeAction` `sourceCheck` `revisit` `returnTo` `resumeOf` `stageCheck` `crossDomain`）原样。`session_opened.ticket` 与卡上的单子**不改**（只追加） |
| 2 告知学习对话 | `hub.send(loopId, { role: 'program', text })`（排进队列，成为学习对话下一轮的输入）。`text` = `学习者改了这次的单子（第 <line> 行），之后按改后的来。\n改前：<describeTicket(before)>\n改后：<describeTicket(after)>`；不含“闭环 / M0x / M1x” |
| 3 回 | 200 `{ line, ticket: after }` |

`currentTicket(records: NumberedRecord[]): Ticket | undefined`（新文件 `src/core/ticket.ts`）：最后一条 `ticket_edited.after`，没有就 `session_opened.ticket`。凡把“这次学习现在的单子”拿来用的地方都改用它：守卫开场（`studium.ts` 收口时取单子那处）、W2 的 `src/core/learned.ts`（`Learning.ticket`；W4 的沙盒渲染与 W3 的接着学开场经它取，自然跟上）、`evidence.ts` 的学习视图。用 `rg -n "\.ticket\b" src/core` 逐处过：卡上的单子、`choose` 时写进 `session_opened` 的那张不改。

`Learning` 加 `ticketEdits?: { line: number; at: string }[]`（`src/shared/protocol-learned.ts`；没改过就不带）。

界面：`thread-model.ts` 把 `ticket_edited` 转成一条 `system` 消息，`line` = 记录行号，文字 `W.ticketEdited`（见 §4.4）。
