# 审查做法（给审查会话）

> 状态：现行。审查方 = 云端 Claude 会话。每单施工推上来后照这页审。W1、W2 照此审过，记录在 `进度/W1-审查.md` `进度/W2-审查.md`。
> 新开审查会话时，把文末“开场提示”整段贴进去。

## 步骤

| # | 做什么 | 怎么做 / 注意 |
| --- | --- | --- |
| 1 | 找到这单的改动 | `git fetch origin`；分支 `deepseek/Wn`。若已被合进 `main`（产品负责人有时先合），就在 `main` 上审，改动 = 合并提交的第一父到第二父：`git log --first-parent origin/main` 找到那次合并 |
| 2 | 开单独的工作目录 | `git worktree add <目录> <提交>`，在里面 `cd 原型 && npm ci`；审完删掉工作目录 |
| 3 | 读施工自述 | `进度/Wn.md`：步骤、遇到的问题、和工单不同的地方、拿不准、疑似测试错；再看前几单审查记录里“留给后面的”有没有归到本单 |
| 4 | 核验收测试没被动 | ① “test: Wn 验收测试就位”那次提交之后 `tests/验收/` 没有改动（`git diff --name-status <就位提交> <末提交> -- tests/验收`）② `工单/验收/Wn/` 每个文件与 `tests/验收/` 的拷贝一模一样（`cmp`）③ 删掉的旧测试与工单 §5 第一列一致 |
| 5 | 跑工单 §3 的空检查 | 从工单里抽出所有 `` `rg -n …` `` 逐条跑（`\|` 换成 `|`）；命中的逐条判断：工单自己要求留的（如回放认旧动作名）放过，其余记下 |
| 6 | 跑 `npm run check` | 施工方报的“疑似测试错”先判：是测试写错就改测试（`工单/验收/Wx/` 原件与 `tests/验收/` 拷贝同改，保持一致），是实现错就记“必须修” |
| 7 | 派独立审查子代理 | Opus、只读、探针脚本写 scratchpad；要它对照工单 §4 逐条核、找半截旧逻辑、判断施工方“和工单不同的地方”、查越界与真实错误；交回一张表（必须修 / 建议 / 无碍 + 证据 + 最小改法） |
| 8 | 自己核“必须修” | 子代理会误报：先读代码确认，再改。教训（W1）：真模型经工具参数形状（zod）核，假模型绕过它；不要在 `run` 里加会让旧测试帮手全挂的核对 |
| 9 | 修 | 改动最小；每个修过的漏洞补一条回归测试，放 `工单/验收/Wn/<名>.test.ts` 并拷进 `tests/验收/`，先确认它在修之前失败；`功能清单.json` 加一条；死代码顺手删 |
| 10 | 写审查记录 | `进度/Wn-审查.md`，格式照 `进度/W1-审查.md`：核过的 · 疑似测试错 · 审查发现已修 · 留给后面的（写清归哪一单） |
| 11 | 交 | 提交到本会话指定的 `claude/*` 分支，开合并请求到 `main`，订阅它；CI 绿了告诉产品负责人可以合，并说下一单可以起 |

## 开场提示（新开审查会话时贴）

```text
审查原型改造工单 Wn（仓库 w23x0/Studium，分支 deepseek/Wn，可能已合进 main）。
先读 原型/工单/审查做法.md 并照做；工单在 原型/工单/Wn-*.md，共用约定在 原型/工单/README.md §2。
审完把修补与 原型/工单/进度/Wn-审查.md 提交到你的分支、开合并请求，告诉我能不能合、下一单能不能起。
```
