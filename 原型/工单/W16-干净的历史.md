## 产品负责人定（11-05）

| 结论 | 理由 |
| --- | --- |
| 不做检索工具，模型用通用工具（读文件、grep、命令）搜原文 | 给模型自主空间；转成向量或定制工具会限制它、质量也不高 |
| 项目能做的是让进入它上下文的内容干净、整齐、结构规整，让它少花 token、一次找准 | 分类、结构要项目自己想 |
| 不派子代理去找内容 | 交回来的只是“该看哪些”，主模型还得看，不如把它自己查找这一步优化好 |
| 旧的在上、新的在下 | 现在已经这样，保持 |

agent 原来提的“程序把更早的原文裁成只剩学习者的话”撤回：裁不裁、怎么裁由模型自己决定。

## 看到的问题（代码 `src/core/sandbox.ts`；真实数据在本机 `var/`，云端读不到，要点都在这里，文中 L 行号指学习对话 `20261105-023806-loop-bc279f`）

| 问题 | 想法 |
| --- | --- |
| `学过的记录/` 平铺：各项目混在一起，每次两个文件（`<id>.md`、`<id>-对话.md`），文件名看不出内容 | 按项目分目录；一次学习一个文件，头上是标题、状态、时间、收尾那一句，下面是原文。文件名怎么起你定（id 要留着，跨次记录的出处按 id 找） |
| `索引.md` 只有开始时间，不标项目 | 按项目分组，本项目放最后（离得近）；加结束或最后活动时间、距今几天。产品负责人关心：上次学这个隔了多少天、中间学了什么会干扰 |
| 主对话原文只能用 `read_project_chat` 拿，不能搜 | 放成文件（学习对话的只读区，每轮刷新）；谈方向的对话同样放（里面有学习者想拿这个做什么）。学习对话的工具能不能因此去掉，你看；谈方向没有沙盒，它的工具留着 |
| 以前的组件读不到：学习者要上次那张图，模型只能重画（这次 L43） | 组件最新一版放进记录目录，原文或文件头能看出在哪。来源 `var/screens/<id>/` 或 `put_component` 记录 |
| 说明写 `只读/资料/目录.md`、`只读/资料/<id>/`，实际文件是 `只读/资料目录.md`，正文在别处（目录里列了完整路径）；模型第一条命令就失败了（这次 L8、L13） | 让说明和实际一致，`loop.md`「资料与引用」跟上 |
| 旧原文里留着“（程序附）……”一大段（W14 之后新开的没有） | 渲染时去掉，旧记录不动 |
| 没告诉模型原文的格式 | 只读区说明里写一句事实：每条以 `L行号 谁（时间）：` 开头，续行缩进。这样它要只看学习者说的，自己 `grep '学习者（'`（STM32 第一次 31 KB → 6.7 KB，多行的话只留第一行） |

只读区还有什么乱的、多余的（比如 `.claude`、已不用的旧数据字段、外部导入的两份说明），你看到了一并理。判断标准：模型 `ls` 一眼明白，读进去的都有用。

## 一个边界（没实测）

检索的结论主要来自代码，代码里名字是精确的；学习原文是口述转写，错字多，关键词可能搜不到。W17 的整理版就是为这个。整份读仍是主要方式，开场约 100k token 的预算够读（平均一次学习约 1 万 token，粗估）。

## 不做

程序按远近裁原文；子代理查找；向量或定制检索工具；上下文压缩（第一步读完超过约 100k 再谈，#84）。
