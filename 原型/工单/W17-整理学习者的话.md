## 想要什么

产品负责人原话要点：对学习者说的话做一次结构整理，模型先把这段话结构化输出；这样能分类他的话，回答也能按结构回答，前端可以有更多展示方式，也能消除口语错词，方便他回看自己说的话，也方便后续整理。

他多用语音输入，转写有错字（“大地”是 D、“back”是 Buck、“绘画”是会话），一段话里常有几件事、说到一半改口。

为什么现在做：以后的对话靠 grep 和读原文找他说过什么（W16），错字和混在一起的话搜不到、读不清。

## 边界

| 边界 | 为什么 |
| --- | --- |
| 原话不动，整理版只是加一份；原话照旧是证据 | `记录/学过的记录.md`：读原文时只认学习者的行；正本只追加 |
| 由学习对话的模型自己整理，不另开模型 | “大地”是 D，要懂上下文才认得出；11-03 定一个对话一个模型 |
| 只写“他说了什么”（改错词、分几件事、改口后的结论），不写“他懂没懂、水平如何” | 10-23 定稿撤了每轮诊断记录：分析就是模型的思考，不另写。写判断就是把它换个名字加回来 |
| 不用固定分类枚举 | 固定格式死板（11-03 产品负责人否掉单子的原因之一）；模型按这段话的内容分 |

## 想法（你定）

- **形式：** 一个写入工具，如 `tidy_message { line, text }`：`text` 是自由文字，程序核对 `line` 是本对话学习者的话，存一条新记录，同一行再写以后者为准。也可以有别的形式（比如回话里单独一块），你比较后定；要考虑多花多少输出 token、有没有打乱“最后写的话才上页面”。
- **什么时候：** 回他之前。短到不用整理的（“A吧”）不用；这条交给模型。模型漏了不强求，真用里看。
- **提示词：** `loop.md` 写事实：他多用语音、有错字，以后的对话靠原文找他说过什么，所以长的话先整理一遍。怎么写你定。
- **原文里：** 整理版接在原话下面，标明是模型整理的，不和 `学习者（` 这个开头混（W16 告诉模型能 grep 它只看原话）。
- **界面：** 学习页上他那条默认还是原话，能点开看整理后的。更多展示方式先不做，产品负责人用了再说。
- **回答“按结构回答”：** 不写成规则，看整理之后模型自己会不会这样。
