## 4 加 / 改什么

### 4.1 记录（`src/shared/records.ts`）——只加不改旧字段意思

```ts
export interface GoalAbility {
  ability: string;          // 学成后能做什么
  reason: string;           // 这块为什么学
  confirmedReason?: string; // 学习者认可时自己给的理由
}
export interface ProjectGoal {
  type: 'project_goal';
  at: string;
  text: string;             // 旧字段，意思不变（方向目标一句话）；新记录 = abilities[].ability 用“；”连起来（程序拼）
  title?: string;           // 方向目标短名，同时作项目名
  abilities?: GoalAbility[];
  orderHint?: string;       // 顺序参考，只作参考
  deadline?: string;        // YYYY-MM-DD（同时照旧另写 project_deadline）
  provisional?: boolean;    // 冷启动临时版；只在 true 时带
  talkSessionId?: string;   // 哪个畅谈交回的
  supersedes?: number;      // 主对话里上一条 project_goal 的行号；第一条不带
}
// 新记录（主对话正本）：本轮给模型的开场，可回查（§4.4）
export interface TurnContext { type: 'turn_context'; at: string; forLine: number; text: string }
```

- 新字段全是可选：旧形状（只有 `text`）的 `project_goal` 照样合法、照样能读（W3 的测试直接 `hub.record` 只带 `text` 的记录）。
- “当前方向目标” = 主对话里**最后一条** `project_goal`（不看 `supersedes`）；它之前的都算“已被取代”。不改旧行、不另写“已取代”记录。
- `turn_context` 不进派生索引的全文（`derived-index.ts` 的 `searchableText` 不加它）、不在对话界面显示（`thread-model.ts` 走 `default`）。

### 4.2 方向目标的读与写法（新文件 `src/core/goal.ts`）

| 函数 | 定死 |
| --- | --- |
| `currentGoal(records: NumberedRecord[]): { line: number; goal: ProjectGoal } \| undefined` | 主对话记录里最后一条 `project_goal` |

### 4.3 `settle_goal`（`studium.ts` `settleGoalTool`）

| 参数（zod 写给真模型看；程序核对在 `run` 里再做一遍，假模型不过 zod） | 说明 |
| --- | --- |
| `title: string` | 方向目标短名，几个字，同时作项目名 |
| `abilities: { ability: string; reason: string; confirmed_reason?: string }[]`（≥ 1） | 每块目标能力与为什么学；`confirmed_reason` 只在学习者自己说了认可理由时填 |
| `order_hint?: string` | 谈到的先后，只作参考 |
| `deadline?: string` | YYYY-MM-DD（同旧） |
| `provisional?: boolean` | 冷启动临时版填 `true` |
| `known?: { text: string; lines: number[] }[]` | W2 原样，不动 |

程序核对（任何一条不过 → `isError` 退回、什么都不写、畅谈不结束；全部先核再写）：

| # | 规则 | 退回说明（要点） |
| --- | --- | --- |
| 1 | 已有 `talk_ended` | 已经交回过了（同旧） |
| 2 | `title` 是字符串、`trim()` 后非空 | 要给 title |
| 3 | `abilities` 是数组且 ≥ 1 项；每项 `ability` `reason` 是字符串、`trim()` 后非空；`confirmed_reason` 给了就须是字符串（空白当没给） | 写明第几块缺什么；参数形状是 `{ title, abilities[{ability, reason}] }`（模型若交了旧的 `goal` / `project_name`，也是这条退回） |
| 4 | `order_hint` 给了须是字符串（空白当没给）；`provisional` 给了须是布尔 | — |
| 5 | `deadline` 同旧 | 同旧 |
| 6 | `known` 同 W2 | 同 W2 |

写（按顺序，同一时间戳 `at`）：

1. 主对话 `project_goal`：`text = goalText(abilities)`、`title`、`abilities`（`confirmed_reason` → `confirmedReason`，空的不带；字段只有这三个）、`orderHint?`、`deadline?`、`provisional: true`（只在真时带）、`talkSessionId`、`supersedes = currentGoal(主对话)?.line`（没有就不带）。
2. `project_title { title, source: 'goal' }`；有 `deadline` 再写 `project_deadline`（同旧）。
3. W2 的外部导入（同旧）。
4. 畅谈 `talk_ended { goal: text, title }`；主对话程序事实原句（“…方向目标是“<text>”，项目名改为“<title>”。”）；后台状态整理（同旧）。

畅谈加一个只读工具 `list_learned`（与主对话同一实现，§4.5）：设计里畅谈能读学过的记录，原型现在畅谈只有资料工具。

### 4.4 主对话：每轮新开、开场从记录重建

现状（查过）：主对话是一条无限长的连续会话——`hub.openConversation` 每次都带正本里最近的 `model_session` 续接凭据，进程活着时模型对话一直不关。设计要“上下文小、可随时换掉从记录重建”。最小做法（定死）：

| 项 | 定死 |
| --- | --- |
| 开关在哪 | `KindConfig`（`hub.ts`）加 `rebuild?: (sessionId: string, inputLine: number) => Promise<string>`；hub 只看这个开关，不看种类名（`src/core/hub.test.ts` 的 kinds 不带它，续接行为不变）。`Studium.kind('main')` 带它，其他种类不带 |
| 每轮 | 队列项记下这条输入在正本里的行号（`send` 里已有 `line`）。`runTurn` 发现 `rebuild`：① `text = await rebuild(id, line)` ② 追加 `turn_context { forLine: line, text }` ③ 关掉旧的模型对话（若有），新开一个、**不带** `resumeToken` ④ 发 `{ ...input, preface: text }` ⑤ 本轮结束（成或败）关掉并丢弃这个模型对话 |
| 中途插话 | 照旧交给本轮正在跑的模型对话（不带 `preface`） |
| `TurnInput`（`port.ts`） | 加 `preface?: string`；加导出函数 `modelText(input)` = （有 `preface`：`formatProgramFact(preface) + '\n\n'`）+（`program`：`formatProgramFact(text)`；学习者：`text`）。`fake.ts` 的 `seenText` 与 `claude-agent-sdk.ts` 的 `push` 都改用它。`input.text` 不含 `preface`（应答函数按 `input.text` 认话的旧测试不受影响） |
| 录带 | `recorder.ts` 照记整个 input（含 `preface`）；`replay.ts` 照旧只比 `text` |

`Studium.mainPreface(mainId, inputLine)` 的内容（顺序照写；不用“触发原因”“本闭环的单子”这类别的开场的标题字样）：

```text
主对话开场（程序每轮从记录重给；以这里为准，前面的轮次你看不到）
<describeGoal(当前方向目标)；没有写“方向目标：还没有”>
期限：<原 deadlineText 格式；没有写“没有记”>
── 最近的消息 ──
L<行> 学习者：<前 300 字>     （inputLine 之前最近 12 条 user_message / assistant_message / program_fact；助手写“你”，程序事实写“程序”）
── 路线记录 ──
最新路线决定 L<行>：<decision>（理由：<reason>）     （主对话最后一条 route_decision；没有写“还没有路线决定”）
- 卡 <cardId>（L<行>）：1「<title>」2「<title>」…，推荐第 <k> 项；学习者选了第 <j> 项 → 学习 <loopId> / 还没选     （最近 3 张）
```

理由：设计只要求“能从记录重建”，每轮重给是最直接的重建；主对话只做分类与转交，一轮里需要的就这三样，其余（学过什么、某次学习的状态）经 `list_learned` 按需读；不碰模型侧压缩、不依赖 SDK 续接文件。代价是每轮重复几百字开场，主对话默认低强度，可接受。
