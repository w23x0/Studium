# 1.4 读清单变成机器可查的权限矩阵

> 状态：建议（记录待用）。不作产品结论。

## 问题根据

| 观察 | 出处 |
| --- | --- |
| 12 个判断点的读清单是文档，装配器里靠手写代码遵守 | `../Harness设计/02-上下文资产格式.md` §6；`../../proto/studium/assemble.py` |
| 隔离红线（M09↔M15 互不读、M02/M03/M14 不读 M09、诊断记录不回灌）只靠人工审计，且是作者自审 | `../Harness设计/_research/审计-红队-发现.md`、`审计-权限表核对.md` |
| 实验 3 曾发现判断调用意外加载 MCP、破坏隔离 | `../Harness设计/_research/原型实验-3-发现.md` |

## 做法

| 步骤 | 内容 |
| --- | --- |
| 数据文件 | `proto/studium/readlist.toml`（标准库 `tomllib` 可读）：每个判断点列允许的槽位、必需 / 条件、缺料规则 |
| 装配按它生成 | `assemble.py` 改为通用函数：给判断点名，按矩阵取槽位、拼段落、缺必需项抛 `MissingInput` |
| 断言 | 每次调用前检查上下文里的段名 ⊆ 允许槽位；越界即拒发并记日志 |
| 测试 | 一个纯标准库测试：遍历判断点，断言红线（守卫读不到诊断记录、教学调用读不到上一轮诊断、M05 路线调用读不到对话本体……） |
| 文档 | `02` §6 的表由数据文件生成，只留一处定义 |

## 为什么值得

| 点 | 说明 |
| --- | --- |
| 护城河由代码保证 | "判断的隔离"是产品总览列的模型替代不了的第 4 项；现在靠人记，改后每次改提示词或装配都自动复查 |
| 阶段 6 第 4 步的输入 | 要不要引图框架，取决于分叉 / 并行时读清单能否管住；先把读清单变成数据，评估才有依据 |
| 便宜 | 一天工作量，无新依赖 |

## 风险与不确定

| 项 | 说明 |
| --- | --- |
| 双写漂移 | 矩阵与文档若各写一份必漂移；必须生成，不能手抄 |
| 槽位粒度 | 现在的槽位（场景、对话本体、守卫结果、策略知识）很粗；接 M07 / M08 / M09 后槽位要细到"M09 相关片"，矩阵设计要预留 |
| 只管输入 | 矩阵管"读什么"，管不了"模型在输出里偷偷推断了不该推断的"；那部分仍靠输出契约上锁 |
