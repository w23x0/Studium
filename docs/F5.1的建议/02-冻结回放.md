# 1.2 冻结回放：运行记录变成判断点的回归测试集

> 状态：建议（记录待用）。不作产品结论。

## 问题根据

| 观察 | 出处 |
| --- | --- |
| 提示词补丁要"模型变强时逐条试删"，但没有试删的办法 | `../../proto/README.md` §提示词补丁登记；`00` 核心原则 5 |
| 运行记录全部进 git，"以后可挖掘"但未启动 | `../../proto/runs/README.md`；`待确认项.md` P-01 |
| 判断只承诺"依据可核对"，不承诺"结论可复现"；一致率从未量过 | 产品总览 横切原则 4 |

## 做法

| 步骤 | 内容 |
| --- | --- |
| 冻结 | 每个运行目录的 `transcript.md`（截到第 N 轮）+ 当时的 `scene.md` 就是一份冻结输入；`turns/NNN/{guard,diagnosis}.md` 是当时的输出 |
| 回放 | `python3 -m studium.replay runs/<名> --point guard\|teach --model X`：对冻结输入重跑，写到 `replays/<名>/<日期-模型>/` |
| 比较 | 结构化字段先比（守卫每条主张的有 / 无、条件、强度；诊断记录的改线依据、未满足项编号）；文字段交 `compare.py` 盲评 |
| 用法 A：删补丁 | 去掉一条补丁 → 全部回放 → 结构化字段不变即可删 |
| 用法 B：换模型 | 新模型回放 → 与旧输出比 → 差异处人工看，判断是模型进步还是判断漂移 |
| 用法 C：一致率 | 同一输入同一模型跑 3 次 → 一致率低的主张说明验收范围写得含糊，反馈给 M05 设计 |

## 为什么值得

| 点 | 说明 |
| --- | --- |
| 隔离设计的红利 | 判断点无状态、输入由装配器决定，所以天然可回放；这是 agent 方案做不到的 |
| 横切原则 3 | 已记录实际执行模型，回放结果能标"哪个模型在哪份输入上怎么判" |
| 零新依赖 | 全是现有文件 + 标准库 |

## 风险与不确定

| 项 | 说明 |
| --- | --- |
| 只验"变没变" | 不验"对不对"；差异仍要人看 |
| 样本少 | 现有十几份运行，覆盖面窄；随第 3 步推进会积累 |
| 盲评偏差 | 用模型盲评文字段可能偏好某种风格（未验证） |
| 教学调用的回放意义有限 | 每轮输出会改变后续对话，只能回放"同输入的这一轮"，不能回放整条对话 |
