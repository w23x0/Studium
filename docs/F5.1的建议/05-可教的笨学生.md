# 1.5 可教的"笨学生"（只记录，不推进）

> 状态：**只记录，不推进**（产品负责人 2026-09-25）。与 `../Harness设计/00-技术方向确认.md`"不做多身份 / 角色扮演 agent、不用提示词角色"有张力，需要产品负责人拍板后才可能进入设计。不作产品结论。

## 想法

| 项 | 内容 |
| --- | --- |
| 动作 | 闭环里加一个学习者可选的动作"给 TA 讲"。TA 是一个便宜模型，只会说"没听懂，从头讲一遍""这一步为什么"，不评价对错、不判断 |
| 数据流 | 学习者对 TA 讲的内容进入讲解稿（`01-讲解稿与版本差异.md`）；强模型的教学调用只旁观、只诊断，不介入这段对话 |
| 隔离 | TA 不参与任何判断、不读诊断记录、不读 M09；只是面向学习者的**引出工具** |

## 依据

| 点 | 出处 |
| --- | --- |
| 教中学在"知道要教 + 有人追问"时效应最强 | `../Harness设计/_research/讲解式学习证据-发现.md` §1 结论 2、3 |
| 可教代理（teachable agent）有二十年 ITS 先例：Betty's Brain（Biswas 团队），学习者教一个虚拟学生、系统旁观 | 记忆中的先例，本文未联网核实 |
| 对 TA 讲比对系统讲的心理负担小，"被反复审视的感觉"（me-3）可能减轻 | 推测 |

## 张力与风险

| 项 | 说明 |
| --- | --- |
| 与技术方向的张力 | "不用提示词角色"原意针对系统内部判断分工；TA 是学习者面对的对象，不是判断者。这个区分是否成立，由产品负责人定 |
| TA 质量 | 幼稚问题若质量差，会把学习者带偏或激怒 |
| 一致性 | 学习者同时面对"系统"与"TA"两个说话者，产品立场（不贴标签、产出可见）要覆盖 TA 的话 |
| 成本与披露 | 多一路模型调用；学习者的讲解送到哪个服务须按横切原则 2 披露 |
