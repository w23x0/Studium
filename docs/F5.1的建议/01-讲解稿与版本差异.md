# 1.1 讲解稿与版本差异

> 状态：建议（产品负责人 2026-09-25 认可方向；尚未落入审查单）。不作产品结论。

## 问题根据

| 观察 | 出处 |
| --- | --- |
| 真人试用里学习者从未写出一段完整讲解，产出只有一两句或公式片段 | `../Harness设计/_research/原型实验-4-发现.md` §1 |
| 教学调用一给编号小问题，讲解就碎成问答；提示词禁止后仍难杜绝 | 同上 §2 判断 2 |
| 判断：根因不全在提示词，在**媒介**。聊天框催短答、历史往上滚、学习者看不到自己讲解的整体，也没有"我在写一份东西"的位置 | 本建议 |

## 做法

| 步骤 | 内容 |
| --- | --- |
| 开头 | 系统按验收范围建一份空白「讲解稿」：每条教学主张一节，只有标题（确认类主张不进稿子） |
| 学习者动作 | 在稿子里写、改、补；聊天只用来追问和补讲一小段 |
| 教学调用输入 | 稿子当前版本 + 与上一版的差异（不是"最近一句"）；追问指向稿子里的行号，像代码评审批注 |
| 守卫输入 | 稿子定稿 + 对话本体；要点覆盖、常见误解直接对稿核对 |
| M09 证据单位 | 某条主张 = 稿子第 N 版第 X 段 + 提示条件（独立 / 提示后 / 补讲后） |
| 复检 | 让学习者不看旧稿重写一节，两版做差异 → 天然的"含延迟"证据（配合 `03-证据强度当负债.md`） |

## 为什么值得

| 点 | 说明 |
| --- | --- |
| 教学目标 | 学习者拥有一份自己的东西，系统围着它批注；与"激发主动钻研 / 学习者带路"同向 |
| 证据 | 书面讲解有组织、利概念（`../Harness设计/_research/讲解式学习证据-发现.md` §2）；稿子比散落的对话片段更好核对 |
| 护城河 | 跨时间的记忆与证据（产品总览"设计取向"第 1 项）有了载体：同一节稿子跨闭环的差异就是学习轨迹 |
| 机制复用 | 版本链 = M14 已有概念；引用 = `02` 的"引用=链接"；等于把 M14 的能力提前搬进 M02 |
| 前沿位置 | "聊天 + 可编辑画布"已是主流交互，但把画布的版本差异当学习证据尚无先例（未联网核实，把握中等） |

## 风险与不确定

| 项 | 说明 |
| --- | --- |
| 口头 vs 书面 | 口头讲解更利迁移；稿子最好接语音转写来改，不只靠打字（me-4 已定语音经外接转写输入） |
| 稿子 vs 对话的证据分工 | 稿子是讲解证据；追问中的即时回答仍在对话本体，守卫要两处都看，读清单要加一项 |
| 学习者不动稿子 | 有人只在聊天里答；需要教学调用把"请写进稿子第 N 节"当作默认动作 |
| 产品层决定 | 学习者交互形态属产品决定，需落 M02 审查单后才算数 |

## 原型落法（v0 改动小）

| 项 | 做法 |
| --- | --- |
| 载体 | 运行目录下 `draft.md`；每轮结束存一份 `turns/NNN/draft.md`，差异用标准库 `difflib` 生成 |
| 学习者输入 | CLI 里学习者用编辑器改 `draft.md`；`loop` 每轮读文件、算 diff、拼进教学调用 |
| 装配 | `assemble.for_teach` 加"讲解稿（当前版 + 差异）"段；`for_guard` 加"讲解稿定稿"段 |
| 提示词 | `teach.md`【给学习者】的默认动作改为"请在稿子第 N 节写 / 改"，追问引用稿子行号 |
