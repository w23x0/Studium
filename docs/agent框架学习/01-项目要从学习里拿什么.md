# 项目要从 agent 框架学习里拿什么

> 状态：待定（2026-09-29 建）。本文不写结论，只列出项目需要学习来回答的问题。
> 背景：项目暂停期间，产品负责人自学 agent 框架原理，读 pi，再读 oh-my-pi（omp）。本文把学习引向项目要用的地方：每个问题都注明项目里现在怎么做、疑点在哪、读的时候看什么、答案会改动哪里。
> 疑点的出处是 `../Harness设计/00-技术方向确认.md` 文件头部的「待重审」一节。

## 1 骨架：流程由谁控制、守卫放在哪（先读）

| # | 项目需要回答的问题 | 项目里现在怎么做 | 疑点 | 读 pi / omp 时看什么 | 答案会改动 |
| --- | --- | --- | --- | --- | --- |
| 1.1 | 一轮对话里，流程由程序控制，还是由模型控制？两者的界线画在哪？ | 程序（状态机）决定何时调用哪个判断点；模型只在一次调用内决定读什么（原则 2、3；`proto/studium/loop.py`） | “模型只是判断函数，不是 agent”是从 ITS 研究推出来的，没有和 agent 框架的做法对照过 | agent 主循环怎么写；控制权什么时候交回程序；有没有钩子、事件可以插入程序逻辑（pi-agent-core，待核实） | 原则 2、3 |
| 1.2 | 守卫（独立核对“这段链闭合了没有”）在框架里算什么？ | 教学调用提议结束时，另起一次隔离调用（`guard.md`，`loop.py` 的 `_guard`） | 说不清它是循环的停止条件、外部钩子、子 agent，还是评审者（critic），也就难分析交互契约 | 框架有没有独立验证环节；编程 agent 里“做完没有”由谁判定（可能是模型自己停，加上人审阅，待核实）；omp 有没有加验证或子 agent | 原则 2；收口流程；交互契约 3.3 |
| 1.3 | 什么时候要隔离，再开一次调用？代价是什么？ | 教学、守卫、M05 各自是隔离调用；隔离的依据是“信息是否不同、是否自我确认”（原则 5） | 隔离的收益来自 ITS 与多 agent 文献，没在 agent 框架里看过子调用是怎么取舍的 | pi 是否刻意不内建子 agent，理由是什么（待核实）；omp 如果加了，为什么加 | 原则 2、5 |

## 2 上下文：每轮给模型什么

| # | 项目需要回答的问题 | 项目里现在怎么做 | 疑点 | 读 pi / omp 时看什么 | 答案会改动 |
| --- | --- | --- | --- | --- | --- |
| 2.1 | 每轮重新装配上下文，还是让会话消息往下累积？ | 每轮重新装配：这段链、M08 片、M09、守卫结果、带行号的完整对话（`assemble.py`） | 重装是为了隔离和可控，但它让模型“每轮失忆”；me-9 曾怀疑这是回复过长的原因（重放后被否定，见实验 9 §6 #4） | 会话怎么存、怎么续；上下文太长时怎么压缩（compaction）；会话树、分支怎么用（待核实） | `assemble.py`；待确认项 A-04 |
| 2.2 | 模型自己上一轮的判断和笔记，要不要带进下一轮？ | 诊断记录不放回下一轮（`assemble.py:4-6`），怕模型把自己的推断当成学习者的证据 | **没有实验过**当下的模型是否真会受到这种干扰；成熟框架可能有更好的处理 | 模型的思考内容、计划、笔记在轮与轮之间怎么处理；有没有区分“事实”和“模型的推断” | 原则 5；可能需要一个实验：回传与不回传对照 |
| 2.3 | 常驻放什么，按需读什么？ | 常驻索引，细节交给模型用三个只读工具翻（原则 2；`env.py`） | 这条借鉴自 Claude Code / pi，属于框架原理，但我们没弄懂它为什么成立、到什么规模会失效 | 系统提示放了什么、多长；项目说明文件（如 AGENTS.md）怎么加载；pi 的最小系统提示理念（待核实） | 原则 2；审查单清理 1.7 |
| 2.4 | 模型怎么指向证据？ | 对话带行号，守卫和记录用 `transcript.md:行号` 引用 | 这对应 Claude Code 指向代码行；应该从原理出发来定 | 框架里的引用、定位机制是什么（文件 + 行号、编辑时的锚点，omp 可能有相关改动，待核实）；它解决的是什么问题 | `guard.md`、`teach.md` 的记录格式 |

## 3 模型的行为：靠什么约束

| # | 项目需要回答的问题 | 项目里现在怎么做 | 疑点 | 读 pi / omp 时看什么 | 答案会改动 |
| --- | --- | --- | --- | --- | --- |
| 3.1 | 模型的行为，靠提示词约束，还是靠结构约束？ | 提示词只写定义与底线；原则 7 主张契约由结构保证，但具体结构还没设计 | 找不到纯结构的办法让回复在该停的地方停下（实验 9 §6 #4） | 框架里哪些行为交给提示词、哪些写进代码；系统提示为什么可以很短 | 原则 7 后半；交互契约 3.3 |
| 3.2 | 一轮什么时候结束、什么时候把话交还给人？ | 教学调用一次就输出整轮回复；“停在第一个取决于学习者回答的地方”写在 `teach.md` 里 | 编程 agent 的一轮是“模型不再调用工具就结束”，天然倾向一次做完 | 一轮结束的条件；用户中途打断、插话怎么处理；有没有让模型主动停下来问人的机制 | 交互契约；`loop.py` |
| 3.3 | 同一个框架换一个模型，行为差多少？怎么应对？ | `agent.run` 统一接口，后端有 claude -p / OpenAI 兼容 / Anthropic 三种 | 原则 7 说“提示词对不同模型效果不同”，没查过框架怎么处理 | pi-ai 的统一接口（待核实）；按模型分别调整的部分放在哪里 | `agent.py`；原则 6、7 |
| 3.4 | 工具要设计成什么样？学习场景需不需要写入类的工具？ | 三个只读工具；写入全部由程序做 | 不清楚工具集的大小和粒度该怎么取舍 | pi 为什么只用少量工具（待核实）；omp 加了哪些工具、为什么 | `agent.py`、`env.py` |
| 3.5 | skill 这种形式是原理还是约定？ | 教学工具仿照 skill 格式：描述常驻，正文按需读（`proto/skills/`） | 仿的是 Claude Code 的形式，没问过它为什么有效 | 框架怎么加载 skill、提示模板，模型怎么决定去读 | M03 教学工具 |

## 4 omp 相对 pi：针对性优化是怎么做出来的（读完 pi 再看）

学这一节的目的：看别人从一个极简框架出发，是**怎么判断要改什么**的。我们也要从一个通用的底子出发，改成适合学习的。

| 对 omp 的每一处改动都记下 | 为什么要记 |
| --- | --- |
| 改了什么，在哪一层（循环、上下文、工具、提示、界面） | 对应 §1 到 §3 的问题 |
