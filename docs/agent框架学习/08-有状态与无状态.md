# 有状态与无状态：取舍与按职责分界

> 状态：待定（2026-09-30 建）。产品负责人问“有状态 / 无状态的取舍”，联网核对后讨论，得出按职责分界的倾向。**参考材料，不作产品结论**；分界表未实验，现有实验支撑不了更精确的内容。落点：`../Harness设计/00-技术方向确认.md` 原则 1、2。

## 1 这个词指三层

| 层 | 有状态 | 无状态 | 业内倾向 |
| --- | --- | --- | --- |
| 外壳进程 | 外壳在内存里记着会话 | 外壳不记，状态全在外部日志；崩了换一个读日志接着干 | 无状态。Anthropic 托管 agent：外壳当“牲口”不当“宠物”，`wake(sessionId)` 重启；12-factor agents：每步是纯函数（状态 + 事件 → 下一步 + 新状态），可重放、好测试（该页作者自称“写着玩”，分量轻） |
| API | 服务器存对话（OpenAI `previous_response_id`） | 客户端每次发全部历史（Anthropic API） | 都可用；OpenAI 无状态时要回传加密思考，否则连续性悄悄丢失 |
| 模型的上下文 | 一条对话只追加 | 每次按状态重新拼 | **有分歧**；对项目要紧的是这一层 |

## 2 第三层的代价

| | 连续追加 | 每轮重装 |
| --- | --- | --- |
| 得到 | 保住上一轮思考（前面一字未改才保留，见 `02-pi与omp笔记.md` 2.1）；缓存命中；教学连贯 | 程序完全控制每轮看什么；上下文短；单轮可复现 |
| 付出 | 越长越不可靠（Chroma 2025-07，18 个模型，简单任务也一样）；错误推断留在上下文 | 思考与缓存每轮作废；连续性靠程序猜 |

## 3 “日志与上下文分开”的三种做法

| 谁 | 做法 |
| --- | --- |
| Anthropic 托管 agent（2026-04） | 会话日志在模型外、只追加；外壳用 `getEvents()` 从日志挑片段组成上下文；理由：“预测不了未来模型需要什么样的上下文编排”，所以不做不可逆的删改 |
| Manus（2025-07） | 上下文只追加、前缀稳定（缓存）；压缩只丢可找回的（丢网页正文留网址）；**报错留在上下文**：“模型看到失败会隐式更新判断” |
| Letta | 每步从数据库“编译”上下文，自称 stateful，实为每轮重装——各家用词不一 |

分开解决了“状态丢失”和“压缩不可逆”，但没解决核心矛盾：改动前面的内容，思考与缓存就作废。所以真正的旋钮是**在哪些时刻重装**。

## 4 对项目：按职责定连续还是重装（倾向，未实验）

产品负责人判断（2026-09-30）：追加 / 重装的边界就是要找的大小循环边界；现有双循环按闭环内外分，不够描述追加与重装，闭环内还要按职责分。日志与上下文分开 = 项目的“上下文资产为中心”（`05-讨论存档-回复过长与分析资产.md` §3），推荐模仿托管 agent：资产 = 会话日志（只追加），程序状态机 = 无状态外壳，进模型的上下文按职责从资产里挑。

判断尺子沿用原则 5 的隔离粒度（信息是否不同、是否自我确认）：这个职责要不要自己上一轮的判断？会不会被别人的推理带偏？

| 职责 | 上下文 | 理由 |
| --- | --- | --- |
| 教学调用（M02 / M03 表达 + M04 进行中诊断 + M10 策略） | 有状态：闭环开头装配一次，会话内只追加，太长再压缩 | 需要连贯；带着自己上一轮的判断是连续不是污染（`02` 2.2）；保住思考与缓存 |
| M04 闭环守卫 | 无状态：每次从资产装配，不看教学推理 | 核对的要拆（`02` 1.3，Cognition 2026） |
| M15 状态判断 | 无状态 | 输入是事实读数；原则 5 本就不读历史 |
| M05 路线（闭环外） | 无状态：从资产装配 | 每闭环一次，用跨闭环资产，不需要对话线 |

**教学会话怎么压、缓存怎么用（2026-09-30，倾向，未实验）**：

| 项 | 内容 | 依据 |
| --- | --- | --- |
| 缓存机制 | 前缀逐字节相同才复用；改动点**之后**全部重算，之前照常命中；没有“改中间而不重算后面”的机制（每个字的计算依赖前文），只有“追加代替修改”（对话中途系统消息、按消息调整力度） | claude-api 技能 `shared/prompt-caching.md` |
| 价格（Opus 5.5） | 输入 $4 / 百万；缓存读 $0.20（5%）；写入 5 分钟有效 1.25 倍、1 小时有效 2 倍；读取会重置计时 | 同上 |
| 有效期 | 教学会话按人的节奏走（常超 5 分钟），用 1 小时；重装的调用（守卫、M15、M05）只有固定开头可复用，差别小。只追加对我们省钱的理由弱于编程，更站得住的理由是保住上一轮思考。**文档确认与缓存无关**：思考块签名记录前文（系统提示、工具集、之前每条消息逐字节）并链接上一个思考块，服务器按签名核对，不看缓存（Mythos 5.1 不做此核对，但改历史仍重建缓存，二者独立）。2026-08-31 后注册的账号改历史直接 400，更早账号默认只记录；原型走 `claude -p` 每次新对话、不回传思考，暂不涉及 | 同上；claude-api 技能 `shared/model-migration.md`「Breaking change 3」；产品负责人 |
| 何时压 | 不随时压，涨到上限压一次（缓存与思考都只在前缀不变时保住） | CliffCompaction（arXiv 2609.26779，编程、Kimi / GLM） |
| 压什么 | 按需读进来的教材 / M08 片段原处还在，可删、留出处，但要用**服务器端上下文清理**（context editing，清工具结果），不能客户端自己删（删中间旧工具结果会让之后的思考全部作废）；**学习者原话不删不改写**（诊断按行号指回原话，`02` 2.4）；不专门做召回（模型几乎不用，arXiv 2609.20804；我们本有按需读） | 同上两篇；`model-migration.md`「Breaking change 3」；产品负责人：闭环任务明确，可删的东西明确，是优势 |
| 压缩时的取舍 | 官方安全的压缩是服务器端压缩或客户端“整段写成一份摘要”，都会改写原话；“压前面、留最近几轮原文”会让保留轮的思考作废。文档：边界处丢一次思考影响很小，所以真要压缩时接受那一次丢思考，学习者原话照留（原话也在资产里，可按行号再读）。对话中途追加系统消息（`role: system`）不破坏缓存与思考，是 `02` 3.1“程序按事件追加事实”的落地手段 | `model-migration.md`「Breaking change 3」 |
| 每轮重装的外部实测 | CCM（arXiv 2609.35540，2026-09-28）：每轮只给“原任务 + 模型自写记忆（1–1.4k token）+ 最新观察”。TerminalBench-2（89 题，各跑一次）：Opus 4.6 完成率 58.4% → 40.4%、Sonnet 4.6 42.7% → 31.5%；成本反而持平或更高（完整历史约 90% 输入走缓存，重装需多跑几轮）。**边界**：终端任务、4.6 一代；记忆由模型自写，我们的重装是程序按读清单从资产装配。**结论分寸**：对教学调用，“每轮重装”大概率不好；对守卫仍成立。属外部旁证，未做本项目对照（可用 me-9 同一输入比较重装 vs 连续） | 正文 Table 1、Table 5 |
| 上限 | 1M 是兜底不是目标；靠闭环设计让会话短、资产放模型外 | Chroma；arXiv 2609.20804（128k 时上下文管理几乎不改变行为） |
| 闭环实际规模（2026-09-30 估） | me-5 至 me-9（7–27 轮）：原型每轮重装的教学输入末轮 14k–42k；改成只追加，闭环末尾约 1.4 万 – 19 万（上界计入各轮输出含思考，偏大；未计工具读入内容）。离 1M 很远，只有最长的 me-6 上界越过服务器压缩默认线 15 万。轮间间隔中位 7–37 分钟，60%–90% 超 5 分钟、10%–30% 超 1 小时。原型 `cache_read` 基本为 0 | `proto/runs/me-*/calls.log`、`transcript.md`；`in` 含 `claude -p` 外壳开销 |

由此，原则 2 登记的矛盾（“连续”与“不回灌”难兼得）有了方向：“不回灌”只管守卫的独立，不管教学。即 `05` §5 #2 未试过的组合。M02 审查单写的是“不回灌”，改动需产品负责人确认。**2026-10-05 产品负责人已确认**：教学调用连续、只守卫独立，审查单已改，技术内容见 `../Harness设计/03-运行设计.md`「教学调用」（仍未在本项目实验）。

## 6 旁证与反例（只取原理层面）

| 来源 | 原理 | 适用边界 |
| --- | --- | --- |
| VibeMemBench（arXiv 2609.23570，2026-09） | ① 注入记忆的伤害主要来自篇幅而非内容（检索记录均 65 行 vs 人工提炼约 5 行；随机删行与删问题指令恢复效果相近）→ 旁证 §2 “越长越不可靠”，跨闭环交给模型的内容要提炼、不带原对话。② **反例**：同一条经验对弱模型有益、对强模型有害（118 次双向变化中 64 次方向由模型基线强弱决定）→ 给教学模型喂“怎么教”类操作经验不能默认有用 | 编程任务、可执行测试判对错；只测开源模型（无闭源前沿）；记忆是操作经验、开工前推入 1 条，未测按需读；验证经验的提升 95% 置信区间全部跨 0。**不能**用来支持或否定“学习者记忆”（关于学习者是谁的事实）。产品负责人判断：除原理层面的反例外用不上 |
| Hallucination as Context Drift（arXiv 2606.21666，2026-06；单作者） | 多 agent 每步全量广播上下文：分歧最小、幻觉最多（0.49 → 0.66），即收敛到同一个错误认识。评估警告：守卫与教学结论一致不等于都对，二者上下文越接近，一致越不说明问题 | Claude Haiku 4.5、旅行规划 n=30；子任务独立的软件规划中不出现；幻觉由模型评委判定。产品负责人判断：信息一般 |
