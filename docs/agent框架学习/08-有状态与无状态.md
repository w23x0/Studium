# 有状态与无状态：取舍与按职责分界

> 状态：待定（2026-09-30 建）。产品负责人问“有状态 / 无状态的取舍”，联网核对后讨论，得出按职责分界的倾向。**参考材料，不作产品结论**；分界表未实验，现有实验支撑不了更精确的内容。落点：`../Harness设计/00-技术方向确认.md` 原则 1、2。

## 1 这个词指三层

| 层 | 有状态 | 无状态 | 业内倾向 |
| --- | --- | --- | --- |
| 外壳进程 | 外壳在内存里记着会话 | 外壳不记，状态全在外部日志；崩了换一个读日志接着干 | 无状态。Anthropic 托管 agent：外壳当“牲口”不当“宠物”，`wake(sessionId)` 重启；12-factor agents：每步是纯函数（状态 + 事件 → 下一步 + 新状态），可重放、好测试（该页作者自称“写着玩”，分量轻） |
| API | 服务器存对话（OpenAI `previous_response_id`） | 客户端每次发全部历史（Anthropic API） | 都可用；OpenAI 无状态时要回传加密思考，否则连续性悄悄丢失 |
| 模型的上下文 | 一条对话只追加 | 每次按状态重新拼 | **有分歧**；对项目要紧的是这一层 |

## 2 第三层的代价

| | 连续追加 | 每轮重装 |
| --- | --- | --- |
| 得到 | 保住上一轮思考（前面一字未改才保留，见 `02-pi与omp笔记.md` 2.1）；缓存命中；教学连贯 | 程序完全控制每轮看什么；上下文短；单轮可复现 |
| 付出 | 越长越不可靠（Chroma 2025-07，18 个模型，简单任务也一样）；错误推断留在上下文 | 思考与缓存每轮作废；连续性靠程序猜 |

## 3 “日志与上下文分开”的三种做法

| 谁 | 做法 |
| --- | --- |
| Anthropic 托管 agent（2026-04） | 会话日志在模型外、只追加；外壳用 `getEvents()` 从日志挑片段组成上下文；理由：“预测不了未来模型需要什么样的上下文编排”，所以不做不可逆的删改 |
| Manus（2025-07） | 上下文只追加、前缀稳定（缓存）；压缩只丢可找回的（丢网页正文留网址）；**报错留在上下文**：“模型看到失败会隐式更新判断” |
| Letta | 每步从数据库“编译”上下文，自称 stateful，实为每轮重装——各家用词不一 |

分开解决了“状态丢失”和“压缩不可逆”，但没解决核心矛盾：改动前面的内容，思考与缓存就作废。所以真正的旋钮是**在哪些时刻重装**。

## 4 对项目：按职责定连续还是重装（倾向，未实验）

产品负责人判断（2026-09-30）：追加 / 重装的边界就是要找的大小循环边界；现有双循环按闭环内外分，不够描述追加与重装，闭环内还要按职责分。日志与上下文分开 = 项目的“上下文资产为中心”（`05-讨论存档-回复过长与分析资产.md` §3），推荐模仿托管 agent：资产 = 会话日志（只追加），程序状态机 = 无状态外壳，进模型的上下文按职责从资产里挑。

判断尺子沿用原则 5 的隔离粒度（信息是否不同、是否自我确认）：这个职责要不要自己上一轮的判断？会不会被别人的推理带偏？

| 职责 | 上下文 | 理由 |
| --- | --- | --- |
| 教学调用（M02 / M03 表达 + M04 进行中诊断 + M10 策略） | 有状态：闭环开头装配一次，会话内只追加，太长再压缩 | 需要连贯；带着自己上一轮的判断是连续不是污染（`02` 2.2）；保住思考与缓存 |
| M04 闭环守卫 | 无状态：每次从资产装配，不看教学推理 | 核对的要拆（`02` 1.3，Cognition 2026） |
| M15 状态判断 | 无状态 | 输入是事实读数；原则 5 本就不读历史 |
| M05 路线（闭环外） | 无状态：从资产装配 | 每闭环一次，用跨闭环资产，不需要对话线 |

由此，原则 2 登记的矛盾（“连续”与“不回灌”难兼得）有了方向：“不回灌”只管守卫的独立，不管教学。即 `05` §5 #2 未试过的组合。M02 审查单写的是“不回灌”，改动需产品负责人确认。

## 6 旁证与反例（只取原理层面）

| 来源 | 原理 | 适用边界 |
| --- | --- | --- |
| VibeMemBench（arXiv 2609.23570，2026-09） | ① 注入记忆的伤害主要来自篇幅而非内容（检索记录均 65 行 vs 人工提炼约 5 行；随机删行与删问题指令恢复效果相近）→ 旁证 §2 “越长越不可靠”，跨闭环交给模型的内容要提炼、不带原对话。② **反例**：同一条经验对弱模型有益、对强模型有害（118 次双向变化中 64 次方向由模型基线强弱决定）→ 给教学模型喂“怎么教”类操作经验不能默认有用 | 编程任务、可执行测试判对错；只测开源模型（无闭源前沿）；记忆是操作经验、开工前推入 1 条，未测按需读；验证经验的提升 95% 置信区间全部跨 0。**不能**用来支持或否定“学习者记忆”（关于学习者是谁的事实）。产品负责人判断：除原理层面的反例外用不上 |
