# 学习场景的开源 agent 项目（"教学版 omp"候选）

> 状态：待定（2026-09-29，子代理调研，主 agent 未逐条复核）。**参考材料，不作产品结论**。星数与更新时间是 2026-09-29 的 GitHub 快照；各项目自报的效果数据都没有复跑。
> 总判断：没找到改造通用 agent 循环本身的"教学版 omp"。能学的做法有三类：① 在循环外面加确定性的掌握度和判分状态；② 按模式给工具加门控；③ 用外部图或状态机管住模型。

## 1 精读候选

| 优先 | 项目 | 规模 / 更新 | 针对教学改了什么 | 证据（自报） | 读哪里 |
| --- | --- | --- | --- | --- | --- |
| 1 | [DeepTutor](https://github.com/HKUDS/DeepTutor)（HKUDS） | 40.5k 星，2026-09-27 | Mastery Path：`policy.py` 是"纯决策、不调 LLM"的掌握门（记忆类和步骤类要求近期加权正确率 ≥ 0.9；概念类要求学生复述，由 tutor 判定）；`next_objective()` 从掌握情况算出下一步；outline / study / review 三种模式，工具在调用时检查模式（因为模式可能在一轮中途切换）；提一道题就结束这一轮；学习者自称掌握和系统判定掌握分开记 | [arXiv 2604.26962](https://arxiv.org/abs/2604.26962)：TutorBench 上个性化指标 +10.8% | `learning/policy.py`、`capabilities/mastery/mode.py`、`loop.py`。**对照点**：概念类"通过"由 tutor 自己判定，不是隔离调用 |
| 2 | [CogniFlow](https://github.com/sohan1611/CogniFlow) | 1 星，黑客松作品，2026-09-16 | LangGraph 状态图，加 BKT（贝叶斯知识追踪）和先修图；连续失败时找最弱的前置技能，补完再回来；模型只提议（`AdaptationDecision`），`guard.py`（142 行）用规则裁决，违规就覆盖，并记录覆盖率；学生的错和系统故障分成两种类型，系统故障不扣掌握度；LLM 只用在 3 处 | 80 个"植入先修缺口"的模拟学生做消融：找到缺口 57.5%（对照组 0%），尝试次数少 19%，误重定向 7.5% | 整仓；`guard.py`、`eval/`。评估方法可借给 `docs/学习者模拟与评估/` |
| 3 | [mastery-tutor](https://github.com/fanfanfanfanfan626/mastery-tutor) | 3 星，2026-09-14 | 两个 Agent Skill，状态在 `.mastery/` 追加式证据日志；`teaching_turn.py` 机器校验每个教学回合（一个心智动作、术语不超过 3 个等）；同一时刻只有一个组件能写学习状态；掌握要求独立检索、迁移、延迟复习三类证据；掌握后再失败标"脆弱" | 证据分 E0–E4 五级，写明"研究启发，非效果已证" | `docs/architecture.md`、`docs/evaluation.md` |

## 2 其他

| 项目 | 要点 | 价值 |
| --- | --- | --- |
| [open-learning-ai-tutor](https://github.com/mitodl/open-learning-ai-tutor)（MIT） | 先用 LLM 把学生的话分成 12 类，再用确定性规则映射成教学意图，意图进提示词；循环本身很普通 | "外部图管教学策略"的最小实例（约 1500 行）；[arXiv 2410.03781](https://arxiv.org/abs/2410.03781)，17 人样本 |
| [pi-learning-tutor](https://github.com/majorgilles/pi-learning-tutor) | pi 扩展：`pi.on("tool_call")` 拦截，学习模式下禁止改文件，让学生自己写代码；有 `/learn` 等命令 | 在 pi 上改造教学的最小实现 |
| [pi-tutor](https://github.com/denismrvoljak/pi-tutor) | pi 扩展：`before_agent_start` 注入学习者档案；状态全是 markdown 文件 | "markdown 当状态"的对照 |
| [GenMentor](https://github.com/GeminiLight/gen-mentor) | 9 个分工 agent 组成的流水线，含模拟学习者反馈；没有掌握门 | 低优先；[arXiv 2501.15749](https://arxiv.org/abs/2501.15749) |
| [cc-self-train](https://github.com/zainnab-sparq/cc-self-train) | 用 Claude Code 的 hook 观察学生参与，按两种时间尺度调整脚手架 | hook 观察参与信号的做法可参考 |
| [tutor-runtime-lab](https://github.com/hmhm2333/tutor-runtime-lab) | 在 pi 上做教学 runtime：模型只提候选，评分和状态迁移由确定性服务负责 | 成熟度低（1 次提交） |
| [TutorGym](https://github.com/Teachable-AI-Lab/tutor_gym) | 评测框架；摘要称 LLM 标记错误步骤不比随机好 | 对"模型自己判分"的反证线索；[arXiv 2505.01563](https://arxiv.org/abs/2505.01563) |

只作线索、未列入：AskTIM（仓库 404）、OpenTutor、OATutor（不含 LLM）、IntelliCode / AgentTutor（未找到代码）。
