## 1 设计理念（作者原话）

| 框架 | 作者 | 理念 | 出处 |
| --- | --- | --- | --- |
| pi | Mario Zechner | 前沿模型已被强化训练成编程 agent，"本来就会"；外壳越接近零越好：4 个工具，系统提示不到 1000 token；不内建子 agent、计划模式、MCP、待办；精确控制进入上下文的内容 | [设计文章 2025-11](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/) |
| pi（后期） | 同上 | 审查 agent 能抓局部问题，抓不到架构问题；人要读关键代码、做架构决定 | [演讲整理](https://mlnotes.substack.com/p/slop-speed-and-discipline-hard-truths) · [视频](https://www.youtube.com/watch?v=RjfbvDXpFls) |
| omp | Can Bölük | 模型常常不是不懂，而是"表达不出来"（"怪飞行员，其实是起落架的问题"）；外壳几乎和模型一样重要。只换编辑格式，16 个模型大多变好，最差的从 6.7% 升到 68.3% | [The harness problem 2026-02](https://stencil.so/blog/the-harness-problem) |
| omp（后期） | 同上 | "强化训练只教会了它练过的形状"；格式越嵌套、越花哨越容易错；工具一多，原生工具调用更顺手 | [The Minutiae of Tool-calling 2026-08](https://blog.can.ac/2026/08/03/the-minutiae-of-tool-calling/) |

"agent"的通行说法：模型在循环里调用工具、直到完成目标（Anthropic《Building effective agents》2024-12；Simon Willison 2025-09）。Anthropic 同文区分 **workflow**（程序按预设路径编排模型和工具）与 **agent**（模型自己决定流程）。产品负责人的看法：两者是同一条"灵活性"轴，没有新旧之分；业内偏向 agent 端是因为编程和通用智能需要。

## 3 对问题清单的回答

| # | 回答 | 出处 |
| --- | --- | --- |
| 1.1 | pi 默认由模型控制：有工具调用就执行、结果喂回模型，直到某次回复不再调用工具。没有最大步数限制。程序在每一步的边界上可以插手：`finishTurn`（结束或继续）、`beforeToolCall` / `afterToolCall`（拦截、终止）、`transformContext`（发给模型前改写消息）、steering / follow-up（中途插话，下一步前注入）。这些钩子设计文章里没写，是后来加的 | `agent-loop.ts:174-316`、`:389`、`:724`、`:829` |
| 1.2 | 待讲。线索：omp 有 advisor（旁路审阅模型，读主对话的增量，按严重程度把意见注入主对话） | omp `docs/advisor-watchdog.md` |

## 4 omp 相对 pi 的改动

| 改了什么 | 哪层 | 动机 / 证据 | 三分法 | 换到学习场景 |
| --- | --- | --- | --- | --- |
| hashline 编辑：读文件时每行带 2–3 字符内容哈希，编辑时引用哈希，不复述原文 | 工具 | 复述原文时空格错一个就失败；实验见上 | 主要是原理（降低表达负担），与训练无关 | 同一思路：对话带行号、守卫按行号引用 |
| 31+ 内置工具（LSP、调试器、持久内核、多格式读取） | 工具 | 给模型可核对的反馈 | 针对编程 | 大多不需要 |
| 子 agent、按角色路由模型 | 循环 / 模型 | 并行、分工 | 原理 + 编程 | 待 1.3 |
| advisor 旁路审阅 | 循环 | 见 1.2 | 待定 | 待 1.2 |
| 40+ 模型提供商 | 模型接口 | 覆盖面 | 工程 | 我们只做两个模型，见 §6 |

代价：一份第三方测试（Composio，30 个任务，DeepSeek V4 Flash）里 pi 通过 20 个，omp 通过 17 个，omp 单次成功成本约为 pi 的 3.7 倍。单一二手来源，样本小。[来源](https://composio.dev/content/pi-vs-omp)

## 5 三分法小结：两人对"拟合"的态度

| | pi 作者 | omp 作者 |
| --- | --- | --- |
| 态度 | 承认靠拟合，主动利用：模型练过什么就给什么 | 认为拟合脆：换一个没练过该格式的模型就失败，外壳按"出错面"设计 |
| 厂商公布了什么 | 厂商会公布自家训练过的工具与格式（Anthropic 官方定义的编辑、命令行工具；OpenAI 提示词指南里的补丁格式）；其他格式的表现不公布，只能实验 | |
