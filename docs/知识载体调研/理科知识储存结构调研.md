# 理科知识储存结构调研

> 面向数学、物理等理科内容,梳理「知识如何被**组织、存储、检索**」的结构与系统。
> 侧重**储存结构本身**——库里存什么、用什么结构组织、如何索引与查询——而非单一的表达形式。
> 每条均带 arXiv 编号或官方地址,可直接核验。整理日期:2026-08-09。

## A. 形式化数学库(机器验证、显式依赖)

### A1. 数学库本体与结构
- **The Lean mathematical library**(mathlib)— arXiv:[1910.09336](https://arxiv.org/abs/1910.09336),2019,mathlib 社区。Lean 的标准库,覆盖代数、分析、拓扑等,是当代最大的形式化数学库之一。
- **The Network Structure of Mathlib** — arXiv:[2604.24797](https://arxiv.org/abs/2604.24797),2026。把 mathlib 当依赖图分析,发现开发者平均只用导入范围的 1.6%——大规模库的「引用坍缩」现象。
- **Growing Mathlib: maintenance of a large scale mathematical library** — arXiv:[2508.21593](https://arxiv.org/abs/2508.21593),2025。维护策略:弃用机制、linter,应对库的高速增长。
- **Mizar Mathematical Library**(MML)— arXiv:[1107.3212](https://arxiv.org/abs/1107.3212)(许可证)、[1107.4721](https://arxiv.org/abs/1107.4721)(细粒度依赖, mizar-items 系统)。
- **Metamath Zero: The Cartesian Theorem Prover** — arXiv:[1910.10703](https://arxiv.org/abs/1910.10703),2019。极简验证内核;Metamath 的 set.mm 库是目前最大的单文件库之一。
- **The Lean mathematical library** 之外,统一格式方向:**Experiences from Exporting Major Proof Assistant Libraries** — arXiv:[2005.03089](https://arxiv.org/abs/2005.03089),2020,Kohlhase & Rabe。把六个证明助手的库统一翻译成 OMDoc/MMT。

### A2. 库的依赖图与前驱选择(检索 = 找对公理/定理)
- **Premise Selection for Mathematics by Corpus Analysis and Kernel Methods** — arXiv:[1108.3446](https://arxiv.org/abs/1108.3446),2011。前驱选择的奠基工作之一,构造**证明依赖知识库** + 核方法学习。
- **Magnushammer: A Transformer-Based Approach to Premise Selection** — arXiv:[2303.04488](https://arxiv.org/abs/2303.04488),2023。对比检索式前驱选择,胜过 Sledgehammer。
- **Machine-Learned Premise Selection for Lean** — arXiv:[2304.00994](https://arxiv.org/abs/2304.00994),2023。在 Lean 4 里实现的在线随机森林,以 suggest_premises 策略暴露。
- **Premise Selection for a Lean Hammer** — arXiv:[2506.07477](https://arxiv.org/abs/2506.07477),2025。LeanPremise + LeanHammer,Lean 第一个端到端 hammer。
- **Combining Textual and Structural Information for Premise Selection in Lean** — arXiv:[2510.23637](https://arxiv.org/abs/2510.23637),2025。图增强方法:文本嵌入 + 依赖图上的 GNN。
- **Dependencies in Formal Mathematics: Applications and Extraction for Coq and Mizar** — arXiv:[1109.3687](https://arxiv.org/abs/1109.3687),2011。依赖提取方法对比(Coq 与 Mizar)。
- **MathlibPR: Pull Request Merge-Readiness Benchmark for Formal Mathematical Libraries** — arXiv:[2605.07147](https://arxiv.org/abs/2605.07147),2026。LLM 判断 mathlib PR 是否可合并。

### A3. 自动形式化(把非形式数学变成库内容)
- **Autoformalization with Large Language Models** — arXiv:[2205.12615](https://arxiv.org/abs/2205.12615),2022。LLM 自动形式化的早期里程碑。
- **Autoformalization in the Era of Large Language Models: A Survey** — arXiv:[2505.23486](https://arxiv.org/abs/2505.23486),2025。综述。
- **Theory-Level Autoformalization: From Isolated Statements to Unified Formal Knowledge Bases** — arXiv:[2607.13292](https://arxiv.org/abs/2607.13292),2026。立场论文:主张形式化**整部理论**而非孤立命题——直接相关「库的结构粒度」。
- **ProofNet: Autoformalizing and Formally Proving Undergraduate-Level Mathematics** — arXiv:[2302.12433](https://arxiv.org/abs/2302.12433),2023。本科数学基准。
- **MathAtlas: A Benchmark for Autoformalization in the Wild** — arXiv:[2605.14061](https://arxiv.org/abs/2605.14061),2026。研究生级基准,依赖深度越深模型越差。

## 观察与未闭合问题

1. **形式化库的依赖图是唯一「既真实又机器可查」的结构**。premise selection 这一整条线都在消费它。理科知识储存若追求可验证,这是最成熟的地基。
2. **教学结构(前驱、知识态)与本体/图谱(实体、公式)目前是两张皮**。MaRDI 管数学对象与公式,ALEKS/KST 管学习者状态,尚无系统把两者接起来。
3. **公式是理科特有的「对象」,储存结构绕不开它**:MathML/OpenMath、DLMF、Wikidata 公式实体、MIR 的公式检索,构成一条独立支线。
4. **图与向量的混合(RAG/GraphRAG)是当前的工程主流,但图何时真的加分尚无共识**(见 F 族 2506.05690、2502.11371)。
5. **自动形式化的粒度之争**:孤立命题 vs 整部理论(2607.13292)。这直接决定「库」应该被组织成什么形状。
6. 你已有的《几个方向.md》覆盖了**表示形式**(类型论、因果、概率程序、VSA、SAE 等);本文档补的是**储存与检索结构**这一层。两者合起来才是「载体」全貌。

1. [Experiences from Exporting Major Proof Assistant Libraries](https://arxiv.org/abs/2005.03089)——看六个库如何被统一,最直接讲「库的结构」
2. [The Network Structure of Mathlib](https://arxiv.org/abs/2604.24797)——大规模库的真实依赖结构
3. [A Query Language for Formal Mathematical Libraries](https://arxiv.org/abs/1204.4685)——库的查询语义
4. [Knowledge Spaces and Learning Spaces](https://arxiv.org/abs/1511.06757)——教学侧结构的最严整理论
5. [Theory-Level Autoformalization](https://arxiv.org/abs/2607.13292)——库的粒度之争
