# Harness 设计

> **本层是「组合层设计」**：只回答“模块之间怎么传上下文”；**产品结论以 `../模块需求设计/模块审查单/` 为准，本层不新增产品结论**（冲突时以审查单为准）。
>
> Studium 的核心挑战是**上下文组合 + 图式运行**。技术方向（2026-09-23）：按智能辅导系统（ITS）结构构建，确定性循环程序 + 在固定判断点隔离调用大模型；不用 DSH，不做多身份 agent。
>
> 模块拆分只是方便设计；真正围绕的是主要模块之间的**上下文资产**如何在交接点选取、组合、标记证据并流动。

## 核心方向

- **上下文组合工程**：模块职责靠不同的上下文组合方式区分，而不是靠提示词角色设定（M04 与 M02 分开选型：M04 看分析判断、M02 看教学行为，见 M02 审查单；M02 必须先拿 M04 的分析）。
- **图式运行**：M02/M03/M04/M10 是可回流、可分支的图中的职责，不是固定串行流水线。
- **上下文资产**：模块间传递的是**便于推理的文字推理链**——带来源、证据关系、因果，逐条可组合，不是 JSON、不是无结构自由文本、也不是人类可读的成段陈述。定型表述见 [00-技术方向确认.md](./00-技术方向确认.md) §2。
