# Harness 设计

> Studium 的核心挑战是**上下文组合 + 图式运行**。技术方向已确认路径 3（基于 DSH SDK Runtime 全权定制 Studium runtime），DSH 只是承载基础能力的 runtime 底座，不是设计结论本身。
>
> 模块拆分只是方便设计；真正围绕的是主要模块之间的**上下文资产**如何在交接点选取、组合、标记证据并流动。

## 核心方向

- **上下文组合工程**：模块职责靠不同的上下文组合方式区分，而不是靠提示词角色设定（M04 用高级模型、M02 用低级模型；M02 必须先拿 M04 的分析）。
- **图式运行**：M02/M03/M04/M10 是可回流、可分支的图中的职责，不是固定串行流水线。
- **上下文资产**：模块间传递的是**便于推理的文字推理链**——带来源、证据关系、因果，逐条可组合，不是 JSON、不是无结构自由文本、也不是人类可读的成段陈述。定型表述见 [00-技术方向确认.md](./00-技术方向确认.md) §2。
