# 原型实验 6：纵向写足后的真人试用 me-6（发现）

> 状态：现行（2026-09-27）。组合层证据；检验实验 5 后的改动（纵向按学段写足、纵深主动挖、讲过的内容须非复述取证）。
> 原型：`../../../proto/`。运行 `proto/runs/me-6`；学习者 = 产品负责人本人。场景由 M05 设计，目标“深入学习牛顿第二定律”，自述里临时写入 me-5 做过的题（代替 M09）→ M05 选了**变质量系统**。
> 测试面很窄：单学科、单个学习者、单个闭环、冷启动（产品负责人提醒，结论按此打折）。

## 1 结果

| 项 | 内容 |
| --- | --- |
| 轮数 / 时长 | 21 轮，09-26 17:29 → 09-27 02:10（约 8.7 小时，含多段离开：最长约 2 小时）；未提议结束，停在主张 2 的边界要点（下次开场请学习者整段讲） |
| 主张 1【确认】动量守恒 + 相对速度 | 花了 4 轮（含一道变式）；题面“船连人总质量 M”有歧义，学习者质疑“挖坑”，系统承认题面不清 |
| 主张 2【结构】变质量方程 | 推导由学习者在引导下亲手完成；系统主动挖了三处纵深：漏燃料预测（相对速度为 0 时是否加速）、从燃气一侧独立求推力（不借用方程）、伽利略变换下 F = d(mv)/dt 的参考系依赖 |
| 主张 3【近迁移】两小车对比 | 未到 |
| 学习者状态 | 第 15 轮起明显下降：“不太想算了”“大脑不怎么能深入思考”“中途离开，细节连不到一起”“我想不明白了”。系统在第 15–21 轮连续说“做完这一小步就停”，却又追了 4 轮，第 21 轮才直接讲出原因 |
| 系统造成的混乱 | 三处：题面歧义（M 含不含 m）；字母 F 在两处指不同的东西（第 8–10 轮）；带撇 / 不带撇的约定没说清（第 15 轮）。学习者：“这个属于我不知道，你没讲清楚” |
| 教学形态 | 全程是引导式小步追问；成段讲解只出现在学习者卡住后（第 9 轮讲清 F 与 m 指谁、第 21 轮讲清参考系原因） |
| 安全分类器 | 第 2 轮回复被安全分类器截断（误判，推测与“火箭”相关词有关，不确定），自动重调成功；两次调用实际模型都是 opus |
| 调用 | 每轮约 40–80 秒、输出 4–6k token |

## 2 判断

| # | 判断 | 把握 |
| --- | --- | --- |
| 1 | **纵深主动挖生效**：边界、预测、换参考系都是系统主动抛出的，内容质量明显高于 me-5 | 较高 |
| 2 | **非复述取证生效**：推力从燃气一侧重新求、换参考系检验，都是“讲过后换方式再表现” | 较高 |
| 3 | **只有“引导”一种教学形态**：规则（作答前不给答案、先讲后追问、脚手架最后才自己讲）让直接讲授成了最后手段。对基础好的学习者，缺少一种高信息密度的成段讲授（产品负责人称“吸取状态”，“像好书一样”）。学习理论里“结构级理解不足 → 偏输入讲解”“输入与练习不可替代”本来支持输入环节，现在被压成了只在卡住时才用 | 较高；是否加这种形态属产品决策 |
| 4 | **状态下降无人处理**：M15 未接入；会话内只有教学侧自己“降一点强度”，且说停不停。产品负责人提议：状态下降时**动态切到一个更简单的闭环**，比缩小当前闭环目标好（现行设计：疲劳退化 → M10 降载、M05 只在会话外留恢复期） | 现象确定；处理方式属产品决策 |
| 5 | 系统自己的记号和题面不严谨，制造了学习者的困惑；产品负责人分不清是自己状态不好还是教学质量不好——两者在第 8–21 轮混在一起 | 较高 |
| 6 | 【确认】主张花了 4 轮、还加了变式：“有行为证据即可”没被执行到位 | 中 |
| 7 | 闭环内冒出的问题（如变质量）可成为新闭环的起点；物理与数学高度绑定，可以从物理闭环出发学数学（现实问题找理论解，适合工科）——产品负责人提出，尚无设计 | 想法，待设计 |
