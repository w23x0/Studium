# 权限表逐条核对

> 用法：`claude -p --permission-mode bypassPermissions "$(cat 本文件)"`

---

你是 Studium 项目的核对员。任务：把 Harness 设计里的**读/写权限表**与产品基线的**关系矩阵**逐条比对，找出不一致。

## 读什么

1. `docs/Harness设计/01-容器与路线设计.md` 的「**读范围 = 集中权限表**」一节（待核对草案）。
2. `docs/实现基线/模块关系提取.md` —— 尤其「正向关系矩阵（关系台账）」「禁止关系矩阵」「数据对象归属表」。
3. `docs/实现基线/模块检查点.md` 的「全局不变量」。
4. 产品权威：`docs/模块需求设计/模块审查单/` 各模块的「输入」「输出」「边界和信息流」段。

## 怎么核对

对权限表里的**每一行（每个模块）**，逐条检查：

| 检查项 | 说明 |
|---|---|
| 可写 | 该模块写的东西，产品文档承认归它所有吗？有没有写到别人区里？ |
| 可读 | 该模块读的每个来源，产品文档真的允许吗？ |
| 漏读 | 产品文档要求它能读、但权限表里漏了的？ |
| 越权读 | 权限表给了、但产品文档禁止的？ |
| 红线 | 5 条红线段是否都被权限表正确体现？ |

## 硬性要求

- **每条结论带证据**：`文件:行号` 或原文引用。
- **输出格式**：一张「不一致清单」表：`模块 | 权限项 | 权限表说的 | 基线说的 | 判定（漏/越权/错） | 证据`。
- 找不到不一致的地方也要写「已核对一致」。
- **不修改任何文件**（包括不要改那张表）。

## 产出

写到 `docs/Harness设计/_research/审计-权限表核对.md`，≤400 行，面向 agent 阅读。
