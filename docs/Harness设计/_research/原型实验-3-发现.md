# 原型实验 3：M05 设计闭环（发现）

> 状态：现行（2026-09-23）。组合层证据；对应 `../00-技术方向确认.md` §实施顺序 第 2 步“闭环设计”，通过标准见该表。
> 原型：`../../../proto/`。运行 `proto/runs/design-a-kernel`、`design-b-newton`。

## 1 接法

| 环节 | 做法 |
| --- | --- |
| 调用 | `studium.design`：一次隔离调用（`prompts/design.md`），读学习目标、学习者自述（条件项，缺则按学段假定）、是否冷启动；v0 无 M09，一律冷启动 |
| 产出 | `scene.md`（与手写场景同格式）· `design.md`（含设计说明、下一闭环候选）· `route.md` 首条“闭环设计”记录 |
| 约束 | 前置逐项标来源（自述 / 假定），离不开的假定前置设【确认】主张；冷启动 ≤3 条、否则 ≤5 条；至少一条【结构】；证据须只看对话可判；目标笼统时只取最先该学的一块 |
| 衔接 | `loop` / `sim` 省略 `--scene` 时读 `--run` 目录里 M05 设计好的场景，开场白取学习目标 |

## 2 结果

| 项 | A 核（有自述） | B 牛顿（笼统目标、无自述） |
| --- | --- | --- |
| 场景 | 3 条：定义与判断 → 用矩阵求核 → 证明是子空间；手写版的“定义动机”“核与单射”挪入下一闭环候选 | 3 条：确认加速度 → 合力决定加速度（一条含三个表现）→ 一维 F=ma；第三定律、斜面、连接体入候选 |
| 前置来源 | 几乎全来自自述 | 全为假定，只为“加速度定义”设【确认】 |
| 运行 | 10 轮守卫通过（手写版 12 轮） | 8 轮守卫通过 |
| 守卫拦下 | 2 次，均在主张 3：漏数乘封闭；补上但在答案展示后，条件不达标 | 2 次，均在主张 3：漏单位；提示后才做对 |
| 逐条核对 | 每条给有 / 无 + 行号 + 缺口；无“太笼统无法判断” | 同左；含三个表现的主张 2 首次核对即判“有” |
| 改线 | 无 | 无 |

结论：通过标准全部满足。拦下原因都对应模拟学习者人设里的毛病，守卫拦得准。

## 3 顺带发现

| 发现 | 处理 |
| --- | --- |
| A 主张 3 的证据写“被追问时能推出 T(0)=0”——依赖教学侧问某个特定问题，对话里没人追问，守卫只好改用学习者主动推导的两处 | `prompts/design.md` 加一条：证据不写成依赖某个特定追问才出现的表现（补丁，未重跑） |
| `claude -p` 会异步加载账号上的 MCP 连接器说明，混进判断调用的上下文：**隔离有漏洞**，且前缀不稳，提示缓存命中不了（同一输入两次调用长度差约 800 token、第二次未读缓存）；关掉 MCP 后三次调用全部命中缓存 | `llm.py` 加 `--strict-mcp-config` 空配置；`calls.log` 单列 `cache_read`。此前各次运行的判断调用是否确实混入了连接器说明，**未核实** |
| 跨轮次缓存：对话每轮变长且作为一整块发送，只有固定前缀能命中 | 未处理（成本暂不考虑）；要命中需把输入拆成固定段 / 历史 / 本轮新增分块发送 |
