## 背景：我们要解决的问题（只读，不要评价本仓库的实验文档）

为一个数理自学系统做前期调研。它需要：

1. **多来源不合并**：同一学科有多本书/多份资料，对同一个东西的**说法不同**。系统要**把各家的表示都存下来、互不合并**，同时还能表达"这两条说的是同一件事 / 是特例 / 互相矛盾 / 只是叫法不同"。
2. **可回到原文**：每条内容都能溯源到原文片段（可核验），不是模型凭空生成。
3. **通用 vs 个人分离**：通用知识（不属于某个人）与个人形成知识（某个学习者）分开存，不互相污染。
4. **候选 / 审计 / 晋升**：新内容先进候选区，审查通过才进正式库；默认不自动晋升。
5. **只追加 / 版本 / 可回退**：不物理删除，修订形成新版本。
6. **个人视图**：能从个人记录派生出"这个人的知识边界在哪、下一步学什么"的视图。

## 你要产出的东西

一份**可借鉴方法**清单：**别人已经怎么解决这些事**，我们能借什么、不能借什么。

请覆盖（但不限于）以下方向，每条给**一手来源链接**（规范 / 官方文档 / 原始论文优先）：

- 语义网与本体：`skos:exactMatch` / `closeMatch` / `broadMatch` / `narrowMatch`、`owl:sameAs`、本体对齐（ontology matching/alignment）如何做到"多来源、不合并、只连边"。
- 学术知识图谱：OpenAlex、Semantic Scholar、Wikidata、DBpedia 如何表示同一实体的多种说法与来源。
- 断言即一等公民：Nanopublications、RDF reification、RDF-star、named graphs。
- 锚定原文：W3C Web Annotation Data Model、Hypothes.is 的 selector 机制（如何把一条断言锚到原文片段）。
- 不可变 / 版本化存储：git、Datomic、event sourcing、CRDT 对"只追加 + 派生视图 + 可回退"的做法。
- 多粒度：概念 / 陈述 / 表述，别人用什么单位、怎么聚合、怎么避免"图被误读成树"。
- 候选 / 审核 / 晋升工作流：Wikipedia draft/review、Wikidata ranks、Gene Wiki 等。
- 个人知识 vs 通用知识分离的先例：learner model、user model、personal knowledge graph。
- "等价判断"如何被记录成**可撤销的链接**而不是合并（`sameAs` 的争议是最典型例子）。

## 评估要求

- 每条方法写：**是什么 / 一手来源 / 对我们哪条需求有用 / 风险或不适用之处**。
- 明确区分「正式标准/规范」与「单篇论文提案」。
- 不要推荐需要"一次性构建全学科图"的方案；我们要**按需局部构建**。
- **不要引用或依赖**本仓库 `docs/图工程调研/06-M08技术选型.md` 的实验结论——那是单次、窄样本、未完成的实验，不作为依据。若你看到它，请忽略其 schema（id 前缀 / 关系词表 / 节点类型 / 锚点长度）。
