# 派生层外部设计：发现

> 状态：已归档（2026-10-06，#22；调研子代理读一手来源，主会话抽查 Wikipedia 短描述规范与 SkillsBench 正文属实）。参考材料，不作产品结论；采纳的部分落在 `闭环成环-技术调研.md` §5.13「点的派生文本」。
> 问题：M08 派生层的读者是模型、模型本来就懂大部分内容——派生文本用途 = 划边界 + 激活 + 经锚点回原文；在这个用途下派生层架构合不合理，外部有什么可借。

## 结论

| 项 | 内容 |
| --- | --- |
| 直接证据 | 没有研究测过“给模型读的短概念描述（划边界 / 激活）”对数学教学的效果；用途判断只有设计主张支持，须用当下模型实测 |
| 采纳 | ① 定义与范围分开（Wikipedia 短描述规范：“not intended as a definition”；SKOS definition vs scopeNote）② 激活键单列（LightRAG 键值分离；mathlib Notation / Tags）③ 按依赖顺序生成、喂入已生成的前置描述（LeanSearch v2、Matlas）④ 生成时给章节上下文（Alexander 等 2602.05216，有测量） |
| 反证 / 限定 | SkillsBench 2602.12670：模型自生成技能包低于不给包（Opus 4.7 −8.1、GPT-5.5 −11.3、Gemini 3.1 Pro −11.5 pp；过程性知识、智能体任务，类推）→ “模型补的”须标出并传给读者、锚点核验不省 · Dai 等 2402.11541：模型改写事实不如三元组（2024 旧模型，待实测）· MCP 工具描述 2602.14878：补全描述平均 +5.85 pp，但 16.7% 任务变差、无通用最优组合 → 不默认越长越好 |
| 待议 | Lean blueprint 分“陈述所需”与“证明所需”依赖；我们只有子句（学会路线），是否区分“看懂命题所需”与“学会它的路线”留到 B2 |

## 案例

| 案例 | 存什么、给谁读 | 证据 | 可借 |
| --- | --- | --- | --- |
| Wikidata Help:Description | 标签 + 2–12 词描述，消歧 | 设计 | “标签 + 描述”整体唯一，可机检 |
| Wikipedia Short description | ≤40 字符，补标题、标范围，不是定义 | 设计 | 范围说明 ≠ 定义 |
| SKOS Primer | definition / scopeNote / editorialNote / historyNote 分工 | 设计 | scopeNote ≈ 范围说明；editorialNote ≈ 候选待核 |
| LightRAG 2410.05779 | 实体 / 关系 = (检索键, 总结段落) | 测（GPT-4o-mini，模型评委） | 激活键与内容分离 |
| GraphRAG 2404.16130 | 实体描述聚合 + 分层社区摘要 | 测（全局问答胜率 72–83%） | 分层摘要省 token，可供 M05；划边界无可借 |
| RAPTOR 2401.18059 | 递归摘要树 | 测；人工标注约 4% 摘要有轻微幻觉 | 模型摘要须抽检 |
| Dense X 2312.06648 | 命题（原子、自包含一句）作检索单位 | 测（检索器，非对话模型） | 支持“点 = 自包含命题” |
| Contextual Retrieval（Anthropic） | 块前 50–100 token 情境前缀 | 厂商自测：检索失败 5.7%→1.9% | 范围说明 ≈ 原文块的情境前缀 |
| BLINK 1911.03814 | 实体 = 标题 + 描述 | 测（2019，非大模型） | 描述可充当消歧信息 |
| leanblueprint | `\uses` 依赖，陈述依赖与证明依赖分开 | 设计 | 见“待议” |
| mathlib 文档规范 | docstring；模块头 Main definitions / Notation / Implementation notes / References / Tags | 设计 | 记号与标签单列；“选了哪个定义”单记 |
| LeanSearch 2403.13310、v2 2605.13137 | 形式 + 模型生成非形式描述 | 测（合用 nDCG@20 0.545 > 单用） | 派生与原文并存；按依赖序生成 |
| Alexander 等 2602.05216 | 定理“口号” | 测：给第一节上下文明显好于只给摘要；Opus 4.5 Hit@20 0.842 | 生成给章节上下文；它去符号，与激活相反，不照搬 |
| Agent Skills 文档 | description ≤1024 字符：做什么 + 何时用；正文按需加载 | 设计（“只补模型没有的上下文”） | 支持用途判断；“何时用”= 条件式边界 |
| SkillsBench 2602.12670 | 有无技能包对比 | 测（见上） | 来源标签、锚点核验 |
| MCP 工具描述 2602.14878 | Purpose / Guidelines / Limitations / 参数 / Examples | 测（见上） | Limitations 独立成分；长短须实测 |
| ProofWiki、nLab、llms.txt | 多定义并存（Also defined as）· Idea 段 · H1 + 摘要 + 链接 | 设计 / 无效果测量 | 多路线并存有先例；其余可借度低 |
| LLM 辅导系统（Borchers 2504.05570 等） | prompt 放知识组件标识 | 测：模型对 KC 标识响应弱 | 只给标识名不够；无“怎么写描述”可借 |

## 未核实

GraphRAG 实体描述提示词原文 · BLINK 描述长度消融 · ProofWiki Help:Multiple_Definitions · LeanSearch v2 转引出处 · 辅导类后两篇只读摘要。
