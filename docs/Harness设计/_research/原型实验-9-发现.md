根因：闭环被定义成“主张 + 证据、由守卫核对”，系统围着拿证据转；每条规则都是之前试用的补丁，合起来让单次教学不如通用对话模型、也不如教材。**最小实验的问题在于地基没打好，怎么试都是错的**——先把地基（资料、结构、环境、按需读取）做好。

| 按需读取 | 教学与守卫改为带三个只读工具的 agent，在“学习环境”（M08、路线、原文、M09 的软链接 + README 索引）里自己翻；对应 Claude Code 的“常驻索引、细节按需读” | 产品负责人：M08 是索引，模型按需读取，不靠记忆 |

## 4 真人试用 me-9：闭环只剩“快速讲授”

| 观察 | 位置 / 原话 | 含义 |
| --- | --- | --- |
| 被考的情况几乎没有了，接近直接问 Claude | 产品负责人 | 单次下限（不差于“通用模型 + 教材”）基本达到；跨闭环的价值还没有 |
| 4 轮就被关闭：学习者还在往下推（“后面的我不清楚怎么推了”），系统判走通、守卫通过、程序直接收尾 | `me-9/transcript.md:108` 起；`closure-withdrawn.md` | 结束没问学习者；守卫从分散表现拼出“走通”，未要求从头连贯走一遍；守卫写了“还差”仍判通过 |
| 顺利但效果不好：只有推导，没有应用训练；链是直线，没有“绕回来、连上” | 产品负责人：“闭环在哪里，知识点是怎么串联回环的” | 重建时删掉了 M03（训练），新定义漏了“理解 ↔ 训练”这一层 |

处理：闭环定义补成三层（产品总览「闭环定义」）——① 闭环内理解 ↔ 训练；② 收口：学习者确认、判定能从头走通并在新情境下能用、记下连上了哪些已关闭的点；③ 闭环之间串联上升（产品特别之处，属未来）。me-9 的 M09 记录撤回，按“理解已走通、训练未做”记入停车场。
