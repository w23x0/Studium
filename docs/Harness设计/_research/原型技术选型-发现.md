## 先看：一条 2026 年的硬约束

| 事实 | 对选型的含义 |
| --- | --- |
| Opus / Sonnet 5.5 的思考块记住产生它时的前缀（系统提示、工具集、之前每条消息）；之后前缀被改，重放就报 400（2026-08-31 后的账号默认强制），或开 `drop_block` 静默丢掉思考 | Studium 已定“一个闭环一份上下文、只追加”，天然合规 |
| 不破坏的写法：只追加；中途追加 `role:"system"` 消息（= 程序追加事实）；开场声明全部工具、隐藏的标 `defer_loading`，之后用 `tool_addition` 放出（= skill / 工具按需）；服务器端压缩 | 四个接口都能直接落到 API 自带机制上 |
| 会破坏的写法：每轮重渲染系统提示、历史裁剪、“保留最近几轮”式总结、中途改工具数组 | 很多框架默认就这么做。**选框架时这比“功能全不全”更要紧** |

## 1 闭环内循环（agent 框架）

| 候选 | 结论 | 主要理由 |
| --- | --- | --- |
| **Anthropic 官方 SDK（`@anthropic-ai/sdk`）+ 其自带循环 Tool Runner** | **建议第一选择** | 官方维护，新机制当天可用；记录就是 API 原生消息，原样存、原样重放，不经第三方转换；只 Claude，beta |
| Vercel AI SDK（TS） | 备选，到接 OpenAI 时再看 | 厂商最全，Claude 新机制跟得最紧；自有消息格式，往返是否逐字节不变未实测；约半年一个破坏性大版本 |
| pi（pi-agent-core + pi-ai，已改名 `@earendil-works/*`） | 备选 | 接口形状最贴四个接口；10-01 才出 1.0；对 Opus 5.5 写死静默丢思考、没有服务器端压缩；新贡献者 issue 默认自动关闭 |
| Pydantic AI（Python） | 核心若用 Python 选它 | 对思考绑定、中途系统消息、按需 skill、服务器端压缩处理最完整 |
| Claude Agent SDK | 不选 | 本质是把 Claude Code 当子进程跑；编程假设（cwd、CLAUDE.md）；记录不是 API 原文；商业条款 |
| Claude Managed Agents | 不选 | 拿不到思考内容，记录无法原样导出重放 |
| OpenAI Agents SDK | 不选 | Claude 走它自称 beta 的适配层，Claude 新机制推断会丢 |
| LangGraph、Mastra | 不选 | 自带记忆 / 总结中间件，与只追加冲突；闭环外“事件 → 清单”不需要图引擎 |

**与原则 4“不自写闭环内循环”的关系**：子代理原建议“自写薄循环”；主会话改为用官方 SDK 自带的 Tool Runner，循环不自己写，仍守原则。代价是闭环内框架第一版只接 Claude；接 OpenAI 时按同样四个接口再接一套（届时比 Vercel AI SDK 与 OpenAI 官方 SDK）。依据：一个闭环只用一个模型，换厂商发生在会话之间，不需要能跨厂商互转的统一消息格式。DeepSeek、智谱、Kimi 有 Anthropic 兼容端点（只 DeepSeek 见官方出处），思考块兼容程度未核实。

## 2 语言

| 选择 | 理由 |
| --- | --- |
| **核心与界面都用 TypeScript** | 界面是 web / 桌面技术，前后端共用类型；类型检查是“人不看代码”时最便宜的护栏；聊天界面、公式渲染、模型 SDK 在 TS 里都是一等公民 |
| `书库处理/` 继续 Python | 离线处理，与在线核心只经文件交接，不改 |

## 3 界面外壳与核心接口

| 项 | 建议 | 理由 / 坑 |
| --- | --- | --- |
| 核心形态 | 常驻本地服务：HTTP 收命令、SSE（服务端单向推事件）推给界面；只绑本机地址 + 口令 | opencode、Codex 都是“核心独立进程、界面只是客户端”；界面关了后台 agent 照跑，正合“核心不绑界面” |
| 第一版外壳 | 浏览器打开本地页面；要原生体验时用 Electron 包同一个前端 | opencode 就这么做；Playwright 测浏览器最成熟。同类开源项目桌面版几乎都是 Electron；Tauri 在 Linux 用 WebKitGTK，官方自列图形问题，而书库设备是 Linux |
| 前端 | React + Vite + assistant-ui（聊天原语，能接自建后端） | 主对话 + 线程列表、选择卡（工具卡片）都有现成原语 |
| 公式 | 流式时“没写完的公式先显示原文，写完再渲染”，并把 `\(\)` `\[\]` 归一成 `$` | streamdown 会自动补收尾符号，半截公式短暂显示成错误；效果未实测 |
| 原件截图 | 核心预先裁图存 PNG，界面只显示图片 | 与界面无关、可缓存、模型也能读 |
| 行号跳转 | 长对话用支持“按索引滚动”的虚拟列表 | 目标行没渲染时要先滚到再高亮 |

## 4 本地存储

| 项 | 建议 | 理由 / 坑 |
| --- | --- | --- |
| 正本 | 每个会话一个 JSONL 文件，一个写者，只追加，**永不改写**（格式升级只产出新文件或派生层，清理默认关） | 看过的产品（pi、Codex、Claude Code、opencode）都会改写、迁移或删除旧记录；`文件:行号` 要稳定，这条必须是硬规则 |
| 派生层 | SQLite 存索引、列表、检索，坏了从 JSONL 整个重建 | Codex 正是“JSONL 正本 + SQLite 可重建” |
| 中文检索 | 先 grep；量大了再上分词 + 全文索引 | 实测 SQLite trigram 搜不到两个字的词（“动量”） |
| 大文件 | PDF、MinerU 输出不进 JSONL，只存路径 + 内容哈希 | — |
| 哈希链审计 | 暂不做 | 没找到同类先例，价值待定 |

## 5 “代码全交 agent 写、人不看”怎么保质量

**总的情况**：所有来源都把质量放在“环境”上（检查命令、门禁、写审分开、文档当地图）；**没有任何来源证明人完全不看代码能让架构长期不烂**（OpenAI 列为未知；Zechner 认为做不到，主张架构由人定）。所以：架构由设计文档定（Studium 已有 00 / 03），代码里用依赖方向测试守住；产品负责人检查的对象从代码换成对话记录、截图、功能清单状态、评测结果。

| 优先 | 从第一天就有 | 为什么 |
| --- | --- | --- |
| P0 | 一条检查命令：`tsc` 严格 + lint + 格式 + 测试，几十秒跑完，报错一行一条 | 所有门禁都调它 |
| P0 | 假模型：程序测试一律不调真模型（照 pi 的 faux provider） | 会话接线、工具权限、存盘、钩子可确定地测，不花钱 |
| P0 | 依赖方向测试（dependency-cruiser）：模型 SDK 只能在适配层被引用，报错写明怎么改 | 架构是最大风险，也是唯一能部分机械化的 |
| P0 | Claude Code hooks（进 git）：改文件后格式化 / lint，结束前跑检查，禁改验收测试目录 | CLAUDE.md 是建议，hook 才确定执行 |
| P0 | CI 跑同一条检查；短 CLAUDE.md（约 100 行，当地图）；功能清单 JSON（每条带“怎么验证”，初始全失败） | 防“过早宣布完成”；产品负责人看清单知进度 |
| P1 | Playwright 走主路径并截图；用真实运行录带做离线回放；独立审查子代理（新上下文、最好换模型、只报正确性与需求缺口） | 界面与接线问题单元测试测不到；自审偏正面 |
| P1 | 行为评测单独一个目录：模拟学生多轮、每个失败模式一个过 / 不过判定、看 k 次全过；**不进每次提交的门禁** | 模型行为不能靠代码测试；结果连对话记录给产品负责人看 |
| P1 | 测试改动单独提交、CI 报告删改了哪些断言 | 模型会改测试“通过”（METR、ImpossibleBench；Anthropic 模型主要是直接改测试文件） |
| P2 | 定期清理会话（去重、死代码、文档新鲜度）；定期换模型做架构审查；核心模块跑变异测试 | 代码量上来后防腐化 |

不建议：覆盖率门槛（最易刷）、模型原文快照测试、大而全的 CLAUDE.md、第一天就上多 agent 编排与自动合并、让写代码的会话自评完成、审查意见条条照改。

## 6 写原型时第一批要确认的

不是先做实验再写原型，而是原型第一批测试就覆盖这几项：

| 项 | 怎么确认 |
| --- | --- |
| 思考块原样重放 | 多轮带工具会话 + 隔天重放，开 `thinking-binding-controls` 看 `input_transformations` 有没有丢块 |
| 账号是否强制 | 产品负责人账号创建日期是否在 2026-08-31 后（未知） |
| 公式流式显示 | 录真实 Claude 理科回答的流式分片，离线回放到界面看闪烁与漏渲染 |
| 多个 agent 会话并发 | 每会话一个 JSONL 写者，Linux 上实测追加不交错（ext4 已测一次）；macOS 未测 |
