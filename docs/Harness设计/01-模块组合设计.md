## 1 运行主链总览（以 M04 为中心）

```text
学习者输入
   │
   ▼
M04 诊断（每轮必跑，高级模型）───→ M02 教学（低级模型，表达）
   ▲                                   │  ▲
   │ 可观察表现 / 教学条件               └──┘ 串行：M02 必须先拿 M04 分析
   │                                        │
M03 练习活动 ──（练习条件/产出/过程）────────┘
   ▲
M10 策略与强度条件（诊断事实 + M15 承载读数 → 策略，不重诊断）

闭环结束点：M04 闭环守卫 → 通过则一次性提交 M09 + 通知 M01
跨闭环改动：M04 改线依据 → M05 路线决定 → M01 落实
状态侧：M15（低频）独立提取；承载读数直连 M05/M10，解释候选交 M04 评估
```

关键规则（`已确认`）：
- M04 与 M02 **串行**：学习者输入 → M04 分析 → M02 基于分析生成回复；不并行。
- M10 四项强度（信息量 / 提示强度 / 挑战程度 / 节奏）**只由 M10 拥有**，M02/M03 只执行。
- M04 只出**诊断事实与验证需要**，不出教学建议；M10 不重做诊断、不拥有闭环守卫。
- M15 信息流严格单向；M04 只能回发重新确认请求。

### 1.1 架构视角：中心资产池，不是模块链路

**不要用“模块 → 模块”的链路思维**（容易误判）。正确模型：

```text
        ┌──────────── 中心上下文资产池 ────────────┐
        │   按结构寻址：产出者 + 位置 + 时间          │
        └──▲─────────────▲─────────────▲──────────┘
           │ 按需读        │ 按需读        │ 按需读
         M04            M10          M02 / M03
           │ 写回          │ 写回          │ 写回
           └─────────────┴─────────────┘
```

| 视角 | 流水线式（Dify 那类） | Studium |
| --- | --- | --- |
| 中心 | 节点与连线 | **上下文资产池** |
| 模块 | 流水线工位 | 围绕池子的**加工厂** |
| 数据流 | 模块→模块按序传递 | **都从池里取、加工后写回池** |
| 前提 | 提示词按节点拼 | **结构索引**（产出者 + 位置 + 时间） |
| 产品红线的落法 | 路由限制 | **池上的读 / 写权限** |

要点：
- 模块**不互相调用**；消费者可以**直接读上游资产**，不必经过中间模块（例：M02/M03 可直接读 M04 的输出，不必先经 M10）。
- 产品文档里的边与禁止关系 = **池上的读写权限**：谁可读谁的资产、谁可在哪里写（如 M09↔M15 无引用 = 互不可读；M04→M09 只在闭环结束写一次）。
- **分发 = 运行时按各模块的**读清单**（结构槽）取**上游输出**整份装配**（`02` §3.6，不做全局引用闭包）；防污染靠**读范围**（权限表），不靠链路裁剪。
- “上下文怎么寻址、怎么索引”是地基（**不靠语义标签**，见 `02` §3.2）。
- 禁止把模块图当成固定执行顺序或严格路由（与 `00` §3 一致）。

### 1.2 拆分模块的第一原理

拆模块**不是为了流程**，是两条：

1. **隔离上下文**：每个模块在**干净、专属**的上下文里做自己**唯一**的判断；输出**不回流、不串味**。
   判据：① 不回灌；② 各取字段；③ 判断性质不同就分。
2. **不同性质的判断用不同模型**：M04 = **分析**模型（逻辑判断）；M02/M03 = **表达**模型（**文学工作**——把 M10 定的方案表述出来）。

**反向**：同性质、同输入、同作用域的，**不拆**（拆了只增加交接成本）。
