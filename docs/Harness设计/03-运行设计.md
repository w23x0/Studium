## M01 学习项目与会话

| 项 | 设计 |
| --- | --- |
| 何时被调用 | **不是判断点，不调模型**。程序在每个事件后写入：学习者每句话、每次调用的产出、状态变化（开始 / 暂停 / 搁置 / 结束）、M05 的路线决定、闭环收口快照。装配其他调用前，程序从这里读 |
| 读什么 | 不读语义；只按 项目 / 会话（= 闭环）/ 时间 给事件定归属 |
| 连续还是重装 | 自身没有上下文。它就是上面说的“会话日志”：教学调用的连续上下文、守卫 / M15 / M05 的重装，都从这里取料 |
| 交给谁 | 程序（装配器）；各模块经程序按权限表读 |

**会话里存的东西**：事实记录（对话原文带行号、各调用产出、状态与时间、路线决定、跨模块链接——M09 ↔ M15 经此关联）；另存教学调用的原始消息（逐条原样，含思考块），**只有教学调用自己读**，守卫、M15、M05 装配时不取。

**跨天续接 = 原样重放**（产品负责人 2026-10-05）：缓存过期只多付一次缓存写入。离开多久由程序作为事实追加，模型自己据此回应。

**容器与事实槽**（09-16 起沿用）：M01 只存事实、不存解释——存“各次会话启动间隔”，不存“启动困难”，解释由 M15 / M04 重新导出。

| 项 | 内容 |
| --- | --- |
| 容器树 | 项目 → 会话（= 一个闭环）→ 主线轮次；分叉 = 新会话 / 新闭环，返回条件由 M05 定、M01 存；分叉会打断缓存前缀 |
| 目标面 | 粗目标 + 已锚定的 M08 对象，逐步补齐（D-06、D-16） |
| 路径事实 | 主线 / 分叉 / 当前位置 / 返回条件；M05 的决定（含“维持”及理由）存成路线事实（D-17） |
| 状态关联事实 | M09 记录 ↔ M15 记录的归属链接，只存位置（两者互不可读，经此关联） |
| 产出归属 | 各调用产出的位置与产出者；归属 / 位置类跨区写入由 M01 统一落账 |

## 教学调用（M02 / M03 / M04 进行中诊断 / M10）

四个功能在同一次调用里完成：先写记录（不设固定栏目），再写给学习者的话。职责分工以审查单为准（M02「职责分工」）；本节只管怎么调用。

| 定了什么 | 内容 | 依据 |
| --- | --- | --- |
| 合在一次调用，不拆串行 | 同信息的职责不拆成串行调用；判断点只在必须隔离处分开 | `00-技术方向确认.md` 原则 2（产品负责人 2026-09-29 确认）；外部旁证 `_research/前沿架构对照-发现.md`（拆分的理由只能是隔离） |
| 独立调用只给必须隔离处 | M04 闭环守卫（防自我确认）、M15（与 M04 单向隔离）、M05（会话外） | 同上 |
| 模型 | 每个判断点（教学调用、守卫、M05）可各自指定，默认同一个当下最强模型；不按模块职责分别选型（属模型迭代会解决的问题）；选模型看教学行为，不只看解题能力 | 产品负责人 2026-09-24；MathTutorBench（arXiv 2502.18940）；arXiv 2505.15607 |
| 连续上下文，只守卫独立 | 教学调用一个闭环一份上下文（下表），自己上一轮的记录留在上下文里；原“诊断记录不回灌 / 只出不回”收窄为只约束守卫 | 产品负责人 2026-10-05，见本节末「为什么连续」 |

| 项 | 设计 |
| --- | --- |
| 何时被调用 | 学习者每发一次话调用一次。另有两种程序事件会让它接着跑一次：守卫判未闭合（核对结果作为系统消息追加，教学据此继续）；学习者离开后回来（离开多久作为事实追加） |
| 读什么 | **开头装配一次**：提示词、M05 的单子（新点 + 选中的子句 + 路线动作）、M08 相关片段、M09 相关记录（有才放）。**之后只追加**：学习者原话、程序事件。**调用内按需读**：学习环境（M08、教材路线、M07 原文、M09、教学工具），读什么由模型定 |
| 连续还是重装 | **连续**：一个闭环一份上下文，只追加；太长才压缩一次，用服务器端清理，学习者原话不删不改；跨天原样重放（见 M01） |
| 交给谁 | 给学习者的话 → 学习者；记录 → 存进 M01，供审计、M09 提交、学习者查阅；**守卫不读这份记录** |

| 上下文 vs 提示词 | 放进资产的是上下文，放进 system prompt 的是提示词；判据：能作为事实被继续推理的是上下文，只命令模型怎么做的是提示词。位置 / 状态 / 策略 / 系统限制都以事实进入（B-03）；职责靠上下文组合区分，不靠角色提示词；提示词只留最小约定，不用角色、不用输出模板（B-05） |
| 资产有主 | 产出者拥有、其他只读；派生资产归产出它的调用，带来源指回原资产；容器归 M01 |
| 分发（D-21） | 默认 = 程序按读清单取上游整份资产装配，信任上游，不做全局引用闭包；准确性来自上游输出的完整度；下游要原文时用工具按引用取。教学调用只在开头这样装配一次，之后只追加（「教学调用」） |
| 新鲜度（读侧） | 每条资产带产出时间；同一槽出新产出时旧的标“已被取代”（保留审计、不再作当前值）；装配取最新有效一份，不新旧并喂；槽内无有效资产 = 缺槽，按「缺料与冲突」处理；产出侧不管消费者（原实现基线 D-001 归此） |
| 两种流式 | 闭环内：随学习者输入逐轮长（诊断、回复、练习证据）；闭环外：闭环结束后定格的总结（M09 记录、M05 路线） |
| 成本 | 设计时暂不考虑（09-09 核心需求） |
| 明确不做 | JSON / schema、固定字段模板、角色提示、语义相似度当选取键、下游默认自取全库 |
| 未验证 | “自由文本 + 引用”更适合跨模块资产仍是假设；格式实验暂不做（B-04），留案：① 纯自由文本 ② 自由文本 + 来源引用（现行）③ 轻结构；指标：续推质量 / 溯源准确率 / 跨模型跨轮一致性 / 提示词开销 |
