> **运行方式**：每个会话是一个 agent——带工具，自己决定查什么、查几次、何时完成，不按“装配一次材料、调用一次模型”。程序不替会话挑料，只管会话之间：开场交付什么、给哪些工具（写权限靠这个卡）、会话中追加什么事实、收口时插手、把每个事件存进 M01。每个会话回答四件事：**何时开 · 开场交付 · 工具 · 交回什么**。读权限不在各节重复，以「读写权限」为准。闭环外流程怎么串（固定流程还是别的）未定（`../../会话记录/2026-10-07-32-pi理念与闭环内外/README.md` 开着的问题 1）。

## M01 学习项目与会话

| 项 | 设计 |
| --- | --- |
| 何时被调用 | **不是会话，不调模型**。程序在每个事件后写入：学习者每句话、每个会话的产出、状态变化（开始 / 暂停 / 搁置 / 结束）、学习者在选择卡上的选择与 M05 的路线决定、闭环收口快照 |
| 读什么 | 不读语义；只按 项目 / 会话 / 时间 给事件定归属 |
| 在运行里的位置 | 它就是会话日志：各会话的开场交付、查询工具查到的记录，都从这里取 |
| 交给谁 | 程序（开场交付）；各会话经查询工具按权限表查 |

**会话里存的东西**：事实记录（对话原文带行号、各会话产出、状态与时间、路线决定、跨模块链接——M09 ↔ M15 经此关联）；另存闭环对话的原始消息（逐条原样，含思考块），**只有闭环对话自己读**，其他会话的工具查不到。

**跨天续接 = 原样重放**：缓存过期只多付一次缓存写入。离开多久由程序作为事实追加，模型自己据此回应。

**容器与事实槽**（09-16 起沿用）：M01 只存事实、不存解释——存“各次会话启动间隔”，不存“启动困难”，解释由 M15 / M04 重新导出。

| 项 | 内容 |
| --- | --- |
| 容器树 | 项目（一个方向目标）→ 主对话 + 任务对话（畅谈对话；闭环对话 = 一个闭环）→ 轮次；分叉 = 新闭环对话，返回条件由 M05 定、M01 存；分叉会打断缓存前缀 |
| 目标面 | 粗目标 + 已锚定的 M08 对象，逐步补齐（D-06、D-16） |
| 路径事实 | 主线 / 分叉 / 当前位置 / 返回条件；路线决定（含“维持”及理由）存成路线事实（D-17） |
| 状态关联事实 | M09 记录 ↔ M15 记录的归属链接，只存位置（两者互不可读，经此关联） |
| 产出归属 | 各会话产出的位置与产出者；归属 / 位置类跨区写入由 M01 统一落账 |
| 与域数据分开 | 会话日志不混存 M07 / M08 / M09 / M15 / 路线决定等域数据；Studium 自己拥有它们的格式、迁移、审计与一致性规则 |
| 缺料 | 不因缺料而不写：缺什么只登记“暂无产出”，不推断；只收事实，诊断 / 掌握 / 状态结论不收 |

## 闭环对话（M02 / M03 / M04 进行中诊断 / M10）

四个功能在同一个会话里完成：先写记录（不设固定栏目），再写给学习者的话。职责分工以审查单为准（M02「职责分工」）；本节只管怎么跑。

**闭环内用通用 agent 框架，可整个替换**：Studium 不自写闭环内的循环，自己做闭环外；两边只经下面四个接口。框架满足入选条件就能换，Studium 这边不改。

| 接口 | 内容 |
| --- | --- |
| 开场交付 | 提示词 + M05 单子（新点 + 选中的子句 + 路线动作）+ 程序从 M08 / M09 挑的片（单子涉及的点与子句、M09 相关记录，有才放） |
| 工具 | 查询类，只读：M08、教材路线、M07 原文、M09、M01 本闭环记录；skill 形式的教学工具（下表）；“申请收口”。不给写别区的工具（「读写权限」） |
| 钩子 | 申请收口：交给 Studium 的守卫（「收口与闭环守卫」）；程序在会话中追加事实：守卫结论、离开多久、M15 读数等 |
| 交回 | 结束时交回对话原文，存进 M01；含思考块的原始消息仍只给闭环对话自己 |
| 入选条件 | 记录可读、能挂工具和 skill、会话中可追加、收口时程序能插手 |

| 项 | 设计 |
| --- | --- |
| 何时跑 | 学习者每发一次话跑一轮；程序追加事实（守卫判未合上、学习者离开后回来）后接着跑一轮 |
| 上下文 | **连续**：一个闭环一份上下文，只追加；太长才压缩一次，用服务器端清理，学习者原话不删不改；跨天原样重放（见 M01） |
| 合在一个会话 | 同信息的职责不拆成串行会话；会话只在必须隔离处分开：守卫（防自我确认）、M15（与 M04 单向隔离）、M05（闭环外）（`00-技术方向确认.md` 原则 2；外部旁证 `_research/前沿架构对照-发现.md`） |
| 模型 | 每个会话可各自指定，默认同一个当下最强模型；不按模块职责分别选型；选模型看教学行为，不只看解题能力（MathTutorBench arXiv 2502.18940；arXiv 2505.15607） |
| 交给谁 | 给学习者的话 → 学习者；记录 → 随对话原文存进 M01，供审计、M09 提交、学习者查阅；**守卫不读这份记录** |

## 收口与闭环守卫（M04 子模块）

**收口流程**（10-07 定）：守卫是 Studium 自有的，换闭环内框架不换它。

| 步 | 内容 |
| --- | --- |
| 1 申请 | 闭环对话调用“申请收口”工具；学习者也可手动申请（“我觉得懂了”） |
| 2 守卫 | 程序开守卫会话 |
| 3 未通过 | 守卫结论作为事实追加回闭环对话，继续教学 |
| 4 通过 | 学习者确认结束 |
| 5 出口处理 | M09 一次写入（提交什么以 M09 审查单为准）、M01 收口快照、交 M05（主对话接着出下一张选择卡） |

学习者没合上仍要结束 → 进 M05 停车场，不进 M09。

**守卫**：判什么见 M04 审查单「闭环判定与证据守卫」；实现：收口时另开一次调用，与教学隔离（10-07 默认，依据是结构推理“自己教、自己判”，未经实测；以后可给守卫叠 skill 补它不会判的地方）。

| 项 | 设计 |
| --- | --- |
| 何时开 | 收口流程第 2 步 |
| 开场交付 | 本闭环对话原文（带行号）+ M05 单子；**不交**闭环对话的推理与记录（M04 审查单「职责分工」） |
| 工具 | 只读查询（M08、M07 原文）；不给写工具，判定由程序存 |
| 怎么判合上 | 对照 M05 单子（新点 + 选中的子句）读对话原文整体判断，不设条目清单；判断指回原文行号。守卫对照的就是这条子句（出发点 + 预期理解），不另判深度（总览「闭环定义」目标分三层） |
| 交回 | 判定 + 依据 → 程序按收口流程走第 3 或第 4 步 |
| 不降门槛 | 模型自信、学习者自述、单次表现都不能单独关闭闭环（M04 审查单）；M10 只调本次会话内的强度坡度，不下调合上标准 |

## M05 学习导航与计划

只写已定部分。

| 项 | 设计 |
| --- | --- |
| 何时开 | 闭环边界（收口出口处理后，或学习者结束、进停车场后）；学习者在主对话要下一步时；每次只设计**下一个**闭环，偏差判断在闭环外（D-05）。会中：出现要补前置知识或其他路线需求时，由改线依据触发 |
| 会话形态 | 在主对话背后单独开一个 agent 会话，只交回选择卡；主对话不做 M05 的重活 |
| 开场交付 | 目标面与路线事实（M01）、停车场、学习者的期限与选择、触发原因 |
| 工具 | 只读查询：M09 已结束闭环与知识边缘（滞后一拍）、自己的路线偏差记录、M08、M15 承载读数与阶段读数、M07 补资料与来源；外部搜索（D-13）。写：只写自己的选择卡 / 路线决定候选 |
| 开什么单子 | 新点 + 选中的子句 + 路线动作；书给的子句是标准，给谁选哪条由 M05 依据 M09 判断 |
| 交回 | 选择卡（几个选项、各带理由、推荐一个）→ 主对话贴给学习者；学习者选定 → M01 存成路线事实 → 开闭环对话，单子进开场交付 |
| 引用 | 路线决定必标 `文件:行号`，须可回查 |

**路线规则**（09-13～09-23 定，与闭环定义细节无关）：

| 规则 | 内容 |
| --- | --- |

| 证据不足 | 闭环保持进行中、进入复检或标搁置；不因模型自信 / 自述 / 画像 / 单次表现关闭 |
| 分叉中的表现 | 保留路径关系，不直接判为主线缺口 |
| 自述 vs 观察 | 并存标注，自述不覆盖可观察事实 |
| 跨资料冲突 | 并存，不强合并（D-03） |
| M03 生成题 | 不默认入库 M07（`待确认项.md` D-008），来源标“生成” |
| 闭环长期不结束 | M01 照常记事实，路线问题归 M05 |
| 声称超出学习范围（健康 / 心理疾病） | 不诊断，不据以行动 |

## 横切：上下文资产

模块间传的是什么、怎么被挑出来（09-13～09-21 定）。

| 项 | 约定 |
| --- | --- |
| 是什么 | 会话按约定写出的分析文本，给下一个会话接着推理用，不是给人读或给界面展示的；形态 = 带来源、证据关系、因果的文字推理链：逐条、可组合、可被替换或推翻；不是 JSON，不是无结构自由文本，也不是人类可读的成段陈述。第一版只做简单完整的文字推理链，不深入思维链优化 |
| 模型思考 | 模型的思考通道不当资产；例外：闭环对话的原始消息含思考块原样存、只它自己读（「M01」） |
| 来源引用 | `文件:行号`（B-01）：会话记录只追加，行号稳定、可机械核对；M08 面向会被编辑的资料，用锚点 `{file, quote}`，两者不混用（待定：随「M06 转录与修订」定稿改）。行号引用待重审（`00` 头部疑点） |
| 选取 = 结构寻址 | 产出者 + 位置（会话 / 分叉 / 轮次 / `文件:行号`）+ 时间；不打语义标签（B-02） |
| 上下文 vs 提示词 | 放进资产的是上下文，放进 system prompt 的是提示词；判据：能作为事实被继续推理的是上下文，只命令模型怎么做的是提示词。位置 / 状态 / 策略 / 系统限制都以事实进入（B-03）；职责靠上下文组合区分，不靠角色提示词；提示词只留最小约定，不用角色、不用输出模板（B-05） |
| 资产有主 | 产出者拥有、其他只读；派生资产归产出它的会话，带来源指回原资产；容器归 M01 |
| 分发（10-07 取代 D-21） | 开场交付 + 按需查：程序只交开场必需的几样，其余由会话用查询工具按引用查；信任上游，不做全局引用闭包；闭环对话开场交付一次、之后只追加（「闭环对话」） |
| 新鲜度（读侧） | 每条资产带产出时间；同一槽出新产出时旧的标“已被取代”（保留审计、不再作当前值）；交付与查询都取最新有效一份，不新旧并喂；槽内无有效资产 = 缺槽，按「缺料与冲突」处理；产出侧不管消费者（原实现基线 D-001 归此） |
| 两种流式 | 闭环内：随学习者输入逐轮长（诊断、回复、练习证据）；闭环外：闭环结束后定格的总结（M09 记录、M05 路线） |
| 成本 | 设计时暂不考虑（09-09 核心需求） |
| 明确不做 | JSON / schema、固定字段模板、角色提示、语义相似度当选取键、下游默认自取全库 |
| 未验证 | “自由文本 + 引用”更适合跨模块资产仍是假设；格式实验暂不做（B-04），留案：① 纯自由文本 ② 自由文本 + 来源引用（现行）③ 轻结构；指标：续推质量 / 溯源准确率 / 跨模型跨轮一致性 / 提示词开销 |

**引用约定**（C-02，09-21）：

| 产出 | 标不标 `文件:行号` |
| --- | --- |

| 闭环对话给学习者的话 | 不标（用到资料时给 M07 位置） |

| M06 / M07（出处与原文位置）、M08（锚点 = 原文引用）、M14（随版本保留） | 必标 |
| M01 | 事实带时间与归属，不标语义引用 |
