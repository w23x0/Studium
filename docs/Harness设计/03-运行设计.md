# 运行设计：每个模块在运行时怎么被用

> 状态：待定，**10-05 暂停**（#16）：只写了不依赖闭环定义的 M01 与教学调用；守卫、M05 等要等 10-02 新闭环定义的地基（#22 实验、#12 清理）再写。审查单 M01–M15 是**功能设计**，有意不碰技术实现（产品负责人 2026-10-05）；本文件是技术侧：每个功能落到哪次调用、怎么跑。不新增产品结论；冲突以审查单为准。
>
> 每个模块回答四件事：**何时被调用 · 读什么 · 连续还是重装 · 交给谁**。“连续” = 一次装配、之后只追加（有状态）；“重装” = 每次从资产重新装配（无状态）。总方向：资产 = 只追加的会话日志，程序 = 无状态外壳，进模型的上下文按职责从资产里挑（`00-技术方向确认.md` 原则 2 方向段；`../agent框架学习/08-有状态与无状态.md` §4，未实验）。读权限不在此重复，以 `01-容器与路线设计.md` 集中权限表为准。

## M01 学习项目与会话

| 项 | 设计 |
| --- | --- |
| 何时被调用 | **不是判断点，不调模型**。程序在每个事件后写入：学习者每句话、每次调用的产出、状态变化（开始 / 暂停 / 搁置 / 结束）、M05 的路线决定、闭环收口快照。装配其他调用前，程序从这里读 |
| 读什么 | 不读语义；只按 项目 / 会话（= 闭环）/ 时间 给事件定归属 |
| 连续还是重装 | 自身没有上下文。它就是上面说的“会话日志”：教学调用的连续上下文、守卫 / M15 / M05 的重装，都从这里取料 |
| 交给谁 | 程序（装配器）；各模块经程序按权限表读 |

**会话里存的东西**：事实记录（对话原文带行号、各调用产出、状态与时间、路线决定、跨模块链接——M09 ↔ M15 经此关联）；另存教学调用的原始消息（逐条原样，含思考块），**只有教学调用自己读**，守卫、M15、M05 装配时不取。

**跨天续接 = 原样重放**（产品负责人 2026-10-05）：缓存过期只多付一次缓存写入。离开多久沿用原型已有的做法，由程序作为事实追加（`proto/studium/loop.py:143`），模型自己据此回应。

## 教学调用（M02 / M03 / M04 进行中诊断 / M10）

四个功能在同一次调用里完成：先写记录（诊断 + 策略与强度 + 练习的验证意图），再写给学习者的话。职责分工以审查单为准（M02「职责分工」）；本节只管怎么调用。

| 定了什么 | 内容 | 依据 |
| --- | --- | --- |
| 合在一次调用，不拆串行 | 拆成 M04 → M10 → M02 后，“产生怀疑”与“权衡追问的代价”分在不同环节，没有一环负责“这个疑点值不值得查”：实测过度追问、步子过碎、学习者提问被搁置 | `_research/原型实验-1-发现.md`（2026-09-23） |
| 独立调用只给必须隔离处 | M04 闭环守卫（防自我确认）、M15（与 M04 单向隔离）、M05（会话外） | 同上 |
| 模型 | 每个判断点（教学调用、守卫、M05）可各自指定，默认同一个当下最强模型；不按模块职责分别选型（属模型迭代会解决的问题）；选模型看教学行为，不只看解题能力 | 产品负责人 2026-09-24；MathTutorBench（arXiv 2502.18940）；arXiv 2505.15607 |
| 连续上下文，只守卫独立 | 教学调用一个闭环一份上下文（下表），自己上一轮的记录留在上下文里；原“诊断记录不回灌 / 只出不回”收窄为只约束守卫 | 产品负责人 2026-10-05，见本节末「为什么连续」 |

| 项 | 设计 |
| --- | --- |
| 何时被调用 | 学习者每发一次话调用一次。另有两种程序事件会让它接着跑一次：守卫判未闭合（核对结果作为系统消息追加，教学据此继续）；学习者离开后回来（离开多久作为事实追加） |
| 读什么 | **开头装配一次**：提示词、M05 选定的出发点与新点、M08 相关片段、M09 相关记录（有才放）。**之后只追加**：学习者原话、程序事件。**调用内按需读**：学习环境（M08、教材路线、M07 原文、M09、教学工具），读什么由模型定 |
| 连续还是重装 | **连续**：一个闭环一份上下文，只追加；太长才压缩一次，用服务器端清理，学习者原话不删不改；跨天原样重放（见 M01） |
| 交给谁 | 给学习者的话 → 学习者；记录 → 存进 M01，供审计、M09 提交、学习者查阅；**守卫不读这份记录** |

**为什么连续（产品负责人 2026-10-05 已定）**：

| 项 | 内容 |
| --- | --- |
| 冲突 | 前设计（2026-09-23，从想象写出）：诊断记录不回灌下一轮，防止模型拿自己的分析喂自己。后验证（`../agent框架学习/08-有状态与无状态.md` §4，含外部旁证 CCM：每轮重装使编程 agent 完成率明显下降）：教学调用宜连续。以后验证为准 |
| 收窄后的约束 | 守卫独立调用，不读教学侧的推理与记录 |
| 证据边界 | **未在本项目做过实验**；CCM 是终端任务、4.6 一代，属外部旁证 |
| 已知风险 | 错误推断留在教学上下文里，锚定后续判断（`08` §5：我们是软推断，没有报错那样的纠错信号） |
| 对照办法 | 用 me-9 同一输入比较连续 vs 每轮重装 |
| 审查单原文 | 旧写法存 `../模块需求设计/撤下原文/M02-M04-M10-运行方式.md` |
