## 0 本文范围

只回答：**模块输出的上下文资产长什么样、怎么被寻址与分发**。

不定：存储位置、图节点、模型选型、B/A 层调研（见 `01` §4 A-07）。

## 1 三层定位（回顾）

| 层 | 是什么 | 是否本资产 |
| --- | --- | --- |
| A 模型内部思考 | 模型为得到答案的内部推理 | ❌ |

## 3 最小约定

### 3.1 来源引用（B-01）

- 形式：**`文件:行号`**，例如 `sessions/s1/turn2.md:37`，定位到行即可。
- 理由：精确、输出不易出错、可机械核对。
- **与 M08 锚点不混用**：M08 用 `{file, quote}`（逐字连续子串）——因为 M08 面向会被编辑的资料，行号会漂移；本资产面向**追加式**会话记录，行号稳定，故用行号。

### 3.2 选取键：结构寻址，不是语义标签（讨论结论）

- **结论：不打语义标签。** 语义标签会限制输出、把不相关内容捆在一起，且无法全局一致 → 原"跨模块共享词表"草案**作废**。
- 组合靠**结构寻址**：`产出者（provenance）+ 位置（会话 / 分叉 / 轮次 / 文件:行号）+ 时间`。
- 目标**不是**"每个模块读全部"（那是上下文污染）；而是把正确的上下文**准确分发给"需要它、且被允许知道它"的模块**。
- **分发机制已定**（2026-09-18 用户确认）：默认 = **读清单 + 上游输出整份装配**（信任上游）；**不做全局引用闭包**；引用按模块决定，下游要原文时用工具取——见 §3.6。

### 3.3 动态上下文 vs 提示词的边界（已定）

- 立论：职责靠**上下文组合**区分，不靠提示词 ⇒ 凡是"给模型看的事实"都算**上下文**。
- 因此 M01 的位置 / 状态、M10 的策略与强度、系统限制，应称 **动态上下文**，不是"动态提示词"。
- 提示词只保留**固定的、与状态无关的最小约定**（如"每条结论带 `文件:行号` 来源"）。
- 判据：**能作为事实被下一个模块继续推理 → 上下文；只是命令模型怎么做 → 提示词。**
- 状态：**口径已定**（放置位置）；**术语已统一**（2026-09-21）——`01` 中“动态提示词”全部改称“动态上下文”。
- **边界已按「放置位置」定**：放进**资产**的是上下文，放进 **system prompt** 的是提示词（不靠句子形态判）。
- **“初步分块”落点已定**：产出侧决定**资产粒度**，运行时决定**选中哪份**（§3.6）。

### 3.4 资产归属与容器（讨论结论）

- 资产**有主**：产出它的模块拥有它，其它模块**只读**。
- **容器由 M01 拥有**：项目 / 会话（闭环）/ 分叉 / 轮次的树。
- 结构：

```text
会话(闭环)
└── 主线 / 分叉
    └── 轮次
        └── [模块] 产出资产   ← 产出者拥有，别人只读
```

- **派生资产** = 处理某资产的那个模块**新产出的资产**，归**产出它的模块**所有，但必须带 provenance 指回原资产。→ 不存在"谁拥有别人的派生品"的问题，派生品本身就是新产出。
- **分叉**：M05 决定路线，M01 保存容器结构；分叉是新对话 / 新闭环，会打断缓存前缀。

### 3.5 明确不做

JSON / schema、固定字段模板、角色提示（"你是某某"）。

### 3.6 分发机制（C-05 / C-04 落点，2026-09-18 用户确认；同日修正）

**结论：默认 = 读清单（结构槽）+ 上游输出整份装配（信任上游）；不做全局“引用闭包”。引用按模块决定；下游要原文时用工具按引用取。**

| 候选 | 处置 | 理由 |
| --- | --- | --- |
| (a) 产出侧分块 | **保留，只到「资产粒度」** | 产出者决定自己输出成**几份资产**，不贴标签、不切子字段 |
| (c) 运行时装配 | **默认机制** | 按读清单取**上游整份资产**；确定性、可测、直接落权限表 |
| (b) 下游工具调取 | **降为显式工具通道** | 只用于取**具体外部内容**（M07 检索、M08 查询）或**按引用回原文审查**；**不作默认分发** |

**三层职责**：

1. **产出侧 = 资产粒度 + 输出完整度**：模块决定输出成几份资产（拆到“可被单独选取”即可），并把自己**下游需要的给全**——**这才是准确性的真正来源**。
2. **运行时 = 装配**（默认）：读清单（结构槽 + 必需 / 条件）→ 按 `产出者 + 位置 + 时间` 取**上游整份资产**；缺必需槽 → 不调用 / 降级并标注；冲突按已定规则（现场 > 历史；M15 候选经 M04 裁决）。
3. **下游 = 默认信任上游输出**；需要具体原文 / 审查引用时，用**工具**取（决策，不是每次必跑）。

**引用（`文件:行号`）的定位**：
- **不是分发步骤**，而是**按模块决定的输出约定**：需可核实 / 可审查 / 可深挖的模块（M04 / M08 / M09 / M15）必须标；纯表达类（M02，可能 M10）可不标。
- 用途：① 审计回原文；② 下游按需用工具取原文 / 审查。**不用于自动装配。**

**两条关键判断**：
- **准确性来自上游输出完整度**（输出契约的活），不来自分发算法，也不来自“顺引用翻原文”。
- **“不靠提示词”仍成立**：装配是把事实填进槽；system prompt 只留最小约定（§3.5）。

**明确不做**：全局“引用闭包”；产出侧语义标签 / 固定模板；下游默认自取全库；语义相似度当选取键。

**已落实**：每模块的**读清单**（结构槽 + 必需 / 条件）见 `01-*` 各模块节（A-03）；**读清单（固定骨架 + 按需组合范围）+ 引用约定**见 §6（C-02）。

### 3.7 新鲜度与防污染（读侧）

> 归属：**运行时装配（读侧）**，不是产出模块。产出模块只管产出（读数 / 来源 / 产出时间）；「谁读、何时读、旧版本怎么办」归本机制。**D-001 归此处，不归 M15。**

1. **产出时间**：每条资产带产出时间。同一槽位出新产出时，旧产出标为**已被取代**——保留（审计用），但**不再作为当前值**。
2. **取最新有效**：装配时取该槽位的**最新有效**一份；**不把新旧版本并喂**。
3. **出界不算「未知」也不算「低权重」**：若某槽位当前没有有效资产，就按**缺槽**处理——缺**必需**槽 → 不发；缺**条件**槽 → 降级并标注。这样旧值无法冒充当前值。
4. **分工**：产出侧不管消费者；消费者不管产出侧。

**已覆盖、不在此列**：越界读（权限表）· 自结论回流（只出不回）· 摘要冒充原文（派生不能结案）· 多源讲法（多存不合并）· 语义标签错配（结构寻址）。

## 4 时间连续性与流式

- 流程随用户回复**逐步产出**，时间连续性强。
- M04 每轮读**完整证据历史**，时间结构从证据重建（不回流自身输出，见 `01` §2.6）。
- 输出流本身构成**时间线**，供下游与审计读取细微差异。
- **两种流式**（讨论结论）：
  - **闭环内流式**：随用户输入逐轮变化（M04 分析、M02 回复、M03 证据）→ 动态上下文是"正在长的那段"。
  - **闭环外流式**：闭环结束后的总结（M09 记录、M05 路线）→ 上下文是"已定格的总结"。
  - 一个模块拿哪种，取决于它属于哪种流式。
- **状态提醒（B-03）按模块设计**：固定骨架 + 可选上下文组合；骨架内容与组合范围在 `01` 各模块节中确定。

## 5 验证（B-04：暂不做）

- 原方案（3 格式 × 4 指标）**暂缓**：用户决议小型测试容易跑偏、偏离主线、消耗时间与 token。
- 代价已知：**"自由文本 + 引用"更适合跨模块资产，目前仍是未验证假设**。设计据此推进，风险自负。
- 若日后要验，方案保留在案：格式 ① 纯自由文本 ② 自由文本 + 来源引用（现行）③ 轻结构；指标：续推质量 / 溯源准确率 / 跨模型跨轮一致性 / 提示词开销。
