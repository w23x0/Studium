## 2 M04 诊断（第一条链）

### 2.1 节点定位（`已确认`）

| 项 | 内容 |
| --- | --- |
| 作用域 | 一个进行中的学习闭环（= 一个 M01 会话承载一个闭环目标） |
| 触发 | 学习者每次输入 / M02、M03 产生新的可观察事实之后；每轮必跑 |
| 模型 | 分析判断强的模型；与 M02 分开选型（M02 看教学行为，见 M02 审查单） |
| 职责 | 在闭环内持续维护可推翻的诊断；区分观测/推断/替代解释/证据限制；追溯前置缺口；按验收范围判断证据是否足够；闭环结束点执行证据守卫 |
| 明确不做 | 不生成面向学习者的讲解/练习（M02/M03）；不给教学建议（M10）；不规划跨闭环路线（M05）；不写 M08；闭环未结束不写 M09；不确认/写入 M15 状态结论，只回发重新确认请求 |
| 呈现 | 内部诊断默认不直接展示给学习者；面向学习者的表达由 M02/M03 转译 |

### 2.2 输入上下文组合

**核心机制**（`已确认`）：M04 的职责由**输入上下文的组合**天然产生，不靠提示词角色设定。输入确定，输出自然确定。

M04 的输入分三层——**不是把各模块的产出拼一遍**（那样会形成回环）：

| 层 | 内容 | 进入方式 | 必需性 |
| --- | --- | --- | --- |
| **① 对话本体** | 当前闭环的**完整对话上下文**；天然包含 M02/M03 的教学与练习动作、学习者表达 | 直接作为上下文主体 | 必需 |
| **② 位置与条件** | 闭环目标 / 验收范围（M01，M05 设定）；路径位置（主线 / 分叉 / 迂回、走到哪）；当前策略与四项强度条件（M10）；系统限制 | **动态上下文**（`02` §3.3） | 必需 |
| **③ 条件接入** | M08 通用知识（前置 / 混淆 / 阈值标记）；M09 个人历史；M15 状态读数 / 候选 | 相关才按需**注入** | 条件 |

**① 对话本体自带**（无需另取）：
- 学习者原始表现：表达、答案、关键步骤、理由、行为
- 教学动作与条件：讲解、追问、提示、答案暴露、脚手架（M02 / M10）
- 练习任务与条件：任务、完成条件、独立程度、挑战程度（M03 / M10）

**② 动态上下文提供**（对话本体里没有的“位置 / 条件”）：
- 闭环目标与验收范围（M01，M05 设定）
- 路径位置：主线 / 分叉 / 迂回、当前位置、分叉范围、返回条件（M01 / M05）
- 当前策略与四项强度条件（M10）
- 系统限制：信息缺失、工具失败、模型降级（运行时）

**③ 条件接入**（与当前目标 / 卡点相关才进；不进则标注）：
- M08：前置、组成、混淆、阈值概念标记 → 判断依据
- M09：已结束闭环的个人形成记录 → 背景参考，**不得覆盖本次证据**
- M15：承载读数、解释候选 → 非知识因素；候选待 M04 评估

**关键区分**（`已确认`）：
- M02/M03 的产出**本来就在对话里**，不需要 M04 再去“读它们的输出”。
- M08/M09/M15 **不在对话内**，只在相关时动态接入，不默认进入。
- M04 **不读取其它模块派生出的结论**，也不读自己的历史输出（§2.6）。
- 与 M04 审查单的输入清单**不冲突**：同一批信息，区别只在“进入方式”（对话本体 / 动态上下文 / 条件接入）。

**选取规则**：
- ① 层取**完整闭环内对话**，不是“近 N 轮摘要”。
- ③ 层按需**精准提取**（与当前目标 / 卡点相关），不是整库塞入。
- 分叉、迂回路径的信息**保留关系**，避免不同任务、不同提示条件相互污染。

### 2.3 证据标记规则（`已确认`方向）

每条可观察事实进入 M04 时必须可回答：**谁产生的、在什么条件下、什么时候、原始位置在哪**。

| 维度 | 规则 |
| --- | --- |
| 来源标记 | 每个事实带 来源模块 + 原始位置（会话/轮次/题目）+ 时间 |
| 提示条件 | 同一正确答案按 独立完成 > 轻微提示 > 多次提示 > 答案已暴露 逐级降权 |
| 证据形态 | 过程证据（步骤/理由/自我解释）> 仅最终答案 |
| 硬/软分级 | 区分原始表现、自述、历史已结束记录、软推断、硬证据 |
| 不可单独采信 | 模型自信、用户自述"我学会了"、心理状态、软画像**均不能单独关闭闭环** |
| 状态候选 | M15 的候选与知识解释**竞争**；裁决属诊断的一部分，不是对 M15 的写入 |

### 2.4 输出上下文资产（推理链）

**形态**（`已确认`）：一条**带来源、证据关系、因果的文字推理链**；逐条、可组合、来源可核实；可被下一模块继续推理 / 替换 / 推翻；被消费后不影响其它模块独立读取。

> 最小约定、引用（=链接）、时间连续性与验证方案见 [`02-上下文资产格式.md`](./02-上下文资产格式.md)。

**分节骨架（`待确认`）**——第一版先做"简单完整的输入输出文字推理链"，不深入 CoT 优化：

| 段 | 内容 | 说明 |
| --- | --- | --- |
| 观测 | 本轮可观察事实（带 §2.3 标记） | 原始，不加工 |
| 当前推断 | 对"会什么/卡在哪"的判断 | 可推翻 |
| 替代解释 | 与主推断竞争的解释 | 保留，不急着收敛 |
| 已评估的状态候选 | 检查了哪些 M15 候选、知识证据支持或排除 | 是诊断，不是状态判断 |
| 未满足项 / 前置缺口 | 距验收范围还差什么 | 供 M10/M05 |
| 需要验证的内容 | 下一步需要什么证据才能推进判断 | 供 M10 选策略 |
| 证据限制 | 信息缺失、降级、不可判断处 | 不伪装成完整诊断 |

**对话级 vs 闭环级**（`已确认`）：两者**输出契约相同**，只是上下文不同（部分历史 vs 完整历史）。闭环是否完成由分析过程自然得出，不强制单独输出。

**示例（文字推理链，示意，非定稿格式）**：

```
[观测] 学习者独立求出 f(x)=x^2 在 x=1 的导数，正确，未用提示。（来源：M03 题A / 闭环第2轮）
[观测] 求 f(x)=sin(x) 在 x=0 的导数时，先卡在"极限定义怎么套"，经轻微提示后正确。（来源：M03 题B / 闭环第3轮）
[推断] 导数的机械求导已可用；导数定义在无提示下不稳定，疑与极限定义的提取有关，而非概念完全缺失。
[替代解释] 也可能是符号书写不熟导致的暂时卡顿；本次证据不足以区分。
[已评估状态候选] M15 候选"负荷偏高"：本轮为单轮、无其它佐证，知识证据可解释，暂不采信。
[未满足项] 缺"独立、无提示下用定义求导"的证据；几何意义未取证。
[需要验证] 一道独立无提示的定义求导题 + 一道几何意义复述。
[证据限制] 本轮未采集草稿过程，符号不熟这一替代解释无法排除。
```

### 2.5 交接（类型化边）

| 方向 | 接收方 | 交接内容 | 边界 / 契约 |
| --- | --- | --- | --- |
| M04 → M02 | 教学互动 | **最新一轮分析**（作为核心层上下文） | M02 必须先拿 M04 分析再生成回复；M04 不代 M02 表达 |
| M04 → M03 | 练习活动 | 当前诊断、需验证的内容（经 M02/M10 组织成活动） | M04 不直接出题；练习生命周期归 M03 |
| M04 → M10 | 教学策略 | 诊断事实、替代解释、证据限制、未满足项、需验证内容 | M10 据此选策略与四项强度；M04 不给教学建议 |
| M04 → M05 | 路线规划 | 改线依据（需补前置 / 分叉 / 搁置 / 重规划） | M05 决定路线，M01 落实；M04 不建分叉 |
| M04 → M01 | 会话 | 闭环完成通知 + 理由摘要 + 未完成事项 | M01 只执行生命周期变更，不判掌握 |
| M04 → M09 | 个人知识 | 闭环结束**一次**提交总体诊断与个人形成记录 | 未结束不写；守卫通过是唯一过渡点 |
| M04 → M15 | 学习者状态 | **仅**"某状态需重新确认"的请求，不带结论 | 严格单向 M15→M04 的反向例外只有请求边 |
| M04 → M13/过程记录 | 跨模块技术设计 | 完整动态过程、判断变化、降级与审查事实 | 日志基础设施归后续，M04 只拥有诊断语义 |

### 2.6 闭环工作缓存与"自身不回流"（★核心）

**缓存定位（已统一 2026-09-13）**：
- 工作缓存保存**源上下文与证据**，不保存 M04 自身结论作为下一轮输入；跨轮连续性来自完整证据历史，不来自回灌结论。
- M04 的每轮结论是**只出不回**的输出流：M02 取最新、M09 闭环结束一次、M13 留存审计。
- 前文 `M04-01` 原“中间诊断进入工作缓存”的措辞已改写为与本规则一致。
- 缓存的存储位置、字段、冻结与失效规则：`暂缓`（`00` 标注“存储边界暂不确定”）。

### 2.7 与 M15 同源不同契约（组合层示范）

| 项 | M04 | M15 |
| --- | --- | --- |
| 频率 | 每轮必跑 | 低频（事件触发 + 会话收尾，暂定） |
| 读的字段 | 当前闭环对话、闭环目标、诊断相关 | 跨会话启动间隔、状态可观察事实 |
| 输出 | 诊断与证据判断 | 承载读数 / 解释候选 |
| 隔离实现 | **靠上下文组合不同，不靠同数据 + 不同 prompt** | 同左 |
| 关系 | 严格单向 M15→M04；M04 仅回发重新确认请求 | M15 不读 M04/M09 知识结论 |

要点：两者**拿的字段不同**，本质是**不同的上下文**，不是"同一份数据用不同提示词约束"。两者独立执行、不能合并。

### 2.8 失败与降级

| 情形 | 处理 |
| --- | --- |
| 上下文不完整 / 关键来源不可用 | 把限制纳入诊断，必要时只输出"证据不足"，不伪装完整 |
| 模型或服务降级 | 遵循横切原则 1：能力等价才可降级且必须留痕可见；不等价应失败 |
| 证据不足 | 保持进行中、进入复检或标搁置；**不得**因模型/自述/画像/单次表现关闭闭环 |
| 分叉中的表现 | 保留路径关系，不直接判定为主线缺口 |

### 2.9 M04 输入清单与缺料 / 冲突规则（A-03 的 M04 落地）

**输入清单**（每轮拼上下文时对照）：

| 输入 | 层 | 缺失时 |
| --- | --- | --- |
| 闭环目标 + 验收范围 | ② 位置与条件 | **不发**（没有目标无法判断“是否达成”） |
| 当前对话本体 | ① 对话本体 | **不发**（空对话无意义） |
| 路径位置 | ② 位置与条件 | 降级：按“位置未知”处理，并在输出标注 |
| 策略与四项强度条件 | ② 位置与条件 | 降级：标注“教学条件缺失”，证据权重不可判 |
| M08 通用知识 | ③ 条件接入 | 继续，标注“缺通用知识依据”（前置缺口判断受限） |
| M09 个人历史 | ③ 条件接入 | 继续，标注“缺历史背景” |
| M07 资料原文 / 出处 | ③ 条件接入 | 继续，标注“缺资料依据”（证据核查受限） |
| M15 状态读数 / 候选 | ③ 条件接入 | 继续，标注“缺状态信息”（非知识因素不可判） |
| 系统限制 | ② 位置与条件 | 由运行时按实情注入 |

**规则**（`已确认`，2026-09-21；A-03）：

1. **必需 / 条件**：只有 ① 对话本体 + ② 的“目标 / 位置”缺了不能开工；其余缺失一律**降级 + 标注**，不中止。
2. **缺料检查由运行时做**：每个模块配一张“必需输入清单”，缺必需项就不发；不指望模型自查。
3. **冲突听谁的**：
   - 对话内**现场证据**优先于 **M09 历史背景**（M09 不得覆盖本次证据，`已确认`）。
   - M15 **解释候选**与知识解释竞争 → M04 裁决（`已确认`）。
   - M08 通用知识是**判断依据**，不与现场证据构成冲突。
4. **不读派生结论**：M04 不把其它模块的结论、也不把自己的历史输出当输入（§2.6）。

## 3 M10 教学策略（第二条链）

### 3.1 节点定位（`已确认`）

| 项 | 内容 |
| --- | --- |
| 作用域 | 进行中的学习闭环内（会话内级别） |
| 触发 | M04 产出新诊断后；需重新选择 / 调整策略时 |
| 职责 | 依据 M04 诊断 + M15 状态条件 + 自身策略模型，选择当前策略，产出策略目标、活动倾向、四项强度条件、选择理由 |
| 明确不做 | 不重做诊断（M04）；不拥有闭环守卫；不决定目标 / 分叉 / 收束 / 返回 / 跨闭环路线（M05）；不写 M09 |
| 双重模型 | 通用策略知识层 + 个人策略过程与效果层（M10 自有，不写 M09） |
| 四项强度所有权 | 信息量 / 提示强度 / 挑战程度 / 节奏**只由 M10 拥有**，M02/M03 只执行不自定 |

### 3.2 输入上下文组合

M10 与 M04 不同：它**不读完整对话本体**，而主要读**上游模块加工后的资产** + 自有策略模型 + 位置上下文。

| 层 | 内容 | 进入方式 | 必需性 |
| --- | --- | --- | --- |
| **① 上游资产** | M04 的当前诊断（核心）；M15 的承载读数与已裁决候选 | 结构寻址读取（`02` §3.2） | 必需 |
| **② 位置与条件** | M01 闭环目标 / 位置；M05 目标范围与验收；学习者在会话中**显式提出**的现实需求 | 动态上下文 | 必需 |
| **③ 条件接入** | M08 阈值概念标记 + **前置 / 组成（当前目标相关片）**（强度取值 / 活动选择）；M04 阈值概念跨闭环读数；M15 状态阶段读数 | 相关才注入 | 条件 |
| **自有模型** | 通用策略知识层 + 个人策略过程与效果层 | 模块自有 | 必需 |

关键点：
- **不读对话本体**：M10 拿的是 M04 加工后的诊断，不是原始对话——这正是“模块围绕上下文资产加工”的例子。
- **不自行判断 M15 候选真假**：以 M04 输出中“已评估的状态候选”为准。
- **成因自查义务**：读到“带策略标注”的状态时，先查自身策略是否为成因，再当学习者固有条件——否则 M10 会依据自己制造的后果调策略。
- **学习者请求（`D-20`）**：当**普通对话轮**，**不建专用通道**；产品给 M10 的「当前用户需求」照常读。请求对策略的影响归 M10（M10 不必须照做），习惯靠 M15 被动推断。

### 3.3 输出资产（策略与四项强度）

形态：同 `02` 的文字资产 + `文件:行号` 来源。内容（`已确认`）：

- 当前策略选择 + 选择理由
- 活动倾向：偏输入 / 引导建构 / 独立练习 / 变式验证 / 反馈修正…
- 策略目标
- **强度条件**：信息量、提示强度、挑战程度、节奏——是给 M02/M03 的**可执行规格**（**自由文本**，不必凑成四项；**不是给 M15** 的，M15 是约束输入）；由 M10 自己判，不锚到 M04 字段
- 个人策略过程记录更新

边界：M10 只给“策略目标与强度条件”，**不给面向学习者的讲解 / 练习正文**（M02/M03 负责）。

### 3.4 交接

| 方向 | 内容 | 边界 |
| --- | --- | --- |
| M04 → M10 | 诊断事实 / 替代解释 / 证据限制 / 未满足项 / 需验证 | M10 不重诊断 |
| M15 → M10 | 承载读数直连；已裁决候选 | M10 不判候选真假 |
| M10 → M02 | 策略目标、活动倾向、四项强度条件 | M02 只执行不自定 |
| M10 → M03 | 同上（练习侧） | M03 不自定挑战升降 |
| M10 → 自有策略记录 | 策略与后续 M04 判断 | 不写 M09 |

### 3.5 失败 / 降级 / 缺料 / 冲突规则（A-03 的 M10 落地）

**规则 1–4 同 §2.9**（必需 / 条件、缺料检查由运行时做、冲突听谁的、不读派生结论）。本节只列 M10 自己的输入清单与冲突。

| 输入 | 层 | 缺失时 |
| --- | --- | --- |
