# 知识表示「多来源不合并 + 链接」可借鉴方法（发现）

> 目的：为自学系统调研「别人已经怎么解决」——多来源不合并、可回到原文、通用/个人分离、候选/审计/晋升、只追加/版本/可回退、个人视图。
> 面向 agent 阅读：表格优先、结论密集、每条带一手来源。
> 来源分级：★=正式标准/规范（W3C/IETF/IEEE/ISO），●=项目/产品官方文档（一手），◆=单篇论文/提案（非标准）。
> 需求编号：**R1** 多来源不合并+关系类型化（同一件事/特例/矛盾/别名）；**R2** 可回到原文；**R3** 通用 vs 个人分离；**R4** 候选/审计/晋升；**R5** 只追加/版本/可回退；**R6** 个人视图派生。
> 注：本文不引用、不依赖仓库内任何单次实验结果（含 `docs/图工程调研/`）。

## 0. 判定基线（贯穿全文的 4 个原则）

| # | 原则 | 一句话依据 | 来源 |
|---|------|-----------|------|
| P1 | **链接 ≠ 合并**。两个 IRI 可以"指同一物"而保留各自节点，边是可追加、可撤销的 | SKOS 把映射做成独立属性集；OWL 的 `sameAs` 是**等价断言**而非数据结构操作 | [SKOS §10](https://www.w3.org/TR/skos-reference/#mapping) · [OWL2 语法 §9.6.1](https://www.w3.org/TR/owl2-syntax/#Individual_Equality) |
| P2 | **断言/陈述应是一等公民**，可被单独标注来源、时间、置信度、状态 | RDF 1.2 引入 triple term + `rdf:reifies`；nanopublication 以"单条断言"为发布单位 | [RDF 1.2](https://www.w3.org/TR/rdf12-concepts/) · [nanopub.net](https://nanopub.net/) |
| P3 | **锚点要抗漂移**：同时存"引文原文 + 前后文 + 位置"，而非单一 offset | W3C `TextQuoteSelector`(exact/prefix/suffix)；Hypothesis fuzzy anchoring | [Annotation Model](https://www.w3.org/TR/annotation-model/#selectors) · [Fuzzy Anchoring](https://web.hypothes.is/blog/fuzzy-anchoring/) |
| P4 | **只追加 + 派生视图**：事实不可变，状态由事件/事务重放或 `as-of` 派生；修订=新记录 | Datomic datom、event sourcing、git 对象、xAPI 不可变语句 | [Datomic](https://docs.datomic.com/) · [Event Sourcing](https://martinfowler.com/eaaDev/EventSourcing.html) |

## 2.1 关系类型化：多来源、不合并、只连边

| 机制 | 是什么（一手定义） | 来源 | 服务的需求 | 风险 / 不适用 |
|------|------------------|------|-----------|--------------|
| `skos:exactMatch` / `closeMatch` | 跨词表映射：exactMatch=高置信可互换且**传递**；closeMatch=仅部分场景可互换且**故意不传递**（防"复合错误"） | ★[SKOS §10](https://www.w3.org/TR/skos-reference/#mapping) | R1：把"同一件事"分成两档，弱等价可撤销 | exactMatch 传递闭包仍会放大错误，慎用 |
| `skos:broadMatch` / `narrowMatch` / `relatedMatch` | 特例/上位/关联映射；narrowMatch 是 broadMatch 的逆 | ★[同上](https://www.w3.org/TR/skos-reference/#mapping) | R1：表达"是特例/更一般/仅相关" | 未声明传递；需自行定闭合规则 |
| `skos:broader/narrower`（非映射） | 同一词表内的层级；**非传递**、允许多个 broader（多父） | ★[SKOS §8](https://www.w3.org/TR/skos-reference/#semantic-relations) | R1/R6：图不是树；同一概念可挂多个上位 | 与 mapping 属性混用会让"词表内/跨词表"语义含糊 |
| `owl:sameAs` / `owl:differentFrom` / `AllDifferent` | 个体相等/不等断言；`sameAs` 是**等价关系**（自反/对称/传递） | ★[OWL2 语法 §9.6.1](https://www.w3.org/TR/owl2-syntax/#Individual_Equality) · [OWL2 Primer](https://www.w3.org/TR/owl2-primer/) | R1：可写"别名/不同物" | `sameAs` 一旦断言即不可撤销地"合并语义"，见 §2.9 |
| 本体对齐（ontology matching/alignment） | 产出**对齐集**（correspondence 列表），不修改本体、不合并本体 | ★OAEI [oaei.ontologymatching.org](http://oaei.ontologymatching.org/) · ●[Alignment API](http://alignapi.gforge.inria.fr/) · ◆[Euzenat & Shvaiko 书](https://link.springer.com/book/10.1007/978-3-642-38721-0) | R1：对齐作为独立、可版本化的产物 | 主流方法追求**全量对齐**；我们要的是按需局部对齐 |
| EDOAL（对齐表达语言） | 用带关系（equiv/subsum/instance…）的对应式表达对齐，含置信度 | ●[Alignment API/EDOAL](http://alignapi.gforge.inria.fr/edoal.html) | R1：把"等价判断"记录成**带类型、带分数的链接** | 生态偏学术，工具链重 |
| 标识符交叉引用 | 同一实体多个外部 ID 并列保留（不选一个当"真身"） | ●[Bioregistry](https://bioregistry.io/) · ●[Identifiers.org](https://identifiers.org/) | R1/R2：天然"一物多号、号各有源" | 需自建映射维护流程 |

## 2.2 断言即一等公民（reification / RDF-star / named graph / nanopub）

| 机制 | 是什么 | 来源 | 服务的需求 | 风险 / 不适用 |
|------|--------|------|-----------|--------------|
| RDF 1.1 reification | 用 `rdf:Statement/subject/predicate/object` 描述一个三元组；**规范中是非规范性的**（informative） | ★[RDF 1.1 Semantics 附录 D](https://www.w3.org/TR/rdf11-mt/#rdf-reification-containers-and-collections) | R2：给三元组挂来源/置信 | 冗长、四元组重复、语义弱；**不推荐作为主方案** |
| RDF 1.2 triple terms + `rdf:reifies` | 三元组可作为词项出现在宾语位；reifier 是"关于该命题的断言"，命题**可先不断言为真** | ★[RDF 1.2 Concepts §1.5](https://www.w3.org/TR/rdf12-concepts/) · WG [charter](https://www.w3.org/2022/08/rdf-star-wg-charter/) · ◆[Foundations (arXiv 2107.00156)](https://arxiv.org/abs/2107.00156) | R1/R2/R4：一条陈述连同其来源/状态被整体建模 | 标准仍在推进；生态支持参差 |
| Named graphs / RDF datasets | 一个数据集 = 默认图 + 若干"名字→图"对；**图名语义未统一** | ★[RDF 1.1 Datasets](https://www.w3.org/TR/rdf11-datasets/) · ◆[Carroll et al., Named Graphs, Provenance and Trust](https://dl.acm.org/doi/10.1145/1060745.1060835) | R1/R3：按来源/主体分图，天然隔离不合并 | 语义有 7 种可选解释；若默认图取 union 就等价于"合并"，需显式选语义 |
| Nanopublications | 三个命名图：**Assertion**（一条原子断言）+ **Provenance**（如何得出）+ **Publication Info**（谁/何时/许可） | ●[nanopub.net](https://nanopub.net/) · ●[guidelines](https://nanopub.net/docs) · ◆[Groth et al. 2010, doi:10.3233/ISU-2010-0613](https://doi.org/10.3233/ISU-2010-0613) | R1/R2/R4/R5：断言粒度、自带溯源、可引用、可被新 np 取代/撤回 | 学术生态为主；需自建本地存储与索引 |
| PROV-O / PROV-DM | 通用溯源模型，含 `alternateOf`、`specializationOf`、`wasRevisionOf`、`wasQuotedFrom`、`invalidatedAtTime` | ★[PROV-O](https://www.w3.org/TR/prov-o/) · ★[PROV-DM §5.5](https://www.w3.org/TR/prov-dm/) | R1/R5：表达"同源异形/特化/修订/转引"，**替代 sameAs** | 需要建模纪律；`alternateOf` 语义较宽，须在文档内收紧 |

## 2.3 锚定原文：把断言锚到片段（R2）

| 机制 | 是什么 | 来源 | 服务的需求 | 风险 / 不适用 |
|------|--------|------|-----------|--------------|
| W3C Web Annotation Data Model | annotation = body（内容）+ target（被注资源），支持多种 **Selector** | ★[Annotation Model §3.2](https://www.w3.org/TR/annotation-model/#selectors) · ★[Annotation Vocab](https://www.w3.org/TR/annotation-vocab/) | R2：标准化"断言↔原文片段" | 只给模型，不管抽取；需自定粒度策略 |
| `TextQuoteSelector` | 按**复制文本（exact）+ 前文 prefix + 后文 suffix** 选择，用于消歧同文多处 | ★[§3.2.3/text-quote](https://www.w3.org/TR/annotation-model/#selectors) | R2：抗改动的引文锚点 | prefix/suffix 取多长需权衡；无跨语言/OCR 处理 |
| `TextPositionSelector` / `FragmentSelector` / `RangeSelector` / `CssSelector` / `XPathSelector` | 字符区间 / URI 片段（如 `#xywh`） / 起止选择器 / DOM 选择器 | ★[同上](https://www.w3.org/TR/annotation-model/#selectors) | R2：PDF、DOM、区间等多种载体 | 纯位置/选择器锚点会随文档改动漂移，宜与引文锚点**并用** |
| Selector 精化（refinement） | 在粗选择器上用 `refinedBy` 叠加细选择器 | ★[§4.2.9 Refinement](https://www.w3.org/TR/annotation-model/#refinement-of-selection) | R2：多粒度定位（页→段→句） | 需实现解析优先级 |
| Hypothesis fuzzy anchoring | 先精确匹配引文，再前后文、再模糊匹配，实现鲁棒再锚定；代码即规范 | ●[Fuzzy Anchoring](https://web.hypothes.is/blog/fuzzy-anchoring/) · ●[client anchoring 模块](https://github.com/hypothesis/client/tree/main/src/annotator/anchoring) | R2：文档改动后仍能定位 | Web 文本场景；PDF 支持有限 |
| Memento（RFC 7089） | 基于时间的内容协商（Accept-Datetime / TimeMap）取"某时刻版本" | ★[RFC 7089](https://www.rfc-editor.org/rfc/rfc7089) | R2/R5：锚到**当时**的原文版本 | 需存档端支持；自建存储可简化 |

## 2.4 学术知识图谱怎么表示"同实体的多种说法/来源"

| 系统 | 建模单位与多来源做法 | 来源 | 可借点 | 风险 / 不适用 |
|------|---------------------|------|--------|--------------|
| OpenAlex | `Work/Author/Venue/...` 实体；每个 Work 有 `ids`（openalex/doi/mag/pmid…），重复记录**去重合并到一个 Work** | ●[docs.openalex.org](https://docs.openalex.org/) · ●[Work object](https://docs.openalex.org/api-entities/works/work-object) · ◆[arXiv 2205.01833](https://arxiv.org/abs/2205.01833) | 一实体多外部 ID 的字段设计；大规模去重流程 | 它是**合并式**去重，与 R1"不合并"目标相左，只借 ID 结构不借合并 |
| Semantic Scholar | `Paper` 实体 + `externalIds`（DOI/ArXiv/PubMed…）；S2 Corpus 做消歧 | ●[API docs](https://api.semanticscholar.org/api-docs/) · ◆[arXiv 2301.10140](https://arxiv.org/abs/2301.10140) | 外部 ID 作为"多说法"的桥梁 | 同上，中心化合并 |
| Wikidata | 议题(item) + **陈述**(property→value) + **限定符**(qualifier) + **来源**(reference) + **rank**；同一属性允许多值 | ●[Help:Statements](https://www.wikidata.org/wiki/Help:Statements) · ●[Help:Ranking](https://www.wikidata.org/wiki/Help:Ranking) · ●[Help:Sources](https://www.wikidata.org/wiki/Help:Sources) | R1/R4：**多值并存 + 每值自带来源与优先级** | 仍以"单议题"为中心，本质是聚合而非多源并列 |
| Wikidata P460 / P1889 | `P460 said to be the same as`（"据说同一，可能存疑/有争议"）与 `P1889 different from`（"易混淆但不同"） | ●[P460](https://www.wikidata.org/wiki/Property:P460) · ●[P1889](https://www.wikidata.org/wiki/Property:P1889) | R1：**把等价做成可争议、可撤销的属性**而非合并 | 属维基社群约定，非形式语义保证 |
| DBpedia | 从维基箱抽取 + 本体（DBO）；用 `owl:sameAs` 做跨库互联 | ●[DBpedia Ontology](https://www.dbpedia.org/resources/ontology/) · ◆[Auer et al. 2007](https://link.springer.com/chapter/10.1007/978-3-540-76298-0_52) | 大规模互联的先例 | `sameAs` 互联正是争议源头，见 §2.9 |

## 2.5 只追加 / 版本 / 可回退（R5）

| 机制 | 是什么 | 来源 | 服务的需求 | 风险 / 不适用 |
|------|--------|------|-----------|--------------|
| Git 对象模型 | content-addressable 键值库；对象不可变，提交形成 DAG，分支/回退是移动指针 | ●[Pro Git: Git Objects](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects) | R5：只追加、完整历史、可回退 | 面向文本/文件，不直接表达"链接/断言" |
| Datomic | 数据库=不可变 datom 集合；事务只增不改；支持 `as-of` 时间点查询、完整审计 | ●[Datomic 文档](https://docs.datomic.com/) | R5/R6：事实不可变 + **从历史派生任意视图** | 需引入 datalog/架构；是数据库不是本体 |
| Event Sourcing | 所有状态变更记为事件序列，当前状态由重放派生；可回溯任意时点 | ●[Fowler, Event Sourcing](https://martinfowler.com/eaaDev/EventSourcing.html) | R5/R6：追加式日志 + 派生读模型 | 需要快照/投影策略，否则重放变慢 |
| CRDT | 副本各自更新、无需协调即可收敛（强最终一致） | ◆[Shapiro et al. 2011 (HAL)](https://hal.inria.fr/inria-00609399) · ●[Local-first software](https://www.inkandswitch.com/local-first/) | R5：离线/多端追加不冲突 | **自动合并语义**与"不合并"冲突；冲突仲裁不可省 |
| W3C DWBP BP7/BP8 | "提供版本指示""提供版本历史"为数据发布最佳实践 | ★[DWBP §8.6](https://www.w3.org/TR/dwbp/) | R5：版本元数据的最小约定 | 仅指导性（Best Practice） |
| DCAT v3 | 数据集/分发可声明 `hasVersion/isVersionOf/previousVersion/replaces` | ★[DCAT 3](https://www.w3.org/TR/vocab-dcat-3/) | R5：数据集级版本链 | 面向目录，不覆盖条目级修订 |
| xAPI 不可变 + voiding | 语句**不可修改**；如需撤销，发一条 `voided` 语句指向原语句 | ★[IEEE 9274.1.1 的规范文本 xAPI Data §2.3](https://github.com/adlnet/xAPI-Spec/blob/master/xAPI-Data.md) | R5/R4：撤销而不删；个人记录同样只追加 | xAPI 语句粒度面向"学习经历"，非知识断言 |

## 2.6 多粒度：概念 / 陈述 / 表述（避免"图被误读成树"）

| 粒度层 | 代表单位 | 来源 | 可借点 | 风险 |
|--------|---------|------|--------|------|
| 概念/词项 | SKOS Concept；OWL Class | ★[SKOS §8](https://www.w3.org/TR/skos-reference/#semantic-relations) | 一个概念允许多个 broader → **多父、非树** | 层级关系可成环（SKOS 允许），需应用侧防环 |
| 陈述（三元组） | RDF triple / RDF 1.2 triple term | ★[RDF 1.2](https://www.w3.org/TR/rdf12-concepts/) | 把"一句断言"作为可标注单位 | 需要 reifier 约定 |
| n 元关系 | 把关系实例化为节点，再挂属性 | ★[W3C n-ary Relations Note](https://www.w3.org/TR/swbp-n-aryRelations/) | 给"关系本身"加来源/时间/置信 | 模式设计成本 |
| 原子断言/表述 | Nanopublication Assertion | ●[nanopub.net](https://nanopub.net/) | 最小发布+引用单位，天然防"图被当成单棵目录树" | 需索引聚合视图 |
| 开放世界/无唯一名 | OWL 不假设"不同名=不同个体"、不假设封闭世界 | ★[OWL2 Primer](https://www.w3.org/TR/owl2-primer/) | 支撑"多条记录可能指同物"而**无需合并** | 会带来不确定性，需要显式 `differentFrom` 才能否定同一 |

## 2.7 候选 / 审核 / 晋升工作流（R4）

| 先例 | 机制 | 来源 | 服务的需求 | 风险 / 不适用 |

| Gene Wiki / Gene Wiki 2.0 | 先用权威库生成条目底稿，再由社区协作补充；后迁移到 Wikidata 做语义化 | ◆[Huss et al. 2008](https://journals.plos.org/plosbiology/article?id=10.1371/journal.pbio.0060175) · ◆[Gene Wiki 2.0, doi:10.1093/database/baw015](https://doi.org/10.1093/database/baw015) | R4：机器起草 + 社区审核的分工 | 领域特定，流程不可直接移植 |
| SHACL | 用 shapes 校验图数据，产出合规报告，可作**自动晋升闸门** | ★[SHACL](https://www.w3.org/TR/shacl/) | R4：晋升前的机器可执行检查 | 只校验结构/约束，不判内容对错 |

## 2.8 个人 vs 通用分离（R3 / R6）

## 2.9 "等价判断"记录成可撤销链接（R1，sameAs 争议）

| 观点/机制 | 要点 | 来源 | 对我们的意义 |
|-----------|------|------|-------------|
| `sameAs` 的代价 | 在开放世界 + 无唯一名假设下，`sameAs` 传播所有属性；一旦断言错误会**级联污染**且难以撤回；不同来源用同一 IRI 指不同物时尤其危险 | ◆[Halpin & Hayes, LDOW2010](https://ceur-ws.org/Vol-628/ldow2010_paper09.pdf) · [OpenAlex 记录](https://openalex.org/W1555453389) | **不要把合并当作去重手段**；把"等价"降级为可争议、带来源、可撤销的边 |
| 弱化为带类型的映射 | 用 `closeMatch`（非传递）/ `broadMatch` 等替代全局等价 | ★[SKOS §10](https://www.w3.org/TR/skos-reference/#mapping) | 表达"叫法不同/特例/仅相关"而保留双节点 |
| 降级为"据说同一" | Wikidata P460 = "said to be the same as"（可能存疑/争议）；P1889 = "different from" | ●[P460](https://www.wikidata.org/wiki/Property:P460) · ●[P1889](https://www.wikidata.org/wiki/Property:P1889) | 把等价做成**普通陈述**，可被来源、rank、讨论约束 |
| 用溯源关系代替等价 | `prov:alternateOf` / `specializationOf` / `wasRevisionOf` / `wasQuotedFrom` | ★[PROV-DM §5.5](https://www.w3.org/TR/prov-dm/) · ★[PROV-O](https://www.w3.org/TR/prov-o/) | 表达"同源异形/特化/修订/转引"，不主张全局同一 |
| 可撤销/可修订的信念 | 信念修正理论（AGM）提供"扩张/修订/收缩"的形式化 | ◆[SEP: Logic of Belief Revision](https://plato.stanford.edu/entries/logic-belief-revision/) | 为"矛盾并存 + 可撤销晋升"提供理论词汇（非工程规范） |
| 记录为可重跑的去重 | 实体消歧/去重是**带不确定性、需持续维护**的过程，而非一次性改写主键 | ●[OpenAlex docs](https://docs.openalex.org/) · ◆[arXiv 2205.01833（论文自述去重仍在改进）](https://arxiv.org/abs/2205.01833) | 等价=链接+置信度+来源，可随时撤销、重跑 |

| 需求 | 首选可借机制（标准优先） | 备选/补充 |
|------|------------------------|----------|

## 4. 最值得借的 3–5 条

1. **SKOS 映射属性集 + PROV 实体关系 = "不合并只连边"的现成词汇表。**
   用 `closeMatch`（非传递，防复合错误）表达"叫法不同/可互换"，`broadMatch/narrowMatch` 表达"特例/更一般"，`relatedMatch` 表达"仅相关"，再用 `prov:alternateOf / specializationOf / wasRevisionOf / wasQuotedFrom` 表达"同源异形/特化/修订/转引"。
   → R1，直接可用；标准成熟。来源：[SKOS §10](https://www.w3.org/TR/skos-reference/#mapping)、[PROV-O](https://www.w3.org/TR/prov-o/)。

2. **把等价从"合并"降级为"可争议的陈述"（Wikidata P460 + Halpin 教训）。**
   `owl:sameAs` 会不可撤销地传播属性、级联污染；改用 P460 式的"said to be the same as"普通陈述，附来源、rank、置信度，随时可撤销。
   → R1/R4；避免全局去重陷阱。来源：[Wikidata P460](https://www.wikidata.org/wiki/Property:P460)、[Halpin & Hayes](https://ceur-ws.org/Vol-628/ldow2010_paper09.pdf)。

3. **Nanopublication 三图结构 = 断言粒度 + 自带溯源 + 可被取代。**
   Assertion / Provenance / Publication Info 三命名图，正好对应"每条内容可溯源、可审计、可修订为新版本（不删旧）"；配合 RDF 1.2 `triple term + rdf:reifies` 获得标准化的陈述级标注。
   → R2/R4/R5。来源：[nanopub.net](https://nanopub.net/)、[RDF 1.2](https://www.w3.org/TR/rdf12-concepts/)。

4. **W3C Web Annotation 的选择器组合 = 抗漂移的原文锚。**
   同时存"引文 exact + prefix/suffix + 位置/范围"，用 `refinedBy` 做多粒度精化；参照 Hypothesis fuzzy anchoring 做再锚定。
   → R2；标准 + 成熟开源实现。来源：[Annotation Model §selectors](https://www.w3.org/TR/annotation-model/#selectors)、[Fuzzy Anchoring](https://web.hypothes.is/blog/fuzzy-anchoring/)。

5. **Datomic/事件溯源/Git 的"不可变事实 + 派生视图"= 只追加、可回退、可派生个人视图。**
   变更=追加记录；当前状态/个人边界=按时间或主体**查询派生**（as-of / 投影 / 读模型），修订=新增而非覆盖。
   → R5/R6；与 xAPI 不可变语句 + voiding 同构。来源：[Datomic](https://docs.datomic.com/)、[Event Sourcing](https://martinfowler.com/eaaDev/EventSourcing.html)、[Git Objects](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects)。

## 5. 明确不该借的

| 不该借 | 为什么 | 来源（反例/依据） |
|--------|--------|------------------|
| 用 `owl:sameAs` 做去重/合并 | 等价+传递，错误会级联且不可撤销；正是多源场景最大风险 | [Halpin & Hayes](https://ceur-ws.org/Vol-628/ldow2010_paper09.pdf)、[SKOS 为何让 closeMatch 非传递](https://www.w3.org/TR/skos-reference/#mapping) |
| 一次性构建全学科本体/全量对齐 | 违背"按需局部构建"；OAEI 式全量匹配成本高、维护难 | [OAEI](http://oaei.ontologymatching.org/) |
| 把 RDF 1.1 reification 当主方案 | 冗长、语义弱、规范中仅为 informative | [RDF 1.1 Semantics 附录 D](https://www.w3.org/TR/rdf11-mt/#rdf-reification-containers-and-collections) |
| 让命名图默认取 union/merge 语义 | 会把多来源偷偷合并，与 R1 直接冲突 | [RDF 1.1 Datasets 的多种语义](https://www.w3.org/TR/rdf11-datasets/) |
| 用覆盖/删除处理修订 | 丢失审计与回退能力；应只追加 + void/新版本 | [xAPI 不可变与 voiding](https://github.com/adlnet/xAPI-Spec)、[Fowler](https://martinfowler.com/eaaDev/EventSourcing.html) |
| 把 CRDT 自动合并当默认 | 自动收敛=自动合并；知识层冲突需显式仲裁，不能静默合并 | [Shapiro et al.](https://hal.inria.fr/inria-00609399) |
| 只用单一 offset/位置锚点 | 文档一改就漂移；应引文+上下文+位置并用 | [Annotation Model selectors](https://www.w3.org/TR/annotation-model/#selectors) |
| 照搬 Wikipedia 全开放编辑 | 无门槛会淹没审核；只借其"草稿→评审→晋升"流程而非开放度 | [Wikipedia:Drafts](https://en.wikipedia.org/wiki/Wikipedia:Drafts) |
| 借 OpenAlex/S2 的中心化"合并式"实体模型 | 目标函数不同：它们要单一权威记录，我们要多源并存 | [OpenAlex docs](https://docs.openalex.org/) |
