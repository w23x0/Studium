# 跨会话记忆格式：Claude / OpenAI Codex 现状

> 状态：外部线索，**不作产品结论**（2026-11-05 调研，#83 设计前取料；子代理 Sonnet 取料，主会话抽查 5 处回原文核对一致）。
> 读到的版本：Claude Code 文档页写到 v2.1.309，changelog 顶部 2.1.318；Codex 源码 openai/codex@e8e3197（2026-11-05）；openai-cookbook@0f38c4a（2026-11-03）；deepseek-harness@fcc0ad46（2026-11-04）。

## 0 结论（先看这里）

1. **没有任何一家官方明说“模型训练时适配过某种记忆格式”**。Claude 侧文档只对 bash / text_editor 说 schema 内置于模型（memory tool 页没这句，只能推断），CLAUDE.md、auto memory 全是外壳约定。Codex 侧 cookbook 明说 AGENTS.md “the model has been trained to closely adhere to these instructions”，而自定义工具（含 memory）“hasn’t necessarily been post-trained”。“哪种格式模型最顺手”没有厂商背书的答案，能拿到的是各家推荐写法（§2）。
2. **两家跨会话记忆同形：常驻索引 + 按需读的主题文件 + 压缩器**。Claude Code：`MEMORY.md`（读前 200 行或 25KB）+ topic 文件；Codex：`memory_summary.md`（注入，截断 2,500 token）+ `MEMORY.md` + `rollout_summaries/`；Anthropic 服务端 Managed Agents memory stores 同形（目录挂载 + 每条 ≤100 kB）。
3. **Codex 的记忆由外壳后台写，不由主模型写**：模型一般只读，用户明确要求时只能追加一张 note、下次整合应用。Claude Code 的 auto memory 由主模型用 Write / Edit 自己写。
4. **两家都建议记忆装“工作方式与教训”，不装案例事实或能从代码推出的东西**：OpenAI cookbook “Do not treat Memory() as an unreviewed fact database.”；Anthropic auto memory 跳过可从代码推导的，Fable 5 提示页 “Don’t save what the repo or chat history already records”。
5. **“进度 / 待办”两家都在退**：Claude Code 的 Task 工具 v2.1.233 起对 Opus 4.8、Sonnet 5、Fable 5、Mythos 5 及更新模型默认不提供；Codex `update_plan` 只发事件不另存。跨会话进度靠文件（progress 文件 + JSON 清单 + git）或 Codex 的持久化 goal。
6. **Claude Code Projects（beta）与 Studium 结构同形**：常驻主对话 + 多线程，项目级记忆 + 项目指令，线程启动读索引（§1 第 13 行）。
