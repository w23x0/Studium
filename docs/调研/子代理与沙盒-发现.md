# 子代理与沙盒（#62）

> 状态：外部调研（2026-10-26，云端；子代理查一手资料、主会话抽查 sdk 类型定义），**不作结论**；结论见 `../设计/会话/页面子代理.md`。对象：`@anthropic-ai/claude-agent-sdk` 0.3.293（原型所装）与官方文档 code.claude.com。社区只看了 OpenAI Codex CLI 的 linux-sandbox；X 与 issue 搜索云端做不了。

## 1 SDK 自带子代理能否后台跑、结果怎么回来

| 项 | 发现 | 依据 |
| --- | --- | --- |
| 后台 | 默认后台：Agent 工具立刻返回 `status:"async_launched"`，主模型这一轮可接着答 | `sdk-tools.d.ts` Agent 说明 “Agents run in the background by default”；`sdk.d.ts` AgentDefinition `background?: boolean`；code.claude.com/docs/en/agent-sdk/subagents |
| 结果怎么回 | 子代理只交回最后一段文字，以 user 角色的 `<task-notification>` 消息在之后某一轮进主上下文（不是原工具调用的结果）；宿主同时收到 `task_notification` 事件；中间工具调用不进主上下文 | 同上；`sdk.d.ts` `SDKTaskNotificationMessage` |
| 空闲时唤不唤醒 | **拿不准**：有人报流式输入下主会话空闲时通知排队，直到用户下一条消息才送进（issue 88378，无维护者回复、按不活跃关闭） | github.com/anthropics/claude-code/issues/88378 |
| 打断 | 没声明 `perTaskStopAffordance` 时，interrupt 会杀掉后台任务 | `sdk.d.ts` Options |

## 2 跨次续上、存档、限制

| 项 | 发现 | 依据 |
| --- | --- | --- |
| 跨次 | 每次派 Agent 新开；但主模型可用 `SendMessage({to: agentId 或 name})` 续一个已完成的子代理，带完整历史在后台续跑；主会话 resume 后也能续 | code.claude.com/docs/en/sub-agents；`sdk-tools.d.ts` `name` 字段 |
| 存档 | 子代理改的文件**不**计入 `enableFileCheckpointing` / `rewindFiles` | code.claude.com/docs/en/agent-sdk/file-checkpointing |
| 工具 / 模型 | AgentDefinition 可配 `tools`、`disallowedTools`、`model`、`effort`、`maxTurns` | `sdk.d.ts` AgentDefinition |
| 可写目录 | 没有按子代理配的沙盒或可写目录字段；可靠 `canUseTool`（参数带 `agentID`）或钩子（带 `agent_id`/`agent_type`）按子代理分开判 | `sdk.d.ts` CanUseTool、钩子输入 |
| 权限模式 | 子代理继承主会话权限规则与模式 | sub-agents 页 |

## 3 沙盒

| 项 | 发现 | 依据 |
| --- | --- | --- |
| 现成的 | SDK 自带 `sandbox` 选项（原型已用），底层开源 `@anthropic-ai/sandbox-runtime`（Linux bubblewrap、macOS Seatbelt、网络经本机代理按域名放行；Beta） | code.claude.com/docs/en/sandboxing；github.com/anthropics/sandbox-runtime |
| 边界 | 沙盒只管 shell 命令；Read/Edit/Write/WebFetch、MCP、钩子不在沙盒里，只受权限规则管。原型“文件工具靠 `canUseTool`、Bash 靠沙盒”两层与官方一致 | sandboxing 页 |
| 分不分子代理 | 沙盒配置一个进程一份，主模型与子代理共用（文档未提子代理，拿不准） | 同上 |
| 社区对照 | Codex CLI linux-sandbox：bubblewrap + seccomp，思路同 sandbox-runtime | openai/codex `codex-rs/linux-sandbox/README.md` |

## 对 Studium 的含义（agent 判断）

- 页面子代理可直接用 SDK 子代理：派一次、之后 `SendMessage` 续同一个；程序记下 agentId。
- 子代理“只能写页面目录”靠 `canUseTool` 按 agentID 卡、并不给 Bash；不用另找沙盒库。
- 子代理结果进上下文的形式（`<task-notification>`）与 10-26 定稿“写明是子代理交回、按时间线接在后面”一致。

## 待本机 / 真模型确认

1. 0.3.293 流式输入下主会话空闲时，子代理完成会不会自动起一轮；不会就由程序收到 `task_notification` 后推一轮。
2. `tools` 是否要显式含 SendMessage（init 里 Agent 工具叫 “Task”）。
3. `canUseTool` 的 agentID 是否等于 Agent 结果里的 agentId。
4. 后台子代理的权限请求是否照样走 `canUseTool`。
5. `perTaskStopAffordance` 怎么传、默认值。
