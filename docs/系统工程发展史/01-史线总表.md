> **一句话结论**：agent harness 这条线上，**底座全是几十年的老东西**；真正新的只有一件——**写代码的是模型**。

## § 1 三个时代

| 时代 | 时间 | 特征 | 状态 |
| --- | --- | --- | --- |
| **前 LLM 时代** | 1969 – 2019 | 这些问题在传统软件里全部解决过一遍 | 已沉淀 |
| **原型时代** | 2020 – 2024 | 有人把它接到 LLM 上，但模型不够强 | 试验品 |
| **工程化时代** | 2024 – 2026 | 协议统一 + 模型能力到位 + 产品化 | 进行中 |

**原型时代的意义**：它是「工程化时代」的预演。2022 年就有人做 PTC 的同构物，失败原因不是思路错，是**当时的模型写不出可靠的编排代码**。三年时间水位涨上来，同一个想法才成立。

## § 3 按层归类

同一批技术，分属三个不同的层。混层就会看不懂谁是谁。

| 层 | 老答案（来源） | agent 里的位置 |
| --- | --- | --- |
| **执行边界** | 沙箱（1979–2018） | 容器 / isolate 跑模型生成的代码 |
| **接口发现** | 文件系统（1969） | 工具摆成目录树，模型按需读 |
| **接口契约** | IDL / 类型（1991–2014） | schema → `.d.ts` / `.pyi` |
| **协议** | RPC / Web 服务（1991–2010） | MCP |
| **上下文** | 信息检索 / 缓存（2020） | context engineering |
| **动作空间** | —— | 代码 vs JSON |
| **权限** | ACL / 能力模型（1970s–） | ⚠️ 见 §4 |

## § 4 唯一没有旧答案的一格

上表每一行都能追溯几十年，**只有「权限」这一行情况特殊**：

| | 传统软件 | agent |
| --- | --- | --- |
| 谁在执行代码 | **人**——有身份、有责任、可追责 | **模型** |
| 意图从哪来 | 明确的需求 | 自然语言，可能被注入污染 |

现成的 ACL / 能力模型解决的是「**主体是可信的，但权限要收窄**」；agent 面对的是「**主体生成的代码本身不可信**」。这两件事不同。

官方文档对此有明确表述：

> `allowed_callers` controls how the tool is presented to Claude ... **Do not rely on `allowed_callers` as a security boundary.**
> — Anthropic, *Programmatic tool calling* 官方文档（原文与出处见 `03-PTC机制.md` §2.4）

**结论**：这是整条栈里唯一真正的新问题，也是 adoption 的主要瓶颈（详见 `05-推演与信号.md` §4）。

## § 5 三条可复用的判断规则

从整条史线里能提炼出的规律，用于判断后续新技术的真伪：

```
R1: 如果一个「新」技术能映射到上表某一行的老答案 → 大概率会成，只是接线的活
R2: 如果一个「新」技术声称解决了权限/责任问题 → 值得看，因为那是真新的
R3: 如果某个原型在 2022–2023 年失败过 → 检查它是不是只在等模型能力，是的话会回来
```

`R3` 是这三年最反复出现的一条：CodeAct、Voyager、tool-as-code 全都经历过这个循环。
