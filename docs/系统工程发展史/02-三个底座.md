# 三个底座

```yaml
doc_id: SYSENG_HISTORY_02
status: 现行
evidence_base: LEVEL_A + LEVEL_B
purpose: 拆解 agent harness 依赖的三个老底座
```

> 三个名词各自独立，且都是**几十年的老东西**。分开理解它们，才不会把「沙箱」和「文件系统」混成一件事。

## § 0 三者的分工

| 底座 | 回答的问题 | 诞生 | 在 agent 里的角色 |
| --- | --- | --- | --- |
| **文件系统** | 我怎么**发现**有什么工具？ | 1969 | 工具摆成目录树，按需 `read` |
| **沙箱/容器** | 代码在**哪里**跑才安全？ | 1979 | 跑模型生成的代码，资源受限 |
| **类型系统** | 这个工具**怎么调**？ | 1991（IDL） | schema → `.d.ts` / `.pyi`，模型对着写代码 |

一句话：**文件系统管「找到」，类型系统管「调对」，沙箱管「跑不出事」。**

## § 1 文件系统（filesystem）

### 1.1 在 agent 里指什么

把一堆工具摆成目录树，模型自己 `ls` / `grep` / `read` 去发现和加载。

```
servers/
├── google-drive/
│   ├── getDocument.ts
│   ├── updateRecord.ts
│   └── index.ts
├── salesforce/
│   └── updateRecord.ts
└── slack/
    └── getChannelHistory.ts
```

来源：Anthropic 《Code execution with MCP》，2025-11-04 `LEVEL_A`

### 1.2 为什么好用

| 性质 | 作用 |
| --- | --- |
| 天生分层 | 目录 → 索引 → 单文件，天然三级粒度 |
| 惰性加载 | 不读就永远不占上下文 |
| 模型本来就熟 | 训练语料里有海量文件树，不需要额外教 |

它解决的是**工具定义爆炸**：500 个工具的 schema 全量下发 = 请求还没开始读就烧掉 100K token。

### 1.3 时间线

| 时间 | 事件 |
| --- | --- |
| 1969 | Unix，分层目录 |
| 1970s | "everything is a file"——设备、管道都抽象成文件 |
| 1990s | Plan 9 的 `/proc`：把「非文件资源」也做成文件 |
| 2025-09 | Cloudflare Code Mode：MCP server 自动转 API |
| 2025-11 | Anthropic：工具 = 文件，模型按需 `read` |

**洞察**：文件系统是「接口发现」这个问题的 50 年老答案。agent 只是复用了它。

## § 2 沙箱 / 容器（sandbox / container）

### 2.1 在 agent 里指什么

模型生成的代码在里面跑，只能碰到你给的资源，按周期回收。

### 2.2 为什么必须

因为代码**不可信**——由模型生成，而模型的输入里可能混着 prompt injection。

### 2.3 时间线

| 时间 | 事件 | 隔离粒度 |
| --- | --- | --- |
| 1979 | `chroot`（Version 7 Unix） | 文件系统视图 |
| 2000 | FreeBSD Jails | 进程 + 文件系统 |
| 2004 | Solaris Zones | OS 级 |
| 2002–2008 | Linux namespaces + cgroups | 可组合 OS 级 |
| 2013 | Docker | 工程化普及 |
| 2017 | V8 Isolates / Cloudflare Workers | 进程级以下 |
| 2018 | gVisor / Firecracker | microVM |
| 2025 | 用于跑模型生成的代码 | 各家自选 |

**洞察**：沙箱技术 45 岁了。新的是**被隔离的对象从「陌生人的代码」变成了「模型的输出」**。

### 2.4 PTC 的容器生命周期（现行参数）

以下为 Anthropic PTC 官方文档公布的参数 `LEVEL_A`：

| 参数 | 值 |
| --- | --- |
| 创建时机 | 每次请求新建，除非复用已有的 `container` id |
| 空闲回收 | 约 5 分钟 |
| 最长可复用 | 创建后 30 天 |
| 等待工具结果的超时 | 约 4 分钟，超时后在代码里抛 `TimeoutError` |
| 等待期间 | **必须**回传 `container` id，否则 API 拒绝请求 |

**这些数字的意义**：它们定义了「一次编排能持续多久」。把沙箱做持久（见 `05-推演与信号.md` §2）本质上就是在改这几个数。

## § 3 类型系统（types / schema）

### 3.1 它到底解决什么

要调一个查报销的工具，**光知道工具名没法调**。必须知道：

- 参数叫 `user_id` 还是 `userId`？
- `"123"` 还是 `123`？
- `quarter` 传 `"Q3"`、`"2025-Q3"` 还是 `3`？
- 哪个必填？
- 返回的是数组还是对象？每项是 `amount` 还是 `cost`？数字还是 `"1,200.00"`？

**这些不写下来，没人能调用。**类型就是把这些问题回答清楚的格式。

### 3.2 传统 tool calling 怎么写这份说明书

```json
{
  "name": "get_expenses",
  "description": "Get expense line items for a user in a quarter. Returns a list of expense objects with amount, category, date, and receipt_id.",
  "input_schema": {
    "type": "object",
    "properties": {
      "user_id": {"type": "string", "description": "The user's ID"},
      "quarter": {"type": "string", "description": "Quarter, e.g. Q3"}
    },
    "required": ["user_id", "quarter"]
  }
}
```

一段 **JSON 散文**。能用，但别扭——因为模型要拿它去**写代码**，而它本身不是代码。

### 3.3 有类型之后

```python
class GetExpensesInput(TypedDict):
    user_id: str      # The user's ID
    quarter: str      # Quarter, e.g. Q3

class Expense(TypedDict):
    amount: float
    category: str
    date: str
    receipt_id: str

async def get_expenses(input: GetExpensesInput) -> list[Expense]:
    ...
```

| 好处 | 说明 |
| --- | --- |
| 信息密度 | `amount: float` 六个字符 ≫ `{"type": "number"}` |
| 直接可写 | 模型写代码时对着同一个语言的类型写，无心智转换 |
| 可校验 | 参数名/类型错了，运行前就能发现 |
| 可组合 | `list[Expense]` 本身是信息，模型敢直接 `for e in expenses` |

### 3.4 为什么叫「系统」

一份声明同时给你三样：

| 用途 | 给谁 |
| --- | --- |
| **文档** | 给模型/人读（doc comment） |
| **契约** | 调用方与被调方约定同一形状 |
| **校验** | 不符即报错 |

人写的说明书做不到——它只给眼睛看，机器无法检查。

### 3.5 时间线（这条线真正的名字是 IDL）

| 时间 | 事件 |
| --- | --- |
| 1991 | CORBA IDL |
| 2000 | WSDL（SOAP 时代） |
| 2009–2010 | JSON Schema / Swagger（2015 → OpenAPI） |
| 2012 | TypeScript |
| 2014 | Python PEP 484、`.pyi` |
| 2024-11 | MCP 用 JSON Schema 描述工具 |
| 2025-09 | Cloudflare：schema **自动生成** `.d.ts` + doc comment |

### 3.6 为什么「代码调工具」必然逼出类型

> **一旦决定让模型写代码调工具，工具的接口就必然是代码里的类型。**

**你没法在一个 TypeScript 文件里，对着一段 JSON Schema 写调用。**

```ts
const docs = await codemode.search_agents_code({ query: "sandbox" });
//                                        ↑ 这里必须有个类型才知道要传什么
```

Cloudflare 的做法：连上 MCP server → 抓 JSON Schema → **自动生成 TypeScript 类型 + doc comment**。这不是额外设计，是这条路走到这一步的必然产物。`LEVEL_A`

## § 4 文件系统 vs 类型：同一个问题的两个答案

都是解决「工具太多，怎么让模型按需知道」。

| 方案 | 提出方 | 机制 | 载荷形式 |
| --- | --- | --- | --- |
| **文件系统** | Anthropic | 工具 = 文件，模型 `ls` / `read` | 目录树 |
| **类型系统** | Cloudflare | 工具 = 类型声明，模型读 `.d.ts` | 模块 + 类型作用域 |

两者都 work，原因相同：**模型对文件系统和类型系统都很熟**。它们只是把「按需加载」的梯子搭在了不同的基础设施上。
