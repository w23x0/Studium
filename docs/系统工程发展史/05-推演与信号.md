## § 2 趋势推演

### 2.1 工具定义从「上下文」搬到「文件系统 / 类型系统」`LEVEL_C`

现在是模型在 prompt 里「看到」schema。未来是模型 **grep 目录、读 `.d.ts` / `.pyi`、看 doc comment**。

工具定义变成**库文档**，不是 prompt 的一部分。`search_tools` 这类临时补丁会被「文件系统本身就是索引」取代。

> **对写代码的人**：agent 拿到的是一套 **SDK**，而不是一张工具清单。

### 2.2 沙箱从「临时容器」变成「持久工作机」`LEVEL_C`

现在的限制（空闲 5 分钟回收 / 30 天上限 / 等待工具结果 4 分钟超时）会放宽。

方向：长生命周期 + 文件系统 + 有状态 + 可恢复。

**收敛预测**：这会和 cloud dev environment / computer use / Claude Code 这类东西合流：

> agent 有一台自己的电脑，工具就是那台电脑上的 SDK。

一旦成立，「agent 框架」和「开发环境」的边界会消失。

### 2.3 代码不只编排工具，也编排模型 `LEVEL_C`

```python
results = await asyncio.gather(*[ask_subagent(q) for q in questions])
```

**代码成为通用编排层**：并发子 agent、map-reduce、重试、预算控制，全用代码写。

顺此推演，今天 multi-agent 框架里那堆抽象（graph、node、edge、tool router）大概率会被「**就是一个 for 循环**」吃掉。

### 2.4 模型训练会内化这套循环 `LEVEL_C`

现在靠提示词 + 模型天生会写 Python。下一轮会在 RL 里直接训：什么该写代码、什么该直接调、代码怎么写才省 token。

结果：**直接 tool calling 退化成「简单单次调用」的快捷路径，代码执行成为默认。**

类比现成：tool calling 自己就是从「提示词技巧」变成原生能力的。

### 2.5 语言与类型 `LEVEL_C`

现在 Python（Anthropic）/ TypeScript（Cloudflare）。

方向：**多语言 + 类型即协议**——schema → `.d.ts` / `.pyi`，工具自带类型提示。

## § 4 真正卡住的地方：不是能力，是安全

### 4.1 权限模型 `LEVEL_A`（官方原话）

> `allowed_callers` controls how the tool is presented to Claude ... it is **not a hard API-level block** on direct invocation. Claude is strongly guided to respect it, but your client should still be prepared to handle a direct `tool_use` for any tool it defines. **Do not rely on `allowed_callers` as a security boundary.**

模型生成的代码 = 任意代码执行。链路：

```
prompt injection → 生成代码 → 数据外泄
```

**为什么这次没有旧答案**：

| | 传统软件 | agent |
| --- | --- | --- |
| 执行代码的主体 | **人**——有身份、有责任、可追责 | **模型** |
| 意图来源 | 明确的需求 | 自然语言，可能被污染 |
| 现成方案假设 | 主体可信，只需收窄权限 | **主体生成的代码本身不可信** |

**推演方向**（`LEVEL_C`）：capability-based sandbox、egress 白名单、**数据流策略**（PII tokenize 思路泛化）、确定性策略引擎挡在中间。

> **判断**：安全会是 adoption 的主要瓶颈，而不是模型能力。

### 4.2 可观测性 `LEVEL_C`

「模型写的代码调你的工具、中途暂停、恢复」——出错时基本是黑盒。

需要：trace 标准、record & replay、确定性重演。

### 4.3 适用边界：连续谱而非替代 `LEVEL_C`

| 不该用 | 原因 |
| --- | --- |
| 单次琐碎调用 | 起沙箱不值 |
| 需人逐步确认的高风险操作 | 人的介入点被代码吃掉 |
| 结果必须模型亲自通读 | 结论无法预先压缩 |

未来是**连续谱**：per-tool 的 `allowed_callers` 让模型自己选，而不是一刀切。

## § 5 一个张力

再往前推一步会撞上的对立：

| 一边 | 另一边 |
| --- | --- |
| 模型生成代码 → 显式、**可验证**、可复现 | 模型自身推理越来越强，内部能并行、能潜在推理 |

**如果模型内部「思考」变得又便宜又强**，PTC 从「省往返」这个价值上会**退化**，剩下两个真正的护城河：

| 护城河 | 会不会退化 |
| --- | --- |
| **省上下文** | 不会，反而更重要 |
| **可验证性** | 不会——模型自己算的没法审计，代码算的能看、能重放、能测 |

**预测**：最终形态不是「tool calling 被淘汰」，而是

> **模型负责判断和规划（不确定的、需要语义理解的部分），代码负责一切确定性的部分，边界按任务动态划分。**

「这条边界该画在哪」就是接下来几年真正要解决的问题——Skill、记忆、子 agent 这些概念最后大概率都会收敛到这一件事上。
