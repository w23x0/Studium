# 难题

> 每条：问题 · 已知的 · 为什么不满意。顺序大致按卡得多紧。

## 1. 多本书的结构怎么关联

| 项 | 内容 |
| --- | --- |
| 问题 | 不同书的子句几乎不可能一样，这正是书和书的差距；只看点看不出来。多本书的点线结构怎么连起来，让下游拿到“一个点的几组子句” |
| 已知 | 逐点两两对齐在领域内仍未解决（本体对齐评测 OAEI 2025 报告自述“复杂对齐、非等价关系”未解决）；只对齐“陈述”会在定义不同处出洞——ln 在一本书是积分定义、在另一本是 eˣ 的反函数，两条定义陈述不等，只能互相推出，而子句最大的差别恰恰在“从哪个定义进去”；形式数学库里“比后果、不比定义”认出同一对象有效（Gauthier & Kaliszyk 2019），但没在自然语言教材上验证 |
| 现在的想法 | 不两两比：模型先生成一份子句清单当中心，各书逐本挂上去审核（见背景 §5 末行） |
| 不满意 | 难点挪到“模型说的点落到哪本书的哪个点上”；没有验证过 |

## 2. 先生成后审核：模型清单偏向常见路线

| 项 | 内容 |
| --- | --- |
| 问题 | 模型凭自身知识说出的子句，可能集中在最常见的一两条路线，漏掉书里少见但有价值的讲法（产品负责人认为这正是 M08 的本质：清单要被不断补——书补、学习过程也补） |
| 已知 | 打算审核时反向补：书里有、清单没有的路线补进去 |
| 不满意 | 反向补等于又要读懂每本书的路线；怎么高效地发现“书里有而清单没有”，没有办法 |

## 3. 审核审到什么程度

| 项 | 内容 |
| --- | --- |
| 问题 | 子句与跨书链接都由模型审核。审多严？没有标准答案、没有多个学习者、没有题目对错，拿什么判一个子句“对” |
| 已知 | 书给的有原文作证；模型补的只是候选；学习者真走通了是单人证据 |
| 不满意 | 错误率未知；审核者也是模型，可能和生成者犯同样的错 |

## 4. 簇推到哪里停

| 项 | 内容 |
| --- | --- |
| 问题 | M05 从一个子句出发往下推新点，推到“一次坐下来能走完的量”就停。这个量怎么定 |
| 已知 | 文献里没有用“一次坐下来”（小时级）定学习单位的；认知负荷理论说单元大小相对学习者已有图式；学习者状态（精力、时间）由另一模块给读数 |
| 不满意 | 没有数据校准；靠模型估又怕不准；估错的代价是闭环拖长或太碎 |

## 5. “学出什么理解”能不能写具体

| 项 | 内容 |
| --- | --- |
| 问题 | 子句的价值在“从这里进去，学出来是什么样的理解”。这句话写得出具体内容（如“从积分进去，把 ln 理解为面积的累积”），M05 才能按目标挑；只能写“理解更深”就没用 |
| 已知 | 书里很少直接写这句话，多半要模型从推导过程读出来 |
| 不满意 | 不知道能写到多具体；固定格式（“从 X 出发，把 Y 理解为…；用到 X 的…”）可能僵硬 |

## 6. “同一对象、不同面”怎么判

| 项 | 内容 |
| --- | --- |
| 问题 | 同一个函数或概念从不同定义进来是“不同的面”，不能互相顶替；但两本书讲同一条定理、讲法也相同，又应该能顶替。两者在文字上很像，模型容易混 |
| 已知 | 形式库用后果重合判同一对象；书有时自己写出另一条路（Stewart：“另一种做法是先用积分定义对数”） |
| 不满意 | 抽取出的点是概念点和陈述点混在一起的，“后果”不一定抽得出来 |

## 7. 没有逐条数据回路

| 项 | 内容 |
| --- | --- |
| 问题 | 做题驱动的系统（Math Academy）能按每道例题的通过率改讲解、发现某处切得太粗；我们的讲解是模型现场生成的对话，没有这种回路。路线好不好、子句准不准，拿什么反馈 |
| 已知 | 闭环内有现场出的练习；闭环原始对话全部保存；学习者走出的新路线可作候选回流 |
| 不满意 | 单个学习者没有对照，理解薄是出发点选错还是别的原因分不开 |
