# claude-api skill 的评估指南：现成多少、缺多少

> 状态：待定（2026-09-29 建）。参考材料，**不作产品结论**。
> 来源：https://github.com/anthropics/skills/tree/main/skills/claude-api 下的 `shared/evals/`，共四份指南：`build-eval.md`（建评估）、`eval-hillclimb.md`（爬坡）、`eval-audit.md`（健康检查清单）、`cost-hillclimb.md`（降成本），另有 `report/` 下的报告生成器与运行器模板。2026-09-29 读的是 main 分支。

## 1 已经写好的（可以直接用）

| 部分 | 内容 | 对项目 |
| --- | --- | --- |
| 流程 | 先访谈，再搭建；有两处必须由人点头：一是输入集，二是打分方法。人先看过几份打分结果、确认“换我也这样打”，才往下走 | 正好对应“先让产品负责人校准打分器” |
| 多轮对话 | 支持把一段对话前缀当作输入；要先定打什么：整段对话的结果、每一轮，还是全过程；**默认打整段结果**，因为单看一轮可能不错，但它接在一个错误的前一轮之后 | 我们的教学是多轮的，可以用 |
| 运行器 | 要调用**真实入口**，不能在评估脚本里另写一遍模型调用；逐条写结果、可断点续跑、单条有时间上限、失败要分类（拒答、基础设施错误、超时、真失败） | `proto/studium/sim.py` 本来就调真实的 `Loop`；项目只用 Python，指南允许用项目的语言写运行器，只要守它的文件格式（`results.jsonl` + `traces/`） |
| 打分器 | 从便宜到贵：程序检查 → 盲评两两比较（随机 A / B、允许判平局或都不好、基线输出冻结保存后不再重新生成）→ 单份打分（评分标准写成可核对的陈述）→ 人工抽查。评委模型可以选 `claude-sonnet-5-5` 或 `claude-opus-5-5`，但**不能用被测模型给自己打分** | `compare.py` 要按这个重写：评委用 Sonnet 5.5，被测用 Opus（产品负责人 2026-09-29 确认两者都是好模型） |
| 噪声 | 通过率的噪声约为 `1/√(题数 × 重复次数)`：25 题 × 2 次约 ±14 个百分点，100 × 2 约 ±7。开爬之前，要把噪声、剩余空间、愿意采纳的最小改进三者摆在一起比 | 我们的真人记录只有 me-1 到 me-9，题少，只能靠多重复 |
| 报告 | 自带报告生成器（Node 运行，本机有 Node 22），每条用例能点进完整对话 | 不用自己写查看页面 |
| 爬坡 | 训练集和测试集随机分；每轮只改一处；两边都涨才留下；停滞时先按原因给失败分类；最后停在测试集最好的版本 | 与 `01` §1.3 一致 |

## 2 我们需要自己补的

| 缺口 | 为什么指南里没有 | 怎么补（初步想法，未验证） |
| --- | --- | --- |
| **模拟学习者** | 指南把多轮对话当成**固定的输入前缀**；我们的学习者一方是模型边聊边生成的，没有现成做法 | 让运行器里的一条用例 = 一个人设 + 一段知识链 + 开场，由 `sim.py` 跑完整段对话 |
| **模拟带来的波动** | 指南里最接近的是“产物本身由随机过程生成时，先量生成过程的波动”（`eval-hillclimb.md` Step 0.5 最后一条）：不改任何东西，重复生成两三次，看分数差多少 | 同一人设、同一链、不改提示词，重复跑几次，先量出这个波动。产品负责人 2026-09-29：学习者的情况很乱，这部分波动可能不小 |
| **打什么** | 指南说，对 agent 最弱的信号是“看对话记录判断它说得对不对”，只适合用来查流程是否守规矩。我们的成功是学习者脑中的变化，模拟学习者并不真的学，所以恰好只剩这种最弱的信号 | 要打的东西由交互契约决定（比如回复是否停在第一个取决于学习者回答的地方、是否代做学习者的一步）；**契约没定，打分标准就写不出来** |
| **人设覆盖面** | 指南的输入取自真实流量；我们真实学习者只有一位 | 从 me-1 到 me-9 提炼人设和情境，把“乱”的情况也写进去（中途离开、自述不准、前置不牢等） |

## 3 什么时候搭

| 条件 | 现状 |
| --- | --- |
| 知道要量什么（交互契约） | 未定：项目暂停，等 agent 框架学习完、技术方向重审后再谈 |
| 真人样本足够提炼用例 | me-1 到 me-9 可用，但版本各不相同（旧闭环定义下的对话，只能作人设与情境来源，不能直接当用例） |
| 工具 | 现成：搭的时候运行 `/claude-api build-eval`，把本文件 §2 的缺口作为输入交给它 |

结论（设计侧）：搭建本身不难，指南和工具都现成；卡在“量什么”。所以放在交互契约之后，作为 `01` §2.3 的第 1 步。
