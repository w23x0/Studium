## 定位

Studium 按**智能辅导系统（ITS）结构**构建；闭环内外的每个会话都是 agent——自己决定查什么、查几次、何时完成，不按“装配一次材料、调用一次模型”。闭环内用通用 agent 框架、可整个替换，**打开通用执行能力（脚本 / 命令），在沙盒里跑，往云沙盒方向走**，主任务是分析学习者（10-16）；Studium 自己做闭环外，两边只经四个接口（开场 · 沙盒 · 收件箱 · 事件记录，见 `03-运行设计.md`「闭环对话」）。不基于 DSH 定制，不做多身份 agent（依据：[`_research/前沿架构对照-发现.md`](./_research/前沿架构对照-发现.md)）。与编程 harness 的根本不同：核心挑战是**上下文组合**——给模型什么事实、什么时候给、给谁看（2026-09-09 核心需求）；落在开场给什么、沙盒里放什么、中途推什么事实上。

## 核心原则

1. **结构沿用经典 ITS 的双循环，结合 agent 原理**（2026-09-29 重审，产品负责人确认）：外层循环（每个闭环一次，选下一闭环）= M05；内层循环（每轮一次，诊断 / 策略 / 反馈）= M04 / M10 / M02 / M03；领域模型 = M07 / M08；学习者模型 = M09 / M15。双循环正好对应闭环外 / 闭环内，是目前能做的一步；闭环内的层次以后可能再细分（未实验）。上下文“连续追加 / 重新装配”的边界就是要找的大小循环边界；闭环内不再按职责分模块循环，分析学习者与教学在一个会话、一个主循环里（10-16，见原则 7）。借的是 ITS 的分工，不照搬它的控制立场，也不只看 ITS。**学习者的决定不是直接指挥模型**：即使是学习者拍板的事，模型也站在第三方视角分析学习者为什么这样选（与编程 agent 照用户指令执行不同；对应 `../agent框架学习/02-pi与omp笔记.md` 1.2 底层逻辑③）。学习者决策的边界未定。
2. **会话之间由程序接线，会话内由模型自主**：每个会话是一个 agent（带工具、自己决定查什么、何时完成）。会话只在必须隔离处分开——闭环对话（M04 进行中诊断 + M02 / M03 表达，一个会话、一个主循环）、M04 闭环守卫、M15、M05，外加主对话与畅谈对话（产品总览「交互形状」）；没有身份设定，会话之间不互相对话，只经资产与程序追加的事实。**闭环对话的写权限靠沙盒卡**：能读写哪些数据、能否联网，由程序在执行环境里写死，不靠模型自觉；其他会话（守卫、M05、M15）暂仍按给什么工具，每个只拿到写自己产出的工具；对话记录由程序追加，不做成模型工具。读什么由模型决定；按需读的依据：模型知道自己缺什么时，自己取更准；它不知道自己不知道的，由程序在对的时机追加（`../agent框架学习/02-pi与omp笔记.md` 2.3、3.1）。收口由沙盒里的“申请收口”命令通知程序、交给 Studium 自有的守卫，换闭环内框架不换守卫（`03-运行设计.md`「收口与闭环守卫」）。调用经统一接口，与模型厂商无关。
   - **闭环对话每个闭环一份连续上下文**（2026-10-05）：开场给一次目标和事实、之后只追加、太长再压缩；守卫只读事件记录里学习者看得到的和学习者自己做的，不读模型的工作区、分析记录与思考。依据与风险见 `03-运行设计.md`「闭环对话」「为什么连续」。
3. **程序只管不能交给模型的事**（10-07 收窄，#16）：闭环对话的沙盒怎么划（写权限靠这个卡；其他会话给什么工具）、开场给什么、中途推什么事实、收口时调守卫、存盘，由程序做。开哪个任务对话由主对话按分类决定（产品总览「交互形状」）；收口由闭环对话或学习者申请。闭环外其余流程怎么串未定（`../../会话记录/2026-10-07-32-pi理念与闭环内外/README.md` 开着的问题 1）。
4. **核心与界面分开**（10-07 改写，#16）：会话、沙盒与工具、收口、存盘都在核心里，核心不绑界面；界面是外壳，参照 Claude 桌面版（主对话 + 任务对话，能显示公式与原件截图），第一版在浏览器里打开、桌面外壳打包时再选（`04-实现选型.md`）。不自写闭环内循环，用可替换的通用框架（pi 只作参考），挑框架时看四个入选条件（`03-运行设计.md`「闭环对话」）与**社区活跃度**（发版频率、问题响应、有无更新的替代品）；第一版选定 Claude Agent SDK、走个人订阅、只接 Claude（`04-实现选型.md`；订阅方式与沙盒是否仍成立，实现期待查）。
5. **架构 / 补丁分界**（取向见产品总览「设计取向：做模型进步替代不了的部分」）：判断法 = **假设模型完美，这一条还需要吗**——需要的（数据归属、流程控制、隔离、产品规则）进架构；不需要的是补丁，只放提示词并注明来由（哪次运行引出），模型变强时删。**隔离粒度**按“信息是否不同 / 是否自我确认”定，不按模块逐个隔离：同信息的职责合在一个会话，守卫独立核对（不读教学推理）、M02 / M03 / M10 / M15 不读历史仍保留。
6. **测试用模型**：各会话（M05 设计、闭环对话、守卫、M05 改线）用当下最强模型，免得把模型不足误读成设计问题、诱发过度设计；模拟学习者不属于架构，可用便宜模型。实验只做需要确认的。
7. **交互契约从学习出发自定**（10-07 改写：删去前半“基础设施对齐 Claude Code”，框架从原理出发组合、不拟合 Claude Code；10-16：初始提示只写目标）：**交互契约**与编程根本相反：编程里模型做事、人审阅，成功 = 产物完成；学习里人必须做事，成功 = 学习者脑中的变化，稀缺资源是学习者的注意力（`../学习理论/蔡格尼克效应与认知资源耗散.md`：未完成项累加占用工作记忆）。照搬编程 agent 会把它的契约（替用户做完、一次说完）一起搬进来。闭环内**初始提示只写清目标**，怎么做交给模型；程序只保证三项：**何时停**（收口经守卫判）、**记什么**（事件记录由程序存）、**什么算进展**（守卫只认学习者自己说的；程序核对守卫引用的行号落在学习者的行上，指到模型讲解的行不算证据）。
8. **证据引用照模型最顺手的方式**：程序把事件记录里的对话交给模型时每行前印行号（含中途推来的消息），模型引用只写行号或行号范围，不自己数、不复述原文；原话由程序按行号取出，给守卫核对、给界面跳转高亮。这与编程 / 学习无关，是模型自身的读写习惯，做法同 Claude Code 读文件。截图在原文里单独占一行（如“[截图 3]”）。**原文 → 压缩摘要 → 诊断记录 / 闭环总结**是一条线：越往下信息越少、密度越高、token 越少、越适合作检索材料；每层保留指回上一层的行号，原文不删，必须对着原话的判断（守卫）读原文。压缩后要看原话，模型在沙盒里按行号读回。只在 Claude 上有佐证，接入其他厂商模型时顺带测。

## 不做

- ❌ 基于 DSH 定制（DSH 在 agent 方案调研中评价最差）；闭环内不自写，用可替换的通用框架（见「定位」）
- ❌ 多身份 / 角色扮演 agent、agent 之间对话协作
- ❌ 闭环内按模块排固定循环（M02 → M03 → M04 → M10）：四个职责在一个闭环对话里由模型自主（原意，09 月「图式运行」；与闭环外流程怎么串无关）
