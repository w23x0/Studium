# M04-02 闭环日志与跨模块审查晋升

> 定位：M04 闭环结果向 M09 写入、再由 M09 经候选/审查反向增益 M08 的备忘，不是新的产品模块。
> 状态：已精简（2026-10-05，#24），原文见 `../撤下原文/审查单精简前/`。技术实现见 `../../Harness设计/03-运行设计.md`。闭环怎么定义见产品总览「闭环定义」。已确认“闭环结束后再提交”；M09 的表达结构、M08 的审查与晋升机制、自动审查权限以及退回/撤回规则均未完成设计。

### 核心问题

闭环结束时，M04 记下的动态过程怎样分别交给 M01、M09，以及之后 M09 怎样经候选/审查补充 M08——每个接收方只拿符合自身结构、用途和权限的内容。

### 功能

| 功能 | 产品结论 | 级别 |
| --- | --- | --- |
| 中间诊断不沉淀 | 闭环未结束时，M04 的中间诊断只服务当前闭环的后续教学，不新增 M09 稳定状态，也不新增 M08 正式知识。 | 原则 |
| 记录动态过程 | M04 在闭环中持续记录从最初不会、产生疑点或困难、接受不同教学和练习，到最终形成或未形成理解的动态过程；日志要能表达动态过程，而不只是最终的“掌握/未掌握”标签。 | 原则 |
| 一次闭环级总体诊断 | M04 判断合上后作一次闭环级总体诊断，并通知 M01 结束承载该目标的会话。 | 原则 |
| 按接收方分别输出 | 同一份闭环结果不能不加区分地写入多个模块。完整动态过程可作可追溯日志；闭环结束后，M04 把其中有意义的个人形成事实和证据引用编译为 M09 记录。M04 日志不能直接成为 M08 候选或正式知识。 | 原则 |
| 两类审查门各归各模块 | 闭环守卫（审“该闭环是否合上、证据是否充分”）是 M04 的核心职责；候选审查（审“去个人化、通用性、冲突、权限”）是 M08 的准入规则；**不做可复用审查子图**（2026-08-16 讨论确认）。候选晋升按 M08 侧自动规则（证据充分、已去个人化、无冲突即晋升），人工仅在明确异常时介入。 | 已确认 |
| 审查、晋升和版本 | 守卫不通过则保持进行中、进入复检或标记搁置，不能写成 closed 记录；闭环通过后按 M09 契约编译个人形成记录，可另做结构完整性、冲突和权限校验；M09 → M08 候选审查检查去个人化、通用性、来源、逻辑冲突、隐私和适用范围；明确无问题且满足授权条件的候选可按未来规则自动晋升，有冲突、证据不足、高风险或无法判断的进入人工或更严格的审查；审查可接受、修改后接受、退回补充、拒绝或保持待定；M09 写入和 M08 晋升都保留来源、版本和变更历史，支持更正、撤回或回退。 | 候选方向（2026-08-16 标注，不是已确认规格） |

### 输入输出

**闭环日志应覆盖**：本闭环的单子（新点、选中的子句、路线动作，M05 给出）与目标；实际经过的主线、分支、迂回和前置补足路径；关键教学与练习活动及其提示条件；学习者的原始表现、疑点、混淆、困难和变化；M04 在不同时间形成的诊断、替代解释及其被支持或推翻的过程；采用过的 M10 策略及相关条件；最终总体诊断、已满足项、未满足项和证据限制；使用的 M08 对象与关系、M09 历史背景及原始证据位置；异常、上下文缺失、模型或工具降级及其对判断的影响。

| 接收方 | 输出 |
| --- | --- |
| M01 | 闭环是否合上；合上、未合上或需要重新打开的理由摘要；结束位置以及相关主线/分支关系；后续仍需保存的未完成事项。M01 据此执行生命周期变更，但不自行判断学习者是否学会 |
| M09 | 符合 M09 个人知识形成结构的记录，不能只保存“映射到哪些 M08 节点”或一句总结：学习者掌握了什么、在什么条件下能解释/应用、理解如何组织、形成了哪些个人结构、仍缺少什么、判断依据什么。摘要和四级标签只作索引 |
| M08（经 M09） | M04 不直接给 M08 输出。M09 从一个或多个已结束闭环中去个人化后，形成符合 M08 候选输入结构的材料：候选内容及其连接对象；来源闭环、个人记录和必要证据引用；适用范围、前提、反例和不确定性；个人信息去除或隔离情况；与 M08 现有内容的支持、冲突或重复关系。候选是否自动进入正式 M08 尚未确定 |
| 跨模块过程记录与审查 | 完整过程日志及来源位置；M04 的关键判断变化和最终结论；M04 向 M01 提交了什么、向 M09 编译了什么、后续 M09 向 M08 提交了什么候选；审查、晋升、退回、更正和撤回事件；自动处理失败、人工介入和版本变化 |

### 边界

- M04 → M09 的闭环守卫只审“是否允许结束”；M09 → M08 的候选审查归 M08 准入规则，两者不混。
- 本文各处的“撤回”都指**已写入记录或已晋升候选的撤回**，与 M15 已否掉的**状态记录撤回权**（由学习者裁定哪条状态成立）不是同一件事，不混用同一机制。
- 待定（回到 M08/M09 联合设计再定，本单不提前给结构答案）：丰富个人形成记录的字段怎样保持开放又能稳定查询和审查；如何从过程日志结构化保留关键变化与证据引用、不复制全部同步上下文；M08 尚未表达的个人对象、细节或理解路径怎样暂存、候选化并在晋升后重新锚定；一个闭环涉及多个对象、关系和个人结构时，M09 的最小记录单位是什么。
- 待定：M08 候选在什么条件下允许自动晋升、什么情况必须人工确认；守卫通过后 M09 写入是否还需独立的结构完整性、合并冲突和权限校验；M09 记录或 M08 晋升内容被新证据推翻时，采用更正、撤回、回退还是重新打开来源闭环（连着 M09 体积单调增长的规模问题，见 M09 审查单）。运行日志的权威存储位置、自动审查与人工审查的权限与可见性属实现期（`../../Harness设计/03-运行设计.md`）。
