## 「定位」原文（10-06 版）

Studium 按**智能辅导系统（ITS）结构**构建：一个确定性的循环程序，在固定的判断点上以**隔离调用**使用大模型；不基于 DSH 定制，不做多身份 agent；闭环内的运行外壳参考 pi 等开源框架取舍、不自写（产品负责人 2026-10-06，#26；选型归 #16 / 实现期）（依据：[`_research/前沿架构对照-发现.md`](./_research/前沿架构对照-发现.md)）。与编程 harness 的根本不同：核心挑战是**上下文组合**——给模型什么事实、什么时候给、给谁看——而不是工具调用编排（2026-09-09 核心需求）。

## 原则 2 原文（09-29 重审、10-05 补）

2. **外层由程序定流程，内层由模型自主**（2026-09-29 重审，产品负责人确认；原标题“大模型是判断函数，不是 agent”不准确——判断点内部“调工具、看结果、再调”本就是 agent 循环）：判断点只在**必须隔离**处分开——教学调用（M04 诊断 + M10 策略 + M02 / M03 表达，一次）、M04 闭环守卫、M15、M05；何时调用哪个判断点、结果写到哪由程序决定；没有身份设定，判断点之间不互相对话。**调用内可用只读工具按需读取“学习环境”**（M08 索引、教材路线、教材原文、M09；2026-09-28 产品负责人确认）：读什么由模型决定。按需读的依据：模型知道自己缺什么时，自己取更准；它不知道自己不知道的，由程序在对的时机追加（`../agent框架学习/02-pi与omp笔记.md` 2.3、3.1）。调用经统一接口，与模型厂商无关。
   - **已定：教学调用每个闭环一个连续会话**（产品负责人 2026-10-05）：开头装配一次、会话内只追加、太长再压缩；守卫、M15、M05 无状态（每次从资产装配）。原“只出不回 / 诊断记录不回灌”收窄为只约束守卫：守卫不读教学侧的推理与记录。依据：前设计（09-23）与后验证（`../agent框架学习/08-有状态与无状态.md` §4，含外部旁证 CCM）冲突，以后验证为准；**未在本项目实验**，风险是错误推断锚定后续判断（`08` §5）。细节、对照办法见 `03-运行设计.md`「教学调用」。

## 原则 4 原文（10-06 版，10-07 改为核心与界面分开）

4. **（待重审，#16）** **第一版只做 CLI**，先用纯 Python 自写状态机（10-06：闭环内运行外壳改为参考开源框架、不自写，见上方总述；闭环外流程控制仍随本条重审）；等出现分叉 + 返回、多闭环并行，再评估是否引入图框架——届时联网调研、借鉴、组合再押注，评估标准含**社区活跃度**（发版频率、问题响应、有无更新的替代品；产品负责人判断图框架有过气风险）。`claude -p` 只是接线（统一接口的一个后端），不属于架构。

## 原则 7 原文（09-28，10-07 删前半）

7. **（待重审，#16）** **基础设施对齐 Claude Code，交互契约从学习出发自定**（2026-09-28，产品负责人确认）：工具调用、按需读、skill 格式、上下文装配与编程相同，对齐 Claude Code——模型在这些模式上训练过，顺着用成本最低。**交互契约**（谁做事、每轮说多少、什么算进展、何时停、记什么）与编程根本相反：编程里模型做事、人审阅，成功 = 产物完成；学习里人必须做事，成功 = 学习者脑中的变化，稀缺资源是学习者的注意力（`../学习理论/蔡格尼克效应与认知资源耗散.md`：未完成项累加占用工作记忆）。照搬 Claude Code 会把它的契约（替用户做完、一次说完）一起搬进来。契约由结构保证，不靠提示词（提示词对不同模型效果不同）；具体结构待设计。
