## 11 学习者看到什么（原“活页面”）

一次学习只有一条上下文（§3）；学习者看到的界面是从这条线里取出的、此刻要看的局部。不分“对话”和“页面”两块。三方：主模型（本会话）、子代理（`页面子代理.md`）、框架。

### 11.1 定义

| 项 | 内容 |
| --- | --- |
| 为什么有 | 学习者的注意力几乎只在眼前这一处，对话流越长越乱、位置越难找；上下文仍是一条线，界面把它映射成平面，由主模型控制学习者眼前信息的边界和速度，让学习者一直处在学习状态。作用是控制，不是多装 |
| 块 | 上下文里的每一条都是一块，彼此平行：主模型写的话、学习者说的话与操作、子代理交回、开场、收尾记录等。每块有时间（在线上的位置）、指向（和哪些块有关，一句话记）、内容；内容更新（图改了、答案改了）= 新加一块，旧块不动。主模型一轮的话可以分成几段写，每段是一块、以后能单独点名拿回；分不分由主模型定 |
| 屏幕由谁定 | 每一轮屏幕上有什么，由主模型这一轮的输出定：新写的，加上用极简短的描述点名拿回来的旧块（多远都行）。没提到的就不显示（不是折起、不是压缩）。所以主模型只看自己最近一次输出，就知道学习者眼前有什么 |
| 输入与输出 | 输出 = 主模型决定接下来显示什么；输出之后报回来的（学习者的话与操作、子代理交回、框架对不上时回的一句）按时间接到线后面，两者合起来就是主模型的输入。不另记“屏幕现在是什么样” |
| 为什么回复要完整 | 学习不是直线推进的：常卡住、绕回来，每一段都和前面有重叠，会的占大部分、新的占小部分。学习者只看得到放上屏幕的东西，所以每一轮要完整、对近几轮尽量能单独看懂；远处要用的点名拿回来，可以重复说 |
| 不是什么 | 不是一次性做成的书或课程（`../记录/知识产出.md`「学习内容编制」不做照旧） |

### 11.2 三方各管什么

| | 管 | 不管 |
| --- | --- | --- |
| 主模型 | 每一轮定屏幕：写新的话、点名拿回旧块、用一句话说新内容和什么有关；所有教学文字（讲解、推导、问题、给学习者看的分析）；露什么、露多少、何时露；哪些自己写、哪些派子代理，自己判断；派活时说清要什么、留多大余地、学习者动它要不要观测、报给谁、等不等回应 | 不写要运行的代码；不给坐标；上下文里不出现块编号、版本号 |
| 子代理 | 只为让主对话的上下文干净：写代码、调试这类会把大量细节带进主上下文的活（做函数图、动画、可拖动的代码、可交互的题等组件）；学习者动了它做的组件时先收到，按交代自己处理或往上报。主模型自己开、自己定它活多久 | 不做教学判断；不写教学文字（组件里的坐标轴、标签按交代写）；不自己往屏幕上加或拿掉东西；不管组件之外怎么摆 |
| 框架 | 承载这条线的前端：照主模型的输出把块摆上屏幕；主模型写的文字（含公式、表格、只显示的代码片段、资料截图）直接显示，不经子代理；框架里有一个小模型，每轮只做两件事——把主模型的简短描述对到具体的块（默认最新版，后者压过前者，§3）、按“和什么有关”定位置与排版；同一块再出现时和上次长得一样；按交代把学习者的操作送给该收的一方；子代理的外围（能写哪些文件、交时检查、隐藏小窗试跑，`页面子代理.md`）；记事件记录 | 不定显示什么；不自己留旧块、不按“最新几段”划线；对不上（如屏幕上有两张图）不猜，回一句给主模型；不做教学判断 |

### 11.3 怎么做

| 项 | 内容 |
| --- | --- |
| 提示词 | 底层只写事实：学习者只看得到你每轮放上屏幕的东西、没提到的不在屏幕上；为什么要完整（11.1）；放在哪用一句话说和什么有关，位置由框架摆；子代理为什么有、派活要说清什么；你会收到什么。不写样式、排版规则、何时画图 |
| 输出分两个口 | 给学习者看的照常写；说给框架听的（“题目留着”“接在那道题旁边”）用平常话走工具调用，绝不显示给学习者。具体写法跟着接入的模型换（做薄） |
| 程序推来的块上屏 | 开场、收尾记录这类程序推来的块被点名拿回时，只显示学习者在界面别处本来就看得到的部分：开场显示单子（新点、选中的子句、路线动作），收尾记录显示整理的内容；只给模型看的（沙盒路径等）不上屏 |
| 快路径 | 学习者顺手问一个小问题：主模型直接答、一句话说它和哪块有关，框架摆到旁边；不叫子代理、不生成代码 |
| 组件还没做好 | 主模型的输出里已经给它留了位置，框架先占位；子代理交回后换上，交回那一句按时间接到主上下文后面 |
| 学习者回话 | 有一个总的回话处，也可以在某一块下面回；在哪块下面回就记成和那块有关。学习者刚发的话显示到主模型下一轮输出为止，之后留不留由主模型定。组件自己的输入口由子代理做，经框架的发送口递出（页面不能联网，只经这个口） |
| 观测与回报 | 要不要观测在派活时定，子代理把它做进组件代码：组件只发要观测的事，发出的是看得懂的一句话（如“学习者把弹簧常数调到 3.2”）。回报先回做这个组件的一方，再看指挥做它的是谁、要不要往上报（主对话 / 子代理 / 两边，按交代）；子代理往上报的就是普通的子代理交回（§3）。纯机械的反应（拖滑块、图跟着动）由组件代码在浏览器里自己完成，谁都不经手 |
| 何时跑一轮 | 报给主对话的操作平时攒到学习者下次说话时一起带上；派活时说了等回应的（如提交答案）立刻跑一轮；连续的动作合成一条 |
| 子代理自己改了组件 | 交代里允许直接改的（如学习者在组件里要求换画法），改完报一句，跟学习者下次说话一起带上；主模型因此仍知道屏幕上有什么 |
| 学习者的动作 | 和说的话同一种身份：学习者；只记观测得到的（真操作、打字、说话），不记“看得到哪几块、在哪块停了多久” |
| 低信息量按钮 | 不放选择题、“我懂了”这类按钮（收口时学习者手动申请“我觉得懂了”另算，`../01-流程.md` §4） |
| 看以前的屏幕 | 学习者可以翻看以前任一轮的屏幕，只看：屏幕与上下文都不变、不记进上下文；不做退回，不满意就直接说 |
| 学习位置图 | 不是固定部件，是主模型可以派子代理画的一种组件（例如点 = 知识点、线 = 关系、亮度 = 扎实程度、此刻所在最亮）；画不画、怎么画由模型定。框架给依据：哪些点、此刻在哪、哪些被守卫确认过（来自单子与学过的记录）；只有守卫确认过的才算扎实；线从哪来不预先限定 |
| 我们不做 | 不做技能、不按内容类型定样式；组件长什么样由模型决定 |
| 压缩 | 块有结构，按块压缩好做；暂时不做，§3 照旧 |
| 进外层 | 每一屏由哪些块组成、组件的每次改动，由程序记进事件记录（`../记录/对话与事件记录.md`） |
| 技术架构 | 存法见 `../实现选型.md`「屏幕存储」（一屏 = 一张块清单）；框架小模型用哪个、快慢见同页；子代理怎么改组件见 `页面子代理.md`「怎么改」 |
