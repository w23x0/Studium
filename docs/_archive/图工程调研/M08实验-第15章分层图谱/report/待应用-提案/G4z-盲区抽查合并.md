## 二 各型可机械化程度

下面逐型正面回答。凡我实际跑过判据的，写出实测数；凡我只推断的，写「未实测」。

### B 型：可机械化产候选，不可机械化产判定（精确度约 21%）

判据：`shared-quotes.tsv` 同 (file,quote) 且 **≥2 个 node 持有者**。
我实测了这个过滤器的效果：shared-quotes.tsv 共 **480 组**，
其中 ≥2 个 `node:` 持有者的只有 **158 组**，另 **322 组**是「一个节点 + 若干条边」
（多为该节点自己发出的边复制了同一句）。**先剔除自我共享，候选集从 480 降到 158。**

抽查侧的精确度：45 条里 33 条有共享碰撞，只有 7 条判为有害 → **约 21%**。
所以 B 型的正确定位是**候选生成器**，不是检测器。必须人读 statement 才能分开
「同一句支撑两个不同断言」（合法，26 例）与「借来凑锚点数」（有害，7 例）。

一个机器查不出的漏报：15.05-3 的**功能性借用**——那条 55 字符题目指令句 n_holders=1，
形式上不在 shared-quotes 里，但同节另有一句功能完全相同的指令句被 3 个节点共享，
「把题目指令句当证据」在该节被用了 4 次。这类漏报需要另一条判据（见下）。

**可补的一条真机械判据**：题目指令句黑名单 + grep。
`For those that are not, tell which axioms fail to hold.` /
`If the set is not a linear space, indicate which axioms are violated.` 这类句子
不含任何数学内容，只证明「本节要求做什么」。15.05-3 的报告已建议此项进 SPEC，
我认同：它完全可机械化，代价只是一份指令句模式表。

### E 型：部分可机械化，最有效的是跨文件引证检查

任务说明给的判据「statement 有句子但无对应锚点」需要语义匹配句子与引文，
**不可直接机械化**。但有两个可跑的代理：

1. **跨文件引证检查（可机械化，我未实测但判据明确）**：从 statement 里抽出所有
   形如 `15.\d+`、`Theorem 15.\d+`、`(15.\d+)` 的引证标记，与该节点四层池里
   出现过的 `file` 集合取差集。差集非空 = 该节点引用了一处它无证据的地方。
   这条判据在抽查里能抓到 15.10-3（statement 引定理 15.10，而定理 15.10 在 15.11.md，
   池内两条锚点全在 15.10.md）与 15.16-2（跨节类比 15.11 的 √(2π)，池内无 15.11 引文）。
2. **零池检查（完全可机械化）**：exposure.tsv 的 `pool_total=0`。
   这直接抓到 15.07-3 那条纯粹 E 型，并与 README 已列的 28 个无锚点节点对齐。

**抓不到的那半**：评价句与格言句——「The exercises are a systematic drill in that
detection」、「pairwise independence is not independence」、「这是 Apostol 引入有序基的唯一理由」。
要判它们，机器得先知道这句是教材内容还是模型评论，而这正是 origin 字段本该记录的东西。
**结论：E 型的可机械化部分等于「引证标记比对 + 零池」，评价句部分不可机械化，
只能靠强制 origin 标注把它转成一个可查的字段缺失问题。**

### A 型：主体不可机械化，但有一个可跑的符号不交子判据

正面回答：**不能机械化「对象是否搞错」**——那要求机器理解 statement 说的是哪个数学对象。
但有一个廉价子判据可抓到本章 3 例中的 2 例：

**符号不交检查**：从 statement 抽出所有 `$...$` 内的标识符，从该节点池内全部引文抽出同样的集合，
若两个集合**交集为空**，报候选。
- 抓到 A-1（statement 用 cos²/sin²，锚点只有 u₁/u₂/u₃）。
- 抓到 A-3（statement 用 x/t/S，引文用 f/f_n）。
- **抓不到 A-2**：那是一条边的 dst 指错空间，statement 本身无错。
  要抓它需要比较边两端节点 statement 里的**限定词**（「全体多项式」vs「次数 ≤ n」），
  这是语义比较，不可机械化。

假阳性会很高：OCR 记号变体（15.11-3 的 `(\overline {{y , e _ {i}}})`）、
空格切分（15.02 的 `f o r a l l x i n V`）都会让符号集比对失配。
**结论：A 型可机械化到「候选」层，且只覆盖「statement 与引文符号完全不交」这一子形态；
判定必须人做。这与已知的「E 型数值子情形召回 1/4 失败」是同一类局限。**

### C 型：不可机械化判定，但引文语用类型可机械分类，覆盖本章 11 例中的多数

正面回答：**不能机械判定「引文是端点还是中间步」**——那要求机器知道断言的推理链结构。
但 C 型在本章的实际形态高度集中在两种可机械识别的引文语用类型上：

1. **引文是题目指令 / 问题提法**（C-2、C-3、15.09-2、15.16-1 的反向形态）：
   判据 = quote 以编号习题前缀（`^\d+\.`、`^\([a-z]\)`）开头，
   或含 `Prove that` / `Show that` / `find` / `Compute` / `tell which` 等祈使动词。
2. **引文是结论句**（C-1、15.11-2）：判据 = quote 以 `Therefore` / `Thus` / `This implies` /
   `so ... follows` 开头或含之，而节点 node_type 为 `proof-step`。

这两条判据都是纯字符串匹配，可跑。它们给出的是「**这条引文的语用类型与该节点的
断言类型不匹配**」这一候选，而不是 C 型的确证。
**结论：C 型半可机械化——可机械分类引文语用，不可机械判定错位。**

### D 型：最危险的型，但恰好有一条完全机械的子判据，我已实测

任务说明称 D 型「机器查不出来」。这对 D 型的**语义子形态**（statement 成分数多于引文能兑现的
成分数，如 D-1、D-3）成立。但 D 型在本章还有一个**纯边界子形态**——引文在句子中间截断，
如 D-2（`and is called` 处切掉 `"S perpendicular."`）、15.06-1（起点截掉主语
`The commutative and associative`）、15.15-2（尾部截掉 `, in the sense that the norm ... as small as possible.`）。
这个子形态**完全可机械检测**。

判据：把每条锚点在 source-lines.tsv 里定位到其所在源行，检查
(a) quote 尾部既不落在句末标点上、也不落在行尾 → 尾截断；
(b) quote 起点既不在行首、其前文也不以句末标点结尾 → 首截断。

**我实测跑过这条判据**（只读 tmp_index，未碰 data/）：921 条锚点全部可在单行内定位，
其中**尾截断 117 条、首截断 92 条、二者取并 179 条 = 19.4%**。
D-2、15.06-1、15.15-2 三条抽查命中都落在这 179 条里（形态一致）。

需要说明两点口径：这 179 条**不等于 179 个缺陷**——有意截取从句是合法的，
15.05-1 那条反向问题（引文夹带了第 6 题、超出断言范围）也不在这个集合里。
这是一个**候选集**，把 D 型可机械化的部分从 0 提到了 19.4% 的锚点面，
剩下的语义子形态仍需人读。

**结论：D 型部分可机械化——边界截断子形态完全可机械（实测 179/921），
覆盖不足的语义子形态不可机械。这修正了「D 型机器查不出来」这一表述：
应改为「D 型的语义子形态机器查不出来」。**

## 三 「N/N 已验证」的误报率区间估计

**先说清这是抽样估计，不是全章比例。** 下面所有数字都只描述这 45 条抽查条目，
而 45 条不是随机抽取的（见第四节）。任何把它当全章确定比例引用的做法都是误用。

### 「误报」的两种口径

「N/N 锚点已验证」这句话的真实含义只有一个：**这 N 条 quote 是源文件里的逐字连续子串。**
它被误读成「这 N 条锚点支撑了它们所挂的断言」。「误报率」取决于把哪一层算作误报：

**严格口径**（该条目确有需追责的缺陷，即死因非 0）：
分子 = 死因 6（25）+ 死因 1（6）+ 死因 4 轻度（1）= **32**；分母 45。
→ **71%**（32/45）。

**宽松口径**（五型至少一型实质命中，含已豁免、已声明 origin、根因在 SPEC 的）：
分子 = 45 − 1（唯一五型全清的 15.15-3，且它是有意设置的阴性对照）= **44**；分母 45。
→ **98%**（44/45）。

### 区间估计

按抽样口径给区间：**这 45 条里，「已验证」与「支撑断言」不等价的比例落在 71%–98% 之间**，
其中 71% 是「需要动手改」的下界，98% 是「机器校验完全没覆盖到的问题面」的上界。
按建议动作算则是 **FIX 32 / 保留 13**，即约 **71% 的抽查条目产生了一个待办动作**，
与严格口径一致（两者分子相同并非巧合：判死因非 0 与判 FIX 在本轮几乎同义）。

**若要对全章外推，我拒绝给点估计。** 理由见下节：样本偏差的方向已知为向上，
但**偏差幅度未核**（要核就得随机抽一批新样本重跑，超出本任务范围）。
唯一可外推的是**方向性结论**：本章「N/N 已验证」的正确性保证力不是「较弱」，
而是**只覆盖硬禁令 2（引文不得虚构）这一条，对死因 1 与死因 6 完全不覆盖**。

### 一个不依赖抽样的旁证

上一节实测的 179/921（19.4%）锚点边界截断候选，是**全量**而非抽样。
它给出了一个下界性质的事实：即使只看 D 型里最机械的那一个子形态，
也有近两成锚点在句子中间切断。这个数不是误报率（截断不必然是缺陷），
但它独立于抽样偏差，可作为「N/N 已验证不构成正确性保证」的全量证据。

## 四 抽查方法本身的缺陷

「每节自选 3 条」这个设计带来至少六项偏差，前三项方向明确向上（高报问题率）：

1. **自选偏差，且有自认证据。** 15.10 的报告明确写出了它的挑选原则：
   「一条是我在逐句表里标为**无锚**的（检验我的判断是否成立），一条**锚点数最多**的复合节点，
   一条 `origin=model` 的推论节点」。15.08 同样写明「一条证明步骤、一条例子、一条模型推断，
   覆盖三种不同的**失配风险形状**」。即多份报告是**按预判有问题**来选样的。
   这直接解释了为什么宽松口径高到 98%——样本本身就是朝缺陷筛出来的。
2. **前序小节的溢出效应。** 每份报告的第「二」「三」节刚刚列完该节的 FIX 与未覆盖项，
   第五节的选样很自然落在同一批节点上（15.16 的三条抽查全部对应它 §2.1/§2.2 的 FIX 项，
   15.14 抽查一对应它的 FIX 提案）。抽查因此在**验证自己刚下的结论**，独立性受损。
3. **判定者与产出者同一批次。** 抽查由本轮的逐节报告代理做，
   而「什么算 D 型命中」这条线由它自己划。15.06 报告判 3/3 有实质问题，
   15.10 判 3/3 命中——这两节的判定阈值明显比 15.03（判 1/3 干净）宽。**阈值不一致未校准。**

后三项方向不明或向下：

4. **每节固定 3 条，无视节的规模。** 15.09 全节 9 条锚点抽 3 条（33%），
   15.10 全节 123 条锚点抽 3 条（2.4%）。按节等权而非按锚点等权，
   **小节被系统性过度代表**。练习节（15.05、15.09、15.12、15.16）在 45 条里占 12 条，
   而这类节点有结构性缺证（教材只出题不给答案），会把整体问题率往上拉；
   若按锚点数加权，它们的权重应低得多。
5. **样本重复未去重。** 15.02 抽查 2 与 15.04 抽查 3 是**同一个节点**
   （`d:axiom-5-states-the-zero-only-as-a-right-neutral-element`）的两条不同锚点，
   两处都判 D 型轻度命中但死因分别记 6 与 1。45 条条目实际只覆盖 **44 个不同节点**
   （占 546 个节点的 8.1%）与不到 45 条锚点（占 921 条的约 4.9%）。
6. **零锚点节点无法进入抽查，但它们的 E 型是最纯粹的。** 15.07-3 之所以进来
   是因为该节报告刻意选了它；README 列出的 28 个无锚点节点（含 24 个 L2）
   在其余各节都不可能被「抽锚点」的方式抽到。**E 型在本抽查里被系统性低估。**

**给综合代理的口径建议**：本文件的五型分布可以当作**形态学证据**使用
（哪些型存在、长什么样、能不能机械化），**不可**当作比例证据使用。
若需要全章比例，正确做法是从 anchors.tsv 里随机抽固定条数重跑，
并预先写死判定阈值——这件事本轮**未做**。
