# SPEC 待议项 P11：需不需要「二次使用点复用」关系词

## 〇 裁定（进 SPEC / 不进 SPEC / 有条件进；一句话理由）

**不新增关系词，但 S3 的决定性论证不成立，须换一条论证再进 SPEC。**
「复用」在数据里实际分裂成两个已有栏位分别承担的东西——前向引用由 `requires`（方向反写即可）承担，
论证模式的重复出现由 L2 的 `members` 承担（255 条成员引用、188 个不同下层 id 记的正是「同一模式在多节复现」）；
新增关系词会与 `members` 开第二套账，这才是不扩词的决定性理由。

S3 用的理由是「`sections` 是数组，57 个节点已靠它记多节出现」（`S3:66–68`）。
这条理由在 P09 裁定 `sections` = 语义 A（出处，**不是**被用到）之后失效：
语义 A 下 `sections` 恰恰**不**记第二使用点。裁决方向对，论证须替换。

### 2.1 逐字条文（可直接并入 SPEC）

```markdown
### 词表扩充程序

关系词表**不因新用法而扩充**。遇到现有 9 个词都不贴切的情形,一律用 `other` + `rel_note`,
不得自造 rel 值。扩词必须走单独的 SPEC 修订,提案须附两项实测:
(a) 现有 `other` 边中属于该模式的条数,少于 10 条不予扩词;
(b) 该模式是否已由 `members` 或 `sections` 记账,已记账者一律不扩词——
**同一事实不得在两个栏位各记一遍。**

### 二次使用点：复用不建边

「同一对象或同一论证在第二个使用点被再次用到」**本身不构成一条边**。按下面三种情形分流,
分流依据是「第二处产生了什么新东西」:

1. **只是同一对象再次出现,没有新断言** ⇒ **不建边,也不新建节点。**
   第二处若给出了该节点 `statement` 某个句子的出处,把该节加进 `sections`(判据见 `sections` 语义条);
   若只是提及而不构成出处,则图上不留任何记录。
2. **第二处产生了新断言**(例:例 7 的空间在 15.08 被算出维数为 n+1)⇒ 新建**那个新断言**的节点,
   边写作「新断言 --`requires`--> 原对象」。方向不得反写:`requires` 的语义是
   「要陈述或理解 src 必须先有 dst」,理解维数结论必须先有那个空间,故新断言在 src 侧。
   **粗→细的书写惯例不覆盖此处**——依赖方向优先于发现顺序。
3. **复用的是论证模式或构造手法**(例:(b) 的证明重跑 (a) 的加倍相消论证,只把公理 9 换成公理 8)
   ⇒ 记入抽象层节点的 `members`,不在 L1/D 层建边。
   同一模式的两个实例都必须出现在同一个 L2+ 节点的 `members` 里;
   若找不到能统摄它们的抽象层节点,则该复用**不予记录**,并在报告的「未覆盖」一节写明丢了什么。

**`rel_note` 不限于 `rel=other`。**任何一条边,若它的选词经过了权衡,
或作者刻意回避了一个更强的关系词(例如证据只够 `other` 而语义上像 `equivalent`),
都应在 `rel_note` 里写明**被回避的那个词**与回避理由。这一栏是选词依据的存放处,
不是 `other` 的附属品。新增的 `rel=other` 边,`rel_note` 必须含被回避的词;
存量边不符者列为审计待补项,不判违规。
```

上述第 2 条里的「方向不得反写」是本条文的**唯一可机器化部分**：
凡 `rel=requires` 且 src 的最早 section 严格早于 dst 的最早 section（两端同为 `15.x`）者，
审计须逐条复核依赖方向是否写反。实测该筛子在全图命中 **11/620**（口径与明细见 §四）。

### 5.2 边界情形一：不表达会损失什么
