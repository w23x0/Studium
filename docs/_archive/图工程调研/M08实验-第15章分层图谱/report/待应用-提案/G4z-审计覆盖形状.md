# 审计覆盖形状

## 〇 结论速览

16 份报告全部存在（15.01–15.16，无缺节）。以下只谈审计的**覆盖形状**，不重判任何缺口本身。

**覆盖最密的 3 节**（按锚点/句）：15.10（1.76）、15.03（1.42）、15.11（1.39）。
**覆盖最稀的 3 节**（同一指标）：15.09（0.14）、15.05（0.30）、15.16（0.73）。

一句话诊断：**疏密的分界线不是内容难度，而是"正文节 vs 习题节"这条生产分工线**——
四个习题节（15.05 / 15.09 / 15.12 / 15.16）的锚点每句全章最低、`T3` 全部趋零，
而它们恰好是**唯一没有任何 D 层批次、也没有任何 L2 结构节点**参与生产的四节
（`nodes.tsv` 的 loc×sections 交叉表）。但这四节的稀疏**成因不同**：15.12 / 15.16 稀疏是
**内容性**的（纯计算小问 + OCR 残骸，本不该逐句建节点），15.05 / 15.09 稀疏是
**分工性**的（生产方只派了反例代理 CX2，正面命题整批无人建）。
15.09 是全章唯一"低覆盖率是正确信号"的节：4 个节点扛 65 句，报告提出 8 个补建，全章最高。

反向的一句：**覆盖率高不等于质量高**。15.03 覆盖率 97.2% 全章第一，但它自己的结论是
"真正的问题不在完备性而在记账正确性"（两处 sections 漏登/错登）；15.10 锚点最密，
却有 3 个全章最要紧的式子（公理 (3)、范数定义式、定理 15.9(a)）**没有一条锚点含它本身**，
现有锚点是邻句借用（B 型）。这两处覆盖率都看不见。

## 三 稀疏的成因（内容性 vs 分工性）

### 3.1 分工性稀疏：生产批次×节的交叉表是直接证据

把 `nodes.tsv` 的 `loc` 取文件名、`sections` 拆分后交叉计数，得到一条干净的分界：

| 节 | 参与生产的批次（节点数） |
|---|---|
| 正文节（12 节） | D1/D2/D3/D4/D5 之一 + A1 + 多数还有 H2 / X / structures-L2-a,b,c |
| 15.05* | **只有 `nodes-CX2.jsonl`（11）** |
| 15.09* | **只有 `nodes-CX2.jsonl`（4）** |
| 15.12* | **只有 `nodes-A2-x2.jsonl`（25）** |
| 15.16* | **只有 `nodes-A2-x2.jsonl`（9）** |

四个习题节是全章唯一**单批次覆盖**的节，且是唯一**零 D 层、零 L2 结构节点**的节。
连带后果在 `exposure.tsv` 里可读：这四节的 `T3` 分别为 0 / 0 / 8 / 8，
`n_partof_desc` 为 0 / 0 / 2 / 2 —— 15.05 与 15.09 **完全没有 part-of 层级**，
所以对它们"未覆盖就是未覆盖"，不存在"内容合法下移"这条辩解通道（15.05 报告已自证此点）。
对比正文节的 T3：15.10=176、15.13=172、15.14=168、15.03=130、15.02=123。

**15.05 的分工空档最明确**：其报告指出 CX2 的任务书是反例层，只对"不是线性空间"的 8 道题建了节点，
**21 道"是线性空间"的正面例题一个节点都没有**，并明确判定"这不是 CX2 的失职，是任务分配的空档"，
且 `report/丢弃与未覆盖清单.md` 未记录这一项（属新缺口）。
`进度报告.md:159-160` 印证 CX2 是与 A2-x2 并列的独立小批次（CX2 共 15 节点、A2-x2 共 34），
量级只有 D 层批次（D1 106 锚点、D2 80 节点、D3+D4 123 节点）的零头。

**15.09 是同一空档的更严重版本**：4 个节点覆盖 65 句。其 §二 提出的 8 个补建全部是
Apostol 以习题形式给出的**具名命题**，不是练习题：ex22(e) 两子空间之交是子空间、
ex22(c) 子空间 ⇔ L(S)=S、ex22(d) L 保序、ex24(a) dim S ≤ dim V、ex24(b) dim S=dim V ⇔ S=V。
其中 ex22(a)-(d) 合起来是"L 是闭包算子（扩张、保序、幂等）"，而报告指出 L 保序这条
正是既有节点 `cx-span-does-not-commute-with-intersection` 断言所依赖的**依据**，
该依据目前在图里没有独立节点。这是分工性稀疏造成了**图的推理链断裂**，不只是数量少。
8 个提案的锚点实测 46–72 字符，全在 SPEC 30–200 界内，**技术上没有任何障碍**——
唯一的原因就是没人被派去建。

### 3.2 内容性稀疏：15.12 与 15.16 稀疏是对的

15.12 §三 列出的不建理由几乎全是"纯计算小问"（8(a) 求 ‖√x‖、10(b)(c)、11(c)(d)、13(c) 裂项求和）
与"纯记号约定"，其机制均已由既有 `cx-` 节点承担；另有 3 行（L114/L118/L122）是
**习题 14 题干被 OCR 摧毁后的残骸**，报告明确判"不该建节点"。
15.16 §三 的六个未覆盖单元（L39/43/51/55/59/63）是 Ex5 的孤立裸公式块，
报告判"脱离已丢失的题干后无法确定归属，建节点即虚构归属（死因 3）"。
这两节的低覆盖率**不该被读成审计不足**：分母里本来就有大量不可建、不该建的单元。

### 3.3 第三类成因：SPEC 30 字符地板，与分工无关

有一批未覆盖跨越 7 节（15.02/15.03/15.04/15.09/15.10/15.15/15.16），成因同一：
**唯一逐字载体是短于 30 字符的独立公式行**，而硬禁令 2 不许跨行拼接，故不存在合法引文。
实测值：15.02 四条公理等式 16/18/22/22；15.03 逐点加法式 27；15.09 ex11/ex16 裸公式 10/13、
ex23(f)(i) 26/27；15.10 公理 (3) 21、范数定义式 26、性质 (a) 29；15.15 两式 28/26。
这类节的覆盖率**存在无法达到 100% 的天花板**，把它们的缺口计入"审计稀疏"是误归因。
G5-P02 已就此立案（30 字符地板豁免短行间公式），本节不重复论证。

### 4.4 一条通用的读法建议

单看覆盖率会把 15.12/15.16（该稀）与 15.09（不该稀）归成同一类，
也会把 15.03（覆盖满分但记账错）判成模范节。**覆盖率必须与三个量同看**：
(1) 分母里"不可建/不该建"单元的占比；(2) `exposure.tsv` 的 `T3`（区分下移与缺失）；
(3) 该节是否有 D 层批次参与生产（区分内容性稀疏与分工性稀疏）。
第 (3) 条是本节最可复用的产物：**`nodes.tsv` 的 loc×sections 交叉表可以机械地预测哪些节会稀疏**，
不需要读任何报告正文。

置信度：逐节量化表高（全部出自索引表的机械聚合，可复算）。
§二 的"相称/不相称"判定中等——它依赖"该节内容该不该建节点"这一实质判断，
我采用的是各节报告 §三 自己的理由，未独立复核每条。
§4.2 的四条缺陷均引自各节报告自身结论，我未回到 data/ 逐条复验。
不确定点：15.13 的 31 个下移单元是否全部合法（未逐条核）；
15.05 的"21 道正面例题"计数出自该节报告，我未独立数过源文件。
