**更正 1（实质错误）：S1 依据 4 与逐字条文都写「用 `grep -F` 校验跨行 quote」，这是错的。**
`grep -F` 把含换行的模式**按行拆成多个模式、以 OR 语义匹配**，因此一条伪造的拼接窗口也能命中。
实测（`source/apostol-ch15/15.02.md`）：把公理 6 的引入句与**公理 9** 的公式拼成一条 114 字符的假 quote，
`grep -F "$P" 15.02.md` 命中 **52 行**，与真窗口命中的 52 行完全一样，`grep -Fz` 亦然
（`-Fzo` 的输出显示它分别匹配了 `has the property`、`$$`、`(a + b) x = a x + b x.` 三段）。
Python `bad in text` 返回 **False**，`good in text` 返回 True。
**结论：跨行 quote 的唯一合法校验是全文子串测试（`quote in text`），SPEC.md:53 里的 `grep -F` 必须一并改掉。**
这不只是措辞问题——`grep -F` 恰好放行了「跨行」修订本想防的那类伪造。

**更正 2（数字错误）：S1 依据 3 称 SPECQ §4.2 的 9 条公式「9/9 均有首选窗口」，实测是 8/9。**

108 / 103 / 128 / 131 / 192 / 121 / 110 / 172，均合规且文件内唯一。

**更正 3（规则缺口，由更正 2 引出）：S1 的条文只写了「向上扩窗」，缺「向上超界时改向下」这一档。**

  (1) **先向上**——引入句通常携带量词("For every x in V");

  (3) 上下都越界时,该公式**维持不可引**,如实在报告里留白,不要用截断的 quote 凑锚点。
