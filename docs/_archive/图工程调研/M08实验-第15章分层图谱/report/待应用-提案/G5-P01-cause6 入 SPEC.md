### 条文 A —— 替换 `SPEC.md:100` 整行

```markdown

`6` 引文不支撑该断言。

**`6` 引文不支撑该断言(定义):** 被指控的那句断言,在该节点的**证据池**(见「证据池:四层,
前三层入池」)里找不到任何一条覆盖它的引文。引文本身逐字存在于教材、位置也对,
但它**管不到**这句话。`grep -F` 通过**不能**排除 `6`——机器只能证明「引文未被篡改」。

`1` / `3` / `6` 按失败点落在「引文—断言」链条的哪一环区分,三者互斥且穷尽:

| 编号 | 引文存在于教材 | 引文覆盖该断言 | 断言落在引文射程内 |
| --- | --- | --- | --- |
| `3` | **否** | — | — |
| `6` | 是 | **否** | — |
| `1` | 是 | 是 | **否** |

- `3` 是引文不在书里,`grep -F` 即可判定。
- `6` 是引文在书里、位置也对,但不覆盖被指控的断言。必须人读,机器判不出。
- `1` 是引文覆盖到了,而节点把它**扩大**了:引文只许可某个例子或某个局部,节点说成一般结论。

**`6` 的判定程序(结案前必须跑完,缺一步不得结案):**

1. 把该节点的 `statement` 逐句拆开,指名被指控的是**哪一句**。指控必须落到句,不得落到整个节点。
2. 按「证据池:四层,前三层入池」建池:T1 自身 `anchors` + T2 该节点作 `src` 发出的边的
   `evidence` + T3 `part-of` 后代(传递闭包)的 `anchors` 与它们作 `src` 发出的边的 `evidence`。
   **TD(该节点作 `dst`、别人指进来的边)一律排除,不给例外。**
3. 逐条读池内引文,判它是否覆盖第 1 步指名的那句。**只允许人读判定**,
   不得用「池里有这个 file」或「池变大了」代替。
4. 若池内有引文覆盖该句 ⇒ 指控不成立,按下表改判 `0`,并写明是 T2 还是 T3 塌陷。
   若池内无引文覆盖 ⇒ `6` 成立。
5. 裁决理由里必须回显池的规模,格式 `pool=T1/T2/T3 条数, 覆盖源行 N 条`。

**塌陷分型与药方(不得都报成「锚点不支撑断言」):**

| 塌陷层 | 含义 | 判 | 数据动作 |
| --- | --- | --- | --- |
| T2 | 生产者确实引了那一行,只是记在了边的 `evidence` 上 | `0` | **不动**。仅在该边即将被删或改指时,须先把 `evidence` 搬进节点 `anchors` |
| T3 | 内容合法下移到 `part-of` 后代,由子承载 | `0` | **不动**。父节点通常无须改 |

**`6` 与 `1` 对边证据的敏感度不同,这是两者最要紧的操作差别:**

- **`6` 因边证据而免除。** 它指控的是「这句话没有引文」,而引文可以合法地长在边上或子树里。
- **`1` 不因边证据而免除。** 它指控的是「节点自己多说了」,后代或边上再多引文也替它收不回来。
  判 `1` 时**不需要**跑四层回查;跑了也不改结论。

**`6` 排除 TD 的理由是语义的,不是体量的。** 下游消费者引了某行 ≠ 上游节点引了它。
不要用「计入 TD 会洗掉多少条指控」来论证 TD 该排除——实测计入 TD 只洗掉 15.6% 的候选,
体量论证撑不住这条规则,语义论证撑得住。

**`6` 有一个不可修子类,须在理由里标出。** 「Apostol 在恰好三处点名闭包公理」这类
**章级计数或否定存在断言**,任何单条引文都不可能见证它。它按定义判 `6`,但修法不是换锚点,
而是改写断言。裁决理由写 `6-不可修`,不为它单开编号。
```

### 4.3 cause 6 候选数：三个口径

「候选」定义：`statement` 句数 > 证据池覆盖的**不同源行数**（过报通道 c 的正确度量）。
这是上界不是缺陷数，用来排优先级。

| 口径 | 546 全口径 | 522 口径 |
| --- | --- | --- |
| 按 T1 源行（只算自身锚点） | 327 | 303 |
| 按 T1+T2+T3 源行（**本条文的正式口径**） | **263** | **239** |
| 若误把 TD 也计入 | 222 | 198 |

- **T2/T3 救下 64 个候选**（327→263）。这 64 个若不承认 T2/T3，会被错判为真缺陷，
  修复动作会被带成「去找新引文」，而引文已经在图里了。
- **TD 若误计入，会额外洗掉 41 个 = 263 的 15.6%**。这就是 §1.3(c) 说的：
  S2「几乎所有」的表述夸大了，TD 排除必须靠语义论证。
- 差值分布（句数 − 覆盖源行数，546 口径）：差 1 句 216 个、差 2 句 37、差 3 句 7、差 4 句 1、
  差 5 句 1、差 6 句 1。

### 4.4 池膨胀实测（说明为什么必须按源行算，不按池条数算）

| 量 | 实测 |
| --- | --- |
| 池总条目数（`pool.tsv`，TD 已排除） | 3334 |
| 去重后不同 `(file, quote)` | 1915 |
| 再压到不同源行 | **1385** |
| `pool_total > distinct(file,quote)` 的节点 | 417 / 546 |
| 池 ≥3 条却全压在 ≤1 条源行上的节点 | **88** |
| 池 ≥5 条却只覆盖 ≤2 条源行的节点 | 57 |
| 池条目落在 `n_sentence_end > 1` 的源行上的 | **2261 / 3334 = 67.8%** |

3334 → 1385 是 2.4 倍虚高。**任何按「池条数」判「证据够不够」的写法都会系统性高报覆盖**，
这就是条文 A 第 3 步写「不得用『池变大了』代替人读」的实测依据。
67.8% 落在多句行上，意味着即使按源行算，一条引文命中该行也不等于命中该行里被指控的那一句
——过报通道 b 在池口径下依然全程有效，所以第 3 步的人读不可省。

### 4.5 复现算法

1. 读 `tmp_index/pool.tsv`，按 `node_id` 聚合，得每节点的 `(file, quote)` 集合（TD 已不在此表）。
2. 读 `tmp_index/source-lines.tsv`，按 basename 建 `file → [(lineno, n_sentence_end, text)]`。
   对每条 `(file, quote)` 取所有满足 `quote in text` 的 `lineno`，得该节点的**覆盖源行集合**。
3. 读 `tmp_index/statements.tsv`，把 `$…$` 内容替换为占位符后按 `[.!?。！？]` + 空白/行尾切句，
   句数下限取 1。
4. 候选 = 句数 > 覆盖源行数。零覆盖 = 覆盖源行集合为空。
5. TD 口径用 `pool-TD-excluded.tsv` 重跑步骤 1–2 后并集，仅用于对照，**不得用于结案**。
6. 522 口径 = `nodes.tsv` 中 `loc` 不含 `structures-L2` 的行；546 口径 = 全表。

副产物核验（用来确认脚本没读错表）：池中引文**无法**在 `source-lines.tsv` 定位的条数 = **0**；
`nodes.tsv` 总句数 1149 / 总锚点 921（S2 报 1142/921，切句细节差异）。

statement 两句（`data/inherited/nodes-A1.jsonl:60`）：
`An orthogonal set is called orthonormal if each of its elements has norm 1. Dividing each
element of an orthogonal set by its norm produces an orthonormal set.`

池 9 条（T1 2 / T2 2 / T3 5），去重后 3 条不同 `(file,quote)`，只覆盖 **2 条源行**：
`15.11.md:3`（`n_sent=4`）与 `15.11.md:35`（`n_sent=2`）。第 1 句被 `15.11.md:3` 覆盖。
第 2 句的引文是 `15.11.md:35`「Dividing each $u_{n}$ by its norm, we obtain an orthonormal set…」
——这条引文**存在且覆盖到了**，所以**不是 6**；但它讲的是三角函数例子里的 $u_n$，
那里每个元素非零（Apostol 明说），节点把它说成对任意正交集成立的一般结论，漏了非零前提。
**判 1，且不因池里有 T2/T3 而免除。** 这是分界的标准形态：
6 问「有没有引文管这句」，1 问「引文管的范围有没有被节点超出」。

### 反例 2（T2 与 TD 长得一样，必须分清）—— `apostol:zero-element`

statement 第 2 句「In a function space the zero element is the function whose values are
everywhere zero.」的逐字依据确实在图里：`15.03.md`「The zero element is the function whose
values are everywhere zero.」（`data/inherited/edges-A1.jsonl:18` 的 evidence）。
但那条边是 `apostol:function-space --requires--> apostol:zero-element`，
`apostol:zero-element` 是 **dst**，所以这条是 **TD，不入池**。
按池判：该句无覆盖，**6 成立**。若审查员只做「grep 图里有没有这句引文」，会误判为 0。
`apostol:zero-element` 的 TD 有 14 条，其中 12 条带非空 quote——**TD 最多的节点最容易被误免除**。

### 反例 3（T3 结构上不可达）—— 24 个 `L2:` 节点

`L2:closure-certificate-for-subspacehood`（16 members）与 `L2:dimension-as-a-two-sided-count-barrier`
（9 members）的 statement 都点名了具体节号（15.03/15.06/15.14；15.5/15.06/15.6），
但它们 T1=T2=T3=0：L2 不在 `partof.tsv`（0 行）、不在 `edges.tsv`（作 src 0 条、作 dst 0 条）。
**对 L2 直接套条文 A 的判定程序，24 个全部判 6，这是假阳性 24 个。**
原因是 L2 的下连靠 `members` 而非 `part-of`，而四层池只沿 `part-of` 走。
边界处理：**条文 A 的判定程序不适用于 `L2:` 及以上的抽象层节点**——
它们由 `SPEC.md:56–57` 与 `:87` 的 `members` / `boundary` / `abstraction_gain` 规则管，
锚点本来就不要求。若要让池对 L2 有意义，需引入一个「TM 层 = members 的池并集」，
实测 24 个 L2 全部会因此获得非空池，合计新增 913 条不同 `(file,quote)`。
**我不建议现在开 TM 层**：它会让 L2 借下层引文来「证明」自己的抽象增益，
正是审计 B 要杀的伪抽象的最好掩体。这条留给主控裁。

### 边界情形 1：不可修子类

「Apostol 在恰好三处点名闭包公理」这类章级计数/否定存在断言，任何单条引文都不可能见证。
按定义判 6 但换锚点救不了，只能改写断言。条文 A 已写 `6-不可修` 标记法，不单开编号。

### 边界情形 2：借用引文（盲区 B 型）与 6 的关系

实测：**119 个节点的池里每一条引文都同时被别的节点引用**，347 个节点至少有一条被共享。
这些节点的池是非空的，按条文 A 的第 3 步会被判「有覆盖」⇒ 0。
**但引文被 N 个节点共用，恰恰是它对每一个节点都只是泛泛覆盖的信号。**
条文 A 不为此新增判据（那是 S1/S3 的锚点与共享引文条目的范围），
但第 3 步的人读必须在这 119 个节点上格外谨慎——`shared-quotes.tsv` 的 `n_holders` 最高到 16
（`15.03.md` 那条 115 字符的引文被 7 个节点 + 9 条边共用）。

### 边界情形 3：15 条未校验的 model-quote 进池

`unverified-model-quotes.tsv` 的 15 条边（全在 `data/edges-X.jsonl:106–121`，全为 `generalizes`，
全部 `src` 为 `apostol:`）带 quote 但 `origin=model`，`check_graph` 从不校验它们。
它们会以 T2 身份进池，即**可能免除 cause 6 指控，而其引文从未被任何工具核过**。
我逐条 grep 了 `source-lines.tsv`：**15/15 全部逐字命中源行**，所以本轮不产生错误免除。
受影响面很小：只有 2 个节点的 T2 新引文**全部**来自这 15 条——
`apostol:euclidean-space`（`15.10.md:25`）与 `apostol:orthogonal-to-a-set`（`15.14.md:11`，
该行 `n_sent=2`）。条文 A 无须为此加规则，但结案时若一条指控的免除只靠这两个节点的 T2，
须在理由里注明「免除依据来自未经 check_graph 校验的 model 边」。
