# SPEC 待议项 P04：3 锚点上限是否提高

## 〇 裁定（进 SPEC / 不进 SPEC / 有条件进；一句话理由）

**有条件进 SPEC：数字上限维持 3 不动，改为「3 条 + 按 `sections` 计的追加槽位」的软上限，
同时新增一条真正咬得住「抄整节」的规则——同节点内两条锚点不得落在完全相同的源行集合。**

一句话理由：实测**没有一个节点因 3 条上限而被迫留下无锚断言**——81 个满额节点里，
只有 11 个的 `statement` 句数 ≥3 且无 part-of 后代（T3 救不了），
而这 11 个的无锚句里逐一核过后，**没有一句是「书里有原文、只是锚点槽用光了」**：
它们的无锚句全部是模型自己的对比判断（书上根本没有可引的字），提高上限对它们无效。
真正被 3 条卡住的是另一类——**跨 section / 跨教材节点**：22 个节点的锚点没覆盖到它自己声明的
全部 `sections`，其中 6 个已在 3 条满额，扩不了。所以要动的不是「3」这个数，
而是「3 是按节点算还是按 section 算」。

### 1.6 上限抑制「抄整节」的实际效力：实测它没在抑制

这是我最重要的负面结果。若 3 条上限是防抄的闸门，那么满额节点应当是引文体量最大的。实测：

- **锚点总字符数**（anchors.tsv 的 charlen 逐节点求和）：全图中位 156、p90 273、p99 405、
  **max 463**。满额节点的总字符 min 102 / mean 278 / max 463。
  即**一个满额节点最多也只抄了 463 字符**，而单个源文件最小 950 字符（15.01.md）、
  最大 33872 字符（strang-ch4/4.3.md）。
- **单节点锚点占单一源文件的字符比例** Top 3：`apostol:linear-space` 占 15.01.md 的
  **31.5%**（299/950）、`apostol:theorem-elementary-algebraic-properties` 占 15.04.md 的
  14.5%（372/2572）、`apostol:cx-legendre-family-changes-with-the-interval` 占 15.16-exercises.md 的
  12.3%（330/2694）。**唯一接近「抄整节」的是 31.5% 那一个，而它只有 3 条锚点、299 字符**
  ——它之所以占比高，是因为 15.01.md 只有 950 字符（全语料最小文件），不是因为它贪。
- 真正的「整节被抄光」发生在**文件层面而非节点层面**：全图锚点字符量 / 文件字符量
  （含跨节点重复引用）：15.02.md **209%**、15.03.md **205%**、15.08.md 168%、
  15.10.md 145%、15.11.md 128%、15.06.md 126%、15.01.md 126%、15.04.md 124%。
  **超过 100% 意味着同一段原文被多个节点反复引用。**
  换算成去重后的行覆盖：Apostol 16 个文件的 453 条实质行（≥30 字符）里
  **335 行被至少一条锚点触及 = 74%**，逐文件从 15.09-exercises.md 的 35% 到 15.01.md 的 100%。

**推论：3 条上限管的是「每个节点抄多少」，但「整节被抄成锚点」是靠 546 个节点各抄 3 条
在文件层面累加实现的——上限对这条路径完全无效。**
15.02.md 的 209% 是在**零违规**（无任何节点超 3 条）的前提下达到的。
所以「上限抑制抄整节」这个说法**在本图上被实测否证**：
它在节点层面有效（max 463 字符），在文件层面无效（209%）。

把每条锚点映射回它触及的源行（逐行子串匹配，跨行锚点按段拆分后分别匹配），统计满额节点的

| 3 条锚点触及的不同源行数 | 满额节点数 |
| --- | --- |
| 3 行 | 68 |
| 2 行 | 11 |
| 1 行 | **2** |

**13 个满额节点的锚点槽位被冗余消耗**（3 条锚点只指向 ≤2 条源行），
其中 `apostol:legendre-polynomials` 与 `d:metric-properties-motivate-the-inner-product`
的 **3 条锚点全部落在同一条源行上**。放宽到全图（不限满额）：

## 二 拟并入 SPEC 的逐字条文

### 条文 P04-a（替换现行 `SPEC.md:53` 的「最多 3 条」）

```
- 至少 1 条。上限按下式计算,称为**锚点预算**:

      锚点预算 = 3 + (该节点 `sections` 条数 - 1)

  单 section 节点预算 3 条(与旧规则一致);跨 2 节的节点 4 条;跨 3 节的 5 条,以此类推。
  预算是**上限不是配额**:用不满不是缺陷,只有超出才是。
  上限的目的是抑制「把整节抄成锚点」,**不是**抑制「为多个出处各留一条见证」。
- 若某节点的 `sections` 事后被增删,它的锚点预算随之变化。缩减 `sections` 而不删对应锚点
  是违规,须在同一次改动里一并处理。
```

### 条文 P04-b（新增，紧随 P04-a；这是本项真正的防抄闸门）

```
- **同一节点的任两条锚点不得落在完全相同的源行集合上。**
  判据:把每条 `quote` 按其在 `file` 中出现的行拆开(跨行锚点算它跨过的全部行),
  得到一个行号集合;同节点内两条锚点的行号集合**相等即违规**。
  一条源行含多句时(句末标点数 > 1),从该行切出两条锚点分给同一节点仍然违规——
  要引这一行的两句话,用**一条**覆盖两句的锚点,或把第二句交给一个独立节点去持有。
- **同一节点的锚点总字符数不得超过 600。** 这是抄整节的直接闸门,
  比条数上限更贴近它想拦的东西:现有 518 个有锚节点的总字符 max 为 463,故此界现状零违规,
  留出的余量恰好容纳 P04-a 允许的跨 section 追加槽位。
```

### 条文 P04-c（新增，写进 §锚点规则 末尾；把口传的意图落成文字）

```
- 上述三条界(条数预算、同源行去重、总字符 600)都是**节点级**的。它们**不约束**
  同一段原文被多个节点分别引用:那属于形式 B(借用引文)的审计范围,
  由共享 `(file, quote)` 检查处理,不由锚点上限处理。
  已知现状:去重后 Apostol 16 个源文件的实质行(≥30 字符)有 74% 被至少一条锚点触及,
  个别文件的锚点字符总量达到文件字符量的 209%(同一段被反复引用)。
  **报「锚点零违规」时必须同时报这两个数,否则会让人误以为上限在防抄。**
```

**算法 3（满额 + 无后代 + 句数≥3）**：

句数按 `re.sub(r'\$[^$]*\$','M',statement)` 后 `re.split(r'(?<=[.!?])\s+')` 计。

「A 且 B，因此 C」只算一句，所以 11 是**下界**，真实被卡的节点数 ≥11。
但 §1.4 的逐条复核走的是「书里有没有这句话」而非句数，那一步不受此偏差影响。

**算法 4（source-line 映射，P04-b 的判据实现）**：
把 `source-lines.tsv` 建成 `basename(file) -> [(lineno, text)]`；
对每条 `quote`，先 `q.replace('\\n','\n')` 还原转义，按 `\n` 拆成片段，
每个非空片段在该文件的所有行上做 `片段 in 行文本` 测试，收集命中行号并集。
同节点内两条锚点的行号集合相等 ⇒ 违规。
**已知偏差**：短片段可能在同一文件的多行命中，此时行号集合偏大，

故本轮跨行拆分实际未触发；S1 若放行跨行锚点，此算法仍适用但会开始生效。

**算法 5（每 section 是否有锚）**：`sections` 用 `,` / `;` 拆，

且它只查「文件对不对」，不查「引文是否真在该 section 的语义范围内」——
形式 D（射程不足）它查不出来。

分布：0–99 有 107 个、100–199 有 246、200–299 有 131、300–399 有 28、400–499 有 6。

## 五 反例与边界情形

### 反例 1（对 P04-a 的反例，也是三方案代价的分水岭）：`x:right-count-upgrades-one-basis-property-to-both`

`sections = 15.08, 3.4, 4.1`，现有 3 条锚点：`15.08.md` 1 条 + `4.1.md` 2 条，**`3.4.md` 零锚**。
它的断言是「正确的计数把 basis 的一条性质升级成两条」，这是一个跨教材不变量，
按定义要三处都见证才站得住。

- **维持 3**：它永远缺 `3.4.md` 的见证，形式 D（射程不足）无法消除。
  代价是这个节点的核心断言（「跨三处都成立」）**结构上不可能被证成**。
- **提到 5（一律）**：它得 5 槽，缺口可补。但 465 个单 section 节点也各得 5 槽。
- **P04-a**：它得 `3+(3-1)=5` 槽，缺口可补，且单 section 节点一条不多。

**P04-a 与「一律提 5」在这个节点上结果相同**，分歧只在别处的成本——这就是我采 P04-a 的全部理由：
同样的收益，465 个节点的放宽是可以不付的。

### 反例 2（对 P04-a 的反面反例）：`apostol:cx-l2-sequence-space-is-an-infinite-dimensional-euclidean-space`

`sections = 15.12, 15.10, 15.11`，3 锚全在 `15.12-exercises.md`，缺 15.10 与 15.11。
P04-a 给它 5 槽，恰好补齐。**但这里有一个陷阱**：它的 `sections` 里
15.10 / 15.11 可能是「概念上相关」而非「有原文出处」——
若是前者，P04-a 会诱使抽取者去 15.10.md 硬找一条勉强相关的引文来填槽位，
**制造形式 D 而不是消除它**。

**边界处理**：P04-a 的预算式**不构成填满的义务**（条文已写明「预算是上限不是配额」）。
但这提示 `sections` 语义本身没定清——那是另一个待议项（见 §六）。
**若 `sections` 最终被定义成「概念相关即可列」，P04-a 的预算式就失去依据，须改回按出处文件数计。**
这是 P04-a 唯一的实质依赖，我把它明写在这里。

### 边界 3（对 P04-b 的边界）：源行含多句时的合法写法

`15.13.md:15` 是一条 255 字符、**句末标点数 2** 的源行：

```
(c) The sequence $y_1, y_2, \ldots$ , is unique, except for scalar factors. That is, if $y_1', y_2', \ldots$ , is another sequence of elements in $V$ satisfying properties (a) an...
```

`apostol:orthogonal-sequence-unique-up-to-scalars` 从它切了前 75 字符做锚点（anchors.tsv:8）。
若同一节点再从这一行切「That is, if ...」做第二条锚点，P04-b 判违规。
**合法写法有三个**：(1) 用一条 30–200 字符的锚点同时覆盖两句
（这一行 255 字符 > 200，故须择一或从中途起始——与 S1:85 的「非行首对齐」退化写法耦合）；
(2) 把第二句交给一个独立节点持有，通过 part-of 边成为本节点的 T3；
(3) 只引第一句，第二句作为断言的一部分靠 T2/T3 支撑。
**现状走的是 (2)**，且这正是 `apostol:theorem-15-13-orthogonalization-theorem` 那条无锚句的实际来源
（§1.4 第 1 条），说明 P04-b 与现有实践相容。

### 边界 4（对 P04-b 总字符 600 界的边界）：最接近上界的节点

现有 max 是 463 字符。若某节点因 P04-a 得到 5 槽并全部用满 200 字符，得 1000 字符，越界。
**这是有意的**：600 界的作用正是让「5 槽全用满长引文」不可能，
迫使追加槽位用于**新出处的短见证**，而不是把节点变成引文仓库。
代价：一个跨 3 节、每节都需要 200 字符长引文的节点（例如三个定理陈述都很长）
会在 600 界上撞死。**实测这样的节点现在不存在**（max 463），但它是可能的，
届时该节点应当被拆成三个节点 + part-of，而不是提高 600 界。

### 边界 5（对「取消上限」的反例，即取消方案的实际代价）

取消上限后，节点级唯一约束是 30–200 的单条长度界。
`15.10.md` 有 58 条实质行（≥30 字符）、7547 字符；
一个节点可以合法地建 58 条锚点把整节搬进 `anchors`，`grep -F` 全部通过，
`verify_anchors.py` 报 pass rate 100%。
**而这不是假想的下滑方向**：15.02.md 与 15.03.md 的锚点字符量已达文件的 209% / 205%，
抄的倾向在数据里可测。目前拦住它的**只有**「最多 3 条」这条界——
而这条界正是本项在考虑取消的那条。取消它同时会让 P04-b 的去重条款成为唯一防线，
而 P04-b 只禁「同源行」，不禁「相邻行逐行抄」。**故取消上限不可接受。**

| 方案 | 6 个跨 section 缺口 | 465 个单 section 节点 | 抄整节风险 | 追溯违规 | 形式 B 检测面 |
| --- | --- | --- | --- | --- | --- |
