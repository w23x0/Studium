### 2.1 下拆了（3 个 A1 节点 → 3 个 d: 节点）

**#4 `apostol:theorem-uniqueness-of-negatives`（定理 15.2）→ 2 个子节点**

- `d:thm-15-2-same-sum-evaluated-in-two-groupings`
- `d:thm-15-2-left-neutrality-needs-the-commutative-law`

辅助表达式的选取是整个证明的全部内容，从结论反推不出来。

第二个子节点抓的是原文里一处**可观察但容易滑过去的痕迹**：重结合那一路出现了 `O + y_1`，

`O + y_1 = y_1 + O` 才敢塌成 `y_1`，也正因此这个「看起来只关乎结合」的证明要引 Axiom 3。
它比兄弟节点多给的是：那一步塌陷**不是立即的**。

## §7 边方向的选择及理由

**我的选择：`part-of` 写作 `src = 子节点（d:）`、`dst = 父节点（apostol:）`。**

三条依据一致指向这个方向：

1. **关系词表语义（SPEC 第 19 行）**：`part-of` 定义为「**src 是 dst 的组成成分**」。
   子节点是父节点的组成成分，所以子节点必须在 src 位。
2. **既有惯例**：我读了 `data/edges-D1..D4.jsonl` 共 284 条 `part-of` 边（只看方向，未审计内容），
   **214 条是 `d: → apostol:`**，另有 3 条 `apostol: → d:`（D1，疑似笔误），
   67 条是 `d: → d:`（二级下延，同样是子在 src）。惯例压倒性一致。
3. **与 SPEC 第 75 行「纵向边方向恒为粗 → 细」的张力**：这两条规则在 `part-of` 上冲突。
   我按**语义优先**处理，理由是 SPEC 自己在第 14 行写明「方向严格按下表理解，方向错误判为缺陷」，
   把关系词表列为方向的裁决依据；第 75 行是一条概括性描述，且它同时点了
   `part-of` 与 `requires` 两个词——而 `requires`（「要陈述或理解 src 必须先有 dst」）
   在细→粗方向上才讲得通（要理解一个证明步骤，得先有它用到的公理）。
   若强行按"粗→细"写 `part-of`，得到的是「父节点是子节点的组成成分」，与词表直接矛盾。

任务书边 schema 示例给的是 `{"src":"apostol:<父>","rel":"part-of","dst":"d:<子>"}`，
**与我的选择相反**。我没有采用示例的方向，因为它同时违背词表语义与既有 214 条惯例，
采用它会让 D5 成为全图唯一方向相反的文件。**如果这是刻意的口径变更，请回退我这 3 条边。**

其余关系：
- `requires`（6 条）：子节点 → 它依赖的公理/概念，符合「要理解 src 必须先有 dst」。
- `other`（1 条，`origin: model`，已填 `rel_note`）：
  `d:thm-15-2-left-neutrality-needs-the-commutative-law → d:thm-15-2-same-sum-evaluated-in-two-groupings`。
  两者是同一证明链上的兄弟，前者**限定**后者的一个步骤，既不是成分关系也不是推出关系，
  9 个封闭关系词无一贴合，故用 `other`。此边如实标注为 `model`，未伪造原文依据。
