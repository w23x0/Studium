# 墓地文件截断事故与恢复记录

> 这份文件记录一次由我（执行代理）造成的数据丢失、恢复过程、以及**恢复不完整的确切边界**。
> 写在这里而不只写在实验报告里，是因为任何读 `killed-*.jsonl` 的人都必须先知道这两个文件不是原件。

## 1. 事故

我运行了 `python tools/apply_kills.py --help`，预期得到用法说明。该脚本没有 `argparse`：
`sys` 被 import 但从未读 `argv`，`--help` 被完全忽略，脚本按硬编码默认值直接执行，
其中两处**无条件** `open(..., 'w')` 把两个墓地文件清成 0 字节。

错误的假设是我的：**`--help` 不是只读操作**——我在一个自己没读过源码的写入型脚本上做了这个假设。

- 无法从 git 恢复：`docs/图工程调研/` 未被跟踪。
- 无法从 `/tmp` 备份恢复：当时的备份是 `a2x2 / d1 / l2a / l2b / l2c`，都不含墓地。
- `report/audit-B-verdicts.jsonl` 只有 `['cause','id','reason','verdict']` 四个字段，
  没有节点正文、没有边，所以裁定文件不能替代墓地。

## 2. 恢复结果

| 文件 | 原件 | 现状 | 缺口 |
|---|---|---|---|
| `killed-nodes-auditB.jsonl` | 28 | **28（完整）** | 0 |
| `killed-edges-auditB.jsonl` | 88 | **68** | **20** |

节点从子代理转录恢复：扫描 226 个 `.jsonl`，5 个文件有贡献
（`agent-a2bf6eb6d09f8de88` 5 条、`agent-a68019f3f27c6f0b5` 9 条、`agent-a8df2911809dcfda1` 14 条，
另两个文件只贡献边）。28 条全部字段齐全，共 35 个锚点，28 条都带 `parent`。

边分两类，**标签不同，不可混为一谈**：

- `_recovered_from: <transcript>` —— 40 条，从转录里逐字取回的原件。
- `_reconstructed: true` —— 28 条 `part-of`，**不是**取回的，是从节点的 `parent` 字段推出来的。

## 3. 为什么 28 条 `part-of` 只能推导

去重前的全量重扫（`tmp_diagnose_edges.py`）在**任何**转录里都找不到一条涉及被杀节点的
`part-of` 边：28/28 个被杀节点，0 条命中。原因是生产代理不是把这些边当字面 JSON 写出来的，
而是用脚本遍历 `parent` 字段批量生成的，所以它们从未以文本形式存在过，无从"恢复"。

推导规则先在活图上验证过，不是猜的：

- 活图 287 个带 `parent` 的节点里，**284** 个存在方向为 `src=子, dst=父` 的 `part-of` 边；
- 反方向（`src=父, dst=子`）匹配数为 **0**。

所以三元组 `(src, rel, dst)` 可以确定地重建。但原来的 `evidence` / `origin` / `normalized`
三个字段随文件一起丢了，**这里故意留空而不是编一个**——编一个 `evidence` 就正好是本实验
判死因 2（伪造归属）的行为。

## 4. 永久丢失的 20 条

`requires` 15、`contrasts` 4、`is-a` 1。这 20 条：

- 在转录里不存在字面文本（同 §3 的原因，或写它们的代理转录已不可得）；
- 没有像 `parent` 那样的字段可以反推，`requires` / `contrasts` 只存在于边文件里；
- 因此**不可恢复**，此处不做任何填补。

计数的权威来源是原始运行在主转录里留下的 stdout：

```
graveyard: 28 nodes, 88 edges
edges by rel dropped: {'contrasts': 5, 'other': 1, 'requires': 52,
                       'part-of': 28, 'equivalent': 1, 'is-a': 1}
```

## 5. 影响范围（重要）

**活图未受影响。** 墓地是审计留痕，不是图的一部分；被杀节点和被丢弃的边本来就已经从
`data/` 里移除了。丢的是**丢弃记录的完整性**，不是图的完整性。

具体后果：这 20 条边的 `evidence` 和 `origin` 无法再被复查，
所以"audit-B 的 28 个 KILL 各自牵连了哪些边、依据是什么"这个问题只能回答到 68/88。
实验报告必须如实写出这个数字，不能写"墓地已恢复"。

## 6. 已做的防再犯

`tools/apply_kills.py` 已加固：真正的 `argparse --help`、`--dry-run`、
墓地写入改为**追加或拒绝**（目标文件非空时拒绝覆盖并退出），
恢复脚本 `tmp_recover_graveyard.py` 的写入口同样是"非空即拒绝"。
