#### 1.1 三个判据，逐条给出计算式

设 `cites[(file, quote)]` = 引用该 (文件, 引文) 对的**节点**集合（**边的 evidence 不计入**，
理由见 §1.2）。对每个节点 `v`，令 `B(v)` 为它的批次。

**判据 S1（批次内共享度）**
```
intra(v) = max over groups g containing v of  |{ u in g : B(u) == B(v) }|
```
即：在 v 参与的所有共享组里，**与 v 同批次**的引用者数目的最大值。
`intra(v) == 1` 表示 v 的每条锚点在自己批次内都无人共用。

**判据 S1'（跨批次广度，反向指标）**
```
cross(v) = max over groups g containing v of  |{ B(u) : u in g }|
```
`cross(v) == 1` 表示 v 所在的最大共享组**完全落在一个批次内**。

**判据 S2（源材料类型，与共享无关）**
```
exonly(v) = (v.anchors 非空) and (v 的每一条 anchor 的 file 都匹配 *-exercises.md)
```

**判据 S3（未披露模型内容）**
```
nodecl(v) = ('origin' not in v) and ('origin_note' not in v)
```

#### 1.2 为什么 evidence 不计入分组

`check_shared_quotes.py` 把边的 evidence 与节点 anchors 混在同一个计数里（源码 :68–81），
`--min` 因此同时受两者影响。这与四层证据池的 TD 排除原则冲突：
边的 evidence 是**边**的记账，不是 dst 节点的引用。
实测差异不小：含边时不同 `(file, quote)` 对 875 个、总引用 1852；
只算节点锚点时 708 对、921 次引用。
`report/_形式B-共享引文候选.md` 头部写的「708 对」证明**那份清单实际是按节点锚点算的**，
即它跑的是 nodes-only。本提案沿用 nodes-only，以便与已标注的金标准可比。
