```markdown
## 共享前提的记账(P17)

若两条或更多断言(定理/证明步骤/例)依赖同一个前提,该前提**只建一个节点**,
由每个依赖方各发一条 `requires` 边指向它。**禁止在两处的 `statement` 里各写一遍。**
这是第 45 行「不要造新 id 重复表达同一对象」在内容层的延伸:同一对象不得有两个 id,
同一前提也不得有两份文字。

判定重复的机械口径:两个节点的 `statement` 若有一句在去空白后完全相同,即判重复,
保留锚点更贴合该句的一方,另一方改为发 `requires` 边。

### 建节点闸门(三条,全部必须满足)

1. **自陈锚点**:该节点至少有 1 条锚点,其 `quote` 逐字陈述了这个前提本身,
   而不只是提到前提所属的定理。锚点数为 0 的节点不得充当共享前提。
2. **书面地位**:若该节点的**全部**锚点都与它 `part-of` 父的锚点是同一 (file, quote),
   则该 `quote` 必须含教材自己给的标号(`AXIOM n.` / `THEOREM n.` / `EXAMPLE n.` /
   `DEFINITION` / `Note:` / 行首枚举号 `(1)` `(b)` / 带 `\tag{}` 的编号公式)。
   教材给了标号,前提的独立地位就是书给的,共用同一句是忠实转录;
   教材没给标号而模型仍拆出一个节点,则地位是模型赋予的——必须补一条自有锚点,否则不得建节点。
3. **最短跨度**:锚点应取包含该前提的**最短**逐字连续跨度。若定理的前提与结论写在同一源行,
   不得把结论一起圈进锚点,除非最短的前提-only 跨度不足 30 字符——此时按锚点规则的
   短跨度豁免处理,并在 `atomic_reason` 里写明为何被迫加长。

### 不受闸门约束的情形

被 `requires` 指向次数为 0 或 1 的前提节点**不因此判违规**。前提节点的正当性来自它自己的内容
(例如「这条假设不可去掉」「去掉后有何反例」),不来自被引用次数。
「只是把父节点已写出的内容原样搬出来、自身不加任何断言」才是删除对象,
这一判断由审计 A 逐条做出,**不得用入度阈值机械代替**。

### 死因归属

违反「禁止两处各写一遍」记 **死因 0(仅需 FIX)**:内容都在图里,只是记账重复,
FIX 动作是删去一份文字并补 `requires` 边。
违反闸门 1(无自陈锚点)记 **死因 6**(引文不支撑断言)。
违反闸门 2(借父锚点且父句无书面标号)记 **死因 5**(伪抽象·层塌缩):
该节点与父在证据上不可区分,层次是虚设的。

锚点过覆盖,`grep -F` 全绿而断言与引文不等长。

## 五 反例与边界情形

### 5.1 反例：闸门 2 若写成「不得借父锚点」就会误杀 10 条

最直接的写法是「共享前提节点不得与其 part-of 父共用同一 (file,quote)」。
这会把 14 个全借用者全判违规，其中 10 个是错判。最清楚的一例：

```

它的父 `apostol:linear-space`（或 `apostol:axioms-for-addition`）持同一句。
但教材自己写了 `AXIOM 6.`——这条前提在书里就是一个有编号的独立单元，
子节点引用它自己的编号句是唯一正确的引法，另找一句反而会引到不相干的文字。
`requires` 入度 3，是真正的共享前提。**判它违规就是拿规则惩罚忠实转录。**
这就是为什么闸门 2 的判据必须是「父句有没有书面标号」而不是「有没有借」。

### 5.2 边界情形：入度 0 的前提节点

`d:linear-space-requires-a-nonempty-underlying-set`，`requires` 入度 **0**，
只有一条 `part-of` 出边指向 `apostol:linear-space`。按「共享前提须被 ≥2 处依赖」的
朴素读法它该被折回父节点。但它的 statement 是：

> V is declared nonempty before any axiom is stated. The clause is not idle: of the ten
> axioms only Axiom 5, being existential, would fail for the empty set, so without the
> nonemptiness declaration the exclusion of the empty set would rest entirely on that one axiom.

这是一条可核查的数学观察（十条公理里只有存在性的 Axiom 5 会在空集上失败），
不是记账位。折回去会丢内容。故条文第「不受闸门约束的情形」一段明文写了
入度 0/1 不判违规，且禁止用入度阈值机械代替审计 A 的判断。
代价是这一段不可机械执行——我接受这个代价，因为可机械执行的版本会误杀 4 个带内容的节点
（1.5 节表中入度 ≤1 的四行）。

### 5.3 边界情形：闸门 3 与 30 字符地板冲突时

`d:inner-product-positivity-axiom` 的前提本体是行间公式 `(x, x) > 0 if x != O`。
§3.9 已实测：内积公理 (3) 的最短跨度 21 字符、范数定义 26 字符，都在 30 地板之下；
本节点现锚点 35 字符只因 OCR 把 `\quad i f \quad` 拆开才过线。
若闸门 3 要求「取最短跨度」，而最短跨度不足 30，两条规则直接冲突。
条文用「除非最短的前提-only 跨度不足 30 字符——此时按锚点规则的短跨度豁免处理」
把冲突交回锚点规则去解，并要求在 `atomic_reason` 里写明。
**这是一处显式的向后依赖**：若 §3.9 的豁免条文最终未进 SPEC，闸门 3 在这类节点上无法执行。

### 5.4 边界情形：无 part-of 父的共享前提

132 个共享前提节点里 69 个没有 `part-of` 父（多为 `apostol:` / `strang:` 继承层节点，
如 `apostol:norm` 入度 18、`apostol:inner-product` 入度 16）。闸门 2 对它们**不适用**
（没有父可比对），这是条文的有意留白，不是漏洞：借用只在父子之间才构成层塌缩。
它们仍受闸门 1、3 约束，且全部通过闸门 1。

### 5.5 反例方向的自查：有没有「该重复反而更忠实」的情形

我找过一个反向反例——某个前提在两节里被教材用**不同措辞**各写一遍，
此时建两个节点也许更忠实。候选是 `15.03.md` 与 `15.07.md` 各有一处 `EXAMPLE 7`
（`shared-quotes.tsv` 里 `EXAMPLE 7` 命中 2 条，分别是 76 字符的多项式例与 89 字符的指数例）。
但这两处是**不同的例 7**（不同节各自编号），不是同一前提的两种措辞，
所以不构成反例。**我没有找到「该重复」的实例**，这支持主条文的禁令。
