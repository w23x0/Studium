## 〇 裁定（进 SPEC / 不进 SPEC / 有条件进；一句话理由）

**有条件进 SPEC。** `SPEC.md:53` 与 `:55` 确实互相矛盾（:55 第二分支的前提「找不到可逐字引用的
依据」在 :53 无条件成立时永远无法执行，是死条文），消解方案是：**把「无锚」从「找不到锚点」
收紧为「原理上不可锚」，用一个封闭词表的新字段 `unanchorable` 显式登记，并给
`tools/verify_anchors.py` 补一条对无该字段的无锚节点判失败的检查**——不这样做，豁免默认对全部
522 个节点生效，等于把唯一硬校验作废。

配套的关键更正：`origin: model` **不是**豁免锚点的凭据。现有 24 个 `origin: model` 节点里
**20 个有锚点**（共持 37 条锚点），说明这个字段在既有用法里只表示「statement 的内容出自模型」，
与「有没有锚点」正交。把 :55 读成「标了 model 就可以无锚」会一次性授权全部 24 个节点无锚。

### 1.3 决定性的复核：`origin: model` 与「无锚」在既有数据里是正交的

这是本提案最重要的一次实测，它推翻了「标 model ⇒ 可无锚」这个读法：

| 交叉分类 | 节点数 |
| --- | --- |
| `origin: model` **且有锚点** | **20**（共持 **37** 条锚点） |
| `origin: model` 且无锚点 | **4** |
| `origin: source`（全部有锚点，1–2 条） | 9 |
| 无 `origin` 字段 | 513（其中 24 个是 L2） |

算法：`awk -F'\t' 'NR>1 && $7=="model"{if($6>0)c++;else z++}' tmp_index/nodes.tsv` → 20 / 4。
20 个的清单可由同一条命令加 `{print $1}` 取得，跨 D1/D2/D3/D4/H2 五个批次
（如 `data/nodes-D4.jsonl:19` `d:normalized-element-has-norm-one` 带 **3** 条锚点、
`data/nodes-H2.jsonl:10` `apostol:ext-uncited-dimension-of-a-second-order-de-solution-space` 带 2 条）。

**结论：生产者在既有用法里把 `origin: model` 当作「statement 的内容出自模型」的标记，
不是「豁免锚点」的申请。** 若把 :55 直译为「标了 model 即可无锚」，等于追认这 20 个节点
也可以随时删掉它们的 37 条锚点仍然合规——那是净损失。**故消解方案必须把「无锚」的凭据
与 `origin` 解耦，另设字段。**

## 五 反例与边界情形

### 5.1 反例一：豁免门槛会被「沾边的引文」绕过 —— `:72` 自身就是现成的绕法

`15.08.md:23` 逐字有 `(b) Any set of n independent elements is a basis for V.`
（实测 **55** 字符、文件内出现 **1** 次、不含换行，完全满足 `:53` + `:54`）。
一个生产者完全可以把它挂到 `:72` 上，于是 `:72` 从「无锚」变成「1 条已验证锚点」，
`verify_anchors.py` 通过、`nodes with NO anchor` 归零、豁免与新字段全都用不上。

但这是 **C 型（拿端点当中间步骤）叠加 D 型（射程不足）**：`:23` 是定理的**结论陈述**，
`:72` 陈述的是**论证过程**；用结论去锚论证，等于宣称原文写了论证。该引文另有三个正当持有者
（`apostol:theorem-15-7`、`data/nodes-D2.jsonl:69`、`x:right-count-upgrades-one-basis-property-to-both`），
挂第四个还会加一次 B 型共享。

**这说明新条文的门槛无法机械化。** 「原理上不可锚」的判定需要人读引文与断言的语义关系，
`grep -F` 只能证明引文未被篡改。条文里写了「否定性检索 + 零命中」作为可复核的证据形式，
但它证明的是「关键词不出现」，不是「不存在任何可锚文本」——`:23` 就不含那些关键词却仍可被挂上。
**这是本条文最大的残留风险，写在这里而不是藏在风险节里。**

### 5.2 反例二：豁免与既有 `apostol:ext-*` 机制的正面冲突（丙类必须同批处置）

图里已有处理章外材料的既定模式：`data/nodes-H2.jsonl` 的 `apostol:ext-*` 节点
**锚点取第 15 章的引用语、内容严格限定为「第 15 章向章外索取了什么」**。
实测这 9 个 `origin: source` 节点全部有 1–2 条锚点，无一个无锚。
`apostol:ext-theorem-12-10-part-c` 的 statement 逐字写着
`Chapter 15 does not restate what part (c) of Theorem 12.10 says.`
而 `:72`/`:73` 带着 `sections:["15.08"]` 陈述该 part (c) 的论证正文。

**两者不可能同时正确地描述 15.08 的内容。** 边表证实两条路径并存：
`edges-H2.jsonl:6` 是 `d:thm-15-7b-n-independent-elements-form-a-basis --requires--> apostol:ext-theorem-12-10-part-c`（origin=source），
`edges-D2.jsonl:93` 是 `:72 --part-of--> d:thm-15-7b-n-independent-elements-form-a-basis`（origin=model）。
同一个父节点下，一条边说「证明在章外」，一条边挂着「证明的正文」。

新条文用「`sections` 必须如实 + `origin_note` 须写明本节只有委托语」把这个冲突显式化，
但**没有消解它**。彻底消解要么把 `:72`/`:73` 重挂到 `apostol:ext-theorem-12-10-part-c` 之下
（改拓扑，超出本提案），要么扩语料引入第 12 章（改实验边界）。**本提案只做到「不再隐形」。**

### 5.3 边界情形：`negative-claim` 与 `derived-criterion` 在本轮零实例

词表三个取值里，只有 `external-proof` 有实例（2 个）。另两个是为 `:42`（全称否定）与
`:54`（推出的判据）预留的——但 §4.2 判定这两个**不该走豁免而该补锚**，
所以落盘后 `negative-claim` 与 `derived-criterion` 的实例数是 **0**。

这是有意的：把它们写进词表是为了让「未来真出现一个整节点全无可锚子句的否定性断言」时
有合法出路，而不是给现有节点找台阶。**风险是零实例的取值最容易被滥用**——
没有先例可对照，第一个用它的人定义它。建议主控在词表旁加一句
「`negative-claim` / `derived-criterion` 首次使用须经审计确认」，或干脆先只留 `external-proof`
一个取值、等真实例出现再扩。后者更稳，我倾向后者，但会让 `:42`/`:54` 万一改写失败时无退路。

### 5.4 边界情形：`anchors` 键该保留空数组还是删掉

条文要求豁免节点保留 `"anchors": []`。理由是 `verify_anchors.py:44` 是
`anchors = node.get("anchors") or []`，两种写法它都当空处理，但**保留空数组能让
`grep '"anchors":\[\]'` 定位到全部豁免节点**；删掉键则只能靠遍历 JSON。
L2 那 24 个走的是相反的约定（键整个不存在），所以**同一份数据里存在两种「无锚」写法**——
这不优雅，但改 L2 的 24 行等于动冻结的结构层，代价大于收益。条文里把两种写法的适用范围写死，
是为了让后续 grep 不会漏。
