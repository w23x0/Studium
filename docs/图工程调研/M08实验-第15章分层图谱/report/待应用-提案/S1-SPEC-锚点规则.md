## 待议项一：短行间公式豁免 30 字符地板

### 现状

SPEC 第 54 行：「长度 30–200 字符。不跨行拼接、不改标点、不加省略号、不修正 OCR 噪声。」

两条约束**同时**生效，才产生「引不了」：单行 + ≥30。35 条数学承载行整行 <30，因而在现行规则下不存在任何合法锚点。SPECQ §4.2 由此确证 17 个受损节点。

### 问题

SPECQ §5.2 提出的解法是**新增 schema 字段**（`formula` + `formula_line`）构成「复合锚点」。这个解法要付三笔代价：改 schema、改校验器（双字段分别校验 + 相邻性判定 + 「同块其余行是否都 <30」）、并且它自己在 §5.4 第 2 点承认拦不住量词滑落——因为它只要求配「最近的 ≥30 字符行」，不要求那行含量词。

### 裁决：**不采纳 SPECQ §5.2 的复合锚点，也不改用唯一性判据。改动「不跨行」这一条，保留 30–200，另把唯一性作为附加闸门。**

三点依据，都实测：

**依据 1：唯一性不能替代长度，它比降地板更松。** 若改成「`quote` 在该 file 内全局唯一即可，不看长度」，本语料 215 条短内容行里 **174 条（80.9%）立刻合法**，其中含 81 条短散文与 56 条标题。实际会被放进来的东西包括 `to obtain`（9 字符）、`so we can write`（15 字符）、`</div>`（6 字符）、`## 15.9 Exercises`（17 字符）——全部文件内唯一。SPECQ §5.1「否决一」拒绝把地板降到 12，理由是「同时让任何 12 字符的散文碎片合法」；**纯唯一性判据招进来的碎片比降到 12 更多**，因为它连长度都不看了。唯一性与「是不是公式」是两个正交的性质，前者管不了后者。

**依据 2：真正卡住这 35 条的是「不跨行」，不是 30。** 一条跨行的连续子串**在书里逐字存在**。`quote` 取 `15.02.md` 第 23–26 行整段，得到 108 字符、含真换行的字符串，它是该文件的逐字连续子串、`grep -F` 可验、文件内唯一、全语料唯一。实测：**35/35 条短公式都存在这样一个 30–200 字符、全语料唯一、以整行为边界、且至少含一条实质行（非空、非 `$$`、≥30 字符）的窗口** 中的 29 条；剩 6 条（`15.13.md:46` 与 `15.09-exercises.md` 的 5 条习题项）的相邻实质行本身超长（224 / 227 / 308 字符），整行对齐后越过 200 上限，需用「非行首对齐」的退化写法（见下文第 4 条），实测这 6 条也都有 30–200 的唯一窗口，故合计 **35/35 可解**。

**依据 3：SPECQ §4.2 的 17 个受损节点背后只有 9 条不同公式，这 9 条全部落在「29 条首选形态」里。** 逐条实测：`15.02.md:26/34/40/46`、`15.03.md:16`、`15.10.md:108`、`15.13.md:90`、`15.15.md:6/14` —— 9/9 均有首选窗口。即**本修订覆盖已确证损害的全部**。

**依据 4（这是跨行窗口优于复合锚点的关键）：行首对齐的向上窗口自带量词。** SPECQ §5.4 第 2 点把「量词滑落」列为最应被质疑之处：`x + (- 1) x = O.` 这 16 字符不携带 "For every x in V"。而向上取整行窗口得到的是：

```
AXIOM 6. EXISTENCE OF NEGATIVES. For every x in V, the element $(-1)x$ has the property

$$
x + (- 1) x = O.
```

量词 `For every x in V` 在窗口内，公式也在窗口内，一条 `quote` 同时承载两者。复合锚点做不到这一点（它不要求配的那行含量词），**这正是本方案取代 §5.2 的理由，不只是省一个字段。**

### 可直接并入 SPEC 的逐字文本

目标文件 `SPEC.md`，目标位置：**替换第 54 行整行**（现文为「- 长度 30–200 字符。不跨行拼接、不改标点、不加省略号、不修正 OCR 噪声。**复制粘贴,不要凭记忆重写。**」），替换为以下五条：

```markdown
- 长度 30–200 字符。不改标点、不加省略号、不修正 OCR 噪声。**复制粘贴,不要凭记忆重写。**
- `quote` 必须是该 `file` 的**逐字连续子串**,可以跨行。跨行时 `quote` 内含真实换行
  (JSON 里写作 `\n`),这样的字符串在书里逐字存在,`grep -F` 与 `quote in text` 均可直接校验。
  **禁止拼接**:不得删除、替换或跳过窗口内任何字符,包括空行与 `$$` 围栏行;
  不得把文件里两处不相邻的内容拼成一条 `quote`。判据只有一个——照抄一段连续的原文。
- `quote` 必须在其 `file` 内**只出现一次**。若某段原文重复出现,向外扩窗直到唯一。
- **行间公式必须连同它的断言一起引。** 当断言的公式独占一行且该行 <30 字符时,
  向上扩窗到最近一条实质行(非空、非 `$$`、≥30 字符),整行对齐照抄。
  优先向上而不是向下:引入句通常携带量词("For every x in V"、"for all"),
  向下取收尾句会把量词丢在窗口外。
- 若向上扩窗后越过 200 字符上限(相邻实质行本身超长),允许 `quote` 从该实质行的中途起始,
  但**必须延伸到公式行末尾**,且仍需满足唯一性。此形态下 `quote` 首字符可以不是行首。
```

### 风险

1. **`export_obsidian.py:145` 会被跨行 quote 破坏。** 该行是 `lines.append(f"  > {quote}")`，把 quote 渲染成 Markdown 引用块。quote 内含换行时，只有第一行留在引用块里，其余行掉出块外，而 `$$` 行会被 Obsidian 当作数学定界符，导出笔记的排版会坏掉。**修法**：把 `quote` 渲染前做 `quote.replace("\n", "\n  > ")`。这是本修订唯一确定会破坏的下游消费者，主控改 SPEC 时必须同时改它。
2. **窗口会把邻近的另一条断言一起圈进来。** 例如 `15.09-exercises.md:63` 的首选窗口同时含 `(h)` 与 `(f)` 两个习题项。这就是方法论 4.1 的 B 型（借用引文）与 A 型（宾位错）的温床：一条 quote 覆盖多条断言时，「引文逐字存在」离「引文支撑该断言」更远了。**本修订使锚点变长，因此把 §4.1 的判读负担加重，而不是减轻。**
3. **量词入窗是「优先向上」带来的，不是保证。** 规则要求的是「最近一条实质行」，不是「含量词的行」，后者无法机器判定。实测 `15.02.md` 的四条公理窗口都含量词，但这是 Apostol 的排版恰好如此，不是规则挣来的。**「N/N 锚点已验证」在本修订下仍然不得当作正确性保证。**
4. **退化形态（中途起始）丢掉了行边界这个可读的锚。** 6 条走退化形态的 quote 会形如 `'ave\n\n$$\na (x + y) = a x + a y.'`，首字符是被截断的单词。它逐字存在、唯一、可验，但人读起来像坏数据。这 6 条全部是习题项与证明中间步骤，不在任何已确证受损节点里，**建议主控在这 6 条上不启用豁免、维持现状**（即：这 6 条公式继续不可引），以免用难读的锚点换取零收益。
