## 2 塌缩对清单（含裁定）

### 2.1 内容轴：reason 点名了同批也要杀的节点 —— 3 对，与 `待应用清单.md` §3 逐条对上

机械口径：把全图 522 个 id 拿去逐个匹配每条 KILL 的 `reason` 字段（长 id 优先，剔除被更长命中包含者），
再标注命中者在 B2 里的判决。结果与 `待应用清单.md` §3 表格**完全一致，无新增无遗漏**。

**注意这 3 对不是互相独立的：A 与 C 首尾相接，构成一条 3 节点链。**
`example-1-verification` → `example-3-verification` → `operations-of-example-3`。
逐节点删除测试看不见链式结构，这是 `待应用清单.md` §3 那句「A 判死因为 B 承担，B 判死因为 C 承担」的实例。

| 对 | 被杀节点（reason 的主体） | 它引以为据的节点 | 后者状态 |
|---|---|---|---|
| A | `d:example-1-verification-is-the-field-axioms-of-r`（v:46，**维持 3**） | `d:example-3-verification-reduces-to-arithmetic-in-each-component` | 本批 KILL |
| B | `d:example-2-shows-the-scalars-decide-real-or-complex`（v:49） | `d:real-in-real-linear-space-refers-to-the-scalars`（v:25） | 本批 KILL |
| C | `d:example-3-verification-reduces-to-arithmetic-in-each-component`（v:52） | `d:operations-of-example-3-are-componentwise`（v:51） | 本批 KILL |

裁定原则：**塌缩不塌缩，取决于 reason 引用的是「承载关系」还是「先例关系」。**
承载关系（「这句话的内容在 X 里」）随 X 死亡而失效，必须救一个；
先例关系（「它和 X 属同一 species」）只是类比，X 死不死都不影响本节点是否冗余——
但 reason 文本仍须重写，否则墓地记录里留着一条指向已删节点的论证。

#### 对 B 裁定：**两个都可杀，判定不塌缩（假阳性）**

v:49 与 v:25 的 reason 各自指向的最终承载者都是 `d:example-2-the-complex-numbers-with-real-scalars`
（`nodes-D1.jsonl:47`，B2 = **KEEP**），不是彼此。已逐字核该存活节点的 statement：
「It separates two things the notation tends to fuse, the field the elements come from and the field
the scalars come from.」——「标量而非元素决定实/复」这一洞见在存活 parent 里完整。
它的第二条锚点 `'Even though the elements of V are complex numbers, this is a real linear space because the scalars are real.'`（108 字符，实测）
即 Apostol 承载该断言的原句，且该锚点**不随本批删除**。
v:49 的 reason 顺带点了 v:25 一句（「与被杀的 … 一起构成同一句话的三份拷贝」），那是陈述冗余度，不是把承载责任交给 v:25。
**处置：两个都进本批可杀清单；v:49 的 reason 须重写（见 §5）。**

#### 对 C 裁定：**两个都可杀，但须先确认引文由祖父承载**

v:52 的 reason 把「机制句（逐分量归约）」的承载责任明确交给了 v:51 —— 这是**承载关系**，v:51 同死则该句无人承担。
但再往上追一层即解决：v:51 自己的 reason 说它复述的是祖父 `apostol:v-n-space` 的
「with addition and multiplication by scalars defined in the usual way in terms of components」
与 parent `d:example-3-v-n-with-componentwise-operations`（B2 = KEEP）。**两者都存活**，链条终止在存活节点上。
引文侧已实测：v:51 与 v:52 共用同一条 92 字符锚点（`15.03.md`），删除后
「同引文存活 = 0，但被 4 条更长的存活引文包含」——即该源文段仍被存活侧完整覆盖，**不产生引文损失**。
**处置：两个都进本批可杀清单；v:52 的 reason 须重写，把承载者从 v:51 改指 `apostol:v-n-space` 与 parent（见 §5）。**

#### 对 A 裁定：**先并入 parent 再杀，且 reason 须重写**

v:46 引 v:52 的方式是「属同一 species」——**先例关系**，不是承载关系。v:52 死亡不影响 v:46 是否冗余。
但 v:46 的实质前置条件另有其事，且 `待应用清单.md` §4 第 3 步与 ADJ1 §3.4 已定为强制：
**它那十条「公理 ↔ R 的算术律」映射表必须先并入 parent `d:example-1-the-real-numbers-form-a-linear-space`，不可裸删**，
且 ADJ1 已指出并入后**仍无锚点**——这一项本提案不重复裁断，按原清单执行。
**处置：v:46 不属本批（维持 3），按原清单第 3 步走；reason 须重写以剔除对已删节点的先例引用（见 §5）。**

### 2.2 锚点轴：reason 点名的存活承载者**并不持有**该节点的引文 —— 6 个节点、9 条引文
