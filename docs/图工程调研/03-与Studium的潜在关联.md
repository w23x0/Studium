# 与 Studium 的潜在关联

> 本文只记录可能需要图式执行解决的问题，不定义节点、边、状态结构或技术方案。

> 2026-07-25 补充：后续应联合讨论上下文工程与图工程。下列问题不仅涉及控制流，也涉及每个节点读取的类型化上下文、缓存生命周期、证据完整度和写回契约。

## 为什么值得保留这项研究

Studium 的长期学习过程可能具有以下特征：

- 用户输入对应不同任务类型，不应全部进入同一条固定流程；
- 教学、练习、诊断和导航之间存在条件分支与反馈循环；
- 资料、概念关系和历史证据可能需要独立读取或并行处理；
- 学习者状态更新需要证据、来源分层和时效标注（**不含用户更正或撤回机制**：M15 已判定自述不可信，不建立由学习者裁定哪条状态成立的通道）；
- 各模块的产出、来源和依据都要能在前端展示，可见性是横切原则第 5 条；
- 某些过程需要暂停，等待学习者回答或完成练习；
- 长期项目需要保存当前位置，并在之后恢复；
- 不同失败需要不同处理方式，不能都表现为整条流程失败；
- 产品需要说明一次判断使用了哪些资料、证据和限制。
- 进行中闭环的同步上下文与 M09 已结束闭环的异步记录必须分离。
- M04 -> M09 与 M09 -> M08 具有不同的守卫、候选和审查标准。

这些问题与路由、循环、并行、证据门、检查点、权限边和执行追踪有关，因此图式工作流可能比单一长链更合适。

| M03 练习活动 | 练习任务、学习者产出和诊断证据 |
| M04 诊断、证据与掌握判断 | 判断、依据、替代解释和最小补足动作 |

| M15 学习者状态与条件 | 带时效、来源和不确定性的非知识状态；承载读数直连 M05/M10，解释候选待 M04 裁决 |

M12 已取消，不作为产品模块（编号留空不重排）。M09 与 M15 是一对分开的学习者模型，**双向都无引用关系**，跨两者的关联经 M01 的链接获得，图执行侧不应在两者之间画直接边。

表中关联不表示一个模块对应一个节点。一个模块可能提供多个节点，也可能只提供数据或规则；一个执行节点也可能在契约允许的范围内组合多个模块的只读结果。

## 当前不应提前决定的事项

- 是否存在一张“学习回合总图”。
- 教学、练习、诊断等模块应成为节点还是子图。
- 路由由规则、模型还是二者共同完成。
- 哪些步骤允许并行。
- 哪些状态属于一次运行，哪些属于模块长期数据。
- 状态使用闸门：M05/M10 在什么证据强度与时效下才让 M15 的读数改变行动（已明确留给模块组合阶段的系统性设计）。
- 是否需要单 Agent、多 Agent 或纯工作流。
- 是否需要引入专门的图运行时。
- 每个节点需要哪些信息类型、最低完整度和来源证明。
- 哪些上下文常驻当前闭环缓存，哪些按需读取，哪些只保存引用。
- 摘要、标签和压缩内容是否只能作为索引，怎样回到权威原始记录。

这些问题依赖修正后的模块契约。现在回答会让未经确认的流程假设反过来污染产品模块设计。
