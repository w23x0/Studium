> 依据：`06-M08技术选型.md`、`M08-知识结构与概念关系.md`（审查单）、`M09-动态学习者模型.md`（审查单）、

## 一、调研目标

在**不改变已确认产品边界**的前提下，回答 M08/M09 存储结构与选型的全部待决问题，
使「模块之间的组合与系统性设计」（上下文工程 + 图工程联合设计）可以启动。
凡属推断必须标注；凡属需要实测验证的结论，输出为「待实测清单」而非定论。

## 二、已确认的产品约束（红线，调研不得违反）

1. **读法 B 成立、读法 A 被否**：不变量层 + 各自表示层 + 对齐边。禁止「一份学科规范对象表」。
2. **节点身份 = 锚点集合**，id 只是命名空间；判等看锚点，不看名字。
3. **别名用 `alias-of` 边，不合并节点**（合并不可逆）。
4. **锚点硬校验 = 逐字 `grep -F`**（1–3 条 / 30–200 字符），是当前唯一硬校验；复合锚点为纸面设计待实现。
5. **机械信号只定向、不结案**（召回 1/4、假阳性 84.2%）。数值置信度/向量相似度/固定阈值不能复活为结案手段。
6. **边关系词表封闭（9 + other）**；定理假设/结论移入节点字段，不做边。
7. **高层结构 = 候选池 + 审计晋升，不自动生成**（L2 存活 16.7%、FIX 0）。
8. **审计 A/B 两条正交轴；检测可并行、处置必须单点**；模型可提候选、不能决定正式写入。
9. **存储当前 = append-only JSONL + 独立校验脚本；图数据库暂不选**，触发条件：出现三跳以上遍历或实时交互查询的真实需求。
10. **不物理删除，写 graveyard**；判死也是结论。
11. **四条红线图不能合并**：产品模块图 / 执行工作流图 / 知识关系图 / 学习者状态变化。
12. **M08 与 M09 的关系**：M09 锚定 M08，不是 M08 的个人覆盖层；M09 只收已结束闭环结果。
13. **M09 时间版本不覆盖旧结论**（复检/遗忘/重新掌握形成新版本）；由此引出规模单调增长问题（未决三方向）。
14. **M04-02**：开放字段必须同时可稳定查询和审查；摘要/标签只作索引，不得替代底层记录。
15. **工具安全**：写型脚本必须真 argparse / `--dry-run` / `--only` / 禁裸 `'w'`；`--help` 不是只读操作。
16. **不做**：运行时（LangGraph 等）、向量检索参与候选发现、跨学科命名空间治理——三项刻意不决定，解锁条件已写明，本次调研可为解锁条件提供依据，但不下结论。

## 五、执行方式（沿用项目分层代理团队模式）

```
第 0 层 契约      本文档 + 01-问题清单与产品约束.md（静态文件，非提示词转述）
                     ├─ 每条轨道必须回答的问题
                     ├─ 产出 schema 与判死条件
                     └─ 引文规则（来源可核、关键论断带原文）
                            │  每个轨道代理开工第一件事是完整读它
                            ▼
第 1 层 调研       轨道 T1…T8 并行，互不可见，各自落盘
                            │  增量落盘，产物机器可读
                            ▼
第 2 层 横向       跨轨道对照：重叠、冲突、相互支撑识别（合成前一次）
                            ▼
第 3 层 合成       决策点 × 轨道输入 × 产品约束 → 选型建议草案 + 待实测清单
                            ▼
第 4 层 审计       引文可核性抽检 + 结论与产品约束冲突检查（独立代理）
```

- **并行**：T1–T8 全部并发，不互相等待。
- **串行**：横向对照 → 合成 → 审计。
- **产出落盘**：每轨道独立目录，`.md` 发现文件 + 可选的 `.json` 结构化清单（来源列表）。
- **断点**：任何轨道失败/中断，重跑该轨道即可，不污染其他轨道（沿用增量落盘原则）。

## 六、轨道产出契约

每个轨道必须产出 `docs/图工程调研/存储选型调研/轨道NN-*/发现.md`，结构：

```markdown
# 轨道NN <名称> 调研发现
> 调研日期、执行代理、关键前提
## 0. 一句话结论
## 1. 必须回答的问题逐条回答（引用轨道定义的问题编号）
## 2. 关键发现（每条：论断 + 来源[URL, 标题, 作者/机构, 日期] + 原文摘录/要点）
## 3. 对决策点的输入（明确写到 Dx）
## 4. 与产品约束的冲突/张力（如无则明说无）
## 5. 未决与风险
## 6. 建议的下一步实测（可执行的最小实验）
## 7. 来源清单（全部 URL，标注哪些是二手转引、哪些取到原文）
```

判死条件（产出不合格）：
1. 任何关键论断没有来源；
2. 把二手转引当成原文结论（必须标注证据等级）；
3. 结论违反第二节红线且未标注张力；
4. 回答了「轨道范围外」的问题而漏答范围内问题。

## 七、引文与证据规程

- 关键论断必须可核：URL + 标题 + 作者/机构 + 日期，尽量附原文关键句。
- 明确区分：**原文到手** / **二手转引** / **凭记忆（须标注不可核）**。
- 教育/产品结论与工程事实分开；产品约束的解读以审查单原文为准。
- 数量服从质量：每个轨道 8–15 个高质量来源优于 50 个泛泛链接。

## 八、合成阶段产物

`99-合成/存储选型建议草案.md`：
- 每个决策点 D1–D9 给出：候选方案、各方案支撑/反对证据（引用轨道）、与产品约束的兼容性、推荐、待实测项。
- `待实测清单`：按「可判定性优先」排序的最小实验，每个实验给出输入、判据、通过/失败标准。
- `解锁条件更新`：对第二节第 16 条三项「刻意不决定」给出调研后的解锁条件状态。
