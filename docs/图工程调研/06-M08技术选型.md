## §0: TARGET INTERPRETATION - TWO READINGS, ONE REJECTED

```
QUESTION: "Compile all materials of one discipline into unified knowledge model"
READING_A: REJECTED
READING_B: ACCEPTED
EXPERIMENTAL_BASIS: Cross-textbook alignment experiment
```

### Reading A (REJECTED)

**Interpretation**: One discipline → one canonical object table, textbooks are different expositions of same objects.

**Rejection Evidence**:

```
EXPERIMENT: Linear algebra (linear space, independence, dimension, orthogonal, projection, best approximation)
TEXTBOOKS: Apostol vs Strang
TOTAL_OBJECTS: 180 (both sides)
MATCHED_PAIRS: 42

MATCH_BREAKDOWN:
  strict-same: 9 (21% of matches, ~5% of total objects)
  special-case (one is special case of other): 28 (67% of matches)
  type-flip (same thing, different node types in two books): 5 (12% of matches)
UNMATCHED_SINGLE_SIDE: 99 (2.4× matched pairs)

CONTROL_GROUP: Same book Chinese-English translation
  strict-same: 49/55 = 89%
  same-name-different-object: 0

CONTRAST: 89% vs 21% (4× difference)
```

**Technical Implication**: Two things must go through different pipelines:
- Language/terminology difference = TRUE PROJECTION (same object, different labels → can auto-normalize)
- Representation difference ≠ projection (changes whether object exists, boundary划分, whether it's concept vs theorem → CANNOT auto-normalize, can only align + preserve both sides)

**Anti-pattern**: Any tech solution mixing both (e.g., uniform embedding similarity for entity disambiguation) will:
- Perform well on language lines
- Systematically fail on cross-textbook
- Failure mode: **fabricating false unification** (merging "Apostol dimension" + "Strang rank" looks convergent, actually erases "rank离开矩阵就没有主词" info layer)

### Reading B (ACCEPTED)

**Interpretation**: "Unified" = unified identity-determination procedure + unified audit procedure, NOT unified object table itself.

**Implementation**: Thin invariant layer + each material preserves its representation layer + alignment edges with match strength.

**Experimental Quote**: "Stability comes from verification procedure, not from representation form."

## §1: NODE IDENTITY = ANCHOR SET, NOT NAME

```
SELECTION_ID: S01_IDENTITY_MECHANISM
DECISION: IDENTITY_BY_ANCHOR_SET
REJECTED: IDENTITY_BY_NAME_PLUS_TYPE
```

### Why Name-Based Identity Fails

**Experimental Evidence**: Cauchy–Schwarz in Apostol same page has two forms (vector form + norm form), two different-granularity assertions. Any "name + type as primary key" scheme must choose one, losing info.

### Cross-Textbook Same-Name Different-Object Traps (6 Cases)

```
NAME | APOSTOL_REFERENT | STRANG_REFERENT
-----|------------------|----------------
orthogonal set | allows zero elements, thus NOT guaranteed independent (needs separate Theorem 15.10) | zero vector excluded from start
orthogonal subspaces | not defined (only has S⊥) | defined, gives counterexample (two walls look perpendicular but not orthogonal)
S⊥ | defined for arbitrary subsets | only defined for subspaces, immediately paired with dimension formula
projection | auxiliary quantity subtracted in Gram–Schmidt | chapter foundation, immediately produces matrix P
dimension/rank | only dimension, attached to spaces | two numbers, attached to space vs matrix respectively
basis | set (unordered) | sequence (ordered, because used as matrix columns)
```

### Selection

```
PRIMARY_KEY: <book>:<kebab-slug> (namespaced ID)
EQUALITY_DETERMINATION: anchors集合 whether points to same original-text assertion
NAME_ROLE: label only

ID_PREFIX_SEMANTICS:
  apostol: / strang: → has original-text source
  d: → downward extension atom
  x: → cross-textbook invariant
  L2:...Ln: → upward abstraction layers

EVIDENCE_RESPONSIBILITY: Different by prefix
  apostol: → must character-by-character anchor original text
  x: → must have anchors on both sides
  L2: → does not anchor original text, anchors members

ALIAS_HANDLING: alias-of edge + aliases field, NOT node merge
  Reason: merge is irreversible, alias edge is reversible
```

### Rejected Approaches

- Concept name as primary key → concept table
- Embedding nearest-neighbor auto entity disambiguation → cannot distinguish "same object two writings" vs "same name two objects" (latter has 6 experimental cases)

## §2: ANCHOR RULES - ONLY HARD MACHINE VALIDATION

```
SELECTION_ID: S02_ANCHOR_VALIDATION
MECHANISM: CHARACTER_EXACT_GREP_F
RULE: 1-3 anchors per node, 30-200 characters, must be continuous substring in file
```

### The Rule

```
PER_NODE_ANCHOR_COUNT: 1-3
QUOTE_REQUIREMENT: must be character-exact continuous substring in `file`
CHAR_RANGE: 30-200 characters
PROHIBITIONS:
  - NO cross-line splicing
  - NO punctuation modification
  - NO OCR noise correction
  - If cannot find character-exact quotable basis → do not include
```

### Validation Results

**Chapter 15 Experiment**:
- 921 anchors (min 32 / median 89 / max 198, zero out-of-bounds)
- 902 edge evidences: 902/902 pass
- Cross-textbook experiment: 375+89 anchors, zero failures

**Active Abandonment Records**: This rule directly produced "proactive abandonment" records. D5 round: 9 candidates abandoned, 1 because "original text only gives proposition without proof, standard reasoning but cannot character-anchor" → A rule that makes producers proactively write less is more useful than one that only scores after the fact.

### Measured Cost (Distribution Highly Uneven)

```
METRIC | VALUE
-------|------
True body lines <30 char, thus unusable as anchors | 8.6% (215/2496)
Among math lines, completely unable to find legal quote | 7.7% (35/454)
By book: Apostol / Strang3 / Strang4 | 19.1% / 0.6% / 2.9%
Theorem/definition/axiom title lines | 82 lines, 0 lines <30 (shortest 38, median 165)
```

**One口径 to防误引**: Same report contains 60.3% and 31.1%, denominator mixed empty lines + `$$` fence markers, inflated proportion 7×. Can only use 8.6% or 7.7%.

**Key Structure**: Damage concentrated in display formula lines, NOT in statement sentences.

5 independent display axiom equations: 4 unusable (Axiom 6/7/8/9 = 16/18/22/22 chars). Only one passes by luck: OCR noise tail `f o r a l l x i n V` pads to 36 chars — report self-notes "this is luck, not method".

**Knocked-out Content**: Norm definition formula, Gram–Schmidt projection coefficients, best approximation theorem conclusion inequality, function space addition definition. These are NOT edge cases, they are chapter backbone formulas.

### Secondary Effect (More Serious)

30-char lower bound forces producers to quote prose wider than assertion射程 → quote射程 larger than statement射程 → looks like passing validation, actually misaligned. This is one source of audit death-cause #1 (quantifier over-assertion).

### §2.1: SELECTION - Display Formula Line Lower-Bound Exemption via Compound Anchor

```
SELECTION_ID: S02_1_COMPOUND_ANCHOR_EXEMPTION
FORMAT:
  {
    "file": "15.10.md",
    "quote": "DEFINITION. In a Euclidean space V, the nonnegative number $\\|x\\|$ defined by the equation",
    "formula": "\\| x \\| = (x, x) ^ {1 / 2}",
    "formula_line": 108
  }
```

**Three Conditions (ALL required)**:

1. `formula` must be one complete content line inside a `$$` block, character-exact whole-line copy, NOT extracted from prose line
2. Regular rules genuinely cannot be satisfied: every content line in this block <30 chars. If block has ≥30 char line, must quote that line
   - This condition MUST be machine-checkable, else exemption degenerates to "use if want"
3. Must pair with adjacent ≥30 char non-empty prose line. Two independently validated separately, NEVER spliced
   - Adjacency machine-checkable: guards against cherry-picking distant line to force anchor
   - Purpose of preserving "no cross-line splice" original intent: splicing fabricates strings not in book, `grep -F` fails

**Compound Anchor Counting**: Counts as 1 anchor, not two slots. `formula` and `quote` same standards: no ellipsis, no punctuation modification, no OCR noise correction. `formula_line` required, purpose not disambiguation (measured 36 short formulas all unique within file), purpose让 audit not need to re-search to verify condition #2.

### Two More Intuitive Schemes REJECTED (Already Measured)

**Lower General Threshold**: Drop to 12 saves 34/36 (94%), but simultaneously makes ANY 12-char prose fragment legal. Original lower bound exists to block fragment quotes; drop to 15/16 only saves 28/36 and same cost. **Length threshold is not the right knob.**

**Require Exempted Short Formulas Must Contain Relation Symbol** (`=`/`\leq`/`\in`): Measured 36 cases, 7 don't contain relation symbols, and those 7 include Gram–Schmidt projection coefficient + `L(x_1,…,x_r)` — account for 17.6% of confirmed damage. Reason: math writing definition-formulas often "bare expression + prose naming".

**1–3 Cap Unchanged**: 17 damaged nodes individually calculated, all can grab formula within 3 anchors post-revision, none needs 4th. Raising cap saves no confirmed cases, only raises per-node audit volume ~33%.

`x:` 触顶率 72.7% (`apostol:` 24.5%, `d:` 3.8%) is one **unresolved pressure**, but "therefore change to 4" lacks measurement support — to move cap, first measure those 22 `x:` nodes' "ideal anchor set" size distribution.

### Honest Costs (Report Self-Listed)

- Exemption will EXPAND quantifier-drift space, and quantifier drift IS death-cause #1
- Existing 921 anchors need re-validation
- This scheme is PAPER DESIGN ONLY — `verify_anchors.py` not modified, not run on 921 anchors, "compound anchor can pass validation" NOT YET VERIFIED
- Three validation logics needed (dual-field separate validation, adjacency determination, same-block other lines all <30) do not exist yet
- Complexity added to everyone, benefit only lands on Apostol side

### §2.2: MACHINE VALIDATION BOUNDARIES

```
CAPABILITY_ID: MACHINE_VALIDATION_SCOPE
CAN_PROVE: Text character-exact appears in that file
CANNOT_PROVE: Quote supports its attached assertion
```

**The Blind Spot**: Classified into five types, only one type (quote明显 shorter than assertion射程) semi-mechanically detectable.

**Supporting Negative Measurements**:

```
SIGNAL | PERFORMANCE
-------|------------
Unanchored number screening check_unanchored_numbers.py | Recall 1/4
Shared quote signal check_shared_quotes.py | Precision OK, but 238/522=46% nodes永久不可见 (every anchor unique永远进不了清单); actual list only covers 8% (≥4 times), threshold drop to ≥2 only reaches 54%
SPEC defect positive screening | 57 hits → 9 true, false positive 84.2%; reverse search found 8 more, so positive recall 9/17=52.9%, and 17 is only lower bound
```

**Selection Conclusion**: Mechanical signals can only be used for targeting, NOT for closing case. Any "auto-audit pass即晋升" design will leak.

This independently rejects revival possibility of audit review-downgraded historical tech schemes — numerical confidence, vector similarity, fixed thresholds: all "close case with one number", measured single-signal recall all failing.

## §3: RELATION VOCABULARY - CLOSED WITH `other` THERMOMETER

```
SELECTION_ID: S03_RELATION_VOCABULARY
DECISION: CLOSED_CORE_PLUS_OTHER
TENSION_WITH_AUDIT_REVIEW: RESOLVED
```

### Tension with Audit Review

Audit review main body wrote: "Relation families remain open, examples not closed enumeration."

Both experiments ran: CLOSED vocabulary: 9 relations + `other` catch-all
- `is-a` / `part-of` / `requires` / `implies` / `equivalent` / `contrasts` / `applies-to` / `generalizes` / `alias-of`
- Each specifies direction and whether symmetric

### Measured Result

Closed vocabulary DOES RUN, but pressure concentrates on one word:

```
SHARD | REQUIRES_PERCENTAGE
------|----------------------
Single-chunk lowest | 27%
Single-chunk highest | 75%
Whole-book | 55% / 61%
```

And this proportion POSITIVELY CORRELATED with that shard's theorem count. Reason not that `requires` is easy to use, but theorem hypothesis + conclusion have nowhere to go: vocabulary lacks "hypothesis-of" "conclusion-of", producer can only stuff "this theorem needs this premise" + "this theorem derives this result" together into `requires`, so one word carries two semantics.

### Correct Fix

**NOT opening vocabulary**, is moving theorem hypothesis + conclusion out of edges, into node fields.

Edges express relations between nodes; theorem hypothesis + conclusion are theorem node SELF STRUCTURE, shouldn't be edges in first place. Make them `theorem` node's `hypotheses` / `conclusion` fields, `requires` immediately returns to original meaning (prerequisite dependency), proportion also drops.

Opening vocabulary does opposite: disguises a "field modeling error" as "vocabulary not enough", then uses more words to cover, eventually nobody can tell what relation between two nodes is.

### Reconciliation with Audit Review

Both non-contradictory, premise is positioning "open" correctly:

- CLOSED: Edge relation vocabulary (small core + `other`)
  - Closure enables writing validation, enables statistics
- OPEN: Node fields
  - When adding knowledge structure类, add fields (like `hypotheses`), don't add relation words
- `other` as vocabulary thermometer
  - Using `other` must fill `rel_note`
  - `other` occurrence frequency被统计, it measures whether vocabulary sufficient
  - This is "examples not closed enumeration" executable version: vocabulary not permanently frozen, but decided by measured `other` frequency WHEN TO EXPAND, not pre-留白 waiting for people to casually add

**Rejected**: Letting each producer self-invent relation name open vocabulary. Measured 4 node types (`concept`/`method`/`theorem`/`notation`) equally closed, equally no problem — pressured one always `requires`, not type table.

## §4: HIGH-LEVEL STRUCTURE - AUDIT GIVES QUANTIFIED NECESSITY

### §4.1: Survival Rate 16.7%

Audit review marked "high-level structure candidates" as core direction but capability not型ed, and明确 "layer only describes abstraction depth + learning progression, should NOT write死 as fixed structure."

Chapter 15 experiment did exactly this thing's first real measurement: from A1 (original-text layer) upward raise L2 candidates, downward extend D layer, then audit.

```
METRIC | VALUE
-------|------
L2_CANDIDATES_TOTAL | 24
AUDIT_KEEP | 4 (16.7%)
某一提案文件的存活 | 0/8
判FIX (fixable) | 0
DEATH_CAUSE_DISTRIBUTION | All death-cause 5: pseudo-abstraction·layer collapse
```

**Zero FIX most important number**. It says pseudo-abstraction not "not written well enough", is "that thing originally doesn't exist" — cannot fix, can only delete.

This directly determines engineering form: **L2+ must be candidate pool + audit promotion, cannot be auto-generation layer.** An 83% death-rate generator, if its output directly enters formal graph, graph destroyed.

This consistent with audit review "candidate isolation, audit与晋升" main-body judgment, experiment only quantified its necessity.

### §4.2: Only Operable Criterion - Deletion Test

Old problem of abstraction layer is "what counts as truly abstracted" impossible to define. Experiment used executable version:

```
DELETION_TEST:
  Delete this high-level node from graph.
  If downstream nodes all still can each independently说清, nothing lost,
  then it has no abstraction gain, judge死.
```

Auditor forced to further write gates into three determinable conditions, else 24 candidates will all-pass or all-死 (each can讲 套 sounds-like-methodology story):

```
L2 MUST propose one FALSIFIABLE cross-member assertion, which:
  (a) NOT stated by any single member
  (b) CANNOT be derived from 2-3 members one-step juxtaposition or one-step term-movement
  (c) Swapping statement's this-chapter proper nouns with other-chapter ones MAKES STATEMENT FALSE
```

(b) is decisive: vast majority killed candidates not nonsense, are **correct but cheap** — its "gain" just lines up two facts already in members再起 name, and learners already have those two members, juxtaposing them doesn't need this L2.

(c) eliminates another batch: proposition true and migratable, but **migratable to any chapter any textbook**, that's not this-chapter abstraction layer, is study habit.

Supporting schema forces three fields, missing one即判死:

- `members`: members must TRULY EXIST downstream (machine-checkable: 124 references, 0 missing)
- `boundary`: must give CONCRETE counterexample (what doesn't belong)
- `abstraction_gain`: deleting it what gets lost

Also one measured补充 rule: deletion test cannot only face parent node + same-file siblings, must face full graph. (One candidate looks like having gain within this file,放到 full graph discovers its content already covered elsewhere.)

Plus one machine-validation extension: not only validate IDs in `members`, also validate `boundary` / `abstraction_gain` PROSE-MENTIONED IDs — because fabricating members in prose same thing as fabricating in `members` (second round 30 references, 0 missing).

### §4.3: Stop Rule

Don't preset layer count. Audit review opposes "fixed four-layer tree tower as data structure", experiment gives替代 is one **survival-rate-triggered stop rule**:

```
STOP_CONDITION:
  某一层 audit survivors <2 ⇒ this layer is current-corpus abstraction ceiling, stop upward-raising
```

By 16.7% survival, L2 survivors 4; from 4 continue upward-raising to L3, target written as "at least 1 L3 stands" not "construct complete L3 layer". **Layer count measured out, not designed out.**

### §4.4: Layer ≠ Shard

One easily-confused, and already paid cost in measurement, distinction:

- Vertical (A1 → D, or A1 → L2) MUST串行, because upper-layer members must exist first
- Horizontal (same-layer different shards) CAN concur, measured indeed ran this way
- L1 once frozen, downstream all depend it, rework cost high — so freeze前 must nail ID清单死
- `parent` field semantics STILL UNDEFINED: measured 7 nodes marked `atomic: true` yet still have children. Individually查清: among them 2 truly atomic marked wrong, other 5 USING `parent` edge AS "inference/specialization", not as decomposition edge. Meaning this not data dirty, is schema missing one definition: **`parent` whether only表 decomposition?** Must nail死 in SPEC, else same edge has two readings, and "multi-branch graph误读成 single-path tree" exactly comes from here.

## §5: AUDIT - TWO ORTHOGONAL AXES

Measured ran two sets independent audit, cannot merge into one-time scoring:

- Audit A (content correctness): math whether correct, source whether real, anchor whether supports assertion
- Audit B (abstraction gain): deletion test

Orthogonal meaning: one node can be math completely correct, anchor completely legal, but abstraction gain zero (this is vast majority situation of 24 L2 candidates); reverse also exists. Merging into one score will让两者互相掩盖.

### Six Named Death Causes (Directly Usable as Audit Checklist)

```
DEATH_CAUSE_01: Quantifier over-assertion (quote射程 < statement射程)
DEATH_CAUSE_02: Fabricate member attribution
DEATH_CAUSE_03: Forge textbook source
DEATH_CAUSE_04: Math error
DEATH_CAUSE_05: Pseudo-abstraction·layer collapse
DEATH_CAUSE_06: Anchor drift
```

### §5.1: Reproducibility Measurement Determines Parallel Boundary

Same batch nodes让 different auditors independently run, result splits into two tiers:

```
AXIS | CONSISTENCY
-----|------------
该不该判死 (kill / no-kill) | 8/8 consistent
Concrete disposition (KILL / FIX / KEEP) | 7/8 consistent
```

**Selection Conclusion: Detection CAN parallel, disposition MUST single-point.**

Multiple auditors concurrently find problems, results take union; but "this problem how to handle" decided by single裁定 loop, no voting, no writing multiple copies.

This simultaneously explains why audit reports cannot直接落盘成 formal graph by discoverer.

### §5.2: Borrowed Quotes - One类 Per-Node-Invisible Errors

One类 problem completely invisible at single-node perspective: multiple nodes share same quote, each single-look "has anchor, and anchor legal", but that quote only supports one node's assertion among them, remaining nodes BORROWED.

This is WHOLE-TABLE PROPERTY, not node property — per-node validation永远 discovers不了.

Engineering implication: audit must have one "full-table perspective" loop. `check_shared_quotes.py` is往这个 direction做 first-version attempt, direction right: it already produced过 one real fix (`nodes-X.jsonl` only-group shared quotes里, two nodes撞到 together, read statement后 discovered shared那句 only撑得起 one of them). But it对 46% nodes永久不可见 (§2.2), and full-graph 148-group shared quotes STILL未逐组审查. **Direction right, coverage unqualified.**

### §7.1: Tool Safety - This Line换来 from Accident

Two real accidents, both改了 engineering constraints:

**`--help` Data Wipe**: Script没有 argparse, `--help` treated-as unknown param ignored, script照常 executes, unconditional `open(..., 'w')` zeroed two graveyard files, 20 edges永久丢失.

Fix法:
- All write-type scripts must have real argparse
- Must have `--dry-run`
- Must have `--only` limiting scope
- Graveyard改 append-only且 rejects duplicate id
- DELETE ALL裸 `'w'` opens

Inference (valid对 this-project all people): `--help` NOT read-only operation, cannot用它 to试探 unknown script usage.

**Main-window误关, 7 in-progress agents all died**:

Fix法:
- Every 5-8 items incremental落盘
- Shrink single-agent scope
- On-disk永远是 legal JSONL
