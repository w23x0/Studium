## 0. 先把目标翻译成技术命题

「把一门学科的所有资料汇总成一个统一的知识模型」在技术上有两个完全不同的读法，
实验已经把其中一个否掉了。

**读法 A（被否）**：一个学科一份规范对象表，各教材是它的不同讲法。
**读法 B（成立）**：一层薄的表示不变量 + 每份资料各自保留的表示层 + 带匹配强度的对齐边。

否掉 A 的是跨教材实验最干净的一处对照。同一批数学（线性空间、独立性、维数、正交、投影、
最佳逼近），Apostol 与 Strang 各自独立抽取，两侧共 180 个对象：

| 量 | 值 | 占比 |
| --- | --- | --- |
| 有跨书对应的对象对 | 42 | — |
| 其中 strict-same（严格同一） | 9 | 占匹配 21%，占全部对象约 **5%** |
| 其中 special-case（一方是另一方的特例） | 28 | 占匹配 67% |
| 其中 type-flip（同一件事在两书里节点类型不同） | 5 | 占匹配 12% |
| 单边存在（另一本书里没有对应物） | 99 | 是匹配数的 2.4 倍 |

对照组是同一本书的中英文两条语言线：55 个匹配里 **49 个 strict-same = 89%**，
且零个「同名异物」。

**89% vs 21%，四倍差距。** 它的技术含义是两件事必须走不同管道：

- 语言/术语差异是**真投影**——同一个对象换了标签。可以自动归一。
- 表示差异**不是投影**——它改变对象是否存在、边界划在哪、以及它是 concept 还是 theorem。
  不能自动归一，只能对齐并保留两侧。

一个把两者混在一起处理的技术方案（例如统一用 embedding 相似度做实体消歧）
会在语言线上表现良好、在跨教材上系统性造错，而且错的方式是**制造虚假的统一**：
把「Apostol 的 dimension」和「Strang 的 rank」合并成一个节点看起来收敛度很高，
实际抹掉了「rank 离开矩阵就没有主词」这一整层信息。

所以「统一」的技术含义只能是：**统一的是身份判定规程和审计规程，不是对象表本身。**
实验方法层面给出的一句话就是这个结论——「稳定性不来自表示形式，来自验证程序」。

## 1. 身份：节点身份 = 锚点集合，不是名字

这是全部选型里最先要定的一条，因为它决定了后面所有去重、对齐、版本机制的形态。

反例是实测的：Cauchy–Schwarz 在 Apostol 的同一页上有两种写法（向量形式与范数形式），
两个不同粒度的断言。任何以「名字 + 类型」为主键的方案在这里必须二选一，
选哪个都丢信息。跨教材侧更狠：6 个「同名异物陷阱」全部是名字相同而对象不同——

| 名字 | Apostol 的所指 | Strang 的所指 |
| --- | --- | --- |
| orthogonal set | 允许含零元，因此**不保证独立**（需定理 15.10 单独补） | 零向量一开始就被排除 |
| orthogonal subspaces | 不定义（只有 `S⊥`） | 定义，且给反例（两面墙看着垂直但不正交） |
| `S⊥` | 对**任意子集**定义 | 只对子空间定义，且立刻配维数公式 |
| projection | Gram–Schmidt 里被减掉的辅助量 | 全章地基，立刻产出矩阵 `P` |
| dimension / rank | 只有 dimension，附着于空间 | 两个数，分别附着于空间与矩阵 |
| basis | 集合（无序） | 序列（有序，因为要当矩阵的列） |

**选型结论**

- 主键 = `<book>:<kebab-slug>` 的命名空间 id，但**判等**看 `anchors`。
  两个节点是否同一个对象，由「锚点集合是否指向同一段原文断言」决定，名字只是标签。
- 因此 id 必须带命名空间前缀，且前缀是**语义前缀不是目录前缀**：
  实验用的是 `apostol:` / `strang:`（有原文出处）、`d:`（下延原子）、
  `x:`（跨教材不变量）、`L2:`…`Ln:`（上行抽象）。
  这五类的**证据责任不同**，前缀让责任在 id 上就可见：`apostol:` 必须能逐字锚定原文，
  `x:` 必须两侧各有锚点，`L2:` 不锚原文而锚 members。
- 别名（M08 要求的「合并别名和不同表述」）走 `alias-of` 边 + `aliases` 字段，
  **不做节点合并**。合并是不可逆的，别名边是可逆的。

**这条否掉了什么**：以概念名为主键的概念表；以 embedding 近邻做自动实体消歧的去重管道
（它无法区分「同一对象两种写法」与「同名两个对象」，而后者在实测里有 6 例）。

## 2. 锚点规则：唯一的硬机器校验，以及它的实测代价

M08 审查单要求「每个结果保留可理解位置并可回到原文」、
「不能把模型记忆伪装成原文引用」。实验把这一条实现成一条可 `grep -F` 的硬规则：

> 每节点 1–3 条锚点；`quote` 必须是 `file` 里逐字连续出现的子串；
> 30–200 字符；不跨行拼接、不改标点、不修 OCR 噪声；找不到可逐字引用的依据就不收录。

**它是有效的。** 第 15 章实验 921 条锚点（min 32 / median 89 / max 198，越界 0 条）、
902 条边证据 902/902 通过；跨教材实验 375+89 条锚点零失败。
且这条规则直接生产了一批「主动放弃」的记录——
D5 那一轮 9 个候选被放弃，其中 1 个的放弃理由就是「原文只给命题没给证明，标准推理但无法逐字锚定」。
一条能让产出者主动少写的规则，比一条只会事后打分的规则有用。

**但它有实测代价，且代价分布极不均匀。**

| 量 | 值 |
| --- | --- |
| 真实正文行中短于 30 字符、因此无法作为锚点的比例 | **8.6%**（215/2496） |
| 其中带数学的行完全找不到合法引文的比例 | **7.7%**（35/454） |
| 按书分：Apostol / Strang3 / Strang4 | **19.1% / 0.6% / 2.9%** |
| 定理/定义/公理的**标题行** | 82 行，**0 行短于 30**（最短 38，中位 165） |

（一个必须防的误引口径：同一份报告里出现过 60.3% 和 31.1%，
分母里混进了空行和 `$$` 围栏标记行，把比例抬高了七倍。只能用 8.6% 或 7.7%。）

关键结构：**损伤集中在 display 公式行，不在陈述句上。**
5 个独立 display 的公理方程里 4 个无法引用（Axiom 6/7/8/9 = 16/18/22/22 字符），
唯一能过的那个是靠 OCR 噪声尾巴 `f o r a l l x i n V` 凑到 36 字符——
报告自己写的是「这是运气，不是方法」。
被打掉的具体内容包括范数定义式、Gram–Schmidt 投影系数、最佳逼近定理的结论不等式、
函数空间的加法定义。这些不是边角，是章的骨干公式。

更要紧的是它的**次生效应**：30 字符下限迫使产出者去引用比断言更宽的散文，
于是引文的射程大于 statement 的射程——看着过校验，实际没对准。
这正是审计里排第一的死因（量词过度断言）的成因之一。

### 2.1 选型：display 公式行豁免下限，用复合锚点

```json
"anchors":[{"file":"15.10.md",
            "quote":"DEFINITION. In a Euclidean space V, the nonnegative number $\\|x\\|$ defined by the equation",
            "formula":"\\| x \\| = (x, x) ^ {1 / 2}",
            "formula_line":108}]
```

三个条件，缺一不可：

1. `formula` 必须是某个 `$$` 块内的**一整条**内容行，逐字整行照抄，不得从散文行截取。
2. **常规规则确实无法满足**：该块的每一条内容行都 <30。块内有 ≥30 的行就必须引那一行。
   这一条必须机器可判，否则豁免退化成「想用就用」。
3. 必须与紧邻的、≥30 字符的非空散文行配对。两者**分别独立校验、永不拼接**
   （保留「不跨行拼接」的原意，拼接会造出书里不存在的字符串，`grep -F` 随之失效）。
   相邻性可机器判定，这是防滥用的着力点：不能拿远隔两行凑一条锚点。

一条复合锚点计 **1** 条，不占两个名额。`formula` 与 `quote` 同标准：不得含省略号、
不得改标点、不得修 OCR 噪声。`formula_line` 必填，用途不是消歧
（实测 36 条短公式在其文件内全部唯一），是让审计不必重搜就能复核第 2 条。

**两个更直觉的方案已被实测否决，不要重走**：

- **单纯下调下限**。降到 12 能救回 34/36（94%），但它同时让**任何** 12 字符散文碎片合法，
  而下限本来就是为拦碎片引用；降到 15/16 只救回 28/36 且代价相同。
  **长度阈值不是正确的旋钮。**
- **要求豁免的短公式必须含关系符**（`=`/`\leq`/`\in`）。实测 36 条里 7 条不含关系符，
  而这 7 条里就有 Gram–Schmidt 投影系数与 `L(x_1,…,x_r)`——
  占已确证损害的 17.6%。原因是数学写作的定义式常是「裸表达式 + 散文命名」。

**1–3 条的上限不动**。17 个受损节点逐个验算，修订后全部能在 3 条内取到公式，
无一需要第 4 条；提高上限救不回任何已确证案例，只让每节点审计量升约 33%。
`x:` 触顶率 72.7%（`apostol:` 24.5%、`d:` 3.8%）是一处**未解决的压力**，
但「因此改成 4 条」没有测量支撑——要动上限，先测 22 个 `x:` 节点各自的「理想锚点集」规模分布。

**诚实的代价**（报告自己列的，不是我补的）：豁免会**扩大**量词滑移的空间，
而量词滑移就是死因 1 本身；已有 921 条锚点需要重新校验；
并且这套方案**只是纸面设计**——`verify_anchors.py` 未改，未在 921 条锚点上跑过，
「复合锚点能通过校验」这件事**未经验证**；
复杂度加给所有人，收益只落在 Apostol 一侧。

### 2.2 机器能校验什么、不能校验什么

这是本项目最反复被证实的一条，直接决定审计的自动化上限。

`verify_anchors.py` 能证明的只有「这段文字确实在那个文件里逐字出现」。
它**不能**证明这段引文支撑它所挂的那个断言。这个盲区已被分成五型，
只有一型（引文明显短于断言射程）能半机械化检出。

配套的负面实测结果：

| 机械信号 | 实测表现 |
| --- | --- |
| 无锚点数值筛查 `check_unanchored_numbers.py` | 召回 **1/4** |
| 共享引文信号 `check_shared_quotes.py` | 精确率不错，但 **238/522 = 46%** 的节点永久不可见（每条锚点都独有就永远进不了清单）；实际清单只覆盖 8%（≥4 次），阈值降到 ≥2 也只到 54% |
| SPEC 缺陷的正向筛查 | 57 命中 → 9 真，假阳性 **84.2%**；反向搜索又找到 8 个，故正向召回 **9/17 = 52.9%**，且 17 只是下界 |

**选型结论：机械信号只能用来定向，不能用来结案。**
任何「自动审计通过即晋升」的设计都会漏。
这一条独立地否掉了 M08 审查单已经降格的那批历史技术方案的复活可能——
数值置信度、向量相似度、固定阈值：它们都是「用一个数结案」，而实测表明单一信号的召回全部不及格。

## 3. 关系词表：开放还是封闭

这是审查单和实验之间**唯一一处正面张力**，必须明写。

审查单的主干写的是「关系族保持开放，示例不是封闭枚举」。
两个实验跑的都是**封闭**词表：9 个关系 + `other` 兜底，
`is-a` / `part-of` / `requires` / `implies` / `equivalent` / `contrasts` /
`applies-to` / `generalizes` / `alias-of`，每个都规定方向和是否对称。

实测结果是：封闭词表**跑得动**，但压力集中在一个词上。

| 分片 | `requires` 占比 |
| --- | --- |
| 单块最低 | 27% |
| 单块最高 | **75%** |
| 整书 | 55% / 61% |

且这个比例与该分片的**定理数量正相关**。原因不是 `requires` 好用，
而是定理的假设和结论无处可去：词表里没有「假设-of」「结论-of」，
产出者只能把「这条定理需要这个前提」和「这条定理推出这个结果」
一起塞进 `requires`，于是一个词承载了两种语义。

**正确的修法不是把词表放开，是把定理的假设与结论移出边、放进节点字段。**
边表达的是节点之间的关系；定理的假设与结论是定理这个节点**自身的结构**，
本来就不该是边。把它们变成 `theorem` 节点的 `hypotheses` / `conclusion` 字段，
`requires` 立刻回到它本来的意思（先修依赖），比例也会回落。
放开词表则相反：它把一个「字段建模错误」伪装成「词表不够用」，
然后用更多的词去掩盖，最后谁也说不清两个节点之间到底是什么关系。

### 3.1 和审查单的调和

两者不矛盾，前提是把「开放」定位准：

- **封闭的是边的关系词表**（一小组核心 + `other`）。封闭才能写校验、才能统计。
- **开放的是节点字段**。新增一类知识结构时，加字段（像 `hypotheses`），不加关系词。
- **`other` 是词表的体温计**。用 `other` 必须填 `rel_note`；
  `other` 的出现频率被统计，它衡量词表是否够用。
  这就是「示例不是封闭枚举」的可执行版本：词表不是永久冻结，
  而是**由实测的 `other` 频率来决定何时扩**，而不是预先留白等人随手加。

**这条否掉了什么**：让每个产出者自行发明关系名的自由词表。
实测里 4 个节点类型（`concept`/`method`/`theorem`/`notation`）同样封闭，
同样没出问题——受压的从来是 `requires`，不是类型表。

## 4. 高层结构：审查单说「核心方向，实验能力未定型」，实验给出了定型所需的数字

审查单把「高层结构候选」标成核心方向但能力未定型，
并且明确「层只描述抽象深度和学习推进，不应写死为固定结构」。
第 15 章实验做的正是这件事的第一次真实测量：从 A1（原文层）向上提 L2 候选，
向下延 D 层，然后审计。

### 4.1 存活率：16.7%

| 量 | 值 |
| --- | --- |
| L2 候选总数 | 24 |
| 审计后 KEEP | **4（16.7%）** |
| 某一提案文件的存活 | **0/8** |
| 判 FIX（可修） | **0** |
| 死因分布 | 全部是死因 5：伪抽象·层塌缩 |

**零个 FIX 是这组数字里最重要的一个。** 它说明伪抽象不是「写得不够好」，
是「本来就没有那个东西」——改不出来，只能删。
这直接决定了工程形态：**L2 及以上必须是候选池 + 审计晋升，不能是自动生成层。**
一个 83% 死亡率的生成器，如果它的产物直接进正式图，图就毁了。
这与审查单「候选隔离、审计与晋升」的主干判断一致，实验只是把它的必要性量化了。

### 4.2 唯一能操作的判据：删除测试

抽象层的老问题是「什么叫真的抽象出来了」没法定义。实验用的是可执行版本：

> 把这个高层节点从图里删掉。如果下游节点全都还能各自独立说清楚、
> 没有任何东西丢失，那它就没有抽象增益，判死。

而审计者被迫把门槛进一步写成三条可判定的条件，
否则 24 个候选会全过或全死（每个都能讲一套听着像方法论的故事）：

> L2 必须提出一条**可证伪的跨成员断言**，它
> （a）不被任何单个 member 陈述；
> （b）**不能由两三个 member 一步并置或一次移项得出**；
> （c）把 statement 里的本章专有名词换成别章的之后**不再成立**。

(b) 是决定性的：绝大多数被杀的候选不是胡说，是**正确但便宜**——
它的「增益」只是把两个已在 members 里的事实并排放好再起个名字，
而学习者手里既然还有这两个成员，他并置它们不需要这个 L2。
(c) 淘汰另一批：命题为真且可迁移，但**可迁移到任何章任何教材**，
那不是本章的抽象层，是治学习惯。

配套的 schema 强制三个字段，缺一即判死：

- `members`：成员必须在下游**真实存在**（机器可查：124 个引用，0 缺失）
- `boundary`：必须给**具体反例**（什么不属于它）
- `abstraction_gain`：删掉它会丢什么

还有一条实测出来的补充规则：
**删除测试不能只对着父节点和同文件兄弟做，必须对全图做。**
（一个候选在本文件内看起来有增益，放到全图里就发现它的内容已被别处覆盖。）
以及一条机器校验的扩展：不只校验 `members` 里的 id，
还要校验 `boundary` / `abstraction_gain` **散文里提到的 id**——
因为在散文里编造成员，和在 `members` 里编造成员是一回事（第二轮 30 个引用，0 缺失）。

### 4.3 停止规则

不要预设层数。审查单反对「固定四层树塔作为数据结构」，
实验给出的替代是一条**由存活率触发的停止规则**：

> 某一层的审计存活者少于 2 个 ⇒ 这一层就是当前语料的抽象天花板，停止上提。

按 16.7% 的存活率，L2 存活 4 个；从 4 个继续上提到 L3，
目标写成「至少 1 个立得住的 L3」而不是「构造完整的 L3 层」。
**层数是测出来的，不是设计出来的。**

### 4.4 层 ≠ 分片

一条容易混淆、且已在实测中付出代价的区分：

- **纵向（A1 → D，或 A1 → L2）必须串行**，因为上层的成员必须先存在。
- **横向（同层不同分片）可以并发**，实测确实这样跑的。
- L1 一旦冻结，下游全部依赖它，返工成本高——所以冻结前要把 id 清单定死。
- `parent` 字段的语义**至今未定义**：实测有 7 个节点标了 `atomic: true` 却仍有子节点。
  已逐个查清：其中 2 个是真的 atomic 标错，另 5 个是**把 `parent` 边当「推论/特例化」用**，
  而不是当分解边用。也就是说这不是数据脏，是 schema 缺一条定义：
  **`parent` 是否只表示分解？** 必须在 SPEC 里定死，否则同一条边有两种读法，
  而「多分支图被误读成单一路径树」正是从这里来的。

## 5. 审计：两条正交的轴，以及它的并行边界

实测跑的是两组独立审计，不能合并成一次打分：

- **审计 A（内容正确性）**：数学是否正确、出处是否真实、锚点是否支撑断言。
- **审计 B（抽象增益）**：删除测试。

正交的意思是：一个节点可以数学完全正确、锚点完全合法，
但抽象增益为零（这就是 24 个 L2 候选里绝大多数的情况）；
反过来也存在。合成一个分数会让两者互相掩盖。

已命名的六个死因，可以直接当审计清单用：

1. 量词过度断言（引文射程小于 statement 射程）
2. 编造成员归属
3. 伪造教材出处
4. 数学错误
5. 伪抽象·层塌缩
6. 锚点漂移

### 5.1 可复现性实测决定了并行边界

同一批节点让不同审计者独立跑，结果分裂成两个层次：

| 轴 | 一致性 |
| --- | --- |
| 该不该判死（kill / no-kill） | **8/8 一致** |
| 具体处置（KILL / FIX / KEEP） | **7/8 一致** |

**选型结论：检测可以并行，处置必须单点。**
多个审计者并发找问题，结果取并集；
但「这个问题该怎么处理」由单一裁定环节决定，不投票、不多写多份。
这条同时解释了为什么审计报告不能由发现者直接落盘成正式图。

### 5.2 借来的引文：一类逐节点看不见的错误

有一类问题在单节点视角下完全不可见：多个节点共用同一条引文，
每个单看都「有锚点、且锚点合法」，但那条引文只支撑其中一个节点的断言，
其余节点是**借**来的。这是**整表属性**，不是节点属性——
per-node 校验永远发现不了。

工程含义：审计必须有一个「全表视角」的环节。
`check_shared_quotes.py` 是往这个方向做的第一版尝试，方向对：
它已经产出过一处真实修正（`nodes-X.jsonl` 唯一一组共享引文里，
两个节点被撞到一起，读 statement 后发现共享的那句只撑得起其中一个）。
但它对 46% 的节点永久不可见（§2.2），且全图 148 组共享引文**尚未逐组审查**。
**方向对，覆盖不合格。**

审查单写「不追求一次穷尽全学科」。下面是它对应的实测数字，
用来防止把两次实验的结论当成全学科结论。

| 项 | 状态 |
| --- | --- |
| 规模 | 一门学科**两本教材的各三四章**（Apostol 第 15 章、Strang 第 3–4 章） |
| 第 15 章图谱规模 | 节点 **522**、边 **1433** |
| 跨教材对齐 | 已完成，有报告 |
| 图机器校验 | 干净（`check_graph.py` problems 0；边证据 902/902） |
| 内容审计 | **未完成** |
| 形式 D 猎手实际覆盖 | D1 30/81、D2 35/80、D3+D4 20/123（**D4 完全未动**）⇒ **199 个节点没查** |
| A、B 两判全空的文件 | `nodes-D1`(81)、`nodes-A2-x2`(34)、`inherited/nodes-A1`(63)、`inherited/nodes-S1`(62)；`nodes-X`(22) 只做了 A 判 |
| 共享引文组待审 | 全图 **148 组**，尚未逐组审查 |
| 已判死边写入 graveyard | **68/88**（20 条在 `--help` 事故中永久丢失，git 未跟踪该目录，无法恢复） |

其中 `inherited/nodes-A1`(63) 与 `nodes-S1`(62) 两判全空，
是 **L1 底座冻结策略的直接代价**——冻结换来了下游可并行，代价是底座本身没被审。
这是选型上要接受的交换，但要写明。

所以：本文所有「比例」都是这个规模下的比例。
外推到一门学科的全部资料，是**推断**。

### 6.1 规模算术：人工审计是瓶颈

用实测的量做一次外推（推断）：三四章产出 522 节点 / 1433 边 / 921 锚点；
一本教材 30+ 章，一门学科多本教材。
锚点校验是机器的，成本≈0；**但审计 A 和审计 B 全是人工，且不可并行到处置环节。**

这就是为什么「一次穷尽全学科」不是意志问题而是算术问题。
可行的形态只有一个：**按需求驱动，逐块推进，每块跑完整的审计规程。**
不是「先建全图再用」，是「用到哪块建哪块」。
这也反过来支持第 0 节的结论——统一的是规程，不是一次性建成的对象表。

## 7. 存储与工具：选什么、以及为什么先不选图数据库

审查单把「图数据库或关系表」放在**以后转技术方案**里，没有预先定。
实测支持继续维持这个状态，理由是**还没有任何查询需求逼出图数据库**。

| 决策项 | 选 | 理由 |
| --- | --- | --- |
| 数据格式 | **append-only JSONL** | 崩溃安全：磁盘上任何时刻都是合法文件；实测两次中断事故都靠这个止损 |
| 校验 | **独立脚本 + 退出码**（`verify_anchors.py` / `check_graph.py`） | 校验必须能脱离产出流程单独重跑 |
| 图数据库 | **暂不选** | 现有需求全是「按 id 取、按边遍历一两跳、全表校验」，JSONL + 脚本够用。选型条件见下 |
| 删除 | **不物理删除，写 graveyard** | 判死也是结论，要留证据链 |
| 别名 | **`alias-of` 边 + `aliases` 字段，不合并节点** | 合并不可逆，边可逆（§1） |

**什么时候才该上图数据库**（写成可判定的触发条件，不靠感觉）：
出现需要三跳以上遍历、或需要在图上做实时交互查询的真实产品需求时。
在那之前，图数据库只增加运维面，不解决任何已知问题。

### 7.1 工具安全：这条是事故换来的

两次真实事故，都改了工程约束：

- **`--help` 数据清空**：脚本没有 argparse，`--help` 被当成未知参数忽略，
  脚本照常执行，无条件 `open(..., 'w')` 清零了两个 graveyard 文件，**20 条边永久丢失**。
  修法：所有写型脚本必须有真 argparse；必须有 `--dry-run`；
  必须有 `--only` 限定作用域；graveyard 改 append-only 且拒绝重复 id；
  **删除所有裸 `'w'` 打开**。
  推论（对本项目所有人有效）：**`--help` 不是只读操作**，不能用它来试探未知脚本的用法。
- **主窗口误关，7 个进行中的 agent 全死**。
  修法：每 5–8 项增量落盘；缩小单个 agent 的作用域；磁盘上永远是合法 JSONL。

这不是运维琐事。它决定了产出流程能否承受中断——
而按 §6.1 的算术，这个流程会跑很久，中断是常态而不是意外。

## 8. 知识载体调研的取用结论

`知识载体调研/几个方向.md` 列了五个家族（纯逻辑、数学结构、因果与概率、
程序与编译、自然语言与向量）共九条路线。逐条对照实测瓶颈，结论是：

**没有一个家族现在到了可选型的程度，因为瓶颈不在表达力，在验证。**

实测的失败全部是内容失败——量词过度断言、编造成员、伪抽象——
没有一次是「这个关系表达不出来」。换任何一种更强的载体都不会改善这些，
因为它们的强项是保证**推导**正确，而这里出错的是**断言与原文的对应**。
后者是锚点问题，没有任何形式系统能替你确认「这句话确实是那本书说的」。

可以现在借用的，只有三处局部机制：

| 来源 | 借什么 | 不借什么 |
| --- | --- | --- |
| 依赖类型论（命题即类型） | 「证明作为对象」的形态——正好对应 §3 把定理的假设/结论放进节点字段 | 整套形式化验证：代价与收益不成比例 |
| 向量嵌入 / SAE | **只做定向**：找候选、找可能的同义对 | 结案权。§1 已实测它无法区分「两种写法」与「同名两物」 |
| DreamCoder 式抽象入库（wake-sleep） | 「从解法里提炼可复用抽象、库变厚」这个循环形状，与 L2 提案同构 | 自动入库。§4.1 的 16.7% 存活率说明必须过人工审计 |

`未命名.md` 里的自进化方向（EvoGraph-R1 闭环自修正、Graph-R1 强化学习寻路、
MemGraphRAG 动态演化状态）与 M08 的一条硬边界直接冲突：
审查单写「不能让模型无边界地决定目标、权限或正式写入」。

**取用方式：借候选生成，不借自我进化。**
闭环反馈可以用来提出候选、提出可能的错误，
但不能自动改正式图——否则 §5.1 的「处置必须单点」就被绕过了。
Graph-R1 那类图上寻路策略要等到有真实的多跳查询需求才有意义（见 §7 的触发条件），
现在引入是提前决定。

## 10. 对审查单 7 个产品负责人问题的实测输入

这些是产品决策，不由技术选型定。下面只提供实验能提供的输入。

**Q1（正式对象范围；定理/题型/应用情境/研究问题是对象、关系还是属性）**
实测：`theorem` 作为独立节点类型跑了两个实验，没出问题。
定理**必须**是对象而不是关系——§3 的 `requires` 坍塌（55–61%，与定理数正相关）
正是把定理挤进边导致的。题型模式、应用情境、研究问题本轮**未测**。

**Q2（高层候选的最小表达）**
实测给出的必需项是三个，缺一即判死：**组成对象（`members`）、边界/反例（`boundary`）、
抽象增益（`abstraction_gain`）**。「共同机制」实际是 `abstraction_gain` 的内容。
「教学用途」「迁移方向」本轮未作为必需项测，未测即未验证。

**Q3（晋升的审计条件；各方权限）**
实测：审计 A + 审计 B 两条正交轴（§5），六个死因清单。
权限的实测输入是 §5.1：**检测可并行、处置须单点**；
以及审查单自己的边界——模型可提候选，不能决定正式写入。

**Q4（候选区内容能否用于教学探索）**
本轮未测。技术上可行的区分手段已经有了：id 前缀本身就带证据责任（§1），
`L2:` 与 `apostol:` 的锚点义务不同，天然可分。

**Q5（「层」是否只作抽象深度、不设固定层数）**
实测强支持不设固定层数：§4.3 的停止规则（存活 <2 即天花板）
让层数变成测量结果。避免误读为单一路径树的技术前提是 §4.4——
**层 ≠ 分片**，且 `parent` 的语义目前未定义（7 个 `atomic: true` 节点仍有子节点），
这个未定义正是「多分支被误读成树」的来源，要先修。

**Q6（用户编辑通用结构的默认行为）**
本轮未测（实验没有用户编辑场景）。唯一相关的实测经验是 §7 的
「不物理删除、不合并节点」——可逆优于不可逆。

**Q7（M08 与 M09 同界面叠加）**
本轮未测。相关红线在 §9：四种图不能合并；M09 锚定 M08，不是它的覆盖层。

**一句话**：这份选型的重心不在选什么工具，在于把「什么算证据、什么算抽象、
谁有权结案」这三件事写成可执行、可复现、能让产出者主动放弃的规程。
两次实验里真正起作用的都是规程，不是格式。
