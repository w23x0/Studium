# ADR 0001：M1 应用技术栈

- 状态：Accepted
- 日期：2026-07-14

## 背景

M1 只验证一条纵向链路：用户在浏览器发送多轮消息，Studium 的唯一后端调用真实模型并返回结果。当前没有 Python 领域逻辑、数据库、后台任务或独立部署前后端的需求。

技术栈必须减少活动入口和重复契约，同时保证模型密钥不会进入浏览器，并为请求、响应和失败状态提供自动化验证。

## 决策

- 使用 Node.js 24 LTS 作为应用运行时，并在仓库中声明版本约束。
- 使用 npm 和 `package-lock.json` 安装、锁定 JavaScript 依赖。
- 使用 TypeScript、React 和 Next.js 建立一套活动应用。
- 浏览器页面和服务端 Route Handler 位于同一 Next.js 应用；浏览器只调用同源 `POST /api/chat`。
- 使用 Zod 定义并校验前后端共享契约。
- M1 采用非流式 JSON 响应；服务端通过原生 `fetch` 调用 LLM 网关。
- M1 不引入数据库、会话持久化、Markdown 资料上下文、诊断或闭环状态。

## 理由

- 单一应用只需要一个活动入口，不需要跨域配置或两套构建流程。
- TypeScript 与 Zod 让页面、Route Handler 和测试共享同一份可执行契约。
- Route Handler 保证网关地址和密钥只存在于服务端。
- 非流式响应足以验证 M1 的主要不确定性，并使超时和统一错误语义更容易验收。
- Node.js LTS 比本机偶然安装的非 LTS 版本更适合作为可复现基线。

## 后果

- M1 的唯一应用开发入口为根目录 `npm run dev`。
- 长耗时后台任务、独立扩缩容或 Python 领域计算若成为真实需求，需要新的 ADR 评估是否拆分后端。
- 引入流式输出会改变响应契约，必须单独评审，不能在 M1 中隐式加入。

## 未采用方案

- Vite 加 Fastify：会立即产生两个应用入口和额外的开发编排。
- React 加 FastAPI：当前没有足以承担跨语言契约和双运行时成本的 Python 业务逻辑。
- Vercel AI SDK：M1 只有一个非流式调用点，原生 `fetch` 已能满足需求。
