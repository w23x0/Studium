# 同类项目对照

> 状态：待定（2026-10-01 建）。**参考材料，不作产品结论**；对照中想到要改自己设计的，记成 `任务线路.md` §3 的新线，走审查单 / Harness 流程，不在这里直接定。
> 目的（产品负责人原话）：一个一个看别人的项目，学习对比技术、方向、边界，扩大视角，确立自己的方向和边界。

## 做法（DeepTutor、WeSmartFlow、ai-learning-support-test 三轮后修订）

| 步 | 做什么 |
| --- | --- |
| 1 准备 | 读本页；`git clone --depth 1` 到 `~/参考项目/<名字>`（仓库外，不进 git）；同时派两个子代理：**读码**（流程谁控制 / 学习者状态 / “学会了”怎么判 / 知识结构 / 路线 / 上下文与记忆 / 评测），**读文档**（方向 / 边界 / 证据 / 定位变化 / 团队）。主会话抽查关键行再讲。**以代码为准**：README、落地页宣称的功能可能没实现（`03`） |
| 2 讲 | 一次一条，等回应再讲下一条。**每条先说它帮我们回答什么问题，说不出就不讲**。只讲技术核心与方向；产品形态、内容生态、营销功能（课件、游戏、积分、接入渠道等）一句带过 |
| 3 放进外部光谱 | 讲一个技术点时不局限于这个项目：外面还有谁这样做、这种做法何时出现、何时流行 / 成熟、我们在光谱的哪一端。**举例只举成熟代表作或最新前沿**，小项目、非最终版本不作论据。多讲对比，让产品负责人对它的设计有具体概念 |
| 4 讨论 | 产品负责人直接指出和我们不同的地方；agent 先讲它为什么这样设计（在它的约束下是否自洽）、双方各自的代价，再记；拿不准就标出来 |
| 5 记 | 当场写进 `NN-<项目名>.md`，**只记实际需要的**：不为总结而总结、不为底层而底层，没有内容的节可以不写。建议节：定位一句 · 技术核心（带出处）· 外部光谱位置 · 产品负责人判断与 agent 分析 · 启示 |
| 6 收尾 | 产品负责人说够了就停；更新本页清单与 `任务线路.md` §3 #20 |
| 预扫 | 外部对话的快速预扫只当线索，放项目文件 §0 标未核实，读码子代理逐条核对，核完删。`03` 的预扫多半与代码不符 |
| 并发 | 两个会话同时看两个项目：各自只写自己的项目文件；本页清单、`任务线路.md` 收尾时先重读再改、只改自己那一行；提交只 `git add` 自己改的文件，不推送 |

## 讨论时守的规矩

| 规矩 | 来由 |
| --- | --- |
| 先过定位筛子：靠答对率、规则替模型判断、弱模型兜底的做法，一句带过归反例，不当基础或经典验证逻辑 | `02` 1.4a：CogniFlow 按对错算掌握 |
| 不凑优点：我们已有对应的算“同”，不算“借鉴”；真没有可借鉴的就说没有 | `01` 1.5：四条“可借鉴”三条是已有的 |
| 讲设计先讲成因：同一做法放在它的约束下（模型、判分方式、团队）是否自洽 | `01` 1.5b |
| 猜测要核实：产品负责人对背景的猜测，agent 去查事实再回应 | `01` 1.1 |
| 从多个项目的试错里提炼一般经验，但只在确有内容时写 | `02` 1.5a |

## 每个项目看什么

| 维度 | 要回答的问题 |
| --- | --- |
| 方向 | 想解决什么学习问题、面向谁（自学 / 课堂 / 教师）、成功怎么算；定位怎么变过 |
| 技术 | 流程谁控制（程序 / 模型）、学习者状态存什么、“学会了”由谁怎么判、知识结构怎么建、路线学前定还是学中长、上下文与记忆；**首要判别：学习结构进了 harness，还是“通用 harness + 学习插件”** |
| 外部光谱 | 同类做法的代表作、出现与成熟时间线、我们的位置 |
| 边界 | 刻意不做什么、明说的局限；有没有“决定不做”这一档 |
| 证据 | 效果数据从哪来、样本多大、自报还是第三方、评测用的什么模型 |
| 团队 | 只在能解释定位与功能形态时看 |
| 对照与启示 | 同 / 不同 / 各自代价；归类：同 · 方向不同 · 反例 · 边界 · 只作参考 · 暂缓；方向或边界要不要动（只提出，不定） |

我们这边的对照对象：`docs/模块需求设计/00-第三次重构-产品设计总览.md`「闭环定义」「设计取向」· `docs/Harness设计/00-技术方向确认.md`（核心原则，正在重审）。
