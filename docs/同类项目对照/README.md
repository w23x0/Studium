# 同类项目对照

> 状态：待定（2026-10-01 建；2026-10-05 看完 C–F，#20 收回）。**参考材料，不作产品结论**；对照中想到要改自己设计的，记成 `任务线路.md` §3 的新线，走审查单 / Harness 流程，不在这里直接定。
> 目的（产品负责人原话）：一个一个看别人的项目，学习对比技术、方向、边界，扩大视角，确立自己的方向和边界。

## 做法（五轮后修订：DeepTutor、WeSmartFlow、ai-learning-support-test、Math Academy、知识空间理论）

| 步 | 做什么 |
| --- | --- |
| 1 准备 | 读本页与本项目在「待看」表的问题。派一个**读材料**的 `researcher` 子代理（流程谁控制 / 学习者状态 / “学会了”怎么判 / 知识结构 / 粒度 / 关系种类 / 评测；无代码读论文、书稿、技术博客），背景（方向 / 边界 / 证据 / 时间线）只要能解释设计的部分，可并入同一个或另派一个**轻量**的。要求子代理把抽取的原文存进会话 scratchpad，主会话按关键引句抽查。有代码才 `git clone --depth 1` 到 `~/参考项目/<名字>`。**以代码 / 原文为准**（`03`） |
| 2 定焦 | 讲第一条后，产品负责人常会点出真正关心的一两个问题（`05`：粒度、结构）。点出后**按这几个问题再派一轮聚焦调研**，带上我们这边的实际难题（相关审查单、`_research` 文件的现状），不再按“每个项目看什么”全表铺开 |
| 3 讲 | 一次一条，**只说重点**：先说帮我们回答什么、结论一句，再给依据；说不出用处就不讲，**没有可借的就直接说“没有”**，不把理论铺开让产品负责人自己找用处。产品形态、营销功能一句带过 |
| 4 放进外部光谱 | 只在帮助理解时加：谁也这样做、何时出现 / 成熟、我们在哪端；只举成熟代表作或最新前沿 |
| 5 讨论 | agent 先讲它为什么这样设计（约束下是否自洽）、双方代价；对产品负责人的推理先分清哪部分成立、哪部分要分开看，守住观点但不展开成多主题 |
| 6 记 | 当场写进 `NN-<项目名>.md`：技术核心（带出处）· 对照表（产品负责人 / agent 分析 / 归类）· 启示；理论学习另开一节按课记 |
| 7 收尾 | 产品负责人说够了就停；写启示、更新本页清单与 `任务线路.md`（#20 和受影响的线）、提交 |
| 学理论模式 | 产品负责人要“系统学”某理论时：**不做对照**，按“重点课”讲——理论要点 + 证据 + 我们自己想不到的部分；前沿方向先交子代理核实再讲 |
| 预扫 | 外部对话的快速预扫只当线索，放项目文件 §0 标未核实，子代理逐条核对，核完删 |
| 并发 | 两个会话同时看两个项目：各自只写自己的项目文件；本页清单、`任务线路.md` 收尾时先重读再改、只改自己那一行；提交只 `git add` 自己改的文件，不推送 |

## 讨论时守的规矩

| 规矩 | 来由 |
| --- | --- |
| 先过定位筛子：靠答对率、规则替模型判断、弱模型兜底的做法，一句带过归反例，不当基础或经典验证逻辑 | `02` 1.4a：CogniFlow 按对错算掌握 |
| 不凑优点：我们已有对应的算“同”，不算“借鉴”；真没有可借鉴的就说没有 | `01` 1.5：四条“可借鉴”三条是已有的 |
| 讲设计先讲成因：同一做法放在它的约束下（模型、判分方式、团队）是否自洽 | `01` 1.5b |
| 猜测要核实：产品负责人对背景的猜测，agent 去查事实再回应 | `01` 1.1 |
| 从多个项目的试错里提炼一般经验，但只在确有内容时写 | `02` 1.5a |
| 设计偏差大时不硬对照：只在确有我们没想到的东西时一句话点出 | `05` 2.3 后产品负责人：“不用一直对照了” |
| 不替已实验过的部分出主意：闭环内的提问、节奏由模型内化，关注点放在闭环外（M05 方向、M08 结构） | `05` 重点 1 |
| 消费者筛子：一个外部做法（粒度、关系、信号）对我们有没有用，看哪个模块会用它、用来做什么；说不出消费者就归“只作参考” | `05` 2.1、2.2 |
| 算法类前沿先问数据：它要的数据我们有没有；没有就归“只作参考”，不展开 | `05` 重点 3 |

## 每个项目看什么

| 维度 | 要回答的问题 |
| --- | --- |
| 方向 | 想解决什么学习问题、面向谁（自学 / 课堂 / 教师）、成功怎么算；定位怎么变过 |
| 技术 | 流程谁控制（程序 / 模型）、学习者状态存什么、“学会了”由谁怎么判、知识结构怎么建、路线学前定还是学中长、上下文与记忆；**首要判别：学习结构进了 harness，还是“通用 harness + 学习插件”** |
| 外部光谱 | 同类做法的代表作、出现与成熟时间线、我们的位置 |
| 边界 | 刻意不做什么、明说的局限；有没有“决定不做”这一档 |
| 证据 | 效果数据从哪来、样本多大、自报还是第三方、评测用的什么模型 |
| 团队 | 只在能解释定位与功能形态时看 |
| 对照与启示 | 同 / 不同 / 各自代价；归类：同 · 方向不同 · 反例 · 边界 · 只作参考 · 暂缓；方向或边界要不要动（只提出，不定） |

我们这边的对照对象：`docs/模块需求设计/00-第三次重构-产品设计总览.md`「闭环定义」「设计取向」· `docs/Harness设计/00-技术方向确认.md`（核心原则，正在重审）。

## 和同类项目的不同（供将来对外 README 起草）

> 从各项目的对照里收拢的“我们和别人不一样的地方”，产品负责人 10-05 要求记下，方便写给别人看。**以产品总览为准**；这里每行只是索引，细节看出处文件。

| 不同点 | 别人通常怎么做 | 我们 | 出处 |
| --- | --- | --- | --- |
| 学习结构在哪 | 通用聊天 / 工具循环 + 学习插件（DeepTutor、WeSmartFlow、ai-learning-support-test） | 闭环、证据、知识面进到系统本身 | `01` §6、`02`、`03` §6 |
| 判什么 | 判做题、算答对率或掌握概率（Math Academy、ALEKS、Cognitive Tutor、对话知识追踪） | 判理解：靠所选出发点把新点理解到目标层次 | `04`、`05`、`06`、`07` |
| 谁来判、认什么 | 辅导者自判（DeepTutor）、权重公式（WeSmartFlow）、词语相似度（AutoTutor） | 与教学隔离的守卫判，只认学习者自己的输出；讲过的部分检验更严 | `01`、`02`、`06` 1.1 |
| 一个点怎么学 | 一个点一组前置，状态只记“会 / 不会”（Math Academy、ALEKS） | 一个点可从不同出发点学，理解不同；记下用了哪组出发点 | `04`、`05` 1.1 |
| 路线 | 学前定好的课程图或固定课程 | 按学习者知识面在学中长出，以书本路径为基准 | `01` §6、`05` 2.1b |
| 价值在哪 | 单次辅导做好（LearnLM、Khanmigo、哈佛物理 RCT） | 单次不差于通用模型 + 教材，价值放在跨闭环：记得学到哪、会了什么、下一段走哪、连上了什么 | `06` 1.2、`08` |
| 任务与学习 | 学习长在真实任务里，需要时才拉引导（Matuschak） | 知识结构为先，真实工程作迁移检验 | `09` |
| 给谁用 | 课堂配套、教师 / 家长端（ALEKS、Cognitive Tutor） | 使用者 = 学习者本人，不做账号 / 家长 / 教师 / 班级 | `01` §6、`05`、`06` |
| 角色扮演 | 虚拟同学、多身份 agent 课堂（Betty's Brain、OpenMAIC） | 不做角色扮演（“不做多身份 agent”在 #16 重审中） | `07` 1.1 |
