# 同类项目对照

> 状态：待定（2026-10-01 建）。**参考材料，不作产品结论**；对照中想到要改自己设计的，记成 `任务线路.md` §3 的新线，走审查单 / Harness 流程，不在这里直接定。
> 目的（产品负责人原话）：一个一个看别人的项目，学习对比技术、方向、边界，扩大视角，确立自己的方向和边界。

## 做法

| 项 | 约定 |
| --- | --- |
| 节奏 | **一个项目一个会话**。agent 先读代码和文档，再按下方维度一条一条讲给产品负责人，等回应再讲下一条 |
| 读法 | 代码克隆到仓库外（`~/参考项目/<名字>`，`git clone --depth 1`）；联网走 `web-access` 技能；读原文，自报数据标“自报”，没核实的标“未核实” |
| 分工 | 检索、读代码、量数据可交子代理；主会话负责和产品负责人讨论，并抽查代理结果 |
| 产出 | 每个项目一个文件 `NN-<项目名>.md`（≤ 400 行），格式见下；收尾时更新本页清单与 `任务线路.md` §3 #20 |

## 每个项目看什么

| 维度 | 要回答的问题 |
| --- | --- |
| 方向 | 它想解决什么学习问题、面向谁（自学 / 课堂 / 教师）、成功怎么算 |
| 技术 | 结构：流程谁控制（程序 / 模型）、学习者状态存什么怎么存、“学会了”由谁怎么判、上下文怎么装配 |
| 边界 | 它刻意不做什么、明说的局限、做不到的地方 |
| 证据 | 效果数据从哪来、样本多大、自报还是第三方 |
| 和我们对照 | 同在哪、不同在哪（对照对象见下）；对我们是“借鉴 / 反例 / 只作参考” |
| 对方向与边界的启示 | 看完后，我们的方向或边界要不要动、往哪动（只提出，不定） |

我们这边的对照对象：`docs/模块需求设计/00-第三次重构-产品设计总览.md`「闭环定义」「设计取向」· `docs/Harness设计/00-技术方向确认.md`（核心原则，正在重审）。
