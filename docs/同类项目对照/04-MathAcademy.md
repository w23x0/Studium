## 2. 技术

| 项 | 内容 | 出处 |
| --- | --- | --- |
| 流程谁控制 | 程序：自称“模拟专家导师决定的专家系统”，四件：知识图、学生模型、诊断、任务选择。不用大模型；书明说不做对话：“Dialogue isn't even necessary. We simply hardcode explanations into bite-size pieces” | `官网/how-our-ai-works`；书 p.465–466 |
| 知识图规模与粒度 | 约 2500 个 topic（一个 topic = 一节课），每个 3–4 个知识点 KP（KP = 一个例题 + 2–5 道同类题）；一门课约 150–300 topic；自称比教科书细约 10 倍；粒度靠多年手工拆分“凭感觉” | `建图`；书 p.74、p.218、p.449 |
| 边 | ① 前置（topic → topic，决定能学什么；直接前置最好 ≤3–4 个）② 关键前置（KP → 更早的 topic，这一步直接用到哪块旧知识，用于定向补救）③ 包含（高级 topic 练习时顺带练到简单 topic，带权重 ≈ 练到的比例；“包含的通常是前置，前置常常不被完全包含”）；另有同模块、跨课等价等 | 书 p.69、p.75–78、p.366–371 |
| 边谁建 | 人工：课程总监管前置图，Skycak 管包含图；权重专家逐条估，只填少数非平凡的边 | 书 p.367–368；`建图`；`FIRe` 问答 |
| 学习者状态 | 每个 topic：累计重复数、间隔、记忆强度（随时间衰减）、个人学习速度、近期加权正确率；知识前沿 = 前置都已掌握的新 topic 集合（由画像推出，不单存） | 书 p.212–214、p.370–373 |
| 定位起点 | 自适应诊断 20–60 题；一题平均提供约 10 个 topic 的信息：答对给它和所有祖先前置加分，答错给它和所有后继减分；刚过线的标“有条件通过”，后面做不好就退回；诊断偏保守 | 书 p.375–381、p.444 |
| 下一步怎么选 | 新课只出自前沿；先算到期复习，再挑“隐式顺带复习能覆盖最多到期项”的课 / 复习；新课能顶掉复习时只给新课；按“能顶掉多少复习 + 多少后续依赖它”排序；强制约每 3 个复习 1 节新课；相近内容在时间上隔开；具体打分未公开 | 书 p.369、p.406–407、p.421 |
| 学会了怎么判 | 只看做题：KP 内连对两题过（官网说法；书只写“足够多”），2–5 题内过不了算失败、先做别的再重试；同一 KP 第二次卡住 → 补关键前置。不换讲法、不降门槛。复习 3–5 题看对错顺序。未找到任何判解释 / 理解的机制；书说基线掌握“不等于最大理解”，深理解靠后续复习和在高级内容里反复用到 | 官网/how-it-works；书 p.75、p.299–300、p.397、p.413–419 |
| 复习沿图传导（FIRe） | 高级 topic 复习**成功** → 沿包含边**向下**记给被包含的简单 topic（按权重打折，多层）；简单 topic 复习**失败** → 沿包含边**向上**扣到包含它的高级 topic。走包含图不走前置图（“在前置图上做会让大量错误的复习信用往下漏”）。公式：`repNum → max(0, repNum + speed·decay^failed·rawDelta)`；个人速度 < 1 时不接收隐式复习。实现细节自称专有 | 书 p.363–374；`FIRe` 正文与问答 |
| 教学内容 | 幻灯片式文字讲解 + 例题 + 练习，“最小有效剂量”后立即做题；全部内部专家手写；同一知识点只打磨一种讲法 | 书 p.397–398、p.418、p.462 |
| 首要判别 | 学习结构**就是**系统本身（图、状态、调度全由程序），不是通用 harness + 学习插件；也没有模型参与判断 | 同上 |

## 2a. 建图与教学的经验规则（团队经验，无数据依据，只作参考）

| 规则 | 内容 | 出处 |
| --- | --- | --- |
| 直接前置 ≤3–4 个 | 再多就像“交通堵塞”，该拆 topic、加中间点 | `justinmath.com/math-academy-podcast-4-part-2`（课程总监，转写） |
| 关键前置也别堆 | 每个知识点都挂三四个关键前置（可远在几层之前）时，就是认知过载的信号 | 同上 |
| 粒度凭感觉、反复拆 | “对的块大小”靠多年拆分得来，没有公式 | `建图` |
| 包含边只填非平凡的 | 前置图距离近、比例不能由别的边推出的才显式填权重，其余视为 0 | 书 p.367–368 |
| 一种讲法反复打磨 | 不准备多种讲法；某步通过率低就加中间知识点、改例题，不降门槛 | 书 p.304–305、p.418 |
| 新课与复习配比 | 积压再多也保证约每 3 个复习 1 节新课 | 书 p.406–407 |
| 相近内容隔开 | 相近概念在时间上错开，新知识分块练、复习和测验再交错 | 书 p.415 |

## 3. 边界

| 类 | 内容 | 出处 |
| --- | --- | --- |
| 明说不做 | 不做大模型对话（“把精力放在讲解上是走错方向，该放在脚手架、导航、管理整个学习过程”）；不做视频；不做真人辅导；不让学习者自选任务、不让改知识画像（自报会严重高估）；不给“我不知道”按钮（诊断除外）；卡住不给提示、不降门槛，只补前置 | 书 p.299–300、p.462–467；Ep42 |
| 方法立场 | 初学者靠直接讲授，否定发现式学习与小组合作；先练程序熟练、后学证明 | 书 p.140–146、p.189、p.452–455 |
| 自认局限 | 证明类课程只有两门（2025-08），其余大学课偏计算；复习间隔校准“还有空间”；诊断松推断偶有偏差；包含边可能过宽，自动复核“在待办里”；包含关系稀疏的学科能顶掉的复习有上限 | 书 p.409–411、p.447–454；`FIRe` 问答 |
| 对大模型的最新表态 | 2026-04 访谈：生成内容是随机的、难做内容分析，对话式个性化“出岔子的面太大”，“仍在关注” | justinmath.com/deep-learning-with-yacine-podcast-1（转写） |

## 5. 和我们对照：产品负责人的判断与 agent 分析

| 条 | 产品负责人 | agent 分析 | 归类 |
| --- | --- | --- | --- |
| 1.1 从已会的点定位下一步 | 做题诊断我们也有，靠与模型对话、模型输出即诊断结果，不走概率式评分（差异原因已总结过）；前沿 ≈ 我们的知识面；关键前置的补救 ≈ M05；我们的出发点也是图的属性，闭环由 M08 图结构出来——没有特别的点；要补的是知识空间理论；这个系统基于经典 ITS | agent 原先把“出发点固定在图上 vs 每次选”讲成根本分界，**错**：我们的出发点同样来自 M08。剩下一处不同：它每个点只有一组前置（人工定死）；我们一个新点可有几组可选的出发点组合，学到的理解不同（产品总览「闭环定义」）。知识空间理论里正好有这个区分：每个点可以有几组可选的前置（surmise system），只有一组前置是它的特例（agent 记忆，会话 B 读原文核对）。“直接前置 ≤3–4 个”没有数据依据，是课程总监的经验（`justinmath.com/math-academy-podcast-4-part-2` 转写：“三四个以上我就开始不舒服”），用来决定什么时候拆 topic。“基于经典 ITS”部分成立：四件结构同经典 ITS，但它只做“选下一题”这一层（外循环），没有经典 ITS 题内逐步跟踪；诊断来自 ALEKS / 知识空间理论（作者自己重写过 ALEKS 诊断） | 同；知识空间理论 → 会话 B 重点 |
| 1.2 学新点时用到旧点算不算复习（FIRe） | “两位数乘一位数包含一位数乘法”这类包含像我们说的“推广”；我们的晋升机制不全是 M09 → M08，现有文档有偏差；这类数据对我们是给 M05 看的、用于优化机制，但我们还没下放到算法，目前都靠模型判断；FIRe、记忆算法属算法层，和我们差别很大；复习 / 记忆只能由 M09 承载，还没讨论过，之后会自然讨论到 | FIRe = Fractional Implicit Repetition（分数式隐式重复），是复习调度算法：高级点复习成功沿包含边往下给旧点记部分复习，简单点失败往上扣到高级点，只走包含图不走前置图。对照：M09 已有失败方向（后续闭环发现已会内容答不出 → 提取失败 / 降档），没有成功方向（出发点在闭环里被成功用到不记）。只提出，不开线 | 方向不同（算法层）；暂缓（复习 / 记忆讨论时再看） |
| 1.3 只靠做题判学会，理解从哪来 | 这是它的局限，能理解；我们靠模型能做到很多它做不到的事，整个思路不一样。用户反馈理解难，原因是路径偏固定、不能结合学习者实际知识面，细节上教学达不到闭环，造成理解偏差 | 它连对两题即过，自认“基线掌握 ≠ 最大理解”，理解靠以后被反复用到慢慢长，从不判；成因自洽（不用模型、手写内容，答对是唯一便宜可靠的信号）。外部反馈（Matuschak、HN 成人用户，二手）：练得熟、理解不深，常用 GPT 补讲。同：两边都认为理解在以后被用到时继续长（我们的“知识点的另一面”）；不同：我们在闭环合上时由隔离判断判理解，代价是准确性未经实验、每闭环多一次调用 | 对照面；反例旁证守卫的必要 |
| 1.4 为什么不用大模型 | （讲完即收尾，未回应） | 书 p.465–466：用 AI 做教育的失败者“太专注讲解，不够专注脚手架、导航、管理整个学习过程”；“对话根本不必要”，讲解手写成小块，靠做题闭合反馈。2026-04：生成内容随机、难做内容分析，对话“出岔子的面太大”。同：前半句与我们设计取向（做模型替代不了的部分：跨时间记忆、闭环结构与纪律）同向；不同：它据此不用模型，我们闭环内教学交给模型、把投入放在结构上。它真实的代价点值得记：手写内容能按单个例题的通过率逐题改进，模型现场生成的讲解做不了这种逐题数据回路，我们对应的只有过程记录与可追溯（M13 暂缓） | 同（方向）；方法不同 |
