# 页面子代理

> 状态：已决（2026-10-26；10-27 按 #66 改：只做要写代码的活、位置归框架、回报先回做组件的一方；10-27 W10 回设计：跨次上下文已核对、报错先回子代理、读资料）。来历查 `../../../定稿记录.md`。学习者看到什么、三方分工见 `学习对话.md` §11，本页不复述。

主模型（学习对话）派出的子代理，用 Agent SDK 自带的子代理，统称“子代理”，不另起名字。只为一件事：让主对话的上下文干净——写代码、调试这类会把大量细节带进主上下文的活交给它，主对话只拿它判断要用的最少信息。组件（函数图、动画、可拖动的代码、可交互的题）是它主要做的东西。Studium 只做外围：子代理能写哪些文件、交时检查、浏览器隐藏小窗试跑（见「怎么改」）。

## 何时开、活多久

| 项 | 内容 |
| --- | --- |
| 何时开 | 主模型自己判断：有要交出去的活时派 |
| 活多久 | 主模型自己定；SDK 子代理能后台跑（`../../调研/子代理与沙盒-发现.md`）。主模型自己再叫它能接着它的上下文；框架不经主模型给它送话做不到（10-27 核对，SDK 只有主模型的 `SendMessage` 能送），所以学习者动了组件、要它处理时，框架另开一个子代理，带当初的交代、组件当前版和学习者这次的操作，主上下文不变 |
| 模型 | 单独配；主对话用 Opus 时，子代理用 Opus 或 Sonnet，可选更快的模型 |

## 交接（主对话 → 子代理）

| 项 | 内容 |
| --- | --- |
| 要什么 | 用教学的话说：做一个什么图、换一种画法、改完应该看到什么；组件里的坐标轴、标签按这里说的写，教学文字仍由主模型写在组件外 |
| 留多大余地 | 每次写明这次的问题有多开放，例如“只把第 3 步换成动画”或“把这个概念换一种画法”，子代理据此决定自己能动多少 |
| 观测与回报 | 学习者动这个组件时要不要观测、观测什么、报给谁、等不等回应；交代里是否允许子代理按学习者在组件里的要求直接改 |
| 不交 | 放在屏幕哪里不交给它：主模型一句话说和什么有关，框架摆（`学习对话.md` §11.2） |

## 交回（子代理 → 主对话）

| 项 | 内容 |
| --- | --- |
| 交回什么 | 一句话：做成了什么（如“画了函数图”“加了一段可拖动的代码”），或哪里报错；按普通的子代理交回进主对话的时间线（`学习对话.md` §3），不回头改前面的内容 |
| 学习者动了组件 | 回报先到它这边；按交代自己处理，或往上报一句；自己改了组件的，改完也报一句 |
| 细节 | 子代理做出的东西不在交回里展开；主模型要细节自己调工具查 |
| 不交回 | 代码、调用日志、改动过程、块编号、版本号；改动由程序记进事件记录，留给界面与审计 |
| 改坏了 | 改动先在隔离区里做，框架检查通过才上屏幕；出错在子代理这边改掉，学习者看不到半坏的组件 |

## 怎么改

| 项 | 内容 |
| --- | --- |
| 用什么改 | 不发明新工具：框架把组件按结构块摊成文件放进子代理的沙盒（每块一个文件，加一份目录），子代理用模型自带的读和替换去改 |
| 没看过不许改 | 子代理读过哪些块，框架从沙盒动作里知道；改了没读过的块，退回 |
| 交 | 子代理改完交一次；框架查改的是不是最新的组件、有没有动没读过的块；过了才生成组件的新版本（编号只在程序内部用，不进主模型上下文） |
| 试跑再换上 | 新版本先在学习者浏览器里一个看不见的小窗里跑，没报错才换到前台；报错交回子代理改，学习者看到的一直是上一版。加载后点了才出的错，等学习者碰到时报回：先另开做它的子代理修，修好报一句；没修好又没说，按普通交回附给主模型 |

## 边界

| 项 | 内容 |
| --- | --- |
| 不做教学判断 | 露什么、露多少、观测什么由主对话定；子代理只决定怎么做 |
| 不写教学文字 | 讲解、推导、问题、给学习者看的分析由主模型写 |
| 读写 | 只写它做的组件，收学习者对这些组件的操作；资料只读，学习位置依据只在交代要画位置图时给；范围以 `../记录/读写权限.md` 为准 |
| 代码跑在哪 | 模型写的代码在学习者浏览器的沙盒里跑，不联网，动作都经框架 |
