# 后台整理

> 状态：已决（状态整理、教法记录整理的时机与读写）；阈值概念跨次判断的运行时机与存放：待定。
> 原来对应：原 M15 整理会话、原 M10 事后读记录、原 M04 阈值概念跨闭环子模块；`docs/撤下原文/模块时期/Harness设计/03-运行设计.md`「闭环外：事件与清单」④、「M15」、「教学工具怎么落」；`docs/撤下原文/模块时期/模块需求设计/模块审查单/` M04「边界」跨闭环子模块条、M10、M15。

一次学习（原称闭环）结束后在后台跑、**不挡选择卡**的几件整理。只影响下一次学习怎么教、导航怎么排承载，不影响下一张选择卡出卡。

## 何时开

| 触发 | 跑哪几件 |
| --- | --- |
| 一次学习合上（学习者确认、程序存盘后） | 状态整理、教法记录整理 |
| 没合上就结束（程序存盘后） | 状态整理、教法记录整理 |
| 其他会话结束 | 状态整理 |
| 学习者隔很久回来 | 状态整理（顺带） |
| 学习对话发来“某状态需要重新确认”的请求 | 状态整理 |

| 规则 | 内容 |
| --- | --- |
| 不定时 | 不按钟点跑；没有新记录不整理 |
| 不挡选择卡 | 事件清单见 `01-流程.md`；导航出选择卡不等后台；没跑完，导航与下一次学习对话按“无状态读数”降级（`记录/读写权限.md`「缺料与冲突」） |
| 没有“写学习者模型”这一步 | 合上后不另开会话写形成记录 / 分析层（10-18 第 6 条）；原“先写学习者记录、写完再开导航”的先后约束随之取消 |
| 不另写总结（B5） | 各件直接读原始记录：单子、守卫判定、事件记录、学习者确认或结束原话 |

## 会话形态

| 件 | 形态 | 写 | 为什么这样分 |
| --- | --- | --- | --- |
| 状态整理 | 单开一个 agent 会话 | 只写状态记录两层 | 与学习对话的诊断单向隔离（取不同字段、不读知识结论），必须独立 |
| 教法记录整理 | 未定（原设计只写“事后读记录”） | 只写教法记录 | 它要读诊断与守卫判定，状态整理不得读，所以两者不能合在一个会话 |
| 阈值概念跨次判断 | 待定（见下） | 待定 | 读知识侧记录；不能与状态阶段判断合在一个会话（合成需要一方同时持有两侧结论） |

模型与思考强度按会话类分开配（配置项，不全局一个）；状态整理默认高强度（10-08）；具体模型实现期按基准定。执行方式按给什么工具（`记录/读写权限.md`）。

## 状态整理

记录的定义、两层、两型输出、阶段类型与三锁见 `记录/状态记录.md`；本节只管怎么跑。

| 项 | 内容 |
| --- | --- |
| 读 | 事件记录里与诊断**不同的字段**：时间间隔、中断点、求助频率、放弃点、状态自述、回复里的状态线索；会话事实（节奏起点、时长）；自己的底层记录；授权外部信息；现实约束通道（预留）。字段怎么取、上下文怎么组织：实现期（N-04） |
| 不读 | 学习对话里的诊断与模型分析、守卫判定、学过的记录（知识结论一概不读） |
| 整理什么（只动上层） | ① 过期：时间范围过了的从“当前”拿掉，底层留着 ② 阶段判断：跨几次会话看走势，判阶段类型、写所依据的时间跨度 ③ 并存标注：自述与观察对不上，两条都留、标冲突 ④ 重算：上层可整个重算 |
| 不做 | 把多次记录合并成长期特征 |
| 阶段判断怎么判 | 读会话事实与底层记录，按各类型声明的回看窗口取事实（窗口见 `记录/状态记录.md`「阶段类型」）；窗口内事实取全、多维分别判、留依据与反例；缺证据输出“不确定”，不选边。只出类型 + 时间跨度，不出动作 |
| 新记录从哪来 | 本次会话事件记录里的状态线索，按上列字段提取成底层新条目（每条带来源、时间范围、行号） |

## 教法记录整理

记录的定义见 `记录/教法记录与教学工具.md`；本节只管怎么跑。

| 项 | 内容 |
| --- | --- |
| 读 | 本次学习的事件记录：每轮读了哪份教学工具、用了什么强度（从事件记录取，不靠模型自报）、学习者之后的表现与诊断；守卫判定（合上了才有）；单子；状态记录（含“策略造成的状态”标注）；该学习者已有的教法记录；之后各次学习里诊断的变化 |
| 做什么 | 整理这个学习者在什么教法、什么强度下有反应；靠使用记录与之后是否判合上的对照来比较 |
| 先查自身 | 读到带“策略造成”标注的状态，先查教法本身是否为成因（`记录/状态记录.md`「边界」） |
| 不做 | 不单独核对“读了是否照着用”（B9）；不重做诊断；不下发策略与强度；不写进学过的记录；单次不证因果、不形成固定学习风格 |

## 阈值概念跨次判断

10-18 第 3 条：“哪个是阈值概念”不再由知识结构标记、也不存，用时由模型现场判断。剩下的是这个跨次读数：

| 项 | 内容 |
| --- | --- |
| 回答 | 某个概念跨了几次学习仍没过，是不是质变前兆 |
| 为什么要跨次 | 要看多次已结束的学习；单次学习对话只读与当前目标有关的，看不到 |
| 输入 | 学过的记录（单子、守卫判定、事件记录里的诊断），按概念检索历次学习；不新开通道 |
| 是不是阈值概念 | 判断时由模型现场判，不读存下的标记（没有标记） |
| 输出三锁 | ① 只出“该概念的跨次卡点事实 + 是否属质变前兆”与时间跨度，不出能力评级 ② 只给读数、不给动作（动作在学习对话：调强度不改道） ③ 不与状态阶段判断合成单一“学习压力”量 |
| 谁读 | 学习对话（定本次强度）、导航（各读两个读数，在自己范围内行动：导航不改道而学习对话降载并非不一致——路线不动、本轮减压） |
| 何时跑、结果存不存 | 待定：原设计写“待写”；第 3 条后，是在后台跑完把读数留着，还是由学习对话 / 导航用时现场判，未定 |

## 阈值概念停滞与习惯低谷不合并

两者都属预期内下降、都不该改道，但按级别分开，不抽象成共同概念，避免会话内的判断影响会话外的改道决定。

| | 阈值概念停滞 | 习惯低谷 |
| --- | --- | --- |
| 哪一侧 | 知识侧、会话内 | 状态侧、会话外 |
| 谁看出 | 学习对话现场判断（跨次读数见上） | 状态整理的阶段判断 |
| 怎么应对 | 学习对话内调强度：换切入角、降信息量、加小步验证、加密小反馈；不动路线（改道归导航） | 经状态记录交导航：不改道、不加量（改道会重置计时） |
| 在卡点上 | 作为质变前兆的可能解释之一，不默认按普通错误归因 | — |

加压 / 减压的切换是多输入判断（诊断、阈值概念跨次读数、状态阶段读数），具体组合待定。
