# 教法记录与教学工具

> 状态：已决（10-16 定稿：教学工具作沙盒里的可读资料、强度由学习对话自己定、转为了解学习者）；标“候选 / 第二梯队 / 待定”的除外。
> 原来对应：原 M10（`docs/撤下原文/模块时期/模块需求设计/模块审查单/M10-教学策略系统.md`）；`docs/撤下原文/模块时期/Harness设计/03-运行设计.md`「闭环对话」教学工具表、「跨闭环带什么」教法行；M03「边界」练习形式类教学工具；总览 M10 节。

## 定位

| 项 | 内容 |
| --- | --- |
| 回答 | **这个学习者在什么教法、什么强度下有反应** |
| 怎么做 | 不在一次学习（原称闭环）内下发策略：学习对话据诊断与状态自己选教法、定强度；这里事后读记录，了解这个学习者、把教法定制到他身上（10-16，由“提供教法”转为“了解 / 定制到这个学习者”） |
| 不做 | 不判断掌握、不判合上；不决定目标、分叉、收束、返回或跨次路线；不重做诊断 |
| 两样东西 | 教学工具（通用、可读资料）· 教法记录（这个学习者的） |

## 学习者导向的原则

| 原则 | 内容 |
| --- | --- |
| 为谁服务 | 学习者自己形成理解、结构、逻辑链、独立调用和迁移；不以更快给答案或更像教师讲授为目标 |
| 有限视角 | 从学习者已表现出的理解位置出发、不过早给完整答案（学习对话的教学原则，`会话/学习对话.md`）；定强度和提示条件时遵守。“诊断路径”与“最小推动”拆开：诊断看缺口，学习对话选推动，以学习者视角表达 |
| 活动原则 | 学习者完成关键思考、独立产出并暴露过程 |
| 讲还是练 | “缺输入还是缺练习”是学习对话基于诊断作的判断；诊断只说缺口和证据，不指定讲还是练；输入与练习不可互替 |

## 教学工具（原教法资料 / 通用策略知识层）

| 项 | 内容 |
| --- | --- |
| 是什么 | 预先录入的策略：解决什么问题、机制、适用条件、限制、理论来源；理论存在 ≠ 已证实有效 |
| 含哪些 | 某个情形下可选的教法，例如：引出证据的方法（换情境、预测、对比、找错、反例、解释为什么不行等，可组合），使学习者被讲过之后仍能给出独立证据（证据分级见 `会话/学习对话.md`）；练习形式类（题型、练习生成方法） |
| 放哪 | **不常驻提示词、不装进学习对话**，作为沙盒里的可读资料，模型需要时自己查（以后模型可能内化教法，只需提醒激活）；原型现有 10 份原样放进沙盒 |
| 名字 | 每份须有可识别、可比较的名字，不能退化成临时提示词 |
| 来源 | 非必须、可个性化；预留开放市场：本项目自己出的 + 第三方，不限内置几份；本项目自己出的，效果要靠本项目实验确认 |
| 不写成 | 固定流程：每份写“这种情形下可以这样做”，用不用、怎么组合由学习对话定 |
| 证据边界 | Anthropic 官方数据极薄（只有描述优化 5/6 一条）、无教学类任务；未在本项目实验（`docs/agent框架学习/09-Claude的skill与memory机制.md`） |

## 用了什么：程序照记

| 项 | 内容 |
| --- | --- |
| 用了哪份、什么强度 | 哪一轮读了哪份教学工具、用了什么强度，由程序当场记进事件记录（`记录/对话与事件记录.md`）；不靠模型在记录里自报 |
| 可比较 | 靠使用记录与之后是否判合上的对照 |
| 读了 ≠ 照着用了 | 不单独核对（B9）：守卫只判合没合上，教法管不管用由教法记录整理事后派生 |
| 策略理由与可见 | 每轮的教法、强度、依据、状态条件和主要取舍留在事件记录，供教学界面解释、学习复盘和产品审查；默认展示方式以后定（第二梯队） |

## 强度由学习对话自己定（10-16）

| 项 | 内容 |
| --- | --- |
| 谁定 | 学习对话据诊断事实、非知识状态、现实条件和当前目标，自己选教法、定**本次的强度坡度**：信息量、提示强度、挑战程度、分解粒度、节奏；可调外部数据来判断。信息量的高端是成段讲授（`会话/学习对话.md`） |
| 程序做什么 | 照记每轮用了什么强度；教法记录整理事后读记录整理，不下发 |
| 合上标准不可下调 | 是否合上由守卫判（`会话/守卫.md`）；慢慢施压要的是本次坡度，不是拆掉门槛 |
| 改新点与子句 | 须经导航决定（`会话/导航.md`），不归强度 |
| 叫法 | 这些是学习策略参数，不称方向或分叉守卫 |

## 教法记录（原个人策略过程与效果层）

| 项 | 内容 |
| --- | --- |
| 记什么 | 这个学习者在什么一次学习、表现和状态条件下用过什么教法、什么强度，以及之后表现的变化和证据 |
| 谁写 | 后台整理里的教法记录整理（`会话/后台整理.md`），事后读事件记录与守卫判定整理 |
| 谁读 | 下一次学习对话需要时在沙盒里查 |
| 不写进 | 学过的记录（`记录/学过的记录.md`）；教法记录独立保存 |
| 不证明 | 单次记录不证明因果，不形成固定学习风格 |
| 学习者表达的教学偏好 | 目前不考虑（10-06）；原文 `docs/暂缓设计/M10-学习者教学偏好.md` |

## 边界

| 对象 | 规则 |
| --- | --- |
| 旧动作空间 | 回答、反问、出题、推进、拦截、补资料（六种动作、八组动作空间）只是历史，不限制教法或活动类型；不预设固定调用顺序 |
| 状态 | 压力、疲劳、负荷、注意力、现实时间等不是这里诊断或保存的对象，归状态记录（`记录/状态记录.md`）；承载读数学习对话可直接用，解释候选以诊断里“已评估的状态候选”为准，不自行判真假 |
| 策略造成的状态 | 自查义务见 `记录/状态记录.md`「边界」；这里不向状态记录写入策略决定 |
| 状态阶段类型 | 疲劳退化 → 学习对话降载；阈值型动力低 → 改高频小反馈；习惯低谷与堆积型下滑主要由导航处理；不重判阶段类型 |
| 阈值概念 | 是不是阈值概念用时由模型现场判断、不存（10-18 第 3 条）；停滞时调强度不改道，与习惯低谷不合并；跨次读数见 `会话/后台整理.md` |
| 诊断 | 诊断提供当前理解、卡点、替代解释、证据限制和验证需要，不给教学建议；这里不重复诊断或合上判断；守卫不转给这里（守卫需要整次学习的证据链） |
| 改线 | 要改目标、补前置、搁置或重规划时，诊断向导航提供依据，导航决定，程序落实；不经这里 |
| 学过的记录 | 知识历史先由学习对话的诊断与当前证据合成后才影响教法 |
| 导航 | 分别位于一次学习之外和事后，有必要的信息交流；交换什么后续设计再定 |
| 不进需求 | 固定学历阶段、固定分数阈值、固定策略顺序、“策略一定直接产生某效果” |
| 追溯 | 策略理由、使用记录和之后的判断要可追溯；日志实现不归这里 |
