## 1 定位

| 项 | 内容 |
| --- | --- |
| 前提 | 模型权重不变、每次调用从零开始、不会持续学习 |
| Studium 做什么 | 在学习这件跨几个月的长事上，管好模型每一刻的输入和输出：这一刻给它哪些历史、它产出的哪些要存下来、下次再给 |
| 分工 | 知识本身交给模型；“这个人走到哪了”交给记录 |
| 结构 | 按智能辅导系统（ITS）的分工构建（见 §6 原则 1）；每个会话都是 agent：自己决定查什么、查几次、何时完成，不按“装配一次材料、调用一次模型” |
| 核心挑战 | 上下文组合：给模型什么事实、什么时候给、给谁看；落在开场给什么、沙盒里放什么、中途推什么事实上 |
| 与编程 harness 的根本不同 | 见 §6 原则 7（交互契约） |

## 2 一次学习

一次学习 = 一个学习对话：从学习者已有的认识出发，把一块新东西接上去，不是学成孤立的一块（`../学习理论/已有认识与概念转变/README.md` 取舍表）。主对话开，模型自己读记录、判断从哪接；提示词现在试验“围绕一个他答不上、又在乎的问题”。

| 项 | 现在 |
| --- | --- |
| 上下文 | 一个对话一份，只追加，可以跨天 |
| 看懂 ≠ 理解 | 讲、问、练都是手段，由模型组合；提问是为了让学习者想清楚、用起来，不为取证（`../学习理论/最小学习单元理论.md`） |
| 接没接上 | 模型读对话原文判断，不用条目清单或公式 |
| 出发点不同，理解不同 | 同一个东西从不同已有认识学，理解不一样；所以留下对话原文，不只记“会了” |
| 结束 | 模型和学习者定；结束只是收起，学习者再说话就重开 |
| 超出这次的事 | 请主对话另开一个对话，这次照样开着 |
| 方向 | 学这个能做什么、往哪走，在学习对话里由模型判断何时谈 |
| 跨次判断 | 学到哪、忘了多少、缺什么前置、下一段走哪：撤导航后放在学习对话开头由模型读记录做，没谈完（`任务线路.md` #83、#104） |
| 不存的 | 知识点之间的关系、阈值概念、混淆等，用时现场判断，不存成结构 |

资料不给模型补知识；书默认不导入，学习者导入了资料时资料也定范围（`记录/资料.md`）。

## 3 确定的与不确定的

| 部分 | 是什么 | 来自 | 怎么处理 |
| --- | --- | --- | --- |
| 起点 | 学习者现在有什么 | 以往对话原文、跨次记录；隔久了会忘，原文只说明当时说过什么 | 存事实，用时判断 |
| 终点 | 想学会、想拿来做什么 | 学习者说的、学习对话里谈的 | 存学习者的原话 |
| 中间 | 走哪条路 | — | 不确定，不存，边走边定 |

## 4 读记录：先看索引，要用再读原文

读什么看用处和会不会污染判断，不按“密度”分。跨一次学习以原文为准（10-31）。

| 规矩 | 内容 |
| --- | --- |
| 有什么 | 跨次记录（程序从各对话记下的事实现列，当索引用）；开场附的最近一次整份原文；沙盒里全部以往对话原文 |
| 怎么读 | 模型用通用的读、搜工具自己取；索引只是指针，要下判断就读原文 |
| 不另造 | 不做摘要层、不另写总结：多一份总结就多一个二手版本，漏了或偏了会一路传下去 |

**证据引用按行号**（原 00 原则 8）：

| 项 | 内容 |
| --- | --- |
| 印行号 | 程序把事件记录里的对话交给模型时每行前印行号（含中途推来的消息） |
| 只抄行号 | 模型在工具和记录里引用只写行号或行号范围，不自己数、不复述原文；原话由程序按行号取出。学习者的页面上没有行号，跟学习者说话时用内容指代 |
| 截图 | 在原文里单独占一行（如“[截图 3]”） |
| 指回原文 | 记录保留指回原文的行号；原文不删；判断学习者会什么时读原文 |
| 压缩后 | 学习对话的上下文太长被压缩后，要看原话时模型在沙盒里按行号读回 |
| 依据 | 这是模型自身的读写习惯，做法同 Claude Code 读文件，与编程 / 学习无关；只在 Claude 上有佐证，接入其他厂商模型时顺带测 |

## 5 设计取向：做模型进步替代不了的部分

模型能力持续变强（表达、教学法知识、学科知识、推理），只为弥补模型能力不足而设的设计，价值随模型进步下降。投入重心放在模型再强也给不了的部分：

| # | 模型给不了的 | 落在 |
| --- | --- | --- |
| 1 | 跨时间的记忆与证据：这个人何时、在什么条件下会了或卡住 | 学过的记录、对话与事件记录 |
| 2 | 来源与可核对性：结论依据哪份资料哪一处、学习者原话是什么 | 资料（`记录/资料.md`）、行号引用（§4） |
| 3 | 一次学习的结构与纪律：怎么开头、范围怎么收、什么时候结束（正在谈，#104） | 学习对话 |
| 4 | 判断的隔离：模型看到自己的结论就倾向认同，隔离设计不随能力过时 | §7 横切 4；跨一次学习以原文为准（§4）；状态与知识单向 |
| 5 | 产品立场：不贴标签、产出可见、非医疗 | §7 横切 5；§9 不做 |

判断标准：只替模型补能力的（如为“表达更好”单拆一块、为让模型懂学科而建完整知识图谱），随模型进步做薄或合并；属上表五项的，做厚。职责不等于独立会话：独立会话只用在必须隔离的地方（§6 原则 2）。

## 6 技术原则

| # | 原则 | 内容 |
| --- | --- | --- |
| 1 | ITS 双循环 + agent | 外层循环（选下一次学习）现在没有单独的会话，撤导航后放在学习对话开头做（`任务线路.md` #83）；内层循环（每轮一次，分析 / 教 / 练）= 学习对话，分析学习者与教学在一个会话、一个主循环里，不按职责分循环。领域知识交给模型 + 资料；学习者这边 = 以往对话原文 + 跨次记录。上下文“连续追加 / 重新装配”的边界就是大小循环的边界；一次学习内的层次以后可能再细分（未实验）。借 ITS 的分工，不照搬它的控制立场，也不只看 ITS。**学习者的决定不是直接指挥模型**：即使学习者拍板的事，模型也站在第三方视角分析学习者为什么这样选（与编程 agent 照指令执行不同；`../agent框架学习/02-pi与omp笔记.md` 1.2 底层逻辑③）。学习者决策的边界：未定 |
| 2 | 会话之间由程序接线，会话内由模型自主 | 每个会话是一个 agent（带工具、自己决定查什么、何时完成）；会话只在必须隔离处分开（会话清单见 `01-流程.md`）；没有身份设定，会话之间不互相对话，只经记录与程序推的事实。**写权限**：学习对话靠沙盒、其他会话暂仍按给什么工具卡，不靠模型自觉（怎么卡、权限表见 `记录/读写权限.md`「执行方式」）。读什么由模型决定：模型知道自己缺什么时自己取更准；它不知道自己不知道的，由程序在对的时机推（`../agent框架学习/02-pi与omp笔记.md` 2.3、3.1）。结束照讨论串，由模型或学习者结束。调用经统一接口，与模型厂商无关 |
| 3 | 程序只管不能交给模型的事 | 沙盒怎么划（学习对话）/ 给什么工具（其他会话）、开场给什么、中途推什么事实、存盘，由程序做。开哪个对话由主对话判断；结束由模型和学习者定 |
| 4 | 核心与界面分开 | 会话、沙盒与工具、存盘都在核心里，核心不绑界面；界面是外壳，参照 Claude 桌面版（主对话 + 任务对话，能显示公式与原件截图）。不自写一次学习内的循环，用可替换的通用框架（pi 只作参考），挑框架看入选条件（`会话/学习对话.md`）与社区活跃度（发版频率、问题响应、有无更新的替代品）；第一版选型见 `实现选型.md` |
| 5 | 架构 / 补丁分界 | 判断法：假设模型完美，这一条还需要吗——需要的（数据归属、流程控制、隔离、产品规则）进架构；不需要的是补丁，只放提示词并注明来由（哪次运行引出），模型变强时删。隔离粒度按“信息是否不同 / 是否自我确认”定，不按职责逐个隔离：同信息的职责合在一个会话；“自己教、自己判”的偏不另设会话隔离，跨一次学习以原文为准（§4），读原文的一方按证据标准读（`记录/学过的记录.md`「读原文时什么算证据」；10-31）；读范围的隔离见 `记录/读写权限.md` |
| 6 | 测试用模型 | 各会话用当下最强模型，免得把模型不足误读成设计问题、诱发过度设计；模拟学习者不属于架构，可用便宜模型。实验只做需要确认的 |
| 7 | 交互契约从学习出发自定 | 编程里模型做事、人审阅，成功 = 产物完成；学习里人必须做事，成功 = 学习者脑中的变化，稀缺资源是学习者的注意力（`../学习理论/蔡格尼克效应与认知资源耗散.md`）。照搬编程 agent 会把它的契约（替用户做完、一次说完）一起搬进来。框架从原理出发组合，不拟合 Claude Code。一次学习内**初始提示只写清目标**，怎么做交给模型；程序只保证三项：**何时停**（模型和学习者定）、**记什么**（事件记录由程序存）、**什么算进展**（只认学习者自己说的、做的，程序核对引用的行；见 `记录/学过的记录.md`「读原文时什么算证据」） |
| 8 | 证据引用 | 见 §4 |

## 7 横切原则（所有用到模型的地方共同遵守）

| # | 原则 | 内容 |
| --- | --- | --- |
| 1 | 静默降级必须可见 | 模型或服务能力等价时可以降级，但必须留痕并让学习者看得到；能力不等价时应当失败，不悄悄换一个模型继续（旧后端曾把 BGE-M3 静默退成 384 维 Hash embedding） |
| 2 | 内容外发披露 | 学习者的资料、笔记、作答和过程内容送往哪个服务必须可知；含各类对话用的模型，入口在项目页“记着什么” |
| 3 | 模型身份与版本可追溯 | 各处产出都能追溯到实际执行的模型与版本；各类记录都要记“由哪个模型、哪个版本得出”，记实际模型、不记可变别名（别名可被重新指向，会使整条证据失效；历史上 `studium-m1` 别名与实际模型不一致，使证据链失效） |
| 4 | 判据由系统自己判 | 不靠人工校准，也不靠模型自我辩论；主观判据（如状态记录区分预期内波动与真实恶化）改由准备好充足证据后的隔离式判断：① 每个判断在自己的专属上下文里做，互不污染 ② 判断前把证据取全，缺料就输出“证据不足”，不用推断填补 ③ 多个维度分别判、结果隔离（如知识侧与状态侧不合成一个量）④ 每次判断留下依据与反例，能回到原始事实核对。判断只承诺“依据可核对”，不承诺“结论可复现” |
| 5 | 产出可见 | 所有产出、来源和依据都在前端对学习者可见；可见同时是原则 4 的前提。可见不等于可裁决：学习者的异议按自述来源记录，不覆盖可观察事实 |

## 8 检验

| 项 | 标准 |
| --- | --- |
| 单次学习 | 教学不明显差于直接用同一个模型的通用对话；学习者导入了教材时，对照里也带上同一份 |
| 跨次 | 记得学到哪、会了什么、下一段走哪、连上了什么——明显更好 |
| 最终 | 以产品负责人真人试用为准 |

## 9 不做

| 不做 | 说明 |
| --- | --- |
| 存通用的知识点和关系 | 原“知识结构”整体取消 |
| 另造摘要 / 压缩层、另写总结或分析层 | 以原文为准，不另出第二份说法（§4） |
| 基于 DSH 定制 | 在 agent 方案调研中评价最差 |
| 多身份 / 角色扮演 agent、agent 之间对话协作 | §6 原则 2 |
| 一次学习内按职责排固定循环 | 分析、讲、练在一个学习对话里由模型自主；与一次学习之外怎么串无关 |
| 给学习者贴水平标签、人格类型、能力评级（D-08） | 只存有证据、有范围、可推翻的事实 |
| 医学或心理疾病诊断 | 声称超出学习范围的不诊断、不据以行动 |

## 10 功能分档

功能重要性不写死在页的结构里，各页内部用四档标：

| 档 | 含义 |
| --- | --- |
