## 1 定位

| 项 | 内容 |
| --- | --- |
| 前提 | 模型权重不变、每次调用从零开始、不会持续学习 |
| Studium 做什么 | 在学习这件跨几个月的长事上，管好模型每一刻的输入和输出：这一刻给它哪些历史、它产出的哪些要存下来、下次再给 |
| 分工 | 知识本身交给模型；“这个人走到哪了”交给记录 |
| 结构 | 按智能辅导系统（ITS）的分工构建（见 §6 原则 1）；每个会话都是 agent：自己决定查什么、查几次、何时完成，不按“装配一次材料、调用一次模型” |
| 核心挑战 | 上下文组合：给模型什么事实、什么时候给、给谁看；落在开场给什么、沙盒里放什么、中途推什么事实上 |
| 与编程 harness 的根本不同 | 见 §6 原则 7（交互契约） |

## 2 一次学习（原称闭环）

**一次学习 = 从学习者已会的几个出发点出发，学一个新点，靠这些出发点、沿导航选中的子句把它合上。** 描述的是已会的点与正在学的点之间的连线。新点与子句不存成通用结构，由导航现场说出、选中的写进单子（`会话/导航.md`、`记录/单子与路线.md`）。

| 项 | 含义 |
| --- | --- |
| 合上 | 一次学习结束 = 靠所选出发点、沿选中的子句把新点合上。怎么学：先理解（讲、推导，质量不低于教材），再用它做应用训练，训练中的思考反过来让理解完成；看懂 ≠ 理解（`../学习理论/最小学习单元理论.md`）。合上 = 新点经出发点接进学习者已有的认识（同化或顺应），不是学成孤立的一块（`../学习理论/已有认识与概念转变/README.md` 取舍表）；接没接上由模型读对话原文判断，不用条目清单或数学公式。什么时候算学完由学习对话与学习者定；收尾时守卫独立写下学习者实际表现出的理解，不把关（`会话/守卫.md`） |
| 出发点不同，理解不同 | 同一个点从不同出发点学（含同一物理点从不同数学工具出发），学到的理解不一样；所以学过的记录留下出发点、新点、所走的子句（单子）和学习者实际表现出的理解（守卫判定），不只记“会了” |
| 目标分三层 | ① 方向目标：靠畅谈确认，模型辅助补细节与调研（`记录/方向目标.md`）② 几次学习之间：导航决定方向、节奏、当下能开多少新点 ③ 单次学习的目标：比较固定，沿选中的子句把新点合上；守卫对照的就是这条子句（出发点 + 预期理解）；导航只选、不另定深度，要学得更深就另开一次学习走更抽象的子句（B11） |
| 点按定义拆 | 现场判断时的原则：同一对象的不同定义 / 刻画（如 ln 的积分定义与 eˣ 的反函数定义），学习者可能只会其一的，算不同的点，靠子句相连，不用“点的面”区分；新旧真冲突属教学层面处理 |
| 阶段 | 阶段越高，出发点越抽象、所走的子句越抽象、嵌套越深；单次学习仍一次坐下来能走完，拖长由导航干预。待定：“随阶段增大”只有间接依据 |

**由定义推出**（先有定义，后有这些设计）：

| 范围 | 做法 |
| --- | --- |
| 一次学习之内 | 主任务是分析学习者，据此决定下一步，沿出发点 → 新点进行：该讲就成段讲（质量不低于教材），该练就练，学习者已会的就往前走；前置缺了在过程中发现、记下，不开场考前置；提问和出题是为了让学习者想清楚、用起来，不为取证（`会话/学习对话.md`） |
| 几次学习之间 | 导航给每次学习开单子（新点 + 选中的子句 + 路线动作），定方向与节奏：选对这位学习者有分量的点；出发点缺得多就先学出发点；同领域的几次学习之间有共享部分，跨领域做对比。学习者钻研出的新方向成为下一次学习的候选，由导航在方向目标与学习者兴趣之间控制方向（主线 / 分叉 / 搁置）（`会话/导航.md`） |
| 用时现场判断、不存 | 点与子句、阈值概念、混淆 / 对比 / 同级类比、簇、知识边缘：都由模型用时现场判断，不存成结构；学习者实际混了什么在对话原文里 |

教材 = 作者排定的一条线性学习路线；多本教材是多条路线；导航排顺序时参考（`会话/导航.md`）。

## 4 分层：按信息密度读记录

分层 = 把各自产生的记录按信息密度排开，从上往下读；上层答得了就停，答不了再往下读一层。不另造摘要 / 压缩层。

| 层 | 记录 | 量级 |
| --- | --- | --- |
| 上 | 单子（`记录/单子与路线.md`） | 一两百 token |
| 中 | 守卫判定（`记录/学过的记录.md`） | 几百 |
| 下 | 学习对话的对话原文（`记录/对话与事件记录.md`） | 几千到几万 |

- 没合上就结束的那次学习，上层是什么见 `记录/单子与路线.md`。
- 读的人要细节时怎么往下找：导航的做法见 `会话/导航.md`（检索子代理）。

**证据引用按行号**（与分层配套，原 00 原则 8）：

| 项 | 内容 |
| --- | --- |
| 印行号 | 程序把事件记录里的对话交给模型时每行前印行号（含中途推来的消息） |
| 只抄行号 | 模型引用只写行号或行号范围，不自己数、不复述原文；原话由程序按行号取出，给守卫核对、给界面跳转高亮 |
| 截图 | 在原文里单独占一行（如“[截图 3]”） |
| 每层指回下层 | 上层记录保留指回下层的行号；原文不删；必须对着原话的判断（守卫）读原文 |
| 压缩后 | 学习对话的上下文太长被压缩后，要看原话时模型在沙盒里按行号读回 |
| 依据 | 这是模型自身的读写习惯，做法同 Claude Code 读文件，与编程 / 学习无关；只在 Claude 上有佐证，接入其他厂商模型时顺带测 |

## 5 设计取向：做模型进步替代不了的部分

模型能力持续变强（表达、教学法知识、学科知识、推理），只为弥补模型能力不足而设的设计，价值随模型进步下降。投入重心放在模型再强也给不了的部分：

| # | 模型给不了的 | 落在 |
| --- | --- | --- |
| 1 | 跨时间的记忆与证据：这个人何时、在什么条件下会了或卡住 | 学过的记录、对话与事件记录、守卫判定 |
| 2 | 来源与可核对性：结论依据哪份资料哪一处、学习者原话是什么 | 资料（`记录/资料.md`）、行号引用（§4） |
| 3 | 一次学习的结构与纪律：每次从哪些出发点学哪个新点、守卫、负债与搁置 | 导航、守卫 |
| 4 | 判断的隔离：模型看到自己的结论就倾向认同，隔离设计不随能力过时 | §7 横切 4；守卫独立；状态与知识单向 |
| 5 | 产品立场：不贴标签、产出可见、非医疗 | §7 横切 5；§9 不做 |

判断标准：只替模型补能力的（如为“表达更好”单拆一块、为让模型懂学科而建完整知识图谱），随模型进步做薄或合并；属上表五项的，做厚。职责不等于独立会话：独立会话只用在必须隔离的地方（§6 原则 2）。

## 6 技术原则

| # | 原则 | 内容 |
| --- | --- | --- |
| 1 | ITS 双循环 + agent | 外层循环（每次学习一次，选下一次学习）= 导航；内层循环（每轮一次，分析 / 教 / 练）= 学习对话，分析学习者与教学在一个会话、一个主循环里，不按职责分循环。领域知识交给模型 + 资料；学习者这边 = 学过的记录 + 状态记录。上下文“连续追加 / 重新装配”的边界就是大小循环的边界；一次学习内的层次以后可能再细分（未实验）。借 ITS 的分工，不照搬它的控制立场，也不只看 ITS。**学习者的决定不是直接指挥模型**：即使学习者拍板的事，模型也站在第三方视角分析学习者为什么这样选（与编程 agent 照指令执行不同；`../agent框架学习/02-pi与omp笔记.md` 1.2 底层逻辑③）。学习者决策的边界：未定 |
| 2 | 会话之间由程序接线，会话内由模型自主 | 每个会话是一个 agent（带工具、自己决定查什么、何时完成）；会话只在必须隔离处分开（会话清单见 `01-流程.md`）；没有身份设定，会话之间不互相对话，只经记录与程序推的事实。**写权限**：学习对话靠沙盒卡（能读写哪些数据、能否联网由程序在执行环境里写死，不靠模型自觉）；其他会话暂仍按给什么工具，每个只拿到写自己产出的工具；对话记录由程序追加，不做成模型工具（权限表见 `记录/读写权限.md`）。读什么由模型决定：模型知道自己缺什么时自己取更准；它不知道自己不知道的，由程序在对的时机推（`../agent框架学习/02-pi与omp笔记.md` 2.3、3.1）。收口经沙盒里的“申请收口”命令通知程序、交给 Studium 自有的守卫，换一次学习内的框架不换守卫（`01-流程.md`「收口」）。调用经统一接口，与模型厂商无关 |
| 3 | 程序只管不能交给模型的事 | 沙盒怎么划（学习对话）/ 给什么工具（其他会话）、开场给什么、中途推什么事实、收口时调守卫、存盘，由程序做。开哪个任务对话由主对话按分类决定；收口由学习对话或学习者申请；一次学习之外按事件排（`01-流程.md`） |
| 4 | 核心与界面分开 | 会话、沙盒与工具、收口、存盘都在核心里，核心不绑界面；界面是外壳，参照 Claude 桌面版（主对话 + 任务对话，能显示公式与原件截图）。不自写一次学习内的循环，用可替换的通用框架（pi 只作参考），挑框架看入选条件（`会话/学习对话.md`）与社区活跃度（发版频率、问题响应、有无更新的替代品）；第一版选型见 `实现选型.md` |
| 5 | 架构 / 补丁分界 | 判断法：假设模型完美，这一条还需要吗——需要的（数据归属、流程控制、隔离、产品规则）进架构；不需要的是补丁，只放提示词并注明来由（哪次运行引出），模型变强时删。隔离粒度按“信息是否不同 / 是否自我确认”定，不按职责逐个隔离：同信息的职责合在一个会话，守卫独立核对（不读模型的分析）；读范围的隔离见 `记录/读写权限.md` |
| 6 | 测试用模型 | 各会话用当下最强模型，免得把模型不足误读成设计问题、诱发过度设计；模拟学习者不属于架构，可用便宜模型。实验只做需要确认的 |
| 7 | 交互契约从学习出发自定 | 编程里模型做事、人审阅，成功 = 产物完成；学习里人必须做事，成功 = 学习者脑中的变化，稀缺资源是学习者的注意力（`../学习理论/蔡格尼克效应与认知资源耗散.md`）。照搬编程 agent 会把它的契约（替用户做完、一次说完）一起搬进来。框架从原理出发组合，不拟合 Claude Code。一次学习内**初始提示只写清目标**，怎么做交给模型；程序只保证三项：**何时停**（收口经守卫判）、**记什么**（事件记录由程序存）、**什么算进展**（守卫只认学习者自己说的、做的；程序核对守卫引用的行号落在学习者的行上，指到模型讲解的行不算证据） |
| 8 | 证据引用 | 见 §4 |

## 7 横切原则（所有用到模型的地方共同遵守）

| # | 原则 | 内容 |
| --- | --- | --- |
| 1 | 静默降级必须可见 | 模型或服务能力等价时可以降级，但必须留痕并让学习者看得到；能力不等价时应当失败，不悄悄换一个模型继续（旧后端曾把 BGE-M3 静默退成 384 维 Hash embedding） |
| 2 | 内容外发披露 | 学习者的资料、笔记、作答和过程内容送往哪个服务必须可知 |
| 3 | 模型身份与版本可追溯 | 各处产出都能追溯到实际执行的模型与版本；守卫判定等结论尤其要记“由哪个模型、哪个版本得出”，记实际模型、不记可变别名（历史上 `studium-m1` 别名与实际模型不一致，使证据链失效） |
| 4 | 判据由系统自己判 | 不靠人工校准，也不靠模型自我辩论；主观判据（如状态记录区分预期内波动与真实恶化）改由准备好充足证据后的隔离式判断：① 每个判断在自己的专属上下文里做，互不污染 ② 判断前把证据取全，缺料就输出“证据不足”，不用推断填补 ③ 多个维度分别判、结果隔离（如知识侧与状态侧不合成一个量）④ 每次判断留下依据与反例，能回到原始事实核对。判断只承诺“依据可核对”，不承诺“结论可复现” |
| 5 | 产出可见 | 所有产出、来源和依据都在前端对学习者可见；可见同时是原则 4 的前提。可见不等于可裁决：学习者的异议按自述来源记录，不覆盖可观察事实 |

## 8 检验

| 项 | 标准 |
| --- | --- |
| 单次学习 | 教学不明显差于“通用对话模型 + 同一份教材” |
| 跨次 | 记得学到哪、会了什么、下一段走哪、连上了什么——明显更好 |
| 最终 | 以产品负责人真人试用为准 |

## 9 不做

| 不做 | 说明 |
| --- | --- |
| 存通用的点和子句 | 原“知识结构”整体取消；“去个人化 → 候选审核 → 晋升进通用结构”整条通道取消（§2） |
| 另造摘要 / 压缩层、另写总结或分析层 | 每次学习只有一份结论性产物（守卫判定）（§4；`01-流程.md`） |
| 基于 DSH 定制 | 在 agent 方案调研中评价最差 |
| 多身份 / 角色扮演 agent、agent 之间对话协作 | §6 原则 2 |
| 一次学习内按职责排固定循环 | 分析、讲、练在一个学习对话里由模型自主；与一次学习之外怎么串无关 |
| 给学习者贴水平标签、人格类型、能力评级（D-08） | 只存有证据、有范围、可推翻的事实 |
| 医学或心理疾病诊断 | 声称超出学习范围的不诊断、不据以行动 |

## 10 功能分档

功能重要性不写死在页的结构里，各页内部用四档标：

| 档 | 含义 |

| 主干 | 缺了它，这项核心输出不成立 |
