# 模型基准

> 状态：现行（2026-10-06 建，#22）。**不作产品结论**；只记“同一输入下各模型做得怎样”，用来分清质量问题出在系统还是模型。
> 原始输出（含书的原文摘录）不进本仓库，放私有仓库 `studium-m08-data` 的 `bench/<日期-名字>/`；本目录只放方法、提示词指向与指标。

## 归因规则

| 现象 | 归到 | 处理 |
| --- | --- | --- |
| 强模型（现为 Opus 5.5）也错 | 系统（提示词、给的上下文、结构、核对程序） | 改系统 |
| 只有弱模型错 | 模型能力 | 不改系统，只记录（CLAUDE.md：外壳不为弱模型加复杂度） |
| 拿不准 | — | 改动后用强模型复跑同一小样本核对 |

- 交叉跑：弱模型除了处理自己的产出，还要处理**强模型的同一份输入**（例：审核 Opus 生成的清单），才能逐条对比。
- 先查核对程序：程序判错也算系统问题（例：2026-10-06 摘录核对没容掉公式写法，把真实摘录判成“找不到”）。

## 指标

| 指标 | 定义 |
| --- | --- |
| 摘录核对 | 逐字在标注行（±3 行）· 去掉空格 / `$` / 花括号 / 常见公式写法差后在标注行 · 大段相同（最长公共段 ≥ 60%）· 找不到；只有“找不到”算疑似编造，须人工看 |
| 判定分布 | 审核把子句判为书给的 / 部分 / 模型补的的条数 |
| 回扫 | 书有、清单没有的路线条数 |
| 点落位 | 生成的点在书里一致 / 不同 / 没有 |
| 用量 | 输入 / 输出 token、用时、请求数 |
