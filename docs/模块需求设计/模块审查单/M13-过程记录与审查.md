# M13 过程记录与审查

> **定位说明：暂缓作为一级产品模块审查。** 本文混合了跨模块事件日志、证据链、可观察性、版本记录等技术基础，以及学习复盘、数据查看和审查视图等产品能力。现阶段保留全文，不删除任何能力，但不再把“统一日志系统”预设为独立业务模块。后续在“上下文工程 + 图工程”设计中确定运行状态、检查点、事件和审查链怎样跨模块保存；学习者复盘、数据更正与导出等产品能力再决定归入 M01、各业务模块或独立视图。

### 模块解决的核心问题

让学习者和审查者能回答“这一轮发生了什么、系统依据了什么、作出了什么判断和修改、哪里失败或降级”，同时区分学习复盘、产品审查和开发调试，不默认暴露内部提示、原始响应或敏感数据。

### 输入、主要处理和输出

- 输入：M01 会话/路线事件，M02/M03 的互动与产出，M04 进行中诊断和闭环判断，M06/M07 资料处理与引用，M09 闭环级个人记录写入，M10 策略选择、强度条件和个人策略过程记录，跨模块上下文/工具使用，模型与服务状态及系统异常（原记为 M12，本轮已取消该模块，但状态与异常仍需被记录）。
- 主要处理：按时间和任务串联关键事件；保留资料来源、判断依据和状态变化；面向不同角色生成分级视图；记录异常、失败和降级；提供个人数据查看、导出、更正和清理入口。
- 输出：学习记录与复盘、证据/决策链、资料处理记录、异常与降级说明、审查视图、个人数据控制结果。

### 重复内容合并后的结论

- Transcript、Trace、Inspect、observability 和归档记录不是五个功能：合并为“过程事实 + 面向角色的分级呈现”。
- v0.1-v0.5 反复出现的资料、状态、诊断、守卫和回流记录合并为一条可审查证据/决策链。
- 档案分层文档主要提供权限、安全和成熟度证据，不应把冻结、分包、复现操作升为学习产品功能。
- 学习者复盘和开发调试共用事实来源，但视图与默认可见内容不同。

### 被后续资料覆盖的旧结论

- 右侧 Inspect/Trace 开发字段作为默认体验，被 v0.2 Transcript 可读视图覆盖；原始 JSON/提示内容仅显式深挖。
- v0.2 自身明确 Transcript 只是评估界面，不等于最终审计系统，也不证明策略已优化。
- streaming trace、审计级 provider 原始请求/响应、跨链审查都只是后续建议，不写成已确认功能。
- 历史 allowlist 路径、表字段、桌面打开方式和 trace 事件格式属于技术实现。

### 与其他模块的边界和信息流

- M01 保存并组织会话生命周期；M13 将关键过程变成可复盘/审查记录。两者不能因都保存消息而合并。
- M04 拥有进行中诊断和闭环判断，M09 拥有已结束闭环形成的个人知识，M10 拥有策略模型和当前策略条件；本文只记录它们的依据与变化，不代替业务判断。
- 后续上下文工程与图工程执行工具、交接和运行控制；本文记录实际使用和限制。（原文此处写“M12 提供模型”；本轮已取消 M12。本单为暂缓草稿，其余内容未随本轮改动。）
- M07 保留原始资料与引用位置；跨模块过程记录保存某次运行调用了哪些资料，记录副本不成为新的静态资料库。
