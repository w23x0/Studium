# M10 教学策略系统

### 模块解决的核心问题

Studium 的目标不是把系统做成替学习者讲授答案的“老师”，而是从学习者已经形成的理解和当前条件出发，帮助其通过合适的学习活动走向更高阶的理解、独立调用和思考。

M10 位于一个正在进行的学习闭环内。它接收 M04 对当前学习事实的诊断，以及学习者状态与条件信息，选择当前学习策略，并把策略目标、活动倾向和强度要求交给 M02/M03。M02/M03 再分别形成面向学习者的教学互动和练习活动。

M10 回答的是：**在当前诊断和学习条件下，学习者接下来需要以什么策略继续学习，以及活动应保持怎样的强度和条件。** 它不判断学习者是否掌握，不拥有闭环守卫，不决定学习目标、分叉、收束、返回或跨会话路线。

M04 与 M10 都作用于同一闭环，但职责前后明确：M04 只形成诊断事实、替代解释、证据限制和验证需要，不给教学建议；M10 不重新诊断，而是依据这些信息制定策略。两者未来在运行层是否合并，不改变当前产品职责的划分。

### 输入、主要处理和输出

- 输入：
  - M10 自身的策略模型：预先录入的通用策略知识，以及该学习者过去策略使用与 M04 后续判断形成的个人策略过程记录；
  - M01 当前会话承载的闭环目标和位置，以及 M05 已为该闭环确定的目标范围、验收范围和必要路线条件；
  - M04 的当前诊断、替代解释、证据限制、未满足项和需要验证的内容；
  - M15 学习者状态与条件提供的非知识类信息。它可同时输入 M04、M10 和 M05：M04 用于解释当前表现，M10 用于选择策略和强度，M05 用于跨会话路线；
  - 学习者在当前会话主动提出的现实需求和限制。
- 主要处理：根据当前诊断、学习者状态和策略模型，确定当前学习活动更应偏向补充输入、引导建构、独立练习、变式验证、反馈修正或其他策略；向 M02/M03 给出策略目标、活动条件以及信息量、提示强度、挑战程度、节奏等强度要求；接收 M04 在后续活动中形成的新判断，更新个人策略过程记录。
- 输出：当前策略选择、选择理由、活动倾向、策略目标、强度与条件要求，以及可供 M02/M03 执行的教学/练习指导。M10 不直接拥有最终面向学习者的讲解、追问或练习正文；M10 输出到 M02/M03 的具体粒度，留待 M02/M03 审查时共同确认。

### 学习者导向的策略原则

- M10 的策略应服务学习者自己形成理解、结构、逻辑链、独立调用和迁移，而不以更快给出答案或更像教师讲授为目标。
- “从学习者已经表现出的理解位置出发、不过早给出完整答案”是 M02 的有限视角教学原则，不由 M10 单独占有；M10 只可把它作为选择活动强度和提示条件时应遵守的总体约束。
- “学习者完成关键思考、独立产出并暴露过程”是 M03 的活动原则；M10 通过策略目标、提示和挑战要求调动 M03，而不替代 M03 组织或保存活动。
- “当前缺输入还是缺练习”是 M10 要基于 M04 诊断作出的策略结论。M04 只说明当前缺口和证据，不直接指定应该讲解还是练习。
- 用户可在会话中主动提出现实需求；用户级配置和自定义策略暂不作为默认功能，只保留为第二梯队候选。

### 重复内容合并后的结论

- 旧资料中的回答、反问、出题、推进、拦截、补资料，只是当时的教学动作空间；它们不能直接定义 M10。当前结论是 M10 决定学习策略和条件，M02/M03 分别形成教学互动与练习活动。
- 有限视角材料中的“诊断路径”和“最小推动”必须拆开：M04 形成诊断，M10 选择推动策略，M02 以学习者视角形成表达。M10 不能因为拥有策略而变成教师式讲授模块。
- 压力、疲劳、负荷、注意力、现实时间和其他非知识类条件不再作为 M10 自己诊断或保存的对象；它们属于 M15 学习者状态与条件，M10 只消费其信息。
- 输入/练习、结构理解、独立产出、提示和挑战不是同一模块的全部职责：M10 负责策略目标和强度，M02/M03 分别负责教学与练习活动，M04 负责判断其结果。
- M10 不包含方向守卫、分叉深度、收束、返回或重新规划。它们属于 M05 的跨闭环路线与 M04 的改线依据，不是教学策略模型。

### 被后续资料覆盖或需要降格的旧结论

- 早期五层顺序架构已被后续按需查询和回流的学习过程覆盖。M04 -> M10 表示产品职责上的判断与策略关系，不预设技术上的固定调用顺序。
- 总系统 v0.3 的六种动作，以及更早的八组动作空间，是历史方案，不能限制 M10 策略模型或 M02/M03 的活动类型。
- 旧 `dyn_strategy` 的“下一轮偏好”不可直接解释为稳定学习风格；当前只保留通用策略知识和带条件的个人策略过程记录。
- 旧学习者状态模型把知识、心理、负荷、生理、阶段和效能放进同一个对象。M09 已明确排除高频非知识状态，M10 也不应重新占有它们；M15 现在承担学习者状态与条件的独立边界。
- 固定学历阶段、固定分数阈值、固定策略顺序和“策略一定直接产生某效果”的表达不进入当前需求。

### 与其他模块的边界和信息流

- **M04 -> M10**：M04 提供当前理解、卡点、替代解释、证据限制和验证需要；M10 依据这些事实选择策略。M04 不提供教学建议，M10 不重复诊断或闭环判断。闭环守卫不因 M04 的日常注意力集中在每轮回答上而转给 M10：守卫需要闭环级证据链（M04 持有跨轮诊断与证据），M10 只拿到诊断摘要，让 M10 守卫须重复传输完整证据，属冗余。M04 的守卫是闭环结束点的一次专门汇总动作，与其日常逐轮诊断不冲突。
- **M15 -> M10/M05（主要消费者）与 M15 -> M04（裁决）**：同一状态信息可分别用于调整会话内策略、规划跨会话路线和解释表现。三个模块使用同一信息不等于职责重复；M15 拥有状态对象、范围和时间有效性，三个消费者不反向拥有状态语义。M15 的输出分两型：**承载读数**（当前负荷、可挂核心任务数、可承载连续时长、环境限制）与知识诊断正交，M10 可直接使用；**解释候选**（本次下降的状态解释）与 M04 的诊断竞争，M10 须以 M04 输出中“已评估的状态候选”一段为准，不自行判断候选真假。
- **M10 对状态成因的自查义务**：当前策略本身会制造状态——逐题评判会抬高威胁感，稀释审判频率会降低它。M15 记录这类状态时会标注它出现在某一反馈模式生效之后。M10 读到带此标注的状态时，**必须先检查自身策略是否为成因**，不得直接当作学习者固有条件。否则会出现 M10 依据自己制造的后果调整策略：因威胁感上升而降低难度，而真正成因是逐题评判，正确动作是改为阶段性验收。M10 不向 M15 写入策略决定，该标注由 M02/M03 的可观察事实产生。
- **M15 的状态阶段类型**：M15 的**状态阶段判断跨会话子模块**会给出下降所属阶段（习惯低谷、堆积型下滑、疲劳退化、阈值型动力低）及判断跨度，只给读数、不给动作。M10 侧的对应动作是疲劳退化降载、阈值型动力低改高频小反馈；习惯低谷与堆积型下滑主要由 M05 处理。M10 不重新判断阶段类型。
- **阈值概念停滞：调强度不改道。** 卡在阈值概念上是质变前兆，属预期内下降，M10 的动作是在会话内提高投入、加密小反馈，**不改路线**（改道归 M05，M10 无此权限）。它与习惯低谷刻意**不合并**为同一概念：阈值停滞是知识侧、会话内，走 M04 → M10；习惯低谷是状态侧、会话外，走 M15 → M05。分开是为避免会话内的判断经共用概念影响会话外的路线决定。
- **M04 的阈值概念跨闭环子模块 -> M10**：M04 侧有一个与 M15 状态阶段对称的子模块，输出“某阈值概念跨了多少闭环仍未过”的类型与时间跨度读数，同样只给读数不给动作、不与状态侧合成单一「学习压力」量。M10 与 M05 各读两个读数、在各自作用域内行动；出现 M05 不改道而 M10 降载并非不一致，正是预期结果：路线不动，本轮减压。
- **后续设计项：M10 在会话内的强度调节权限。** 长期卡在阈值概念上时，可能是 M05 规划误判难度过大或当前状态不好。倾向的边界是：M10 参考 M04 的分析与 M15 的状态读数后，可调节**本次会话内的强度坡度**（本轮节奏、信息量、分解粒度、挑战程度）；**达成标准与验收范围不可由 M10 下调**——它由 M04 闭环守卫按 M05 设定的验收范围判断。闭环目标本身的调整必须经 M05 决定、M01 落实。加压/减压的切换是多输入策略判断（M04 诊断、阈值概念跨闭环读数、M15 状态阶段读数），具体组合留到模块组合阶段一并设计。
- **M10 -> M02/M03**：M10 输出策略目标、活动倾向、信息量、提示强度、挑战程度、节奏和必要条件；M02/M03 负责最终的教学互动和练习活动。具体输出粒度以后共同确认。M02/M03 本轮已确认为**只执行不自定**：M02 不做“最小补足”式自主补齐，M03 不自定挑战程度升降；四项强度参数的所有权归 M10。
- **M08 -> M10**：阈值概念标记作为通用对象属性提供给 M10，用于强度参数取值（阈值概念处通常需要提高投入而不是加速通过）。M10 不判断学习者是否已跨过，该判断归 M04。
- **M04 -> M05 -> M01**：若 M04 判断当前闭环需要改变目标、补前置、搁置或重规划，M04 向 M05 提供依据；M05 作跨闭环路线决定，M01 落实会话结构。M10 不拥有这条链路。
- **M09 与 M10**：M09 保存已结束闭环形成的个人知识。知识相关历史通常先由 M04 与当前证据合成为诊断，再交给 M10；M10 的个人策略过程与效果记录独立保存，不写入 M09。
- **M05 与 M10**：M05 与 M10 分别位于闭环之外和闭环之内，存在必要的信息交流，但具体交换内容在后续实际设计中再确认，当前不作为 M10 功能或输出。
- **M13/后续联合设计**：策略理由、使用记录和 M04 后续判断需要可追溯，但日志、复盘、上下文组织和运行实现留到后续阶段。
