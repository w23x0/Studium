# M06 静态资源入库

### 核心问题

把书籍、讲义、论文、题集、网页、字幕等外部材料，转换为有来源、有结构、可定位、可检查且处理状态明确的系统资源；失败或不完整时不能进入 M07 伪装成可用资料。个人或人工编写的笔记不属于本模块，可直接进入 M07。

### 输入、主要处理与输出

- 输入：原始文件或外部材料、资料类型、来源与权利信息、目标项目/资料库归属、用户修正。
- 主要处理：登记来源和类型；提取正文与附件；识别书/章/节/段落/定义/证明/例题/练习等资料结构；形成转换内容与原文件间可联动的定位信息和内容类型候选；显示中间结果与异常；接受修正并重新处理。
- 输出：可进入 M07 的资源、结构、转换内容与原文件间的定位数据、来源/权利信息和处理状态。异常或待人工确认项不得作为可用资源交付。概念及关系只能作为 M08 的候选输入，不在 M06 确认为通用知识关系。

### 重复内容合并后的结论

- “五步流水线”“逐步展开”“失败停留”“按步重跑”“人工抽检”来自多份 PRD、原型和归档，合并为一个产品要求：处理过程必须可观察、可纠正、失败不伪装成功；不把历史五步顺序写死为需求。
- “资料类型、内容类型、章节层级、父子结构、原文位置”共同服务结构化与可追溯入库。转换内容与原文件之间必须保留可联动定位；它们仍是资料结构，不自动生成 M08 概念关系。
- LLM 生成标注、新类型或扩展字段的多种历史描述，合并为“系统可提出候选，原文不被改写，候选可复核”。不确认任何自动标注准确率。

### 被后续资料覆盖的旧结论

- `Learning-Agent-MVP-PRD-v1.md` 的“不做 RAG、整段资料直接放入上下文”被 2026-07-01 `开源前端重构与三模块设计转交文档.md` §1.3 明确推翻；检索与引用重新进入产品范围。
- `版本记录/.../资料层.md` v0.2 的固定质量评分、公式和阈值被文首 v0.3“只做管理+RAG，不做质量评分”覆盖。来源可靠性和异常提示仍有价值，但不能恢复成已确认综合评分。
- `知识库模块设计-v1.md` 的“五步”是产品概念链，归档证据说明旧后端真实时序不同；第三次重构只保留可见阶段、状态和重做能力，不继承步骤或顺序。
- Project、父子分块、多资料类型等在后期 PRD 中是设计提案，归档明确旧后端未实现；可作需求证据，不能写成已验证产品事实。

### 与其他模块的信息流

- M01/M07 -> M06：提供项目/资料库归属；M06 -> M07：交付已通过校核的资源、结构、来源、转换内容与原文件的联动定位数据和处理状态。个人或人工编写笔记可直接进入 M07。
- M06 -> M08：交付概念/方法候选及其来源片段，不直接确认关系。
- M06 的处理任务所需模型能力在本单“以后转技术方案”中一并转出。本轮已取消 M12，不再有单独的模型与服务模块承接；模型能力若发生降级替换，须遵守总览横切原则“静默降级必须可见”，M06 的处理状态与来源标记不得因换模型而失真。
- M06 -> M13：交付处理事件、人工修正和异常，供审查；M13 不替代用户侧状态与纠错。
- M06 -> M14：为知识产出物提供可定位的原始资料来源（经 M07）。
