# M06 静态资源入库

> 状态：已精简（2026-10-05，#24），原文见 `../撤下原文/审查单精简前/`。技术实现见 `../../Harness设计/03-运行设计.md`。

### 核心问题

把书籍、讲义、论文、题集、网页、字幕等外部材料，转换为有来源、有结构、可定位、可检查且处理状态明确的系统资源；失败或不完整时不能进入 M07 伪装成可用资料。个人或人工编写的笔记不属于本模块，可直接进入 M07。

### 功能

| 功能 | 产品结论 | 级别 |
| --- | --- | --- |
| 来源登记与资料类型 | 保存原始来源、作者/许可或可分享状态、资料类型及目标归属；不同类型允许有不同结构和定位方式。个人或人工编写笔记直接进入 M07，不走此处理流程。 | 主干 |
| 内容提取与原文保真 | 提取正文、公式、图片/附件等可学习内容；处理后的正文不能替换原文，并须保留转换内容位置到原文件位置的联动定位数据，使后续界面和 Agent 能回到同一原文依据。 | 主干 |
| 资料结构识别 | 识别章、节、段落及定义、动机、证明、例题、练习、综述等内容单元；书籍保留目录父子结构及章节关联，并形成可供后续调取的最小内容单元。深结构资料与浅结构资料不要求同一形态。资料结构不自动生成 M08 概念关系。 | 主干 |
| 处理过程与状态查看 | 用户能看到当前阶段、产物、待处理、成功和失败，不把资料处理做成黑盒：处理过程必须可观察、可纠正、失败不伪装成功；只保留可见阶段、状态和重做能力，不把历史“五步”顺序写死为需求。 | 主干 |
| 异常、校核与人工修正 | 明确缺页、定位失败、结构异常、公式/图片损坏、待确认类型；允许用户修正后重新处理，不静默跳过。存在这些未解决问题的资料不得进入 M07。 | 主干 |
| 内容预览与定位检查 | 入库前后可抽查正文、结构、内容类型和原文位置；生成性标注与原文分开呈现。不要求所有资料逐项人工确认。 | 第二梯队 |
| 多类型与批量入口 | 支持更多文件、网页、字幕及批量资料；各类型保持清晰的处理状态。批量不削弱逐份定位和失败可见性。 | 第二梯队 |
| 内容类型/扩展标注治理 | 系统可提出新内容类型或扩展标注，但须显示来源、待确认状态并允许接受/拒绝，不能静默改变正式分类；原文不被改写，候选可复核；不确认任何自动标注准确率。 | 第二梯队 |
| 处理成本与产物复盘 | 保存资料处理所产生的阶段结果，供错误复盘和质量检查；面向开发的详细日志交给 M13。详细成本和技术产物是否产品化需另审。 | 候选 |

### 输入输出

- 输入：原始文件或外部材料、资料类型、来源与权利信息、目标项目/资料库归属、用户修正。
- 主要处理：登记来源和类型；提取正文与附件；识别书/章/节/段落/定义/证明/例题/练习等资料结构；形成转换内容与原文件间可联动的定位信息和内容类型候选；显示中间结果与异常；接受修正并重新处理。
- 输出：可进入 M07 的资源、结构、转换内容与原文件间的定位数据、来源/权利信息和处理状态。异常或待人工确认项不得作为可用资源交付。概念及关系只能作为 M08 的候选输入，不在 M06 确认为通用知识关系。

### 边界

- 检索与引用在产品范围内（早期“不做 RAG、整段放入上下文”已推翻）。来源可靠性和异常提示有价值，但不恢复成综合质量评分。
- 后期 PRD 中的 Project、父子分块、多资料类型等是设计提案、旧后端未实现：可作需求证据，不能写成已验证产品事实。
- M01/M07 → M06：提供项目/资料库归属；M06 → M07：交付已通过校核的资源、结构、来源、转换内容与原文件的联动定位数据和处理状态。个人或人工编写笔记可直接进入 M07。
- M06 → M08：交付概念/方法候选及其来源片段，不直接确认关系。
- 模型能力若发生降级替换，须遵守总览横切原则“静默降级必须可见”，M06 的处理状态与来源标记不得因换模型而失真。
- M06 → M13：交付处理事件、人工修正和异常，供审查；M13 不替代用户侧状态与纠错。
- M06 → M14：为知识产出物提供可定位的原始资料来源（经 M07）。
