# M11 Agent 工具与上下文组织

> **定位说明：暂缓作为一级产品模块审查。** 本文覆盖的是各产品模块共同依赖的上下文选择、缓存、工具权限、类型化交接和运行路由，属于“上下文工程 + 图工程”的跨模块技术设计草稿，而不是独立学习产品职责。现阶段保留全文作为后续参考，不用它反向规定 M01-M10、M14、M15 的产品边界，也暂不设计统一汇总 Agent。应先完成各模块自己的职责、输入输出、数据归属和配套设计，再决定将本文拆入各模块技术方案，或重组为统一的上下文/图运行架构。单 Agent、多 Agent、图节点、边、回流、缓存和工具协议均不在当前产品审查中确定。

### 模块解决的核心问题

让学习 Agent 在当前任务中拿到恰当、可追溯且边界清楚的信息，并通过受控能力读取或更新其他模块，避免把全部资料、聊天和画像无差别塞入一次调用。

### 输入、主要处理和输出

- 输入：M01 当前会话/闭环目标/路线位置，图节点的能力请求，M07 静态资料，M08 通用知识，M09 已结束个人知识记录，跨模块过程记录，以及实现期确定的可用模型边界（原为 M12，本轮已取消）。
- 主要处理：确定本轮需要哪些上下文；选择、压缩并标明来源；向 Agent 提供只完成当前任务所需的受控工具；组织调用结果、权限拒绝和失败反馈。
- 输出：本轮上下文包、带来源的工具结果、可见失败/限制，以及供 M13 审查的上下文与调用摘要。

### 内部功能清单、历史依据和重要性建议

| 内部功能 | 合并后的产品结论 | 历史资料依据 | 建议 | 建议理由 |
|---|---|---|---|---|
| 静态资料查找与来源返回 | Agent 可按当前问题取用 M07 内容，结果保留资料、原文位置和必要上下文。 | `API与核心数据流.md`“单点 Query”“学习闭环”；`知识库模块设计-v1.md`；`RAG选择.md`仅技术参考 | 主干 | 无来源资料调用无法支撑可靠教学和高阶阅读。 |
| 概念关系读取 | Agent 可查询 M08 的前置、推导、对比/混淆等关系及依据，不把资料层级当概念关系。 | `知识网络层.md`；`资料层技术结构设计方案v1.md` | 第二梯队 | 对诊断和导航价值高，但 M08 自身仍需产品确认。 |
| 个人知识读取与闭环写入约束 | 图节点可读取 M09 的相关已结束记录；进行中聊天、中间诊断和高频状态不得逐轮写入 M09。只有 M04 闭环守卫通过后，才提交符合 M09 契约的个人形成记录。 | `旧版后端系统.md`“一轮学习链”；当前 M04/M09 产品审查 | 主干 | 是同步上下文与异步个人知识分离的操作边界。 |
| 当前任务与历史上下文选择 | 围绕 M01 当前线程、活动和未完成目标选取必要历史，保留分支来源，不默认携带全量会话。 | `API与核心数据流.md`“一轮学习闭环”“分支线程”；`MVP 实现转交文档`上下文可审查 | 主干 | 上下文必须服务当前任务，避免主线和分支污染。 |
| 同源不同契约的隔离执行 | 多个模块读取同一份记录但输出契约不同时（M04 与 M15 读同一份 M01 过程记录），须是各自独立的执行，不能一次执行输出两段。若某条跨模块请求边仍可能污染上下文（M04 → M15 的重新确认请求），可用分支会话承载该次读取。 | 当前 M04/M15 审查单；`API与核心数据流.md`“分支线程” | 主干 | 隔离靠提取指令加输出契约实现；执行不分开，隔离只是名义上的。分支会话是实现手段，不改变模块边界。 |
| 上下文摘要与压缩 | 长期项目中将历史压缩为可追溯摘要，并可回到原始记录核实。 | `MVP-PRD-v1.md`多轮记忆；`v0.2-Transcript...`；`00 产品设计总览` | 主干 | 长期会话无法依赖全量原文持续进入模型。 |
| 工具能力、权限和副作用边界 | 明确 Agent 能读什么、能提议修改什么、哪些动作需用户确认；失败不得伪装成成功。 | `旧版后端系统.md`降级与写入局限；`私人运行数据档案.md`；`知识库模块设计-v1.md`人工干预 | 主干 | 工具会跨模块读写，边界错误会污染资料或画像。 |
| 失败和降级可见 | 检索、状态读取或模型调用不可用时，Agent 和用户能知道缺了什么、结果受何限制。 | `运行与复现.md`；`旧版后端系统.md`“降级过于静默”；`API与核心数据流.md`错误语义 | 主干 | “能回答”不等于依据完整，失败状态影响产品真实性。 |
| 工具结果一致格式与审查摘要 | 不同工具的结果至少呈现来源、时间/版本、置信或限制和是否产生状态变化。 | `v0.1-纵向闭环骨架与中间产物追踪.md`；`v0.2-Transcript...` | 第二梯队 | 提升可审查性，但具体格式以后设计。 |

候选：暂无。当前资料中的 M11 能力要么构成 Agent 操作边界，要么是其可靠性增强；这不代表产品负责人不能在审查后新增候选。

### 重复内容合并后的结论

- 历史 QueryChain、LearningChain、RAG 和动态检索是同一产品需求的不同实现证据：Agent 应按当前任务取静态、关系、动态和历史上下文，并保留来源。
- “工具”和“库”不能合并：M07/M08/M09 拥有对象与规则，M11 只提供 Agent 操作边界。
- 旧系统大量 API、collection 和 route 名称不构成功能清单；只抽取“查找、读取、提议更新、失败反馈、上下文选择”能力。

### 被后续资料覆盖的旧结论

- MVP“整段资料直接塞上下文、不做检索”被后续 RAG 解冻和知识库 PRD 覆盖。
- 旧系统静默降级仍能返回结果的做法，被冻结复现资料指出有误导风险；需求结论改为失败/降级可见。
- 旧 API 的单机、无鉴权、具体调用协议和多表写入不继承。

### 与其他模块的边界和信息流

- M07/M08/M09 分别拥有静态资料、通用知识、已结束闭环形成的个人知识；本文只讨论图节点如何按权限获取、交接和提交候选，不拥有这些数据。
- M11 决定一次任务给模型哪些上下文和工具。（原文此处写“M12 决定可用模型与任务能力”；本轮已取消 M12，可用模型与任务能力改由实现期横切处理，见总览横切原则。本单为暂缓草稿，其余内容未随本轮改动。）
- 跨模块过程记录保存工具调用、来源和变化；本文不负责长期审查界面。M13 暂作为该方向的参考草稿。
- M01 提供当前任务和线程位置；M11 不管理项目生命周期。

## 产品负责人审查问题


1. 哪些跨模块写操作允许 Agent 自动完成，哪些必须由学习者确认？
2. 学习者需要看到每轮使用了哪些资料/M09 已结束记录，还是只在引用、判断或异常时显示？
3. 上下文摘要能否跨项目复用，还是必须按项目隔离？
4. 工具失败时，产品应阻断教学、降级继续，还是由任务类型决定？
