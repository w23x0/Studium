# M12 模型与服务（已取消，不作为产品模块）

> 本轮审查结论：**取消 M12，不作为产品模块设计。** 模型与服务是实现期的横切事项，由各模块在自己的“以后转技术方案”里各自考虑，不在产品边界层预先定义。模块编号 M12 留空，不重排其他模块编号。

## 取消理由

1. **没有学习语义输出。** M12 的产出是可用模型清单、任务绑定、连接状态和使用边界，全部是运行配置，不构成任何学习产品职责。
2. **它替学习模块预先定死了任务清单。** 原 M12 把任务枚举为“入库、检索分析、教学、诊断、总结”五类，其中两个名字已被已确认模块推翻：M04 明确诊断是贯穿整个闭环的动态判断、不是单回合判断，LLM 也不是最终裁判；M04-02 明确闭环记录不能只保存一句总结。产品边界层不应由一个服务模块反向命名学习行为。
3. **实现方式尚未实验。** 供应商协议、路由、缓存、超时重试、能力探测都要在实际设计和实验中确定，现在写进产品需求只会形成一份需要反复推翻的约束。
4. **各模块已各自转出。** M02、M03、M06、M07、M08、M10、M14 都已在自己的技术方案段里声明所需模型能力，不依赖一个统一模块存在。
