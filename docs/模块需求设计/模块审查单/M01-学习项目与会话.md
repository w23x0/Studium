# M01 学习项目、会话与过程记录

### 核心问题

为持续学习建立稳定的项目和会话归属，把聊天、练习、诊断、路线决定、教学策略及其依据按项目、会话、学习闭环和时间保存下来，形成各处理模块共同读取的记录容器。M01 是分类记录模块，不决定学习路线、会话数量、闭环粒度、教学方式或掌握结果。

一个学习项目可以包含多个跨天进行、可暂停、可恢复和可结束的学习会话；一个会话记录一个学习闭环。会话之间可以存在主从、来源、返回或其他关系，但这些关系的产生条件和后续安排由相应处理模块决定，M01 只记录结果。

### 输入、主要处理与输出

- 输入：用户建立或选择的学习项目；项目与 M07 静态资料的选取关系；各模块产生的聊天、练习、诊断、路线、策略、资料引用和状态事件；会话与学习闭环的归属信息。
- 主要处理：建立和维护项目、会话及记录的归属；保存项目范围、会话内容、跨模块产物、来源、时间、状态和相互关系；按项目、会话和闭环向其他模块提供可读取的记录范围。
- 输出：项目记录及其资料选取范围；会话记录及其学习闭环归属；可追溯的聊天与过程产物；供 M02-M05、M09、M10 及后续上下文工程读取的项目/会话上下文来源。M01 不生成路线、教学、诊断或掌握结论。

### 重复合并后的结论

- M01 是分类记录和共享容器，不是学习导航、教学策略、诊断或闭环判定模块。
- “项目”提供资料选取和记录范围；“会话”承载一个学习闭环的跨天过程；会话内保存聊天及跨模块产物。
- M01 可以记录任意数量的未完成会话和会话关系，不限制同时存在多少会话，也不要求只有一个当前焦点。
- M05 决定会话数量、下一目标、是否建立关系、分叉范围和返回条件；M01 只保存这些决定及其结果。
- M08 提供通用知识对象、关系和可学习结构；M05/M10/M04 负责把这些对象用于规划、教学和判断；M01 记录实际使用的闭环归属。
- M04 拥有诊断和闭环判断，M09 拥有结束闭环形成的个人知识；M01 保存它们在项目和会话中的过程记录，不替代其语义所有权。
- “会话关系”“恢复”“共享上下文”在 M01 中表示可记录、可查询的事实；图节点、边、检查点、缓存分类和上下文拼装留到第二阶段“上下文工程 + 图工程”。

### 被后续资料覆盖的旧结论

- 旧“五层架构”不能作为 M01 的页面层级或处理顺序；资料、通用知识和个人知识是被学习过程查询的不同记录来源。
- 固定 session、固定三栏界面、固定会话数量和按访问时长切割会话，均为历史实现形态，不构成当前产品约束。
- 旧三项闭环验收已由 M04 的当前证据守卫覆盖；M01 只保存判定结果及其来源。
- 旧实现中的 thread、branch、turn 等名称不直接规定新的产品对象层级；M01 只保留当前确认的项目、会话、闭环归属和记录关系。

### 边界和信息流

- M01 与 M07：M01 保存项目对全局资料的选取关系；M07 保存资料本体、目录、检索和引用，不把资料复制进项目。
- M01 与 M08：M08 提供通用对象、关系和结构；M01 保存项目/会话实际引用的对象和来源事实，不拥有通用知识结构。
- M01 与 M02/M03：M02/M03 产生教学互动、练习活动和学习者产出；M01 保存其归属、内容和过程记录。
- M01 与 M04：M04 产生诊断、证据和闭环判断；M01 保存判断及其引用，不能自行判断掌握或关闭会话。
- M01 与 M05：M05 决定下一目标、会话数量、路线关系、分叉范围、返回条件和复习/复检安排；M01 保存并提供这些决定的记录，不执行规划。
- M01 与 M10：M10 产生当前教学策略、方向/节奏守卫和效果记录；M01 保存其与当前会话的关联，不参与策略选择。
- M01 与 M09：M09 保存已结束闭环形成的个人知识、证据边和时间版本；M01 保存闭环及其相关记录的项目/会话归属，不保存另一份个人知识模型。闭环长期无法结束时，M01 仍照常记录会话事实（该闭环停留在未完成状态），M09 不收——M09 是会话外级别，只接收已结束闭环；“十个闭环都结束不了”属路线问题，归 M05 的并行量与限流。
- M01 与 M15：M15 保存带时效、来源和不确定性的动态状态；M01 保存状态与项目/会话的关联事实，不拥有状态语义。
- **M01 是 M09 与 M15 之间唯一的链接位置。** M09 与 M15 是一对分开的学习者模型，双向都没有引用关系；“某闭环完成时学习者处于什么状态”不由任一方持有，而是经 M01 的链接获得——M01 知道这个闭环属于哪些会话、这些会话对应哪些 M15 记录和哪些 M04 日志，各模块产出各自保管，M01 只保管归属与位置。
- **M01 只存事实，不存解释。** 例如存“各次会话的启动间隔”，不存“启动困难”；存“某次会话中断的时间点”，不存“注意力涣散”。解释每次由 M15 的状态阶段子模块和 M04 的阈值概念子模块从各自日志重新导出，不在 M01 沉淀成长期结论。已知代价：输入可复现，导出的解释不可复现，没有校验器可以判定两次导出哪次更对，这一项落在总览横切原则 4 的人工校准范围内。反过来建一份长期状态结论存储能解决可复现性，但那正是人格标签的入口，因此不建。
- M01 与 M13：M01 拥有面向学习项目和会话的产品记录；跨模块技术日志、审查链、权限和数据治理在 M13 及第二阶段技术设计中处理，不能因此把 M01 扩展成通用日志基础设施。
- M01 与 M14：M14 拥有知识产出物本体及其版本链；M01 保存产出物的项目归属和相关过程记录，不保存产出物内容或版本。长周期研究的过程记录归 M01、阶段路线归 M05；“长期研究项目形态”本轮从 M14 退回，落在 M01 既有的“项目模板与强制计划字段”候选项内（该项仍为候选，不因此升级）。产出物能否脱离项目独立存在，见 M14 审查单的产品负责人问题。

### 以后转技术方案

项目、会话、记录和关系的数据结构；跨重启持久化；记录版本与事件顺序；查询范围和权限；上下文快照、缓存、检查点、恢复以及与图节点/边的映射。上述事项不在本轮产品审查中确定。

## 产品负责人审查问题

本轮产品边界已按“分类记录与共享容器”确认，无需再决定路线、分叉或会话数量规则。后续技术设计前只需确认：

1. 项目对 M07 资料采用选取关系还是其他项目范围表达；资料本体仍由 M07 统一保存。
2. M01 保存的跨模块过程记录需要哪些用户可见视图；内部技术日志和审查链另行设计。
3. 项目目标、期限和整体状态是否继续作为可选的第二梯队字段。
