# M04-02 闭环日志与跨模块审查晋升

> 定位：M04 闭环结果向 M09 写入、再由 M09 经候选/审查反向增益 M08 的后续设计备忘，不是新的产品模块。
>
> 状态：暂记。当前确认“闭环结束后再提交”，但 M09 的表达结构、M08 的审查与晋升机制、自动审查权限以及退回/撤回规则均未完成设计。

## 已确认的原则

- 一个学习闭环未结束时，M04 的中间诊断只服务当前闭环的后续教学，不新增 M09 稳定状态，也不新增 M08 正式知识。
- M04 在闭环中持续记录从最初不会、产生疑点或困难、接受不同教学和练习，到最终形成或未形成理解的动态过程。
- M04 判断闭环完成后作一次闭环级总体诊断，并通知 M01 结束承载该目标的会话。
- 同一份闭环结果不能不加区分地写入多个模块。每个接收方只接收符合自身结构、用途和权限的内容。
- 完整动态过程可以作为可追溯日志；闭环结束后，M04 将其中有意义的个人形成事实和证据引用编译为 M09 记录。M04 日志不能直接成为 M08 候选或正式知识。

## 闭环日志应覆盖的内容

- 闭环目标、范围和验收条件；
- 实际经过的主线、分支、迂回和前置补足路径；
- 关键教学与练习活动及其提示条件；
- 学习者的原始表现、疑点、混淆、困难和变化；
- M04 在不同时间形成的诊断、替代解释及其被支持或推翻的过程；
- 采用过的 M10 策略及相关条件；
- 最终总体诊断、已满足项、未满足项和证据限制；
- 使用的 M08 对象与关系、M09 历史背景及原始证据位置；
- 异常、上下文缺失、模型或工具降级及其对判断的影响。

日志需要能表达一个动态学习过程，而不只是最终的“掌握/未掌握”标签。其长期保存位置、结构化程度以及 M04 运行状态与跨模块过程记录的分工仍待设计；M13 暂作为该技术方向的参考文件，不再预设为独立业务模块。

## 面向不同模块的输出

### 给 M01

- 闭环是否完成；
- 完成、未完成或需要重新打开的理由摘要；
- 结束位置以及相关主线/分支关系；
- 后续仍需保存的未完成事项。

M01 据此执行生命周期变更，但不自行判断学习者是否学会。

### 给 M09

输出必须符合 M09 的个人知识形成结构，不能只保存“映射到哪些 M08 节点”或一句总结。需要表达学习者掌握了什么、在什么条件下能够解释/应用、理解如何组织、形成了哪些个人结构、仍缺少什么，以及这些判断依据什么。摘要和四级标签只作索引。

当前尚未解决的问题：

- 丰富个人形成记录的字段怎样保持开放，同时能够稳定查询和审查；
- 如何从过程日志结构化保留关键变化与证据引用，而不复制全部同步上下文；
- M08 尚未表达的个人对象、细节或理解路径怎样暂存、候选化并在晋升后重新锚定；
- 一个闭环涉及多个对象、关系和个人结构时，M09 的最小记录单位是什么。

这些问题需要回到 M08/M09 联合设计后再确定，M04-02 不提前给出结构答案。

### M09 后续向 M08 提供候选

M04 不直接给 M08 输出。M09 在一个或多个已结束闭环中可能积累新的知识细节、理解路径、概念关系、方法、解释结构、适用边界、反例、类比或迁移方向。只有从 M09 记录中去个人化后，才可形成符合 M08 候选输入结构的材料，包括：

- 候选内容及其连接对象；
- 形成候选的来源闭环、个人记录和必要证据引用；
- 适用范围、前提、反例和不确定性；
- 个人信息去除或隔离情况；
- 与 M08 现有内容的支持、冲突或重复关系。

M09 记录及其证据引用可作为候选依据，但候选是否自动进入正式 M08 尚未确定。

### 给跨模块过程记录与审查设计

- 完整过程日志及来源位置；
- M04 的关键判断变化和最终结论；
- M04 向 M01 提交了什么、向 M09 编译了什么，以及后续 M09 向 M08 提交了什么候选；
- 审查、晋升、退回、更正和撤回产生的后续事件；
- 自动处理失败、人工介入和版本变化。

## 审查、晋升和版本方向

需要区分两类审查门，当前只记录可能方向，不确认具体模块形态：

1. M04 -> M09 的闭环守卫：检查目标是否达到、证据是否充分；不通过则保持进行中、进入复检或标记搁置，不能写成 closed 记录。
2. 闭环通过后，按 M09 契约编译个人形成记录，并可另做结构完整性、冲突和权限校验。
3. M09 -> M08 的候选审查：检查去个人化、通用性、来源、逻辑冲突、隐私和适用范围。
4. 明确无问题且满足授权条件的 M08 候选，可以按未来规则自动晋升；存在冲突、证据不足、高风险或无法判断的候选进入人工或更严格的自动审查。
5. 审查可以接受、修改后接受、退回补充、拒绝或保持待定。
6. M09 写入和 M08 晋升都需保留来源、版本和变更历史，支持更正、撤回或回退；具体实现以后确定。

5. M09 记录或 M08 晋升内容被新证据推翻时，采用更正、撤回、回退还是重新打开来源闭环。本文各处的“撤回”都指**已写入记录或已晋升候选的撤回**，与 M15 已否掉的**状态记录撤回权**（由学习者裁定哪条状态成立）不是同一件事，不要混用同一机制。M09 侧还连着规模问题：不覆盖旧结论意味着体积单调增长，处理方向都需在 M08/M09 存储选型时一并决定，见 M09 审查单。
6. 自动审查、人工审查和最终写入分别需要什么权限与可见性。
