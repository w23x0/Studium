# M04 诊断、证据与掌握判断

> 状态：已精简（2026-10-05，#24），原文见 `../撤下原文/审查单精简前/`。技术实现见 `../../Harness设计/03-运行设计.md`（教学调用、闭环守卫）。闭环怎么定义见产品总览「闭环定义」，本单只用“本闭环的新点 / 出发点 / 目标层次”“合上”这些词。

### 核心问题

围绕 M01 当前会话承载的学习闭环目标，持续综合教学、练习、路径和既有知识信息，判断学习者当前会什么、卡在哪里、还需要什么证据，以及本闭环是否已经真正合上。M04 是进行中闭环里的动态诊断，不是一次回合的旁路判断，也不直接面向学习者生成讲解或练习。

M02、M03、M04、M10 在运行中构成可回流、可分支的图：M02/M03 暴露表现，M04 更新诊断，M10 据此选择学习策略并向 M02/M03 给出活动条件，新的活动再形成证据。它们不是固定串行流水线；M04 的“循环”只是它围绕一个闭环目标持续更新诊断的内部视角。

### 功能

**职责分工**：M04 的每轮诊断写入诊断记录，不放进回复、学习者可查阅（见 M02「职责分工」）。先诊断、后表达；诊断不直接给学习者看。**闭环守卫独立**：守卫不读教学侧的推理与诊断记录，防止自我确认（2026-10-05 收窄：只约束守卫，教学侧保留自己上一轮的诊断）。

| 功能 | 产品结论 | 级别 |
|---|---|---|
| 闭环级动态诊断上下文 | 在同一学习闭环内持续读取目标、路径、教学条件、学习者表现、M08 结构和 M09 已结束记录，使诊断可随新证据修正；上下文缓存不改变源信息的模块归属。 | 主干 |
| 多源证据采集与分级 | 区分学习者原始表现、自述、历史已结束闭环记录、软推断和硬证据，并保留来源、时点、提示条件和路径位置；独立完成、轻微提示和答案暴露后的正确回答不是同一种证据。**作答完整度同样分级**：一两句短答、只给结论的作答只记为“这一点答对了”，不据此推断整件事已懂；诊断只记短答里有效的部分（产品负责人 2026-09-24）。**系统讲过的内容**：学习者跟着复述不算独立证据；须用**光靠复述做不到的方式**重新表现（换情境讲、预测结果、对比两种情况、找错、举反例、解释为什么不行等，方式由 M10 从方法库选、可组合）才算独立。诊断判断证据有无时用与闭环守卫**同一标准**，不自行降低门槛。诊断每轮照常记录（观测、未满足项、位置），但**不以未满足项驱动教学去凑证据**（见 M02「理解 ↔ 训练」）；替代解释只考虑知识与输入方面的可能，**不猜测学习者的动机**（状态归 M15，且只记可观察事实）。M09 背景（含外部导入）可以被怀疑：本次表现与之不符时记下，闭环提交时一并交 M09 作提取失败 / 降档依据（2026-09-27）。 | 主干 |
| 理解与掌握判断 | 对认出、复现、结构、迁移等表现分别取证，达标表现随目标和学习阶段变化。它们是判断与索引维度，不是 M09 的固定压缩标签；不用数值评分、固定阈值、高维向量或完整预建图谱。 | 主干 |
| 精准错误归因与替代解释 | 区分没学过、提取失败、概念混淆、步骤断裂、方法或条件问题；从可观察证据定位具体环节，保留替代假设，并通过后续教学或练习验证。分类表不锁死。 | 主干 |
| 前置缺口与分叉依据 | 受阻时结合 M08 子句（新点的出发点）和本次表现验证前置缺口，向 M05 提供是否需要补前置、分叉目标和返回前需要满足什么的依据；M04 不自行建立会话分叉。**出发点来源只是自述 / 假定、对话表现说明它不牢时同样是前置缺口**——自述与假定不是证据（2026-09-27）。 | 主干 |
| 闭环判定与证据守卫 | **判什么**：对照 M05 定的闭环边界（出发点、新点、目标层次），看新点是否经所选出发点接进了学习者已有的认识、到了目标层次（含义见产品总览「闭环定义」“合上”）；由模型读对话原文整体判断，不设条目清单、固定刻度或数学公式，判断指回原文位置。**会话结束 ≠ 合上**：结束总结写明这次合上与否，合上的进 M09，未合上的进停车场并注明缺在哪个出发点（2026-10-05，#25）。守卫是功能，怎么实现（几次调用、是否隔离）属技术设计。其余已定：证据不足时保持进行中或需要复检，不能因模型自信、学习者自述（“我学会了”）、画像、高频状态、策略偏好、历史个人记录或单次表现直接关闭。守卫审查的是“是否允许结束”，不是 M08 的通用知识晋升。 | 主干 |
| 闭环总体记录契约 | 仅在闭环结束后，把个人形成过程中的关键理解、条件、缺口、证据和时间整理为符合 M09 结构的记录；**按新点及所用出发点标明证据强度**（仅当场 / 含变式 / 含延迟、独立或提示后），让日后回看能分辨“当时就学得模糊”还是“后来遗忘或多知识结合时才暴露”（2026-09-23）；摘要只能用于索引，不能替代结构化形成记录和证据引用。 | 主干方向 |
| 判断复核与更正 | 后续证据和用户异议可纠正诊断；自动判断显示依据和不确定性（模型提出判断、守卫确认、允许更正）。已结束闭环记录的版本与更正规则由 M09 确定。 | 主干 |
| 诊断呈现分层 | 内部诊断不等于学习者可见反馈。M02/M03 负责把可用结论转成合适表达；跨模块过程与审查视图留作 M13。 | 第二梯队 |

### 输入输出

- 输入：M01 的当前闭环目标、主线/分叉关系和当前位置；M05 的单子（新点 + 选中的子句 + 路线动作）与本闭环目标；M02 的教学互动和学习者表达；M03 的练习条件、产出和过程；M08 的通用对象/关系及来源；M09 已结束闭环形成的相关个人知识记录；M15 的状态承载读数与待裁决的解释候选；M10 的当前策略和活动条件；用户自述、原始证据引用及运行限制。
- 主要处理：在当前闭环内维护可推翻的诊断；区分观测、推断、替代解释和证据限制；结合实际路径判断概念、提取、干扰、步骤、方法或条件问题；追溯前置缺口；按目标判断理解和掌握。是否合上由 M04 主体在分析中**提议**，交 M04 的**闭环守卫子模块**确认（怎么判见上表，待定）；守卫判未合上则闭环继续，通过后才生成闭环总体记录。
- 进行中输出：当前诊断、替代解释、证据限制、未满足项、前置缺口和**证据缺口（描述；对策略有用就看，无用不看——不是任务处方）**，写在诊断记录内；一段**已评估的状态候选**，说明检查过哪些 M15 解释候选、知识证据支持还是排除；需要改变跨会话目标或路线时，向 M05 提供改线依据（闭环范围过大 / 缺前置等）。中间判断不写入 M09，也不直接写入 M08，对 M15 也只能回发重新确认请求而非结论。
- 闭环结束输出：经闭环守卫确认的总体诊断、个人知识形成记录、未满足项、证据引用和时间信息，提交给 M09；同时通知 M01 结束该会话承载的闭环。M04 不直接向 M08 写入任何内容。

### 边界

- “理解层级、闭环守卫、精准归因、有限视角诊断”是同一动态诊断的不同判断能力，不拆成独立模块。
- M04 贯穿进行中闭环、结束后一次提交 M09；不持续向 M09 提交更新建议。
- M04 与 M01：M01 提供闭环目标、会话和路线事实；M04 判断是否合上，合上时通知 M01 执行结束。暂停、分叉和返回由用户/M05 决定并由 M01 落实；M01 不自行判断掌握。
- M04 与 M05：M04 提供当前诊断、未满足项和前置缺口；M05 决定保持主线、开分叉、范围和返回条件。M04 不规划长期路线，M05 不改写掌握判断。
- M04 与 M10：M04 判断当前理解、卡点、替代解释和证据限制，只输出诊断事实与**证据缺口（描述）**；M10 据此选择学习策略、活动倾向和强度条件，不重做诊断、不拥有闭环守卫，也不向 M05 发出改线信号。M10 只能调**本次会话内的强度坡度**（本轮节奏、信息量、分解粒度、挑战程度），**不能下调合上标准**（由 M04 闭环守卫在结束点判断）：慢慢施压要的是本轮坡度，不是拆掉门槛。
- M04 与 M02/M03：M02/M03 产生教学互动、练习和可观察表现；M04 观察并形成诊断。M04 不直接生成完整讲解或执行练习。
- M04 与 M15：信息流严格单向 M15 → M04。M04 与 M15 读取同一份 M01 过程记录，以各自的提取指令和输出契约隔离；M04 每轮跑，M15 频率更低（触发见 `../../Harness设计/03-运行设计.md`「M15」）。M04 **不能**写入或确认 M15 的状态候选，也**不能**向 M15 提供任何知识结论——前置漏洞、台阶跳跃是否为失败原因、掌握判断都不进入 M15 的上下文（反向读取会使 M15 停发竞争候选，让 M04 的诊断获得未经证据的一致）。M04 可以回发的只有“某状态需要重新确认”的请求，请求不携带结论。
- M04 裁决 M15 的解释候选：M15 输出分承载读数（与知识诊断正交，直连 M05/M10）与解释候选（与 M04 诊断竞争）两型。M04 的进行中输出须含**已评估的状态候选**；这属于诊断的一部分，不构成对 M15 的写入。被裁决为知识侧原因的候选不得沉淀为 M15 趋势。习惯低谷这类节奏候选，M04 只需给出“知识侧解释不了本次下降”，节奏判断本身不在 M04 视野内。
- M04/M10 是会话内级别，M15/M05 偏会话外级别：让会话外的状态判断读入单轮证据，会把长时程状态锚在一次表现上。
- **M04 内部的跨闭环子模块**：阈值概念的跨闭环卡点判断需要看多个已结束闭环，独立成子模块，输入是 M04 已产出诊断日志与 M09 已结束记录的整合，不新开跨模块通道；它放宽了 M09 → M04 通道的读取范围（按概念检索历史闭环，比主体只读“与当前目标有关的”宽），不是新增边。输出契约上锁三条：只输出“该阈值概念的跨闭环卡点事实 + 是否属质变前兆”，不输出能力评级；只给读数不给动作，动作归 M10；不与 M15 侧的状态阶段子模块合成单一「学习压力」量。M05/M10 各自读两个读数、在各自作用域行动。
- M04 与 M08/M09：M08 提供通用对象、关系、对象属性（含阈值概念标记）和来源；M09 只提供已结束闭环形成的个人知识记录。闭环未结束时，M04 的中间诊断只留在当前上下文与过程记录中；闭环结束时，M04 只向 M09 提交个人记录。M09 经候选/审查通道才可能反向补充 M08。
- 阈值概念的分工：M08 标记“哪个概念是阈值概念”（对象属性，二值），M04 判断“该学习者是否已跨过”，M09 保存该判断结果。在阈值概念处遇到卡点，M04 应把它作为质变前兆的可能解释之一，而不是默认按普通错误归因。M08 侧另有「初始学习难度阈值」（高度与深度的范围边界，供规划参考），与二值的阈值概念标记不是同一个东西；其形态留待 M08。
- 阈值概念停滞与 M15 的习惯低谷**不合并**：两者都属预期内下降、都不该改道，但阈值停滞走 M04 → M10（会话内调策略强度：换切入角、降信息量、加小步验证，不动路线），习惯低谷走 M15 → M05（不改道、不加任务）；不抽象成共同概念，避免会话内判断影响会话外的改道决定。
- 遗忘标签的次序约束：会话内发现“以前会的现在答不出”，作为进行中诊断的一条替代解释，可据此给 M10（本轮直接补讲）或 M05（另开会话复习）。**进行中的“遗忘”是候选，闭环提交里的“遗忘/提取失败”才是记录**；提交时必须已排除疲劳退化等状态侧解释。两者之间不设快速写入通道，闭环结束那一次提交是唯一过渡点（复习会话可逆，M09 里一条错的遗忘标签不可逆）。
- M04 → M02/M03/M14：M02/M03/M14 都不直读 M09；相关已结束闭环个人知识由 M04 读取后进入这些模块。M04 只提供诊断事实与验证需要，不提供教学建议（教学策略归 M10）。
- M04 与 M13：完整动态过程、模型/工具使用和审查链属于跨模块技术设计；M04 只拥有诊断语义和闭环判断，不拥有通用日志基础设施。
- M04 的子设计备忘：`M04-01`（诊断上下文）、`M04-02`（闭环日志与审查晋升）。
