# M04 诊断、证据与掌握判断

### 核心问题

围绕 M01 当前会话承载的学习闭环目标，持续综合教学、练习、路径和既有知识信息，判断学习者当前会什么、卡在哪里、还需要什么证据，以及目标是否已经真正完成。M04 是进行中闭环里的动态诊断图，不是一次回合的旁路判断，也不直接面向学习者生成讲解或练习。

M02、M03、M04、M10 在运行中构成可回流、可分支的图：M02/M03 暴露表现，M04 更新诊断，M10 据此选择学习策略并向 M02/M03 给出活动条件，新的活动再形成证据。它们不是固定串行流水线。

### 输入、主要处理与输出

- 输入：M01 的当前闭环目标、验收范围、主线/分叉关系和当前位置；M02 的教学互动和学习者表达；M03 的练习条件、产出和过程；M08 的通用对象/关系及来源；M09 已结束闭环形成的相关个人知识记录；M15 的状态承载读数与待裁决的解释候选；M10 的当前策略和活动条件；用户自述、原始证据引用及运行限制。
- 主要处理：在当前闭环内维护可推翻的诊断上下文；区分观测、推断、替代解释和证据限制；结合实际路径判断概念、提取、干扰、步骤、方法或条件问题；追溯前置缺口；按目标判断理解和掌握；检查闭环证据是否足以结束。
- 进行中输出：当前诊断、替代解释、证据限制、未满足项、前置缺口和需要验证的内容，供 M10 选择学习策略；一段**已评估的状态候选**，说明检查过哪些 M15 解释候选、知识证据支持还是排除；需要改变跨会话目标或路线时，向 M05 提供改线依据。中间判断不写入 M09，也不直接写入 M08，对 M15 也只能回发重新确认请求而非结论。
- 闭环结束输出：经闭环守卫确认的总体诊断、个人知识形成记录、未满足项、证据引用和时间信息，提交给 M09；同时通知 M01 结束该会话承载的闭环。完整过程由跨模块技术设计参考 M13 留存。M04 不直接向 M08 写入任何内容。

### 重复合并后的结论

- M04 的“循环”是它围绕一个闭环目标持续更新诊断的内部视角，不代表 M02/M03/M04/M10 构成固定的线性或单一循环结构。
- “理解层级、闭环守卫、精准归因、有限视角诊断”是同一动态诊断图的不同判断能力，不拆成独立模块。
- 多份理论对错误分类用词不同，稳定结论是：必须从可观察证据定位具体环节、保留替代解释并可通过新活动验证；分类表不锁死。
- “四项证据”保留为当前闭环守卫的验收参考，不是统一算法，也不是 M09 的数值化字段。

### 被后续资料覆盖的旧结论

- “M04 是一次回合或阶段的旁路判断，并持续向 M09 提交更新建议”已被当前“贯穿进行中闭环、结束后一次提交 M09”的口径覆盖。
- `学习会话闭环.md` 的旧三项验收已被 v0.4 四项证据覆盖。
- v0.2 及早期学习者状态中的数值评分、固定阈值、高维向量、完整预建图谱已被自然语言形成记录、证据边和可修正关系方向覆盖。
- “LLM 唯一诊断途径/最终裁判”被“模型提出判断、确定性证据守卫、允许更正”覆盖。
- 自述“我学会了”、高频状态、策略偏好或历史个人记录均不能直接关闭任务。

### 边界和信息流

- M04 与 M01：M01 提供闭环目标、会话和路线事实；M04 判断目标是否完成，完成时通知 M01 执行结束。暂停、分叉和返回由用户/M05 决定并由 M01 落实；M01 不自行判断掌握。
- M04 与 M05：M04 提供当前诊断、未满足项和前置缺口；M05 决定保持主线、开分叉、范围和返回条件。M04 不规划长期路线，M05 不改写掌握判断。
- M04 与 M10：M04 判断当前理解、卡点、替代解释和证据限制，只输出诊断事实与验证需要；M10 据此选择学习策略、活动倾向和强度条件，不重做诊断、不拥有闭环守卫，也不向 M05 发出改线信号。
- M04 与 M02/M03：M02/M03 产生教学互动、练习和可观察表现；M04 观察并形成诊断。M04 不直接生成完整讲解或执行练习。
- M04 与 M15：信息流严格单向 M15 → M04。M04 与 M15 读取同一份 M01 过程记录，通过各自的提取指令和输出契约隔离，且是两次独立执行；M04 每轮对话必跑，M15 频率更低（暂定事件触发加会话收尾）。M04 **不能**写入或确认 M15 的状态候选，也**不能**向 M15 提供任何知识结论——前置漏洞、台阶跳跃是否为失败原因、掌握判断都不进入 M15 的上下文。反向读取会使 M15 停发竞争候选，让 M04 的诊断获得未经证据的一致。M04 可以回发的只有“某状态需要重新确认”的请求，请求不携带结论。
- M04 裁决 M15 的解释候选：M15 输出分承载读数（与知识诊断正交，直连 M05/M10）与解释候选（与 M04 诊断竞争）两型。M04 的进行中输出须含一段**已评估的状态候选**，说明检查过哪些候选、知识证据是支持还是排除。这属于诊断的一部分，不是状态判断，不构成对 M15 的写入。被裁决为知识侧原因的候选不得沉淀为 M15 趋势。习惯低谷这类节奏候选，M04 只需给出“知识侧解释不了本次下降”，节奏判断本身不在 M04 视野内。
- M04/M10 是会话内级别，M15/M05 偏会话外级别。这解释了 M04 与 M15 的频率差和单向约束的同一个来源：让会话外的状态判断读入单轮证据，会把长时程状态锚在一次表现上。
- **M04 内部的跨闭环子模块。** 阈值概念的跨闭环卡点判断需要看多个已结束闭环，输入范围大于 M04 主体（主体是会话内、每轮跑）。它独立成子模块，输入是 M04 已产出诊断日志与 M09 已结束记录的整合，不新开跨模块通道。**但它确实放宽了已有通道的范围**：M04 主体读 M09 限于"与当前目标有关的已结束个人知识"，子模块要问的是"这个阈值概念跨了多少闭环仍未过"，需要按概念检索历史闭环，比主体宽。这是同一条 M09 → M04 通道上的范围放宽，不是新增边，具体查询形态取决于 M09 的存储选型（与 M15 侧不对称：M15 的子模块只读本模块日志，因为 M15 本就不读别的模块）。输出契约上锁三条：只输出“该阈值概念的跨闭环卡点事实 + 是否属质变前兆”，不输出能力评级；只给读数不给动作，动作归 M10；不与 M15 侧的状态阶段子模块合成单一「学习压力」量——合成需要一方同时持有知识侧与状态侧结论，正是严格单向所禁止的。M05/M10 各自读两个读数、在各自作用域行动。
- **后续设计项（模块组合阶段）：** M10 参考 M04 的难度分析与 M15 的状态后，在当前会话内调节强度。这里的边界要在设计那轮解决——闭环目标是 M01 的对象、由 M05 规划，M10 可调节的是**本次会话内的强度坡度**（本轮节奏、信息量、分解粒度、挑战程度），**不能下调达成标准**：达成标准即 M05 设定的验收范围，由 M04 闭环守卫在闭环结束点判断证据是否满足。慢慢施压要的是本轮坡度，不是拆掉门槛。
- M04 与 M08/M09：M08 提供通用对象、关系、对象属性（含阈值概念标记）和来源；M09 只提供已结束闭环形成的个人知识记录。闭环未结束时，M04 的中间诊断只留在当前上下文与过程记录中；闭环结束时，M04 只向 M09 提交个人记录。M09 经候选/审查通道才可能反向补充 M08。
- 阈值概念的分工：M08 标记“哪个概念是阈值概念”（对象属性，二值），M04 判断“该学习者是否已跨过”（个人判断），M09 保存该判断结果。在标记为阈值概念的地方遇到卡点，M04 应把它作为质变前兆的可能解释之一，而不是默认按普通错误归因。M08 侧另有「初始学习难度阈值」（高度与深度的范围边界，供规划参考）这一独立字段，与二值的阈值概念标记不是同一个东西，不得混为一个；该字段的形态取决于 M08 的存储结构选型，留待 M08 那轮。
- 阈值概念停滞与 M15 的习惯低谷**不合并**，各自独立护栏。两者都属预期内下降、都不该改道，但级别与消费者不同：阈值停滞走 M04 → M10，M10 在会话内调策略强度（换切入角、降信息量、加小步验证），不动路线；习惯低谷走 M15 → M05，M05 不改道、不加任务。不抽象成共同概念，是为避免会话内判断影响会话外的改道决定。
- 遗忘标签的次序约束：M04 在会话内发现“以前会的现在答不出”，作为进行中诊断的一条替代解释，可据此给 M10（本轮直接补讲）或 M05（另开会话复习）。**进行中的“遗忘”是候选，闭环提交里的“遗忘/提取失败”才是记录**；提交时必须已排除疲劳退化等状态侧解释。M04 是会话内作用域，遗忘与提取失败是跨会话现象，两者之间不设快速写入通道，闭环结束那一次提交是唯一的过渡点。已知代价：向 M05 提“另开复习会话”时尚未排除疲劳，可能白开一次；复习会话可逆，M09 里一条错的遗忘标签不可逆，代价不在一个量级。
- M04 -> M02/M03/M14：M02/M03 不直读 M09，M14 也不直读 M09；相关已结束闭环个人知识由 M04 读取后进入这些模块。M04 只提供诊断事实与验证需要，不提供教学建议（教学策略归 M10）。
- M04 的诊断呈现分层：内部诊断不等于学习者可见反馈，交由 M02/M03 转成合适表达。
- M04 与 M13：完整动态过程、模型/工具使用和审查链属于跨模块技术设计参考；M04 只拥有诊断语义和闭环判断，不拥有通用日志基础设施。
