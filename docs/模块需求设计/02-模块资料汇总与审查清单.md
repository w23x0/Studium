## 证据与版本口径

- **产品/决策资料**可作为功能和边界的直接依据，但仍需结合后续覆盖关系。
- **历史实现/验收资料**可证明能力曾实现或交互曾出现，不能证明教学效果，也不能反推新架构。
- **理论资料**只支持产品假设、质量原则、诊断词汇或候选方向，不能直接写成已确认功能。
- **原型资料**只证明当时提出过界面和交互，不证明真实链路已完成。
- **技术资料**若包含产品对象可用于边界举证；算法、接口、存储、模型编排和框架选择不进入需求结论。
- **外部产品观察**（`docs/实际使用/`、`docs/DeepTutor/`）是需求来源，不是本项目的实现说明；只能证明“别的产品这样做过”或“产品负责人在使用中有此反应”，需求结论仍需产品负责人在本轮直接确立。依据见 `项目定位与资产地图.md:87`。

主要覆盖结论：

1. 2026-06-29 的“暂不做 RAG、整段资料直接进入上下文”被 2026-07-01 的检索与引用方向明确覆盖。
2. 早期“五层顺序架构”被后续工作流按需查询共享库的方向覆盖；五层只保留为职责解释，不能直接继承为模块或处理顺序。
3. 旧数值化学习者状态、固定阈值和能力分数被自然语言、证据链、弱先验和带时效、带来源、可被新观察推翻的状态覆盖；分数不能表示掌握真值。注意“可推翻”指被新的观察推翻，不指由学习者自述裁定——旧资料的用户更正与撤回权口径本轮不采纳。
4. 旧三项闭环验收被 v0.4 四项证据覆盖；模型自信、用户自述、心理状态和软画像不能单独关闭学习任务。
5. 固定资料质量评分被后续“资料管理 + 检索”范围修正覆盖；来源、缺口和冲突仍可显示，但不能伪装成客观综合分。
6. 完整预建知识图谱被按需形成、带证据、可修正的关系候选覆盖；后期“学习监控图谱”又混合了通用关系和个人状态，必须重新拆分。
7. 旧桌面端、固定三栏界面、开源前端基座、API/数据库字段和模型调用链均为历史形态，不约束本轮产品设计。

## 重点边界审查结论

### M02 / M03

保留两个模块。M02 主要产出讲解、追问、示例和反馈；M03 要求学习者完成题目、推导、证明、实验、复述或表达，产出表现和练习证据。“系统发出题目”是交界，不能仅按消息方向划分；本轮已在两侧都升为主干定义性交界（M02 侧“交接练习动作给 M03”、M03 侧“接收 M02 交接的练习动作”）。M02/M03/M04/M10 处于可回流、可分支的运行图中；M04 不是一次性旁路观察者。

两者都是单向输出：只提供教学表达、练习任务和可观察事实，不写回 M08/M09；都不直读 M09，个人知识经 M04 读取后进入。M10 的四项强度参数（信息量、提示强度、挑战程度、节奏）由 M02/M03 执行而不自定：M02 不做“最小补足”式的自主补齐，M03 不自定挑战程度升降。两者都向 M15 提供状态可观察事实，但不给状态结论。

### M04 / M09

M04 贯穿一个进行中的学习闭环，在当前上下文中持续更新诊断、替代解释和证据判断；闭环守卫通过后才向 M09 提交一次闭环级个人形成记录。M09 只保存已结束闭环形成的个人知识、理解、个人结构、证据边和时间版本，不保存每轮同步状态。单次模型判断、原始聊天或摘要不能成为长期掌握真值。

### M07 / M08 / M09

M07 保存有出处的静态资料、题目和资料结构；M08 保存不专属于个人的概念、方法、结构模型、思维框架及通用关系；M09 保存已结束闭环形成的个人知识和理解。M09 锚定 M08，但不是简单覆盖图；它可把 M08 未表达的细节、理解路径或高层个人结构去个人化后提交候选，未经审计不得进入正式 M08。负荷、情绪、注意力等高频状态不属于 M09 核心。

### M01 / M04 / M05 / M10

M01 保存并展示会话、闭环目标、主线/分叉和恢复位置；M04 在进行中的闭环内形成诊断与改线依据；M05 在闭环之外规划下一目标和跨会话路线；M10 在既定闭环内依据 M04 诊断和学习者状态制定学习策略，并向 M02/M03 输出强度条件。M10 不拥有分叉、收束、返回或路线守卫。

### M01 / M05 / M10 合并确认

- **会话记录与恢复**：M01 保存项目、会话、闭环目标、路线事实、分叉来源和恢复位置；不决定新会话、分叉或结束条件。
- **路线规划与分叉**：M05 在单个会话之外决定下一闭环、主线/分叉、返回条件、复习/复检和跨会话限流；决定交给 M01 记录和落实。
- **当前教学策略**：M10 在既定闭环内依据 M04 诊断和 M15 状态条件，决定策略、活动倾向、提示/挑战强度和节奏；不修改 M05 路线，也不代替 M04 判定掌握。
- **上下文来源**：M01 提供项目/会话范围内的事实与过程记录；M05 产出路线决定；M10 产出当前策略条件；筛选、缓存和拼装留给后续上下文工程与图工程。
- **分叉与恢复**：M05 决定跨闭环分叉及返回条件，M01 保存分叉关系和恢复位置；M10 的活动强度调整不自动变成路线分叉。

### M09 / M10

M10 拥有通用策略知识、个人策略过程记录、适用条件、本轮选择和活动强度条件；M09 只保存已结束闭环形成的个人知识，不保存策略过程或高频即时状态。M04 提供当前证据，学习者状态与条件模块提供非知识类信息，M05 决定闭环之外的路线，M02/M03 执行具体活动。

### M15 与相邻模块

M15 保存带时间范围、来源和不确定性的动态学习状态与现实条件。主要消费者是 M05（跨会话路线的承载限制）和 M10（会话内策略适配条件）；M04 的角色是解释候选的裁决方，而非常规消费者。三个模块的判断和决定仍分别归属各自模块。M01 只保存状态与项目/会话的关联和过程事实，不拥有状态语义。

输出分两型：**承载读数**（当前负荷、可挂核心任务数、可承载连续时长、环境限制）与知识诊断正交，直连 M05/M10；**解释候选**（对当前表现下降的状态解释）与 M04 的诊断竞争，须经 M04 裁决后才可作行动依据。M04 的输出中因此含一段“已评估的状态候选”，说明检查了哪些候选、知识证据支持还是排除；裁决属于诊断的一部分，不构成对 M15 的写入。

信息流严格单向 M15 → M04。M04 与 M15 读取同一份 M01 过程记录，通过不同提取指令和输出契约隔离，且必须是两次独立执行；M15 频率低于 M04（M04 每轮必跑，M15 暂定事件触发加会话收尾）。M15 不读取 M04 的任何知识结论——反向读取会使 M15 停发竞争候选、制造未经证据的一致，并把会话外的状态判断锚在单轮证据上。M15 需要的任务跨度从对话内容自取，M04 只能回发重新确认请求。

M04/M10 是会话内级别，M15/M05 偏会话外级别。这解释了频率差、消费者配对和单向约束的同一个来源。频率完整排序 **M04 > M15 > M09**：M04 每轮必跑，M09 一个闭环只写一次，M15 落在两者之间（具体口径待定）。

M15 含**状态阶段判断跨会话子模块**（习惯低谷、堆积型下滑、疲劳退化、阈值型动力低），盲发候选、各类自带回看窗口。它的输入是 M15 主体已产出的状态日志的整合，不新开跨模块通道；M04 侧有一个对称的阈值概念跨闭环子模块，两者互不读取。输出契约上锁三条：只出阶段类型与所依据的时间跨度、不出特质陈述；只给读数、不给动作；不与 M04 侧子模块的结论合成单一「学习压力」量（合成会要求某一方同时持有知识侧与状态侧结论，正是严格单向禁止的）。它是“历史信息只用于概率参考”的唯一例外来源。由当前策略造成的状态需记录并标注来源，M10 须先自查策略再将其视为学习者固有条件。

采集路线是**被动考察为主并持续优化被动准确率**。主动报告不作为采集重点、也不具备权威：沉浸式产品形态下发生机会稀少，自述受可得性偏差影响，学习者还可能否认或掩盖自身状态。自述与异议按一类来源记录并标注，冲突时并存标注、由 M04 在裁决解释候选时处理。**明确不做**：状态记录撤回权、否认后失效传播、敏感状态屏蔽开关——前提是自述不可信，这本身就否掉了“由学习者裁定哪条状态记录成立”的机制。

M15 与 M09 并列但不合并，且**双向都没有引用关系**：M09 保存闭环结束后形成的个人知识、理解、证据和时间版本；M15 保存学习过程中变化的负荷、情绪、注意力、疲劳、行动条件和现实限制。“闭环完成时处于什么状态”经 M01 的链接获得，M01 只存事实（如各次会话的启动间隔）不存解释（如“启动困难”），解释每次由子模块重新导出——已知代价是输入可复现、导出的解释不可复现，落在人工校准范围内。M15 不作心理疾病诊断、不贴人格标签，也不把一次状态推断写成长期能力或人格结论。

### M14 与相邻模块

M14 只拥有学习者自己的知识产出物：一篇研究、写作或内容编制成品从草稿到定稿的对象、版本链、修订比较、来源引用位置和编辑恢复位置。它与 M08 的去个人化通用知识、M09 的已结束闭环个人知识形成记录并列而不重叠。M14 独立成立的原因是没有别的模块能承载“进行中的成品及其版本链”：M07 要求资料不因学习表现而变，M01 的对象层级只到项目/会话/闭环且已把版本推给技术方案，M09 只收已结束闭环结果。

M14 不输出教学表达、练习任务、诊断结论、掌握判断、跨闭环路线或学习者状态解释，也不直读 M09（相关个人知识经 M04 读取）。它可向 M08 的候选审计通道提交高阶候选，走与 M09 相同的通道，不能直写 M08。产出物跨多个学习闭环存在，但它本身不是闭环，也不产生闭环判断。学习内容编制（书籍/课程/页面）与多人协作、同行评审、知识交流为**明确不做**。

1. M02/M03/M04/M10 保持独立产品职责，并按图关系触发和回流；产品模块不直接等同于固定执行节点。
2. M04 只在闭环结束后向 M09 提交一次丰富个人形成记录；M09 不接收逐轮同步状态，摘要只作索引。
3. M08 通用知识、M09 个人知识形成和运行中上下文严格分离；M09 只能经候选与审计反向增益 M08。
4. M04 只形成进行中的诊断与改线依据；M10 只制定会话内学习策略和强度条件；M05 只规划闭环之外的路线，M01 保存并显示相应路线结构。
5. M15 只拥有动态学习状态与现实条件；M05 与 M10 是主要消费者，M04 是解释候选的裁决方，M01 只记录关联事实。信息流严格单向 M15 → M04：M15 不读 M04 的任何知识结论，M04 只能回发重新确认请求，其输出中的候选裁决不构成写入。M15 输出分承载读数（直连 M05/M10）与解释候选（经 M04 裁决）两型。
6. M11/M13 保留现有内容但暂缓作为一级产品模块，后续纳入“上下文工程 + 图工程”联合设计，并重新区分技术基础与产品视图归属。
7. M02 与 M03 都是单向输出：只提供教学表达、练习任务与可观察事实，不写回 M08/M09；两者都不直读 M09，个人知识经 M04 读取后进入。“系统发出题目”是两者的定义性交界，在两侧均为主干。
8. M14 只拥有学习者自己的知识产出物及其版本链、修订比较和来源引用位置；它不做第二套教学、练习、诊断、规划或状态解释，也不直读 M09。产出物跨多个闭环存在，但它本身不是闭环，也不产生闭环判断。
9. M12 取消，模型与服务不作为产品模块。三项要求已分流：静默降级必须可见、内容外发披露进入总览横切原则；模型身份与版本进入 M09 证据边字段要求。
10. M08 拥有阈值概念标记等通用对象属性；M04 判断某学习者是否跨过，M09 保存该判断结果。M08 侧有两个必须分开的字段：**二元的阈值概念标记**（对象属性）与**初始学习难度阈值**（高度与深度的范围边界，供 M05 规划参考），两者都随 M08 存储选型定稿。
11. M09 与 M15 双向都无引用关系，是一对分开的学习者模型；跨两者的关联经 M01 的链接获得。M01 只存事实，不存解释。
12. 产出可见（横切原则 5）：所有模块的产出、来源与依据都要在前端对学习者可见，不是某个模块的专有能力；可见不等于可裁决，学习者异议按自述来源记录，不覆盖可观察事实。
13. 两个对称的跨会话/跨闭环子模块（M15 状态阶段、M04 阈值概念）各读自己主模块的日志，互不读取，输出契约各上三条锁，不合成单一「学习压力」量。
