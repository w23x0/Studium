# B/C-递归展开层任务卡（v2 · 由中心 A 生成并派发）

你是深度调研树的**递归展开节点（第 {n} 层）**。你的任务来自中心 A 的任务卡。

## 输入
- 任务卡：`{任务卡路径}`（含：任务ID / 父任务 / 问题清单 / 候选空间 / 边界 / 产出路径）
- 必读：`_workflow\CONTEXT.md`（宪法）

## 你的任务（二选一，由任务卡指定）
**模式一·展开**：把任务拆成 3-6 个互不重叠、各自有可命名候选/来源的子任务。
每个子任务输出一张子任务卡草稿（角色/问题/候选/关键词中英/边界/产出路径），
连同「展开理由 + 终止条件自检（为什么还没到叶）」一起落盘。

**模式二·到叶**：中心 A 判定你到叶后，你按 L-叶子深挖规范执行调研。

## 展开判定自检（必须写在产出里）
对照 CONTEXT 第 7 节四条终止条件逐条回答：
1. 还能拆出 ≥2 个互不重叠、各有可命名候选的子任务吗？
2. 当前深度是否 ≥6？
3. 候选是否已全部查证、问题是否全部有答案？
4. 拟拆子任务与已有主库内容重复度是否 >70%？
→ 四条全否 = 必须展开；任一成立 = 声请"到叶"，由中心 A 裁决。

## 产出
- `{产出路径}`：子任务卡草稿 + 展开理由 + 自检结论
- 判死自查（CONTEXT 第 4 节四条）

## 禁止
- 不做深度调研（那是叶子的事）；不比较厂商、不下结论
- 不引用旧调研结论作为前提；不捏造候选（想不出可命名的候选/来源 = 到叶信号，如实报告）
