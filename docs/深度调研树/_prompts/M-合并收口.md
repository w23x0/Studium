# M-合并收口规范（v2 · 主库管理 + 最终收口）

## 一、合并（中心 A 每轮执行）
1. 去重归并：精确哈希 → 近似（SimHash/Jaccard≥0.85）→ 保留证据最强者为 PRIMARY
2. 多来源一致 → 合并为单条多来源记录（来源列表累加）
3. 冲突 → 冲突台账登记（不删旧、双方证据并列），交仲裁：
   - A 级原文 > B 级转引；带快照 > 无快照；日期新 > 日期旧（对时效性论断）
   - 无法裁决 → 标"待用户裁决"，写进收口报告
4. 主库组织：按主题目录，每条记录 = 论断/来源列表/证据等级/快照路径/合并历史/去重哈希

## 二、收口（全部任务终止后）
1. **合成报告**：按 CONTEXT 决策点逐点输出（候选方案/证据/兼容性/推荐/待实测，推断与实测分开）
2. **审计报告**：独立子代理复核（引文抽检+判死+红线冲突），结论追加
3. **缺口清单**：未覆盖/覆盖不足方向 → 建议新任务卡草稿
4. **主库索引**：全部 PRIMARY 记录的总索引
5. 全部落盘，更新任务队列全量 ARCHIVED，报告用户，goal 完成

## 禁止
- 合并时不得改变原论断语义；不得静默丢弃任何来源（归并项进回收站留痕）
- 仲裁依据必须写明；推断不得写成结论
