## 2. 一句话理解

Studium 是 Learning Agent 的第三次实现，也是新的唯一活动产品主线；它要构建的不是通用聊天工具，而是一个能陪伴学习、判断学习状态并推动学习闭环的个人学习系统。

第一阶段的最小用户链路是：

```text
用户提供 Markdown 学习资料
  -> 与 AI 进行多轮学习
  -> 系统记录会话
  -> 系统展示有证据的学习诊断
  -> 系统判断当前学习闭环是否完成
```

这里的核心产品对象应理解为“学习闭环”，而不只是“聊天消息”。回答问题只是教学动作之一，最终价值在于帮助用户沿当前认知位置继续学习，并留下可追溯的判断依据。

## 4. 当前形成的产品理解

以下是基于 Studium README 和 Deep 冻结归档形成的工作理解。它用于保持方向一致，但不自动等同于已经确认的接口或验收契约：

- 学习系统应以“开启、推进、举证、检查、关闭”的闭环组织状态，而不是只保存聊天轮次。
- 诊断必须能回到用户表现、对话内容和资料来源；标签或分数不能独立充当掌握真值。
- 闭环判断应保守。模型语气自信或用户说“我懂了”本身不构成充分证据。
- LLM 适合做语义理解、诊断假设和教学动作生成；确定性代码适合做字段校验、失败兜底和闭环硬条件守卫。
- 关键中间过程应可观察，以便判断模型看到了什么、为何采取某个动作、证据来自哪里以及守卫是否修正了结果。
- 一次优先推进一个足够小、可验收的学习动作，避免把大量后台任务和未来能力同时暴露给用户。

Deep 最后形成过四类闭环证据：解释动机、应用或推导、解释逻辑链、在变式或无提示条件下仍能提取。这四类证据是 M3/M4 设计时值得重新评审的历史候选，不是 Studium 已经确认的字段或算法。

## 5. 工程边界

- 同一职责只保留一个活动实现，只允许一套活动前端和一套活动后端。
- 里程碑必须贯穿用户操作、真实后端和真实模型或数据，不能用模拟成功代替验收。
- 前后端共享可校验契约，统一字段、错误语义和失败状态。
- 数据库、上传文件和模型缓存使用唯一、显式、绝对化的数据根目录；运行、测试和示例数据分离。
- 密钥只能进入环境变量或本地密钥存储，绝不提交 Git。
- 依赖通过正式包管理器安装并锁定版本；不整体复制第三方仓库或 Deep 的业务目录。
- 新抽象至少需要两个真实使用点。当前不为未来的 RAG、图谱、多供应商或桌面端预建平台。
- 共享契约、持久化和学习闭环需要自动化测试；没有实际运行验证时必须明确写“未验证”。

## 6. 与 Deep 的关系

`C:\Users\Wang\Desktop\Deep` 是前两代实现的冻结档案和参考实现，不是 Studium 的活动代码库或运行时依赖。

Deep 能提供的价值包括：

- 学习导航、证据闭环和可观察性的历史设计与复盘；
- 曾经实现过的学习链、闭环守卫、状态持久化和资料处理思路；
- 失败方式、技术债和范围膨胀的真实教训。

使用 Deep 时必须遵守：

- 不直接读写其数据库、运行数据、模型缓存和导入资料；其中存在私人学习数据和历史敏感配置。
- 不把旧 FastAPI、React、RAG、Gateway、数据模型或目录布局当成 Studium 已选技术方案。
- 不整体复制 `src/`、`frontend/`、`app/` 或第三方源码。
- 只有当前里程碑确实需要的最小单元，才能在重新评审依赖、接口、数据路径、许可证并补测试后迁入。
- Deep 的归档链接依赖本机兄弟目录，且归档入口在 Deep 当前工作树中尚未被 Git 跟踪，因此不能把它当作可移植的长期依赖。真正影响 Studium 的结论应写入 Studium 自身文档或 ADR。

## 7. 2026-07-14 仓库事实

当前仓库基线为：

- 活动分支为 `main`，M0 已有独立收尾检查点。
- M1 技术栈与 LiteLLM 边界由 ADR 0001 和 ADR 0002 固化。
- 唯一活动应用是根目录 Next.js 项目，唯一浏览器后端入口是 `POST /api/chat`。
- 前后端通过 Zod 共享非流式聊天契约；浏览器只传递 `user` 和 `assistant` 消息。
- LiteLLM 由 `infra/litellm/` 下的 uv 锁文件管理，使用 Python 3.13，不复制源码且不要求 Docker。
- 根目录 `npm run dev` 同时管理 Next.js 与 LiteLLM；安装、检查和构建命令以 README 为准。
- 自动化测试覆盖契约、API、网关错误映射和页面关键交互。
- 没有 Git remote、submodule、LFS 文件或 sparse checkout；不存在尚未拉取的隐藏应用代码。
- M1 不使用数据库或持久化业务数据；没有 CI。
- `.env`、`.next/`、`node_modules/` 和 uv 虚拟环境均被 Git 忽略，`.env.example` 保持可跟踪。

这个快照只描述更新交接文件时的事实。接手时仍应以实时目录、Git 状态、最新 README、ADR 和测试结果为准。

## 8. 尚未做出的决定

下列事项不能由接手者自行从 Deep 或 `.gitignore` 猜测：

1. LiteLLM 的 `studium-m1` 别名实际映射到哪个上游供应商和模型。
2. M1 真实模型手工验收使用的本地密钥。
3. 唯一数据根目录的位置和配置方式；M1 尚不产生持久化业务数据。
4. 仓库 remote、CI、许可证和发布范围。
5. M3 的诊断字段、证据格式和可靠性要求。
6. M4 的闭环关闭条件、用户覆盖机制和持久化模型。

这些决定应从当前里程碑的最小需求出发；长期有效的重大决定写入 `docs/decisions/`，不要只留在聊天记录中。
